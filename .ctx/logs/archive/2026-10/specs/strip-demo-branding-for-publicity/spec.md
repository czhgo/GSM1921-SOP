# GitHub Pages 宣传形态（去演示化 ＋ 十月活动 ＋ 旧本地数据自动失效）Spec

## Why

支书需要用 **GitHub Pages 静态托管** 的页面做**宣传截图**。当前静态页把「这是演示」写在了脸上（首页/登录页大标题是「示例组织（未登录）」、多处「演示账号 / Mock 校验 / 只读演示 / 进入支部（演示）」），且**没有十月活动**、存在**超期待办**；同时支书自己浏览器里残留着旧版演示数据（localStorage）与旧 JS 缓存，看不出哪里能清掉。

本变更让**静态托管这一份实例看起来就是一个真实在用的支部系统**（直接显示「光华管理学院本科生党支部」、页面无演示字样、十月有活动、无超期待办），并让**任何访客的旧本地演示数据自动失效回种子**，从而根除「旧测试数据」问题。

> 边界（支书明确）：**安装包（Node 一体化后端）仍保留「换壳 / 组织配置」环节**——支部名等仍由支部配置档案驱动、可被换壳向导改；本变更只调**默认种子与静态托管呈现**，不砍掉通用性与可配置性。

## What Changes

- **A. 静态托管直接显示真实支部名，清除全部用户可见「演示 / 示例」文案**
  - 未登录（静态壳）的页眉标题：由中性占位「示例组织（未登录）」改为**支部显示名**（数据驱动：支部配置档案名 → 静态兜底名 = 光华管理学院本科生党支部），不再带「（未登录）」后缀。
  - 首页 / 登录页 / 帮助页 / 关于页的静态 HTML 与 JS 文案：清除「示例组织」「以示例组织为例」「当前页面展示的是示例组织的一套部署」「演示账号」「Mock 校验 · 开发阶段」「进入支部（演示）」「只读演示形态」等表达；涉及**真实姓名 + 学号 + 口令**的演示账号提示一并移除（宣传页不得出现）。
  - 只读拦截提示语（写操作失败时）去掉「演示」字样，改为中性的「浏览模式 / 需登录后编辑」类表述。
  - 党委下钻支部的壳横幅「党委演示只读视图」改为中性表述。
- **B. 十月活动（静态与后端同源，`docs/src/data/mock/activities.js` 为单一源）**
  - `act-36`「党建思想学习会」：`2026-10-15`，已举办（`completed`）。
  - `act-37`「红色徒步·香山行（纪念长征胜利 90 周年）」：`2026-10-22`，计划中（`published`），户外参访载体。
  - 配套十月通知 1–2 条（首页「重要通知」不再只有 7 月内容）。
- **C. 旧本地演示数据自动失效（根除「旧测试数据」）**
  - 新增**种子数据版本号**常量；持久化写入时带上，读取时**版本不一致即整库丢弃并回种子**（顺带修掉「`_schema` 不匹配 → 空页」的既有隐患）。
- **D. 超期待办清零**
  - 种子待办中唯一一条过期项（`todo_seed_6`，截止 `2026-08-01`）重定向为十月主题、截止日改为未来；确保种子内**无任何过去截止的待办**。
- **E. 静态托管形态判定修正**
  - `DEPLOY_MODE` 在**非 Node 托管**（GitHub Pages / 直接打开 `docs/`）应为 `static`，避免静态页误入「服务端会话已失效」浮层、侧边栏缺「关于」等形态错位；Node 托管仍由 `server/app.js` 注入 `server`（不变）。
  - 运行 `node docs/scripts/bump-version.mjs` 统一刷新版本戳（破浏览器/CDN 缓存），帮助页写清 `?reset=demo` 的用法。
- **F. 守卫与文档同步**：更新因文案变更而失效的测试断言；新增/扩展一条「宣传页无演示字样 + 十月活动在册 + 种子无超期待办」的机检；登记执行日志/决策日志/TIMESTAMPS；**提交但不推送**。

## ADDED Requirements

### Requirement: 静态托管以真实支部名示人

静态托管（无后端）打开任一公开页时，系统 SHALL 以**支部显示名**（默认「光华管理学院本科生党支部」）呈现，**不得**出现「示例组织（未登录）」或任何「演示 / 示例 / Mock」字样。

#### Scenario: 未登录打开首页

- **WHEN** 访客在无登录态下打开 `docs/index.html`（静态托管）
- **THEN** 页眉标题显示「光华管理学院本科生党支部」，页面上不存在「示例组织」「演示」「Mock」等文案

#### Scenario: 换壳后仍随配置变化

- **WHEN** 部署方通过换壳向导修改支部名 / 页眉显示名
- **THEN** 页眉与首页标题随之更新（显示名仍是数据驱动，未被写死）

### Requirement: 十月活动在册且可见

静态与后端两形态 SHALL 在 2026 年 10 月呈现两场活动：「党建思想学习会」（10-15，已举办）与「红色徒步·香山行（纪念长征胜利 90 周年）」（10-22，计划中），且首页活动区默认落在十月。

#### Scenario: 打开首页活动日历

- **WHEN** 访客打开首页并查看活动（日历/列表）
- **THEN** 可看到上述两场十月活动，月份默认选中 2026-10

### Requirement: 种子无超期待办

系统种子数据 SHALL 不含任何「截止日早于当前日期且未完成」的待办；用户可见的「我的超期」区域在干净种子下为空。

#### Scenario: 干净种子下的工作概况

- **WHEN** 以干净种子进入含「我的超期」区的工作台
- **THEN** 该区无任何超期条目（显示「无超期…」类空态）

### Requirement: 旧本地演示数据自动失效

当浏览器本地持久化的演示数据版本低于当前种子数据版本时，系统 SHALL 丢弃该持久化数据并按当前种子重新初始化，使任何访客都看到最新、干净的演示基线。

#### Scenario: 老访客打开静态页

- **WHEN** 一个持有旧版演示数据（本地存储）的访客再次打开静态页
- **THEN** 本地旧数据被丢弃，页面按新种子里呈现（含十月活动、无超期待办）

### Requirement: 静态托管形态正确判定

非 Node 托管（GitHub Pages / 直接打开 `docs/`）下，部署形态 SHALL 判为 `static`；Node 托管下仍为 `server`。

#### Scenario: 静态页不误报会话失效

- **WHEN** 一个曾登录过的浏览器在静态托管下打开页面（无 API token）
- **THEN** 不出现「会话已失效」浮层，正常进入静态浏览形态

## MODIFIED Requirements

### Requirement: 未登录页眉标题占位

原判定：未登录 / 查无档案（静态壳）→ 中性占位「示例组织（未登录）」。现改为：未登录 → **支部显示名**（段⑤ 与段③ 同源：支部配置档案名，缺省取支部名兜底）；已登录但确无归属 → 仍为「未绑定支部」（不变）。

### Requirement: 只读拦截提示

原文案含「当前为只读演示：数据不会保存到本机，请登录后使用服务器数据。」现改为不含「演示」的中性表述（保留「不保存到本机 / 登录后可用服务器数据」语义）。

### Requirement: 党委下钻支部的壳横幅

原「党委演示只读视图 · {支部名}…」改为中性表述（保留「以党委组织员会话只读查看，写操作按角色权限拒绝」语义）。

### Requirement: 首页 / 登录页 / 帮助页头名与说明

原「示例组织（未登录）」与「本系统面向各类党支部与学生组织…当前页面展示的是示例组织的一套部署。」改为以本支部为主体的表述（必要时保留「开源通用、可各自部署」的说明，但**不出现「示例组织」「演示」字样**）。

## REMOVED Requirements

### Requirement: 静态页上的演示账号口令提示

**Reason**: 该提示公开暴露「演示/测试账号密码统一 123456」并列出**真实姓名 + 学号**；宣传形态下既不合「像真的」要求，也不合隐私要求。
**Migration**: 帮助页登录说明改为不列具体账号与统一口令的表述；真实部署的账号初始化改走「空库起步 / IAAA 登录 / 党委台建名册」路径（`DEPLOYMENT_GUIDE` / `SERVER_DEPLOY_MANUAL` 已有说明）。

### Requirement: 独立「进入支部（演示）」入口文案

**Reason**: 含「演示」字样、与真实系统观感冲突。
**Migration**: 该入口保留功能，文案改中性（如「进入支部（党委视角）」）。
