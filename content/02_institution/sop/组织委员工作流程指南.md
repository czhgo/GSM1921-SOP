# 组织委员工作流程指南

> 考勤与考察档案同源、思想汇报由党员系统内提交自动归档的规则，与纪检委员指南一致；公共规则见 [常见工作场景快速指南.md](./常见工作场景快速指南.md) 公共规则表。

> **一句话：** 统筹专班招募与发展党员的考察与材料准备。

**术语**（支部党员/支部成员/条条/块块）：见 [INDEX.md](./INDEX.md#术语)

## 适用角色

**组织委员**

- **专班招募**：统筹者——支书、副支书、组织委员均可管理专班（提出需求与招募统筹分离：支书/党小组组长/支委均可提出需求，统一由组织委员在系统内发起「发布招募」，发起即报送支委会表决，表决通过后进入招募）
- **发展党员的考察与材料准备**：考察档案 + 思想汇报 + 发展协助
- **数据共享**：考察档案与纪检委员的考勤数据通用同源

### 为什么这么做

- **两个动作**：发起是"提出需求"——支书、党小组组长、支委都可以提，由组织委员在系统内统一发起并即时报支委会表决；招募是"赋权+记账"——只有组织委员能做
- **如果不分离**：发起者自己招募（如宣传委员自己招募宣传专班），赋权记录散落在各委员手里，工作量记账和解散评议没有统一流程
- **统一招募的价值**：所有专班走同一套赋权→记账→解散流程

母本引用：[COMMISSIONER_DUTY_FRAMEWORK.md](../COMMISSIONER_DUTY_FRAMEWORK.md) §A.6 条块衔接规则 + §A.7 专班生命周期

## 工作台 — 专班管理视图（工作台内 tab）

> 在系统中，组织委员进入工作台后的落点为 **「今天」**；**专班管理**是其工作台内的一个 tab（进入后切换查看）。

> **设计考量**：专班不限时间、不限地点，涉及跨角色、不可拆分的任务需要集中跟踪协调——设专班管理 tab 集中跟踪，确保专班任务不被常规事务淹没。
> **协调观**：支书把「协调」看作**最小三成本原则的具体实现**——专班管理 tab 降低成员寻找专班信息的信息成本、操作成本与适应学习成本，是「管理事、服务人」在专班场景的落地。专班管理 tab 的设置由此获得原则级依据。
> 母本引用：[FLAT_ORGANIZATION_DESIGN.md](../FLAT_ORGANIZATION_DESIGN.md) §三 专班启动的适用条件 + [COMMISSIONER_DUTY_FRAMEWORK.md](../COMMISSIONER_DUTY_FRAMEWORK.md) §A.4 专班核心定义

### 任务流

| 步骤 | 动作 | 时机 |
|------|------|------|
| 1 | 审查「待支委会表决」列中的新专班需求（判定依据见下节） | 随任务产生——有待表决的新专班需求时即审 |
| 2 | 点击「发布招募」→ 填写招募表单（专班名称/任务描述/人数/截止日期/技能/周期起始/周期结束/初始成员/说明） | 确定需求后 |
| 3 | 招募确认后，将专班成员名单同步给纪检委员（纪检委员据此打包确认专班考察；名单统一由组织委员同步，见[纪检委员工作流程指南 §2.2](./纪检委员工作流程指南.md)） | 名单确定后 |
| 4 | 监控进行中列的成员产出与专班进度 | 持续跟踪 |
| 5 | 专班任务完成 → 归档 | 完成后 |

### 专班需求审查——发起条件与放行口径

组织委员是专班管理节点之一（CF §A.6）——支书、副支书、组织委员均可管理专班；需求由支书、党小组组长、支委提出，统一由组织委员在系统内发起（发布招募）；对不再推进的需求，组织委员可「撤销并删除」（不可恢复）。

**发起前须同时满足**：
- 立项：由支委会表决认定——系统内发起即报送表决，通过后进入招募，未通过则退回草稿重新报送
- 要素齐全：名称、人数、周期、考核标准等需求要素完整（CF §A.7），在招募表单中逐项写明（考核标准随「说明」一并写明）
- 必要性成立：专班不限时间、不限地点、跨职能又跨小组、目标导向，是活动之外考察积极分子的载体（CF §A.3/A.4）；满足「跨角色、不可拆分」两项适用条件（[FLAT_ORGANIZATION_DESIGN.md §三](../FLAT_ORGANIZATION_DESIGN.md)）——属人的判断，由组织委员在发起前把关
- 负责人就位：专班组织者（专班负责人）人选明确，由组织委员赋权后承接分工记录职责与专班考察上传（专班考察由专班负责人/组织委员上传，见[纪检委员工作流程指南 §2.2](./纪检委员工作流程指南.md)）

**退回（表决未通过）**：
- 需求未获支委会表决通过——系统内退回草稿，可修改方案后重新报送
- 需求要素缺失（未写明人数/周期等）
- 拟参与人数不清晰——专班成员来自任意党小组、不改变其党小组归属，同一同志可同时加入多个专班、工作量分别记账（CF §A.6），发起前须明确人数

> 处理时限：待支委会表决列的专班需求应及时处理；巡查随任务产生——有新的待表决需求就看，无事不必按固定频次巡查（任务流步骤 1）。
> 母本引用：[COMMISSIONER_DUTY_FRAMEWORK.md](../COMMISSIONER_DUTY_FRAMEWORK.md) §A.3/A.4/A.6/A.7 + §审批流程规范 二、三.1 + [FLAT_ORGANIZATION_DESIGN.md](../FLAT_ORGANIZATION_DESIGN.md) §三 + [SECRETARY_DIRECTIVES.md](../../01_strategy/SECRETARY_DIRECTIVES.md) P-013

### 验收成果

- [ ] 待支委会表决列的专班需求均已处理（表决通过或撤回）
- [ ] 每个进行中专班有明确的招募计划
- [ ] 全部完成专班已在归档库中可查
- [ ] 招募确认的专班名单已同步纪检委员

> **系统承载**：「发布招募」按钮点击后弹出招募表单（专班名称/任务描述/人数/截止日期/技能/周期起始/周期结束/初始成员/说明 9 项），状态按「待支委会表决 → 招募中 → 运行中 → 已完结 → 已归档」流转（表决未通过退回草稿，另有已解散态）。

## 发展党员的考察与材料准备

### 一、考察档案维护

**信息流**：
```
发展对象名单（支委会确定）
    │
    ▼
组织委员建立/维护考察档案
    │
    ▼
发展对象个人档案（含思想汇报 → 转正材料）
```

**任务流**：

| 步骤 | 动作 | 验收 |
|------|------|------|
| 1 | 获取发展对象名单 | 支委会会议纪要 |
| 2 | 建立考察档案（系统内为「数据交接·考察建档」确认接收；档案文本存 `content/03_doc_system/工作模板/`） | 档案目录完整 |
| 3 | 每半年更新考察意见（线下文本） | 有支书签字的考察表 |
| 4 | 转正前汇总全周期档案（线下移交） | 完整档案包移交支委会 |

> **数据同源提醒**：考察档案中的「活动出勤」数据，直接使用纪检委员维护的考勤系统数据，不与考勤表重复录入。「思想汇报」由党员在系统内提交，算法自动归档归集，组织委员查看调用。

> **考察档案记录结构**：每条考察记录包含以下信息——来源类型（活动/专班）、关联活动名称、参与类型（组织者/深度参与者/普通参与者）、具体角色描述、**记录人**；记录时间一并留存。

> **设计考量**：考勤同源而思想汇报不同源——考勤由组织者上传、纪检委员打包确认，组织委员直接读取避免数据冲突；思想汇报由党员在系统内直接提交、算法自动归档（纪检委员不介入），组织委员查看调用。两者写入方不同，数据流也不同。
> 母本引用：[SYSTEM_ROLE_PERMISSION.md](../SYSTEM_ROLE_PERMISSION.md)（系统角色权限矩阵）

### 二、思想汇报归档（算法归档）

**信息流**：
```
党员/发展对象在系统提交思想汇报（文本直接提交）
    │
    ▼
系统自动归档至对应个人档案（算法归集，无需人工归档环节）
    │
    ▼
组织委员查看/调用（考察时直接调用思想汇报记录）
```

> **流向说明**：思想汇报由党员/发展对象在系统内直接提交，提交即入库即归档——算法自动归集到对应个人档案，组织委员只做查看与调用，不再有「收齐→归档」的人工环节。纪检委员不介入思想汇报流程，仅负责考勤考察。

### 为什么这么做

- **职能归口**：组织委员承担发展党员的考察与材料准备，考察档案和思想汇报都是发展党员的核心材料，归口同一人确保材料衔接不断裂
- **权责分离**：纪检委员因权责分离要求不组建专班（审查权限不可转授），同理不介入思想汇报——纪律审查与思想表达分属不同职能

母本引用：[支委与党小组定人定责定岗说明.md](./支委与党小组定人定责定岗说明.md) §2.1 条条支委职责 + [COMMISSIONER_DUTY_FRAMEWORK.md](../COMMISSIONER_DUTY_FRAMEWORK.md) §A.6 条块衔接规则

**任务流**：

| 步骤 | 动作 | 验收 |
|------|------|------|
| 1 | 掌握各党小组思想汇报的提交情况（按系统「人 × 期次」台账） | 与系统归档记录一致 |
| 2 | 查看系统自动归集的思想汇报（系统已归档至个人档案） | 每份有日期标记 |
| 3 | 考察时调用思想汇报记录 | 记录完整可调用 |

### 三、发展党员协助

**信息流**：
```
支委会确定发展计划
    │
    ▼
组织委员启动材料准备
    │
    ▼
公示（线下） → 支部党员大会 → 上级审批（线下）
```

**关键动作**（按发展节点）：

| 节点 | 必须交付 |
|------|----------|
| 确定发展对象 | 发展对象登记表 + 考察档案初稿 |
| 接收预备党员 | 入党志愿书 + 公示材料 + 支部大会记录 |
| 预备党员转正 | 转正申请书 + 全年考察档案 + 支部大会决议 |

> 完整材料清单见附录 A「发展党员时间轴与材料清单」；材料文本在系统外办理，系统只做数据归集与提醒（见附录 A「系统提示」栏）。

## 附录 A：发展党员时间轴与材料清单

> 从入党申请人到正式党员的完整路径；除「思想汇报」在系统内提交外，材料与环节均线下办理，系统只对两个期满节点给出提醒（见「系统提示」栏）。

### 发展阶段与交付物

| 阶段 | 关键动作 | 必须交付 | 系统提示 |
|------|---------|---------|---------|
| 入党申请人 | 提交入党申请 | 入党申请书 | — |
| 积极分子 | 支委会确定 + 培养考察期一年以上 | 积极分子登记表 + 培养联系人考察记录 | 培养考察期满提醒 |
| 发展对象 | 支委会讨论确定 | 发展对象登记表 + 考察档案初稿 + 政审材料 | — |
| 预备党员 | 接收大会 + 公示 + 上级审批 | 入党志愿书 + 公示材料 + 支部大会记录 | — |
| 预备期 | 一年预备期考察 | 半年考察意见 + 思想汇报 | — |
| 正式党员 | 转正申请 + 支部大会 + 上级审批 | 转正申请书 + 全年考察档案 + 支部大会决议 | 预备期满提醒 |

### 各阶段材料清单

**积极分子阶段**：
- 积极分子登记表（姓名/班级/申请日期/培养联系人）
- 培养联系人考察记录（每半年一次，含考察意见和培养建议）
- 思想汇报（积极分子不作硬性要求，按实际培养与需要安排）

**发展对象阶段**：
- 发展对象登记表（含支委会确定日期）
- 考察档案初稿（含培养考察期全程记录）
- 政审材料（本人及直系亲属政治审查）
- 群众意见征求记录

**预备党员阶段**：
- 入党志愿书（本人填写）
- 公示材料（公示期不少于五个工作日——上级《中国共产党发展党员工作细则（2026年）》第十三条）
- 支部大会记录（含表决结果）
- 上级党组织审批意见

**转正阶段**：
- 转正申请书（预备期满前提交）
- 全年考察档案（含半年考察意见）
- 支部大会决议（含无记名投票结果）
- 上级党组织审批意见

## 检查清单

> 自查随任务产生，不按固定频次——任务走到哪一步就勾哪些项，做完即闭环。

### 专班管理
- [ ] 审查专班看板的「待支委会表决」列
- [ ] 专班归档审核

### 发展党员
- [ ] 考察档案更新（所有发展对象）
- [ ] 查看思想汇报提交情况（系统自动归集）
- [ ] 核对思想汇报提交完整（系统按人归集，查缺补漏）
- [ ] 发展对象全周期档案汇总
