# 未登录态身份与公共入口研究

> **本文负责**：回答「未登录用户应当看到什么、登录页品牌归谁、要不要做学院级统一入口」三个问题，给出三种可选方向及其代价与影响。
> **本文不负责**：① 现行角色与权限口径 → [SYSTEM_ROLE_PERMISSION.md](../../02_institution/SYSTEM_ROLE_PERMISSION.md)；② 多支部同实例的技术路线 → [ARCHITECTURE_EVOLUTION.md](./ARCHITECTURE_EVOLUTION.md)；③ 登录实现细节 → `docs/src/entries/pages/login-entry.js`。

## 一、现状事实

1. **未登录即访客**：`SYSTEM_ROLE_PERMISSION.md` 明确「未登录即访客（无角色键）」；公开读口只有归档活动等有限白名单（`server/routes/resources/index.js`）。
2. **登录页品牌按默认支部读**：`login-entry.js` 在未登录时读取 `DEFAULT_BRANCH_ID` 的 `headerTitle || name`，把「光华管理学院本科生党支部」写到登录页标题；`login.html` 的静态默认值却是中性的「党支部管理系统」。
3. **通知读侧已收紧**：2026-11-07 批次 535 起，未登录不读任何站内通知（`canReadNotice` / `list()` 均 fail-closed）。
4. **多支部同实例仅在设计稿**：生产强制一实例一支部（`D-849`、`ALLOW_MULTI_BRANCH`），没有「学院级统一入口」的数据模型与路由。

## 二、必须回答的问题

1. 上线形态是「一实例一支部」还是「一实例多支部 / 全学院」？
2. 登录页品牌应按实例、按学院，还是保持中性？
3. 未登录用户允许看到什么：无 / 学院公共信息 / 支部公开信息 / 归档活动？
4. 是否需要「统一公共入口」：学院级登录页 + 支部选择 / 自动路由，还是各支部分别给登录链接？
5. 与现有 `view_public`、归档活动公开读口、匿名反馈边界如何对齐？

## 三、三种方向

### A 最小收紧（推荐作为上线默认）

- **做法**：保持一实例一支部；未登录只显示中性的「党支部管理系统」，登录后再按支部档案显示支部名。
- **代价**：登录前看不到所属支部；需要支部另行告知登录链接。
- **影响**：不改路由、不改数据模型；只改登录页标题来源与一条守卫。
- **适用**：2026-11 上线窗口，支部数量少、入口由支书定向分发。

### B 学院级统一入口

- **做法**：中性品牌 + 学号登录 + 服务端按人解析支部并路由；登录前不显示任何具体支部名。
- **代价**：需要「人 → 支部」解析、待归属状态、跨支部路由与错误态；与多支部 Phase 1 强耦合。
- **影响**：新增服务端解析与路由，登录页与工作台入口都要改；测试面扩大。
- **适用**：全院统一推广、支部数量增加后。

### C 公共门户

- **做法**：学院 / 支部公开信息 + 登录入口；需先定义公开数据白名单与审核责任。
- **代价**：公开内容要有人审、有人负责；匿名可读会改变现有通知与档案的边界。
- **影响**：新增公开数据域与审核流程；与 `view_public`、归档公开读口重新对齐。
- **适用**：有对外展示需求时，单独立项。

## 四、推荐与边界

- **本批不改登录页品牌与路由**；先把通知读侧 fail-closed 落地，避免匿名读到定向通知。
- **上线默认取 A**：登录前中性、登录后显示支部名；B / C 进入独立 spec。
- **显式广播是否允许匿名**与本文同题：在 A 下仍保持未登录不可读；若未来要公开公告，按 C 的白名单单独放行。

## 五、验收判据（待裁定后）

1. 未登录页面标题不出现具体支部名（A / B）或只出现学院名（C）。
2. 未登录 `list()` 为空、`canReadNotice` 恒 false，除非显式公开白名单命中。
3. 登录后按人解析支部的唯一入口有测试覆盖（B）。
4. 公开数据白名单有审核责任人与过期机制（C）。
