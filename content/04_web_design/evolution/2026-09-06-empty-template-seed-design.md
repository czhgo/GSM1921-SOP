# 立项⑤：演示数据与空组织模板分离（Empty Template Seed）设计

日期：2026-09-06 · 状态：书记批准开 spec（仅设计，不动代码）
定位：模板型的另一半核心体验——clone 后既可直接跑完整演示，也能从**空组织模板**起步建自己的支部；从此演示 seed 与组织模板分层，换组织不必在演示历史上删改。

## Why

- 开源「模板型」需要一个**空组织可运行壳**：clone 下来的仓库不应只有"一套别人支部的演示历史"这一种形态——新组织要能直接以"我的支部还没数据"的空状态跑起来、再逐项填入（支部名 → 成员 → 活动）。
- 现在演示数据与模板耦合：`docs/src/mock/`（people/activities/attendance/seed/… + br-b1）是唯一形态，默认就带着整批演示人物（p1…，含滞留示范）与 7–9 月活动史；「30 分钟换壳指南」步骤 2 的"整体替换 mock"只能靠工作单手工完成，系统内无对应动作。
- 演示人物 id（p1…）是种子引用链的中心（mock-integrity 全量外键审计的锚点），在演示历史上删改极易断引用；"换组织"应当换一份**干净起点**，而不是逐条清洗别人的数据。

## 书记裁定记录（2026-09-06）

- 立项⑤正式启动（评估 P4c，大）：拆分「空组织模板 seed + 演示组织 seed」；seed 校验与一键重置成正式能力；服务端 seed 与 API 模式对齐（.ctx/REVIEW_QUEUE 立项⑤条目）。
- 与向导（立项④）**阶段三目标 1 数据预览划界**：数据预览=运行时 **overlay**（换名单先看效果，作用于视图、不落文件，属向导后续阶段）；本立项负责**文件/种子层**的模板与演示分离。两者互不依赖、语义互补。
- 做法顺序：先做**空模板 seed + 「建新支部（空模板 / 复制现有）」入口**；再做 **?reset=1 分层语义**（演示层重置 ≠ 空模板初始化）。

## 目标与边界

- **空模板 seed**：结构完整、业务为空——1 个空支部：支部名=待填占位；模块/产出块=默认全开（同现有"config null=全开"默认 profile，核心组固定）；people/activities/attendance/agenda/taskforces/notices/thought-reports 等业务域一律为空。
- **制度文本不在数据模板内**：content/02_institution 是仓库文件本体，随仓库分发，不进入 seed；换制度仍走替换入口表/换壳工作单。
- **空模板分支不引用演示人物 id**：引用完整性分层——模板域内引用为空（无 p1… 外键；席位空缺待任命），天然通过引用审计，审计规则按 seed 集分层复用。
- **新建支部入口**：党委台/向导（两种源=**空模板初始化 / 复制现有支部配置**，后者复用向导阶段二已落地的复制语义）；写口沿用 branch 服务既有校验与留痕。
- **服务端对齐**：server seed（server/seed.js，已同源导入 ../docs/src/mock/*）与前端 mock 同源；空模板可由服务端接口创建（API 模式与前端一致）。
- **?reset=1 语义不变**：保持"回演示种子"（浏览器演示层回滚）；空模板初始化另置动作（建新支部），两者不混。
- **与数据预览（目标 1）的关系**：预览=运行时 overlay 不落文件；空模板=文件层新 seed；实现时复用既有 sanitize/净化规则（config-clean 一族），各自独立演进。

## 验收判据（布尔可测）

1. 新空支部可创建：people/activities/attendance/agenda 等业务域为空，config 默认全开。
2. 空模板及其创建的支部**不出现对演示成员 id（p1…）的任何引用**。
3. 在向导对空支部走完 5 步可生成「换壳工作单」（向导报告纯函数对空支部可产出）。
4. 服务端/API 创建空支部与前端 mock 结果一致（双形态对齐）。
5. `?reset=1` 仍回到完整演示种子（既有行为不回退）。
6. 既有 mock-integrity 审计对演示支部不受影响（演示侧保持全绿）。

## 风险与缓解

- **seed 拆分冲击 mock-integrity 全量审计/跨域引用** → 模板遵循"域内引用为空"硬约束，不产生跨域外键；审计按 seed 集分层（演示集审引用完整性、模板集审结构合法性）。
- **演示数据刷新（7–9 月真人名基线）与模板并存的双份 seed 体积** → 空模板=结构清单+空数组，体积可忽略；以同一 collection 抽象+派生默认避免双份维护。
- **工作量分阶段评估**：阶段 A=空模板 seed+创建接口+向导入口；阶段 B=?reset 分层语义与服务端对齐；阶段 C=模板市场化/党委默认模板——C 视多支部场景成形再说（与立项④阶段三登记同口径）。
