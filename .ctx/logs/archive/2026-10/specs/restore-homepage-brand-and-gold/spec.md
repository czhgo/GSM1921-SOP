# 首页抬头、按钮体例与金色回归修复 Spec

## Why

支书实机审查发现三处视觉回归，并质疑党委台支部数据存在计算盲区：

1. **首页组织名与图像消失**：批次 480（`661928088`）以「顶栏 H1 已有品牌」为由，删除了首页的党徽 + 组织名 H2。支书明确要求首页必须保留「抬头式」品牌块。
2. **按钮变丑、半透明底色消失**：批次 477 把按钮收成四类，批次 478 又把主 CTA 改为 `--app-accent-strong`（58% 主题色 + 黑）。在默认金色下，主 CTA 被压成深棕色，半透明主题底的高频动作也退成白底描边。
3. **金色变成深棕色**：批次 462-466（`5da2d0d72`）把默认主题色定为 `#A16207`（amber-700），这是琥珀/深棕，不是党徽金。支书不能接受。
4. **党委台支部数据**：实测 `支部管理` 已显示「50 人 / 21 人」，API summary 还含活动 35 / 专班 8 / 通知 14；`查看该支部` 已能进入完整名册。**没有计算盲区**，缺的是摘要可见性与行内名册。

本 spec 只修这四处回归，不重开 Round 3/4 全量审查。

## What Changes

- **首页抬头恢复**：恢复党徽 48px + 动态支部名（`getHeaderTitle`，不写死示例支部名）+ 一行副标题；位置在统计卡上方。
- **金色改回真金**：默认金 `#F5C518`（支书圈定现代金）；金色实底按钮改深色字，非金色角色仍白字；半透明底仍走主题色。
- **按钮体例恢复**：`.btn-accent-soft` 恢复为「次主操作 / 高频行内动作」的统一外观（主题色透明底 + 主题色描边 + 可读深字）；`.btn-outline` 只留取消 / 中性 / 低频。
- **党委台支部管理**：补「活动 / 专班 / 通知」三列摘要；每行可展开本支部名册（行内，不跳转）；保留「查看该支部」完整只读页。
- **回归守卫**：首页抬头、金色令牌与按钮前景对、支部摘要三列与行内名册各加静态/真机守卫。
- **Round 3 + Round 4 合并审查**：按支书「两轮合为 1 轮」的要求，六个 lens 一次进场、一份报告、一次 frontier；R3 / R4 的输入清单在 Part B 逐条列明。
- **分批修复**：Part A 回归修复先落；Part B 审计后按「低风险高价值 → 结构性改造」分两批修复。

## Impact

- 受影响页面：首页、7 个工作台（按钮体例）、党委台「支部管理」。
- 受影响代码：`docs/index.html`、`docs/src/entries/pages/main-entry.js`、`docs/src/styles.css`、`docs/src/core/domain/constants.js`、`docs/src/core/boot/theme.js`、`docs/src/core/boot/bootstrap.js`、`docs/src/entries/pages/settings-entry.js`、`docs/src/components/governance/org-setup-wizard.js`、`docs/src/entries/tabs/party-committee/branches-tab.js`、`server/routes/resources/branch-scope.js`（只读 summary 已足，预计不改）。
- Part B 受影响面：7 个工作台、关键公共页、共享组件、数据/API 读口；只读审查，修复按审计结果分批。
- 不受影响：后端权限链、数据模型；党委台只读边界不变。

## ADDED Requirements

### Requirement: 首页抬头式品牌块

首页 SHALL 在统计卡上方展示品牌块：

1. 党徽图像（`assets/images/party_emblem.png`，48×48，`alt="党徽"`）。
2. 组织名标题读取 `getHeaderTitle`：登录时按本人支部；未登录按支部显示名；**不得写死示例支部名**。
3. 一行副标题「党支部工作台」。
4. 顶栏 H1 保留；首页品牌块与顶栏不互斥。

#### Scenario: 已登录支书打开首页

- **WHEN** 支书打开 `index.html`
- **THEN** 统计卡上方出现党徽与本支部名称
- **THEN** 未登录打开时显示支部显示名，不出现「示例组织」硬编码

### Requirement: 金色与按钮前景对

系统 SHALL 用真金而不是深棕：

1. 默认主题金改为 `#F5C518`；默认背景/描边用同色相透明度。
2. 金色实底按钮（`.btn-accent`）使用本色金底 + 深色字（`#1F2937`），不再用白字或 58% 压深。
3. 非金色角色（红/绿/蓝等）继续用压深实底 + 白字。
4. `.btn-accent-soft` 的深字由同一前景对决定：亮色主题用深中性字，暗色主题用主题色深字。
5. 新增 `--app-accent-ink` / `--app-accent-text` 令牌，注入点与 `--app-accent` 三件套同源。

#### Scenario: 默认金主题

- **WHEN** 用户未设置个人主题色
- **THEN** 主 CTA 是金底深字，不是深棕底白字
- **THEN** 次主操作是半透明金底 + 深字，不是白底描边

### Requirement: 按钮体例恢复

系统 SHALL 恢复「半透明主题底」的高频动作体例：

1. `.btn-accent-soft` = 主题色透明底 + 主题色描边 + 可读深字；用于次主操作与高频行内动作。
2. `.btn-outline` = 白底中性描边；只用于取消 / 中性 / 低频动作。
3. `.btn-accent` 仍是每屏最多 1 个主操作。
4. 不撤销四类收口；只恢复外观与使用映射，不新增第五族。

#### Scenario: 工作台行内动作

- **WHEN** 用户看到「改派 / 补选 / 排入表决 / 确认生效」等高频动作
- **THEN** 按钮有主题色半透明底，不再一律白底

### Requirement: 党委台支部摘要与行内名册

党委台「支部管理」SHALL 同时提供摘要与名册：

1. 在现有「成员 / 在册党员」之外，补「活动 / 专班 / 通知」三列；数值取 API `summary` 的 `activityCount`、`taskforceCount`、`noticeCount`，运行中数量可并列展示。
2. 每行提供「名册」展开键；展开后在本行下方显示该支部成员（姓名 / 党小组 / 发展阶段 / 档案入口），数据取 `PersonStore.getMembers()` 按 `branchId` 过滤。
3. 保留「查看该支部」完整只读页入口。
4. summary 缺失时显示「—」，不得显示 0 冒充真实数据。

#### Scenario: 党委组织员查看本科生党支部

- **WHEN** 打开「支部管理」
- **THEN** 行内可见 50 人 / 21 人 / 35 场活动 / 8 个专班 / 14 条通知
- **THEN** 点「名册」可就地看到 50 名成员，不必先跳转

## Part B：Round 3 + Round 4 合并审查与修复

### 为什么合并

支书裁定「如果条件允许，可以两轮合为 1 轮」。Round 3 剩余项以布局 / 交互 / 文案为主，Round 4 剩余项以表单标签 / 数据结构为主；两者共享同一份页面清单与真机证据，拆两批会重复进场。本 spec 把 R3 / R4 合成一次审查、一份报告、一份修复清单。

### 审查 lens

| 轨道 | lens | 关注 |
|---|---|---|
| Round 3 | `frontend-design` / `design-with-taste` / `uicraft` | 功能完整性、视觉主张、手感与动效 |
| Round 4 | `fullstack-developer` / `domain-modeling` / `backend-architect` | 前端呈现、服务端写口、数据模型与权限链 |

- 六个子代理各自只加载一个 skill、不互读报告。
- 共享同一份页面清单：7 个工作台 + 关键公共页 + 数据/API 读口。
- 输出：`.ctx/AUDIT_ROUND3_4_COMBINED.md`（六路结果 + 共识 / 分歧 / 待裁定 + 归属）+ 修复 tasks。
- 停线：先出审计报告与修复清单，再按优先级分批实施；不一次性重写 68 页签。

### R4 额外范围

- 只读审查服务端写口 / 权限链 / 数据模型，不在本批改后端。
- 重点：表单 label 体系、宽表卡式化、错误文案按状态码分流、日历键盘可达、看板 / 专班卡语义化、通知下拉嵌套、重绘后焦点恢复。

### 合并审查的裁定纪律

1. 六路汇总后只开**一次** frontier，所有待裁定集中问。
2. 未回答项保持「待裁定」，不写成默认值。
3. 修复清单只收已裁定项；未裁定项留在审计报告。
4. 修复按「低风险高价值 → 结构性改造」分两批，避免一次性重写。
