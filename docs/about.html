光华管理学院本科生党支部管理引擎

GSM1921-SOP · 系统说明书

一、系统概述

本系统是北京大学光华管理学院本科生党支部的数字化管理工具，基于双域管理理论构建——将党支部工作划分为党建工作（创新探索·面向未来）与党务工作（合规运行·面向存量）两大域。系统提供活动日历、专班管理、三委员职能面板、归档回溯与 SOP 资料查询等核心能力，通过多页面架构（MPA）为不同角色提供差异化的工作视图。

二、核心理论

2.1 双域分化

党建与党务不是同一回事。党建工作面向"尚不存在的未来"（策划品牌活动、设计工作方法），强调创新与探索；党务工作面向"已存在的存量"（党员发展流程、补课制度、档案归档），强调合规与运行。两者是产品关系——党建工作产出"怎么做"的方法论，党务工作将其固化为"这样查"的标准规程。

2.2 条块二元结构

条条（职能域）：组织/宣传/纪检三大支委，纵向贯穿所有活动。在党建维度中，宣传委员与纪检委员服务于活动和专班，通过看板视图管理所辖领域的任务，而不直接写入活动。
块块（活动域）：党小组组长按行政/学术方向划分，横向统筹党小组活动。

2.3 决策树四层模型

快速定位能力由浅入深分为四层：默认信息面板（零操作 → 全局概览）→ 角色-规则基线（选角色 → 按规则呈现）→ 决策树向导（按流程 → 交互决策）→ 自由组合面板（深度定制）。

2.4 视图模式（管理模式 / 只读模式）

只读模式：浏览查阅，任何人均可查看全量日历视图。日历视图的核心作用是提醒参与者何时何地参会。
管理模式：编辑写入。条条支委（组织/宣传/纪检委员）天然拥有各自板块的管理权限，其视图为任务看板而非日历——因为他们的工作服务于活动和专班，而不是作为参与者被提醒参会。党支部书记和党小组组长拥有活动写入和专班发起的全面管理权限；党小组组长、条条支委、书记均可发起专班，由组织委员负责招募统筹。
赋权逻辑以 localStorage 模拟（对接用户数据库后台后替换），当前所有需赋权角色均已 Mock 赋权。

三、页面索引

主页（index.html）— 通知公告 + 招募信息 + 活动日历摘要；双卡片 + 单栏布局
党建工作台（workspace.html）— 活动日历创建与编辑、专班发起与管理、角色过滤；条条支委使用任务看板视图，日历视图服务于参与者
党务管理（party.html）— 党员发展全流程（组织委员）+ 宣传委员档案与周报 + 纪检委员考勤补课 + 党支部书记全局聚合；tab 切换 + 子 tab
归档库（archive.html）— 已完成工作归档与回溯；搜索 + 类别过滤
资料查询（search.html）— 合规文件 · 操作指南 · SOP 文档 · 外部链接；分类筛选
意见反馈（feedback.html）— SOP 优化提案反馈表单；Scope/PainPoint/ProposedFix 三要素

四、权限体系

写入权限域授权人享有角色
职能域写入天然权限组织委员 / 宣传委员 / 纪检委员（各自板块）
活动域写入党支部书记 / 党小组组长党支部书记、党小组组长（全域）
活动域写入（需赋权）党小组组长活动组织者 / 深度参与者（经赋权后）

注：只读模式对所有角色开放日历视图浏览。管理模式仅对已赋权角色开放写入。条条支委在管理模式的视图为任务看板而非日历。

五、技术栈

  • 纯前端静态架构 — 无需后端部署
  • ES Modules — 无构建工具、零打包依赖
  • Tailwind CSS CDN — 原子化样式引擎
  • sessionStorage / localStorage — 跨页面状态持久化
  • Custom Events — 组件间解耦通信
  • 多页面应用（MPA）— 7 个独立 HTML 页面
