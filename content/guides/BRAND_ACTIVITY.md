## A. 品牌活动的定义与核心理念

### A.1 定义

品牌活动是支部长期培育、持续迭代、逐步完善的动态工作项目。它不仅具有展示意义，更代表着需要持续更新、跟进打造的逐步完善的动态过程。

品牌活动的核心价值在于：

- **持续性**：品牌活动不是一次性事件，而是需要跨学期、跨年度持续投入和迭代优化的长期项目
- **成长性**：品牌活动有明确的成长路径（萌芽→培育→成熟→标杆），每个阶段有不同标准和支持策略
- **迭代性**：每期活动完成后必须复盘，基于反馈持续改进，形成"执行→复盘→优化→再执行"的闭环
- **体系性**：品牌活动不是孤立的活动，而是围绕特定主题形成的方法论、资源库和人才梯队

### A.2 核心价值

品牌活动的核心价值体现在四个维度，每个维度对应不同的管理策略和评估重点：

| 核心价值 | 含义 | 管理策略 | 评估重点 |
|---------|------|---------|---------|
| 持续性 | 跨学期、跨年度的长期投入 | 长期排期保障、资源持续投入 | 活动频次、时间跨度 |
| 成长性 | 有明确的成长路径和阶段标准 | 阶段性目标设定、成长支持策略 | 评分趋势、阶段晋升 |
| 迭代性 | 执行→复盘→优化→再执行的闭环 | 强制复盘机制、改进措施追踪 | 迭代次数、改进执行率 |
| 体系性 | 围绕主题形成方法论和资源库 | 知识沉淀、人才梯队建设 | 方法论产出、人才储备 |

### A.3 品牌活动生命周期

品牌活动遵循四阶段生命周期，每个阶段有明确的特征、标准和支持策略：

```
萌芽期（第 1 学期）
    │
    │  特征：首次尝试，探索可行性
    │  标准：完成 1-2 次活动，初步形成流程
    │  支持：支委指导、资源倾斜
    │
    ▼
培育期（第 2-3 学期）
    │
    │  特征：流程固化，质量提升
    │  标准：活动频次稳定，参与度提升
    │  支持：质量评估机制、团队建设
    │
    ▼
成熟期（第 4 学期+）
    │
    │  特征：品牌效应显现，可复制推广
    │  标准：成为支部对外展示核心品牌
    │  支持：对外传播、经验输出
    │
    ▼
标杆期
    │
    │  特征：获上级认可和推广
    │  标准：形成完整品牌故事和传播素材
    │  支持：学院/学校层面推广
    ▼
```

**阶段与品牌评分的对应关系**：

| 阶段 | 品牌评分预期 | 品牌标签 | 典型特征 |
|------|------------|---------|---------|
| 萌芽期 | 40-55 分 | 铜标候选 | 初步成型，流程待优化 |
| 培育期 | 55-70 分 | 铜标→银标 | 流程固化，质量稳定 |
| 成熟期 | 70-85 分 | 银标→金标 | 品牌效应显现，可复制 |
| 标杆期 | 85+ 分 | 金标 | 获上级认可，成为标杆 |

## B. 品牌活动案例

### B.1 宣讲团建设

**品牌属性**：持续性品牌项目（跨学期迭代）

```
成长路径：
萌芽期（第1学期）→ 培育期（第2-3学期）→ 成熟期（第4学期+）→ 标杆期

萌芽期：
- 首次组建宣讲团，确定宣讲主题和受众
- 活动频次：1-2次/学期
- 参与人数：10-15人
- 品牌评分预期：40-55分（铜标候选）

培育期：
- 形成固定宣讲团队和选题库
- 建立宣讲质量评估机制
- 活动频次：2-3次/学期
- 参与人数：15-25人
- 品牌评分预期：55-70分（铜标→银标）

成熟期：
- 宣讲团成为支部对外展示的核心品牌
- 形成可复用的宣讲模板和培训体系
- 活动频次：3-5次/学期
- 参与人数：25-35人
- 品牌评分预期：70-85分（银标→金标）

标杆期：
- 宣讲团获学院/学校认可和推广
- 形成完整的品牌故事和传播素材
- 活动频次：5次+/学期
- 品牌评分预期：85+分（金标）
```

**迭代机制**：
- 每次宣讲后收集听众反馈（满意度+建议）
- 季度复盘：分析参与度趋势、内容质量评分、新成员加入率
- 学期迭代：更新选题库、优化宣讲形式、培养新宣讲人

### B.2 人生回望录（老教授访谈活动）

**品牌属性**：特色品牌项目（深度内容驱动）

```
成长路径：
萌芽期（第1学期）→ 培育期（第2-3学期）→ 成熟期（第4学期+）

萌芽期：
- 首次访谈1-2位老教授，形成访谈记录
- 建立访谈流程规范（预约→准备→访谈→整理→审核→发布）
- 活动频次：1-2次/学期
- 品牌评分预期：40-55分（铜标候选，创新性维度得分高）

培育期：
- 形成固定访谈团队，建立老教授资源库
- 访谈内容开始产出系列成果（文章/视频/音频）
- 建立与学院宣传渠道的对接
- 活动频次：2-3次/学期
- 品牌评分预期：55-70分（铜标→银标）

成熟期：
- "人生回望录"成为支部文化品牌
- 形成完整的访谈方法论和内容生产流水线
- 访谈成果被学院官网/公众号转载
- 活动频次：3-4次/学期
- 品牌评分预期：70-85分（银标→金标）
```

**迭代机制**：
- 每次访谈后评估内容质量（深度/可读性/传播效果）
- 季度复盘：分析传播数据、受众反馈、老教授满意度
- 学期迭代：优化访谈问题设计、提升内容制作质量、拓展传播渠道

### B.3 案例对比与启示

| 对比维度 | 宣讲团建设 | 人生回望录 |
|---------|-----------|-----------|
| 品牌属性 | 持续性品牌项目 | 特色品牌项目 |
| 驱动力 | 频次驱动（高频次→高参与） | 内容驱动（深度内容→高影响力） |
| 成长速度 | 渐进式（4学期达成熟） | 渐进式（3学期达成熟） |
| 成长性得分来源 | 迭代次数多、频次稳定 | 评分趋势提升快、创新性加分 |
| 关键成功因素 | 团队稳定性、选题更新 | 内容质量、传播渠道 |
| 迭代重点 | 宣讲形式优化、新宣讲人培养 | 访谈问题设计、内容制作质量 |
| 标杆期特征 | 学院/学校认可推广 | 学院官网/公众号转载 |

**启示**：
- 不同类型的品牌项目有不同的成长节奏和评估侧重点
- 成长性维度应兼顾"迭代次数"和"评分趋势"，避免单一指标偏颇
- 品牌活动管理应因项目类型施策，不宜一刀切

## C. 品牌认定标准与流程

### C.1 硬性门槛

品牌活动的认定需先通过硬性门槛校验，不满足则无法参评：

| 条件 | 阈值 | 说明 |
|------|------|------|
| 活动状态 | `status === 'completed'` | 仅已完成的活动可参评 |
| 归档状态 | `archived !== true` | 已归档的活动不可参评（可考虑"历史品牌"独立维度） |
| 活动类型 | 限定类型集合 | 主题党日、组织生活会、党员培训等指定类型 |
| 时间范围 | 近 24 个月内 | 过期活动自动移出品牌候选池 |

### C.2 量化评分维度

采用加权评分模型，满分 100 分。在原有五维评分基础上，新增"成长性"维度，"创新性"降为子指标：

| 维度 | 权重 | 指标 | 计算方法 |
|------|------|------|---------|
| 参与度 | 25% | 实际参与人数 / 支部总人数 | `min(participantCount / totalMembers * 100, 100)` |
| 成长性 | 20% | 品牌活动的迭代次数与评分趋势 | 迭代次数得分(0-60) + 评分趋势得分(0-40) |
| 影响力 | 25% | 支委评议 + 参与者反馈 + 外部传播 | 1-5 星评价 + 外部转载/采纳记录 |
| 规范性 | 15% | 材料完整度（总结报告 + 照片 + 考勤） | `(hasReport + hasPhotos + hasAttendance) / 3 * 100` |
| 活动频次 | 15% | 同类型活动 12 个月内举办次数 | 频次映射表 |

**成长性维度详解**：

成长性维度由两个子项构成：

- **迭代次数得分**（满分 60 分）：

| 迭代次数 | 得分 |
|---------|------|
| 首次 | 10 分 |
| 2 次 | 25 分 |
| 3 次 | 40 分 |
| 4 次 | 50 分 |
| 5 次及以上 | 60 分 |

- **评分趋势得分**（满分 40 分）：

| 评分趋势 | 得分 |
|---------|------|
| 与上次评分持平 | 20 分 |
| 提升 5 分以内 | 30 分 |
| 提升 5-10 分 | 35 分 |
| 提升 10 分以上 | 40 分 |
| 下降 | 0 分 |

**创新性子指标**：

创新性不再作为独立评分维度，而是作为影响力维度的加分项：

| 创新性表现 | 影响力维度加分 |
|-----------|-------------|
| 活动形式有显著创新 | +5 分 |
| 获学院/学校认可推广 | +8 分 |
| 形成可复用的方法论/模板 | +5 分 |
| 创新性加分上限 | +10 分（不超过影响力维度满分） |

### C.3 评分算法

```
算法：BrandScore(activity, config) → 0-100

─────────────────────────────────────────────────────────
function calculateBrandScore(activity, config) {
  // Step 1: 硬性门槛校验
  if (!passHardThreshold(activity)) return null;

  // Step 2: 各维度得分计算
  const scores = {
    participation: min(activity.participantCount / TOTAL_MEMBERS * 100, 100),
    growth:        calculateGrowthScore(activity),
    impact:        calculateImpactScore(activity),
    completeness:  calculateCompleteness(activity),
    frequency:     calculateFrequencyScore(activity.type, activity.date),
  };

  // Step 3: 加权求和
  const weights = config.weights; // 从品牌配置读取
  let totalScore = 0;
  for (const [dim, score] of Object.entries(scores)) {
    totalScore += score * weights[dim];
  }

  return Math.round(totalScore);
}

成长性得分计算:
  function calculateGrowthScore(activity) {
    const iterationScore = calculateIterationScore(activity.iterationCount);
    const trendScore = calculateTrendScore(activity.previousScore, activity.currentScore);
    return iterationScore + trendScore;
  }

  迭代次数得分:
    首次=10, 2次=25, 3次=40, 4次=50, 5次+=60

  评分趋势得分:
    持平=20, 提升<5=30, 提升5-10=35, 提升>10=40, 下降=0

影响力得分计算:
  function calculateImpactScore(activity) {
    let baseScore = activity.impactRating ? activity.impactRating * 20 : 50;
    let innovationBonus = calculateInnovationBonus(activity);
    return min(baseScore + innovationBonus, 100);
  }

频率分计算逻辑（以 12 个月窗口）:
  举办 1 次 → 20 分（有初步体系）
  举办 2 次 → 40 分
  举办 3 次 → 60 分
  举办 4 次 → 80 分
  举办 5 次及以上 → 100 分（成熟品牌）

材料完整度:
  总结报告: deliverable 中有对应 .md 或 .pdf → 33.3 分
  活动照片: activity.photoUrls.length > 0 → 33.3 分
  考勤记录: attendance 中有对应记录 → 33.3 分

### C.4 认定流程

品牌认定采用五步流程，在原有四步流程基础上增加"复盘迭代"步骤：

```
[活动组织者/党小组组长]
        │
        │ ① 自荐：提交活动参选品牌认定
        ▼
[支委评审会]
        │
        │ ② 支委评审：执行评分算法 + 人工评议
        │    - 系统自动计算量化维度得分
        │    - 支委对影响力、创新性加分进行人工评定
        │    - 加权求和生成 brandScore
        ▼
[党支部书记]
        │
        │ ③ 书记审批：终审确认品牌等级
        │    - 审核评分合理性
        │    - 确认品牌等级归属
        ▼
[系统标记]
        │
        │ ④ 标记品牌：写入 Activity 扩展字段
        │    - brandScore: 评分
        │    - brandLevel: 等级
        │    - brandCertifiedAt: 认定时间
        │    - brandTags: 标签
        ▼
[复盘迭代]
        │
        │ ⑤ 复盘迭代：活动完成后30天内
        │    - 收集参与者反馈
        │    - 支委评审改进点
        │    - 更新品牌评分
        │    - 制定下期优化方案
        ▼
[下一期活动策划]
```

**复盘迭代的执行规范**：

| 步骤 | 时间节点 | 责任人 | 产出物 |
|------|---------|--------|--------|
| 收集参与者反馈 | 活动完成后 7 天内 | 活动组织者 | 满意度问卷汇总、建议清单 |
| 支委评审改进点 | 活动完成后 14 天内 | 支委评审会 | 改进点清单、优先级排序 |
| 更新品牌评分 | 活动完成后 21 天内 | 系统自动 + 支委确认 | 更新后的 brandScore |
| 制定下期优化方案 | 活动完成后 30 天内 | 活动组织者 + 支委 | 下期优化方案文档 |

### C.5 品牌标签体系

采用三级标签体系，与评分阈值挂钩，并增加成长阶段标注：

| 等级 | 标签 | 评分阈值 | 容量限制 | 展示权重 |
|------|------|---------|---------|---------|
| 标杆 | 金标 | >= 85 分 | 每年最多 3 个 | Hero 轮播 + 首页置顶 |
| 优秀 | 银标 | >= 70 分 | 每季度最多 5 个 | 精选推荐卡片 |
| 特色 | 铜标 | >= 55 分 | 展示 top 10 | 分类橱窗列表 |

**成长阶段标注**（附加在品牌标签后）：

| 阶段标注 | 含义 | 展示效果 |
|---------|------|---------|
| 萌芽 | 首次开展，处于萌芽期 | 标签旁显示"萌芽"标识 |
| 培育 | 已迭代 2-3 次，处于培育期 | 标签旁显示"培育"标识 |
| 成熟 | 已迭代 4 次以上，处于成熟期 | 标签旁显示"成熟"标识 |
| 标杆 | 获上级认可推广，处于标杆期 | 标签旁显示"标杆"标识 |

**淘汰机制**：

- 品牌评分每季度重新计算一次（活动时间超过 24 个月自动移出）
- 同类型活动品牌数量上限为 5 个（避免某一类型垄断）
- 首页置顶位置为稀缺资源（3 个），采用"自动排序 + 支委手动调整"双轨制
- 连续两个季度评分下降的品牌活动降级处理

## D. 网页架构与展示

### D.1 定位原则

品牌活动在当前 SOP 引擎中不应被视为与"推演工作台""参考指南""模板与资产"平行的第四模块。其本质包含两层：

1. **展示层**：对活动资产的精选维度，是对既有活动数据的二次组织与突出呈现
2. **迭代驱动层**：品牌活动的成长性、迭代性特征要求系统不仅展示结果，更要驱动"执行→复盘→优化→再执行"的闭环

当前四个模块的分工如下：

| 模块 | 定位 | 数据来源 | 面向角色 |
|------|------|---------|---------|
| 推演工作台 | 操作层：创建、排期、跟踪活动 | 用户创建 + SOP 模板实例化 | 活动组织者、支委 |
| 参考指南 | 知识层：制度流程查阅、角色职责 | content/SOP/*.md 母本 | 全体 |
| 模板与资产 | 资源层：下载官方模板 | content/references/模板库/ | 全体 |
| **品牌活动** | **展示层 + 迭代驱动层：精选优质活动的聚合入口 + 品牌成长闭环驱动** | 推演工作台中的活动数据 + 复盘迭代数据 | 全体（对外展示 + 内部迭代） |

### D.2 信息架构

采用三级信息架构：

| 层级 | 页面 | 内容 | 路由 |
|------|------|------|------|
| 时间线 | 品牌活动首页 | Hero 轮播 + 精选推荐 + 品牌榜 + 筛选列表 | `#/brand` |
| 卡片 | 品牌活动详情 | 基本信息 + 评分雷达图 + Timeline + 照片墙 + 分享 | `#/brand/detail/:id` |
| 详情 | 年度品牌回顾 | 数据大盘 + TOP 10 榜单 + 月度热度图 + PDF 导出 | `#/brand/annual/:year` |

### D.3 与现有模块的集成

```
                    ┌──────────────────────────┐
                    │    推演工作台（操作层）      │
                    │  Activity CRUD + Timeline  │

                    └───────────┬──────────────┘
                                │
        ┌───────────────────────┼───────────────────────┐
        │                       │                       │
        ▼                       ▼                       ▼
  ┌──────────┐          ┌──────────┐           ┌──────────┐
  │ 品牌活动  │  ◄──参考──│ 参考指南  │──引用───►│ 模板与资产│
  │ 展示层    │          │ 知识层    │           │ 资源层    │
  │+迭代驱动层│          └──────────┘           └──────────┘
  └─────┬────┘
        │
        ▼
  ┌──────────┐
  │ 党务管理  │  ← 三委角色在品牌认定中的分工
  │ 组织建设  │

```

- **品牌活动 ← 推演工作台**: 品牌活动的原始数据全部来自推演工作台中存入的 Activity 记录。品牌活动不创建新活动，仅做筛选与重新编排。
- **品牌活动 ← 参考指南**: 品牌活动的展示详情页可通过交叉引用指向参考指南中对应的流程节点，为用户提供完整的 What-Why-How 知识链。
- **品牌活动 ← 模板与资产**: 品牌活动的资源下载入口可直接引向模板与资产中对应的物料。
- **品牌活动 ← 党务管理**: 宣传委员（评审+审核）、组织委员（数据核验+统计）、纪检委员（合规监督）在品牌认定中各司其职。

### D.4 多页面扩展路径

#### Phase 1: SPA 内增加第 4 个 module-tab（推荐起步方案）

在现有 SPA 架构内，沿用 `module-tab` + `view-section` 模式增加"品牌活动"视图。

**实施清单**:

| 步骤 | 描述 | 涉及文件 |
|------|------|---------|
| 1.1 | 在 Sidebar 中添加 `<button class="module-tab" data-module="brand">` | `index.html` |
| 1.2 | 在 Main 中添加 `<section id="view-brand" class="view-section hidden">` | `index.html` |
| 1.3 | 注册 `data-module="brand"` 的视图切换逻辑 | `src/main.js` |
| 1.4 | 从 mockDB 读取 Activity 列表，实现品牌评分筛选逻辑 | `src/workflow/`（新增 brand.js） |
| 1.5 | 编写品牌活动视图渲染函数（Hero、卡片流、榜单） | `src/workflow/brand.js` |
| 1.6 | 品牌活动相关样式（卡片、评分徽章、榜单） | `src/styles.css` |

**优点**: 改动最小，与现有架构高度一致，快速上线。
**缺点**: 无 URL 路由，无法直接链接到某个品牌活动详情。

#### Phase 2: 品牌活动独立子页面路由

当品牌活动内容超出单个 view-section 承载能力时，引入轻量路由层。

**推荐方案**: 使用 `hash` 路由（`#/brand`、`#/brand/detail/activity-id`），完全兼容 GitHub Pages 静态托管。

```
路由表（Phase 2）:
─────────────────────────────────
#/                    → view-calendar (默认)
#/reference           → view-reference
#/templates           → view-templates
#/brand               → view-brand（品牌活动首页）
#/brand/detail/:id    → view-brand-detail（品牌活动详情）
#/brand/annual/:year  → view-brand-annual（年度回顾）
─────────────────────────────────
```

**技术选型**:

| 方案 | 适用场景 | 代价 |
|------|---------|------|
| 手写 hash router（约 80 行） | 路由数量 < 20 条 | 零依赖，需自行处理 history |
| `page.js`（微型路由库，~4KB） | 需要路由参数解析、中间件 | 引入一个外部依赖 |
| Vue Router / React Router | 全面 SPA 重构 | **不建议**：与当前纯 JS 架构断裂 |

**推荐**: 手写 hash router，在 `src/router.js` 中实现 `onRouteChange` 机制，与现有 `module-tab` 点击事件双向同步。

#### Phase 3: 活动详情页与年度回顾等子页面群

## E. 后台系统对接

### E.1 数据模型扩展

当前系统采用双层存储架构：

| 层级 | 位置 | 说明 | 持久性 |
|------|------|------|--------|
| 内存层 | `mockDB` (src/domain.js) | 运行时数据，页面刷新后恢复 | 非持久 |
| 持久层 | `localStorage` (key: `workflowos_branch_db_v1`) | 序列化存储，含 schema 版本校验 | 浏览器本地持久 |

**当前数据模型核心实体**:

```
mockDB
├── _schema: SCHEMA_VERSION    ← 版本防御
├── users: User[]              ← 用户（静态预设）
├── activities: Activity[]     ← 活动（品牌活动的原始数据来源）
├── tasks: Task[]              ← 子任务
├── attendances: Attendance[]  ← 考勤记录
└── deliverables: Deliverable[] ← 交付物
```

**品牌活动需要扩展的字段**:

| 新增字段 | 类型 | 说明 | 存储位置 |
|---------|------|------|---------|
| `brandScore` | number (0-100) | 品牌评分 | `Activity` 扩展字段 |
| `brandLevel` | enum | 品牌等级 (gold/silver/bronze) | `Activity` 扩展字段 |
| `brandCertifiedAt` | ISO datetime | 认定时间 | `Activity` 扩展字段 |
| `brandTags` | string[] | 品牌标签 (如 "高参与度"、"年度品牌") | `Activity` 扩展字段 |
| `isFeatured` | boolean | 是否首页置顶 | `Activity` 扩展字段 |
| `participantCount` | number | 实际参与人数 | `Activity` 扩展字段 |
| `photoUrls` | string[] | 活动照片 URL 列表 | `Activity` 扩展字段 |
| `growthStage` | enum | 成长阶段 (sprout/cultivate/mature/benchmark) | `Activity` 扩展字段 |
| `iterationCount` | number | 迭代次数 | `Activity` 扩展字段 |
| `previousBrandScore` | number | 上次品牌评分 | `Activity` 扩展字段 |
| `reviewRecords` | object[] | 复盘记录列表 | `Activity` 扩展字段 |

**注意**: `SANDBOX_MODE = true` 当前为启用状态，每次刷新清空持久化存储。品牌活动上线前需确保此模式关闭，或切换至后端持久化方案。

### E.3 数据同步策略

依据系统演进阶段，采用分层同步策略：

| 阶段 | 策略 | 实现 | 适用场景 |
|------|------|------|---------|
| Phase 1 (纯前端) | localStorage 持久化 | `saveDB()` / `loadDB()` | 单人使用，本地数据 |
| Phase 2 (Supabase) | 定期轮询（30s） | `setInterval` + Supabase REST API | 多人协作，数据变化不频繁 |
| Phase 3 (高级) | Supabase Realtime (WebSocket) | `supabase.channel()` 订阅 | 实时协作场景 |

**同步优先级矩阵**:

| 数据类型 | 实时性要求 | 推荐策略 | 轮询/推送频率 |
|---------|-----------|---------|-------------|
| 品牌活动列表 | 低（品牌认定后很少变动） | 页面加载时拉取 + 手动刷新 | 按需 |
| 首页置顶推荐 | 中（支委调整后需即时反映） | 轮询 | 60s |
| 年度榜单 | 极低（年度更新） | 页面加载时拉取 | 按需 |
| 活动照片 | 中（上传后需展示） | 上传后立即刷新列表 | 事件驱动 |
| 评分配置 | 低（修改频率极低） | 页面加载时拉取 | 按需 |
| 复盘记录 | 中（提交后需更新评分） | 提交后立即刷新 | 事件驱动 |

品牌活动涉及"对外展示"，需要比内部操作更严格的权限控制：

L3: 支委（条条委员）

- 在 Supabase 接入前，使用 mockDB 中的 `users[].role` 进行本地鉴权

## F. 评估指标体系

### F.1 过程指标

| 指标 | 定义 | 计算方法 | 目标值 |
|------|------|---------|--------|
| 活动策划完成率 | 按计划完成策划的活动占比 | 已策划活动数 / 计划活动数 * 100% | >= 90% |
| 按时执行率 | 在排期日期内完成的活动占比 | 按时完成活动数 / 总活动数 * 100% | >= 85% |
| 参与覆盖率 | 参与品牌活动的成员占支部总人数比例 | 参与人数 / 支部总人数 * 100% | >= 70% |

### F.2 结果指标

| 指标 | 定义 | 计算方法 | 目标值 |
|------|------|---------|--------|
| 品牌认定通过率 | 通过品牌认定的活动占参评活动比例 | 认定通过数 / 参评总数 * 100% | 30%-50%（保持精品属性） |
| 外部展示访问量 | 品牌活动展示页的访问次数 | 页面 PV/UV 统计 | 季度环比增长 |
| 上级采纳数 | 被学院党委采纳或表彰的品牌活动数量 | 统计采纳/表彰次数 | 每学期 >= 1 |

### F.3 迭代指标

| 指标 | 定义 | 计算方法 | 目标值 |
|------|------|---------|--------|
| 季度品牌活动数变化 | 每季度品牌活动数量环比变化 | (本季度数 - 上季度数) / 上季度数 * 100% | 正增长或持平 |
| 评分趋势 | 品牌活动平均评分的变化趋势 | 季度平均 brandScore 对比 | 逐季提升 |
| 改进措施执行率 | 评估后提出的改进措施实际执行比例 | 已执行措施数 / 提出措施数 * 100% | >= 80% |
| 复盘完成率 | 活动完成后 30 天内提交复盘记录的比例 | 已复盘活动数 / 已完成品牌活动数 * 100% | >= 90% |
| 迭代深度 | 品牌活动的平均迭代次数 | 所有品牌活动迭代次数之和 / 品牌活动总数 | >= 2 次 |

## H. 风险与缓解

| 风险 | 影响 | 缓解措施 | 回滚点 |
|------|------|---------|--------|
| 品牌认定主观性 | 影响力维度依赖人工评定，可能导致认定结果不公 | 量化评分占比 80%（参与度 25% + 成长性 20% + 规范性 15% + 频次 15% + 影响力基础分 25%），人工评定仅影响影响力加分；多人评审取均值 | 调整权重配置，提高量化维度占比 |
| 展示数据滞后 | 活动完成后需经认定流程才能展示，时间差导致展示内容不新鲜 | 自动化数据同步：活动完成即进入候选池，支委评审周期不超过 7 天；Phase 2 引入 Supabase Realtime | 缩短评审周期或开放"待认定"预览区 |
| 评估指标过多 | 指标体系过于复杂导致执行成本高、数据采集困难 | 聚焦 3-5 个核心指标：品牌认定通过率、参与覆盖率、评分趋势、上级采纳数 | 精简指标体系，仅保留核心指标 |
| 品牌通货膨胀 | 品牌活动数量过多导致"品牌"含金量下降 | 容量阈值控制：金标每年最多 3 个，银标每季度最多 5 个，铜标展示 top 10；连续两季度评分下降则降级 | 收紧阈值或提升评分门槛 |
| 移动端适配不足 | 品牌活动面向外部展示，移动端体验差影响传播 | 品牌活动模块移动端适配优先级高于内部操作模块；参考现有 `@media` 断点模式 | 降级为桌面端优先，移动端后续迭代 |
| 复盘流于形式 | 复盘迭代步骤可能变成走过场，无法真正驱动改进 | 复盘记录纳入评分（成长性维度），复盘完成率纳入迭代指标；支委审核改进点 | 降低复盘在评分中的权重，改为纯展示 |
| 成长性维度计算复杂 | 迭代次数和评分趋势的计算需要历史数据支撑 | 首次活动默认成长性得分 10 分（迭代次数=首次），后续逐步积累；系统自动追踪评分历史 | 简化成长性维度为仅看迭代次数 |

┌──────────────────┐

│ - 照片墙          │
└────────┬─────────┘
         │
    ┌────┴────┐
    ▼         ▼
[查看其他   [分享给好友]
 品牌活动]     │
              ▼
         [生成分享卡片]
```

#### 路径 B: 内部党员 → 日常使用 → 品牌活动浏览

```
[推演工作台]
    │ 完成活动、上传材料、录入参与人数
    ▼

    │ 分数达到阈值
    ▼
[进入品牌候选池]
    │ 支委审批
    ▼
[品牌活动正式展示]
    │
    ▼
[首页精选 / 年度榜单 / 分类橱窗]
```

#### 路径 C: 支委 → 品牌管理

```
[品牌活动管理后台] (入口：品牌活动页 → "管理"按钮，L3+权限可见)
    │

```

### A.2 分享功能

品牌活动作为对外展示窗口，分享功能是核心交互之一。

#### 分享卡片生成流程

```
用户点击"分享"按钮
        │
        ▼
┌──────────────────┐
│ 分享卡片预览弹窗  │
│ ┌──────────────┐ │
│ │  [党徽]       │ │
│ │  光华管理学院  │ │
│ │  本科生党支部  │ │
│ │               │ │
│ │  [活动照片]   │ │
│ │               │ │
│ │  活动标题      │ │
│ │  2026.04.15   │ │
│ │  ★★★★ 品牌评分│ │
│ │               │ │
│ │ 扫码了解更多   │ │
│ │  [QR Code]    │ │
│ └──────────────┘ │
│                   │
│ [保存图片] [复制链接]
└──────────────────┘
```

**技术实现**:
- 分享卡片使用 HTML5 Canvas 渲染：党徽 + 背景色（党建红渐变） + 活动照片（圆角遮罩） + 标题（Noto Serif SC） + 评分星标 + 二维码（qrcode.js 或 CDN 库）
- Canvas 导出为 `toDataURL('image/png')`，支持长按保存（移动端）和右键另存为（桌面端）
- 分享链接为 `https://gsm1921-sop.example.com/#/brand/detail/xxx`
- 在 Phase 1（纯前端）中，QR Code 编码完整 URL；Phase 2 接入短链接服务

**OG（Open Graph）元数据**（当链接被粘贴到微信/QQ/社交媒体时生成预览）:

```html
<meta property="og:title" content="[品牌活动标题] - 光华管理学院本科生党支部" />
<meta property="og:description" content="品牌评分: 92分 | 参与人数: 28人 | 承办: 第一党小组" />
<meta property="og:image" content="[自动生成的分享卡片图片 URL]" />
<meta property="og:url" content="https://gsm1921-sop.example.com/#/brand/detail/xxx" />
```

**注意**: 由于当前为纯静态 SPA，OG 元数据需在 `index.html` 中通过 JavaScript 动态注入，或通过 GitHub Pages 的 SSG 预渲染实现。建议 Phase 2 引入 Supabase Edge Functions 做服务端渲染 OG 标签。
