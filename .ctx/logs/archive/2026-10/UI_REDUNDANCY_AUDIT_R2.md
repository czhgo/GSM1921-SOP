## 一、本轮判据

> **删掉这句话，用户是否仍能完成动作？**
> 能 ⇒ 判「删」；不能，且这句话本身承载动作 ⇒ 判「改」为按钮 / 短标签 / 徽章；属于结构性问题 ⇒ 判「立项」。

本轮额外收紧一条，专门针对支书点名的「此地无银」：

> **界面已经表达过的事实，再用一句话解释一遍，即为「此地无银」。**
> 典型句式：标题说「系统汇总」，正文再说「由系统汇总」；按钮写「归档」，旁边再解释「点击即可归档」；页签写「只读」，导语再说「本页只读」；帮助页写「原文（原为…界面只留一行摘要）」。

七类形态编号：① `title/aria-label` 解释；② `placeholder` 说明句；③ `<details><summary>` 折叠口径；④ 卡片导语 / 空态；⑤ 「说明 / 规则 / 口径 / 提示」小标题；⑥ 同义重复；⑦ 帮助页重复。

1. **「此地无银」的硬边界：界面已表达的，不再用文字解释。** 标题、按钮、徽章、选项文案本身就是说明；再补一句「系统会自动…」「本页只读…」「点击后…」即删。
2. **一屏之内，同一句话只能说一次。** 标题与正文、徽章与段落、按钮与 tooltip，任一组合同义即判重复；优先删正文，保留最短的控件文案。
3. **系统机制不上页面。** 落档、口径、同判据、自动同步、投递去向、级联完成，一律只进 help 的一个锚点；页面只留用户能感知的结果（状态徽章 / 数量）。
4. **字少且不可改的信息，要么并进标题行，要么删。** 不允许单独占一整行或一整卡；「共 N 条」「† 口径」「应到＝…」都属于此类。
5. **帮助页只写「怎么做」，不写「这页原来怎么写」。** 「原文（原为…界面只留一行摘要）」这类版本叙事应移出用户文档。

## 八、分歧 3 条

1. **「只读知情」是否一律删。** 一方主张普通详情页删（页面本来就没有写入口）；另一方认为跨角色只读页保留一个「只读」徽章有权限边界价值。建议：普通详情页删，跨角色查看页保留徽章，但不再写「知情」。
2. **「应到」双口径说明放哪里。** 一方要求支委会页保留整行（担心纪检把「应到」当考勤应到，误判漏人）；另一方主张只放 tooltip / help。建议：支委会页保留表头徽章「应到（有表决权）」，整行解释移 help。
3. **换组织向导算工程页还是支书产品页。** 若定位为工程页，`npm test` / 源码路径可保留；若支书日常会用，则必须删。建议支书拍板；在拍板前，本报告按「产品页」判删。
