# 活动复盘

## 概述

本目录用于记录和管理**非三会一课活动的复盘总结**。复盘是对活动全过程的反思和总结，旨在总结经验、发现问题、改进工作，为未来的活动提供指导。

**核心理念：**
- 💡 从实践中学习
- 📈 持续改进优化
- 🎯 指导未来工作
- 📚 积累经验知识

**维护方式：** 采用Markdown文件记录，每次活动一个文件

---

## 什么是活动复盘

复盘是一种结构化的反思方法，通过系统地回顾活动过程，分析成功经验和失败教训，提炼可复制的方法和需要改进的地方。

### 复盘的价值

1. **经验传承**：将个人经验转化为组织知识
2. **避免重复错误**：记录问题和解决方案
3. **持续改进**：不断优化工作方法
4. **能力提升**：促进团队学习和成长
5. **决策支持**：为未来活动提供参考依据

### 什么活动需要复盘

- ✅ 党小组组织的各类活动
- ✅ 党团班一体化活动
- ✅ 创新性/品牌性活动
- ✅ 重要的学习实践活动
- ✅ 遇到困难或有特殊收获的活动
- ❌ 三会一课（使用工作记录模板，不需要复盘）

## 复盘流程

### 1. 活动结束后

**时间：** 活动结束后1周内

**参与者：** 活动组织者、主要参与者

**步骤：**
1. 活动组织者发起复盘
2. 收集参与者反馈
3. 整理活动数据和材料
4. 填写复盘模板

### 2. 复盘讨论

**时间：** 复盘文档初稿完成后

**参与者：** 活动团队成员

**步骤：**
1. 回顾活动目标和实际结果
2. 分析成功因素和失败原因
3. 讨论改进措施
4. 提炼可复制的经验
5. 形成行动计划

### 3. 复盘归档

**时间：** 复盘讨论后3天内

**负责人：** 活动组织者

**步骤：**
1. 完善复盘文档
2. 提交至本目录
3. 通知相关同志查阅
4. 在下次活动前回顾相关复盘

## 复盘要点

### ✅ 复盘应该做到

- **客观真实**：如实记录，不回避问题
- **深入分析**：找出问题的根本原因
- **具体可行**：提出具体的改进措施
- **着眼未来**：关注对未来工作的指导意义
- **及时完成**：趁记忆清晰时完成复盘

### ❌ 复盘要避免

- **流于形式**：敷衍了事、走过场
- **互相指责**：把复盘变成批斗会
- **过度自责**：沉溺于失败情绪
- **好人主义**：回避矛盾、粉饰太平
- **不了了之**：复盘后没有行动改进

3. **定期回顾**：每学期末回顾所有复盘，总结规律
4. **新人培训**：作为培训材料，传承经验

## GitHub中的实现方式

### 方式一：Markdown文件（推荐）✅

**优点：**
- 易于版本控制和历史追溯
- 便于长期归档和检索
- 可以结构化组织
- 支持富文本和图片

**使用方法：**
- 在本目录下创建Markdown文件
- 按照模板格式撰写复盘
- 提交到Git仓库
- 通过文件目录浏览和查阅

### 方式二：GitHub Issues

**优点：**
- 便于讨论和互动
- 可以@相关同志
- 支持标签分类
- 便于追踪改进措施

**使用方法：**
- 创建Issue记录复盘
- 使用Label标记活动类型
- 在评论区讨论
- 关闭后链接到Markdown文件归档

### 方式三：混合方式（推荐）✅

**结合两种方式的优点：**
1. 使用GitHub Issue进行初期讨论
2. 讨论成熟后整理成Markdown文件
3. 在Issue中链接到最终的Markdown文件
4. 关闭Issue，Markdown文件作为长期归档

## 注意事项

⚠️ **重要提醒：**
- 复盘不是形式主义，重在真正反思和改进
- 复盘要及时，不要拖延太久
- 复盘要客观，不要粉饰问题
- 复盘要具体，不要泛泛而谈
- 复盘后要行动，不要束之高阁

✅ **质量标准：**
- 信息完整，数据准确
- 分析深入，找出根因
- 建议具体，可操作性强
- 格式规范，易于阅读
- 对未来工作有指导价值
