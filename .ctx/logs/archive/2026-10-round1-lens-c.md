# Lens C — frontend-design

> 审查时点：2026-10-19（当前 HEAD）。未读取 lens-a / lens-b。
> 取证方式：代码定位 + Chromium 真机量测（1440×900 / 1024×768 / 768×1024 / 390×844）+ `server/test/page-sweep.test.mjs` 实跑。
> 视觉主张：本系统已有明确方向——党建红顶栏、华文中宋标题、哑光中性底、金色单一强调色、纸面式卡片。问题不在「没有风格」，而在**风格在具体页面里没有形成自己的信息主张**：大量页面仍停在「白卡 + 数据表 + 描边按钮」的通用后台句式，类型、色彩与层级没有替场景做决定。

## 深审发现

### U-02 「党员结构」下线后，替换它的结论带把「在办」做成了不可行动的大数
- **现象**：2026-10-18 的六台统一概况已没有「党员结构」，改为「四个数 / 条线表 / 待我处理」三层。但四个数里「230 在办」由纪检 195 条考勤记录 + 补课 + 考察相加而成，视觉上却被压到 18px 灰字；「2 待答复」反而与 67 逾期同为 26px。条线表同一行混用 12px 表头、13px 正文、14px 首列。
- **证据**：`docs/src/components/governance/work-overview.js:127-135,163-168,419-429,437-447`；`docs/src/styles.css:4494-4509`。真机 1440 量测：四个指标块宽 138/119/96/92px，数值字号 26/26/18/26px；`page-sweep` P7 命中 `全局概况` 的 `TH 12px` 与 `TD 14px`（应 13px）。
- **影响**：首屏最大的数字是最不可行动的存量，且它把考勤流水伪装成「工作事项」；条线表的三种字号让首列读起来像标题、其余列像注脚，横向比较不稳定。整体读感接近通用 KPI 看板，而不是支书的工作台。
- **建议方向**：把「在办」改名或拆开（如「在办事项 / 考勤记录」），考勤流水不进「在办」；结论带按「需我处理 / 风险 / 存量」重排视觉权重；表格回到 13px 单档，若要表头更轻就用 12px + 更强的字重/字距，而不是让首列变 14px。
- **严重度**：P1
- **可能冲突**：可能与 lens B 的「结论带已经足够克制」冲突；lens A 可能认为 muted 灰仍满足对比度，不把它当问题。

### U-04 纪检考勤拆成两段后，仍是两排同款小钮 + 每段继续堆多类对象
- **现象**：一级「考勤 / 补课」与二级「确认与录入 / 数据查看」是两排视觉完全相同的 30px `.btn-tab`，没有组标签；「确认与录入」里同时放待确认队列、出勤申诉、会议考勤录入表单；「数据查看」里同时放人×活动矩阵与全量总表。页面仍是一段长滚动，只是把原来的四类对象换成了 2×2 的堆叠。
- **证据**：`docs/src/entries/tabs/disc/attendance-tab.js:52-55,64-72,181-199`；真机 390：三张卡、页面底 1562px，两排钮均 30px；页面 27 个 11px 文本节点，含关键状态「请假 / 超期」；`docs/src/styles.css:4584-4592`（状态徽标 11px/500）。
- **影响**：第一次进入的纪检委员看到两排长得一样的钮，无法从形状判断哪一排改变整个工作面；异常队列与会议录入表单争同一视野；最需要被看见的「请假/超期」反而用全页最小字号承载。
- **建议方向**：只保留一排互斥视图，或把「录入」收成队列旁的明确动作（侧滑/弹窗），不让它常驻页面；「考勤 / 补课」若确实切换整个工作面，应使用更强的分区头而不是第二排小钮；异常状态徽标升到 12px。
- **严重度**：P1
- **可能冲突**：可能与 lens B 的「两段式已足够、少即是多」冲突；lens A 可能更关注 tab 的 ARIA 角色而不是视觉层级。

### U-05 专班管理已按对象分段，但看板三色与页签溢出让它更像通用 Trello
- **现象**：三个视图钮（专班工作组 / 活动工作组 / 报名总表）已经把对象拆开，原「三类对象混排」基本解决。但默认看板给三个状态桶各配一个饱和色头（琥珀 / 紫 / 蓝），与全站金色强调色不同族；同时页签条在 1440 宽屏已宽于容器。
- **证据**：`docs/src/entries/tabs/org/taskforce-tab.js:68-91,108-119`；真机 1440：桶头计算色分别约 `#823F03`、`#53378F`、`#234E93`（6% 同色底），页签滚区 `scrollWidth 1279 / clientWidth 1152`，右箭头已出现。
- **影响**：三色桶头让页面像一张独立的项目管理板，无法复用全站「状态色 = 同一套语义」的学习；1440 桌面就藏起后半段页签，用户要靠箭头猜还有什么。
- **建议方向**：桶头回到「中性底 + 一个状态色点」，或映射既有状态色；视图切换用一个分组标签说明它是「视图」而非「页签」；≥1280 时改两行分组或溢出菜单，不把 12 个页签塞进单行。
- **严重度**：P2
- **可能冲突**：可能与 lens B 认为「三色桶有节奏、能快速分列」冲突；lens A 可能接受当前对比度。

### U-06 党委支部管理已从长页改成独立配置页，但目录本身仍是一张通用数据表
- **现象**：支部管理已只保留「支部目录」，换届向导/部署自查移到 `branch-config.html` 的四个分区，原来的叠长页问题已闭环。但目录是单卡六列表格：1440 下整页在 406px 处结束，下面大片空白；390 下表格宽约 965px，操作列在横向滚动外。
- **证据**：`docs/src/entries/tabs/party-committee/branches-tab.js:26-65`（六列、操作在最后一列）；`docs/src/styles.css:493`（`.pc-table-scroll` 仅负责横滚）；真机 1440 `cardBottom=406`，390 表格 `right=965`、页面 `scrollWidth=390`。配置页分区见 `docs/branch-config.html:35-47`、`docs/src/entries/pages/branch-config-entry.js:167-173`。
- **影响**：手机上唯一能进入支部的「支部设置 / 查看该支部」被推到屏外；桌面上目录没有用空间做支部间比较（活动负荷、名册健康），看起来像数据库后台，而不是党委治理面。
- **建议方向**：窄屏把操作列前置或吸底，避免横向找按钮；桌面增加一个可比较的支部级指标/视觉（如支部卡片 + 名册/活动概览）；目录页承担「选支部」，不要再把配置表单塞回同一页。
- **严重度**：P2
- **可能冲突**：可能与 lens B 的「目录就应该安静」冲突；lens A 会同意操作列不可达属于可用性问题。

### U-08 「本组活动」的范围修正是小字，标题仍在过度承诺
- **现象**：2026-10-18 已把列表拆成「本组创建 / 承办（可写入）」与「可见活动（只读）支部级 / 定向下发」，并加了一句范围说明；但页签名仍是「本组活动」，说明是 12px 灰字，两组列表同处一张卡、仅用虚线分隔。
- **证据**：`docs/src/capabilities/leader-workspace.js:61`；`docs/src/entries/tabs/leader/write-tab.js:178-195`；真机 1440 可见「可写入 · N 条」与「支部级 / 定向下发 · N 条」两组计数，说明文字 12px。
- **影响**：组长扫页签时仍会先理解为「只有本组」，范围纠正要靠读小字；一张卡里出现两组不同权限的数据，容易把只读活动当成可编辑。
- **建议方向**：页签改为「活动（本组可写）」或直接「活动」；把范围说明提升为标题旁的 13px meta；只读组拆成独立 section/card，给它自己的表头与视觉边界。
- **严重度**：P2
- **可能冲突**：可能与 lens B 的「小字说明已经足够」冲突。

### U-23 活动材料闭环仍没有自己的承载面
- **现象**：活动结束后的材料闭环仍散落在组长台活动子记录与宣传台「档案归档」里；没有「活动材料闭环」页、tab 或独立区块，也没有一个面向组织者的「还缺什么 / 交给谁 / 到哪一步」视图。
- **证据**：`docs/src/capabilities/prop-workspace.js:22-72`（9 个页签，无材料闭环）；`docs/src/entries/tabs/prop/archive-tab.js:224-296`（审核、归档推进、外发动作都嵌在归档页）；`docs/` 页面清单无 materials 页面。
- **影响**：组织者完成活动后无法在一个地方确认材料是否齐、该交给谁；闭环靠记忆和多个上传块拼起来。这是当前最像「未成品」的功能缺口，而不是审计表上的一个勾选项。
- **建议方向**：在活动详情内做一个闭环块（材料清单 + 上传/提交 + 接收方状态 + 历史），或建一个跨角色收件页；沿用「档案归档」已有的状态词，不新造第二套。
- **严重度**：P1
- **可能冲突**：无（lens A/B 都会同意这是功能缺口）。

### U-52 IAAA 三步已落地，但登录页仍把「开发模式」和两套登录并排给终端用户
- **现象**：统一身份认证按钮、选支部面板、支部确认队列都已实现，原「UI 全缺」已闭环。但登录页仍同时展示 IAAA 与「学号 + 密码」两条路径，页面底部还公开「开发模式」开关；控件高度为 34 / 36 / 38px 三档；选支部是一次点击即提交，没有确认或撤回。
- **证据**：`docs/login.html:103-120,144-150`；真机 1440：IAAA 钮 34px、输入 38px、提交 36px；`docs/src/entries/pages/login-entry.js:196-198,206-220`（点击支部按钮即 `_bindBranch`）。
- **影响**：红金仪式感的登录页被开发开关和并排的密码表单拉回「内部演示系统」；4px 的控件高度漂移在输入框旁肉眼可见；点错支部会直接发出加入申请，只能等驳回。
- **建议方向**：正式形态只留一条身份路径，账号密码/开发模式收进开发构建或折叠区；支部选择改为「选中 + 确认」并允许待确认期间撤回；控件统一 38px。
- **严重度**：P2
- **可能冲突**：可能与 lens B 的「登录页仪式感已经成立」冲突；lens A 会独立命中控件高度与破坏性操作确认。

### U-53 「块决定 tab」仍不存在，落地面只是一张通用拖拽排序表
- **现象**：当前的支部组合面是「工作台默认顺序」：每行一个拖拽手柄 + 页签名 + 组徽标 + 上下移按钮，保存时只写 `hiddenTabIds` / `tabOrder`。页面没有表达「哪个块产出哪个页签」，也没有画布或组合预览。
- **证据**：`docs/src/entries/pages/settings-entry.js:788-810,826-834`；`docs/src/services/branch/branch.js:29-35`。
- **影响**：产品最有辨识度的想法——支部 = 块组合——在界面上完全不可见；用户看到的是任何后台都有的「排序偏好」，这是全站最像模板的一屏。
- **建议方向**：画布落地前，至少在这张卡里显示每行的「来源块」，并把标题改成「页签顺序（不等于块组合）」；画布落地时用双栏：左块、右结果预览，而不是继续扩这张拖拽表。
- **严重度**：P2
- **可能冲突**：无（这是未实现项，其他 lens 不会给出相反结论）。

### U-09 项目分工空态是一条灰字，没有出口，也没有区分「没派任务」和「没进项目」
- **现象**：成员台默认子视图「我的任务」为空时只渲染一句「你暂无可承接的项目任务」，没有动作、没有解释任务如何到来，也没有指向「我的分工」或活动。
- **证据**：`docs/src/entries/tabs/visitor/projects-tab.js:200-211`；`docs/src/components/ui/list-filter.js:264-266`（空态统一输出 `<p class="text-xs text-gray-500 text-center py-4">`）。
- **影响**：新成员落在默认视图里看到死胡同，只能自己猜上方还有两个子视图；空态也无法告诉他是「尚未被分配」还是「根本不在任何项目」。
- **建议方向**：改用既有空态组件：一句说明 + 一个动作（「看我的分工」或「浏览活动」）；若确实无项目，指向活动动态或联系组长。
- **严重度**：P2
- **可能冲突**：无（lens A 可能同时指出空态缺少语义标题/role）。

### U-35 组长台仍没有「我的任务」承载面，SOP 任务只在成员台可切
- **现象**：成员台已有「项目分工 → 我的任务」，按项目内身份读 `listMyProjectTasks`；组长台的 10 个页签里没有对应面，组长本人作为组织者的 SOP 步骤只能进活动详情逐条看子记录。
- **证据**：`docs/src/capabilities/leader-workspace.js:28-80`（无 my-tasks 页签）；`docs/src/entries/tabs/visitor/projects-tab.js:103-109`；`docs/src/services/activity/activity.js:214-226`（同一服务已存在）。
- **影响**：组长台优化的是「发起活动」，不是「把手上的活动做完」；组长要回答「我下一步欠什么」必须逐活动打开，操作成本与角色职责不匹配。
- **建议方向**：给组长台加「我的任务」块或页签，直接复用同一服务；若不想加页签，就把它做成「本组活动」首块「待我完成」。
- **严重度**：P2
- **可能冲突**：可能与 lens B 的「组长台已经够用、不要再加页签」冲突。

### U-12 跨活动议题写入校验已闭合，前端只剩错误提示落点问题
- **现象**：`POST /agenda-votes` 现在会校验 `agendaItemId` 是否属于该活动，并拒绝讨论项；原「可写孤儿票/跨活动议题」已闭环。前端提交失败仍走全局 toast，没有定位到具体议题。
- **证据**：`server/routes/committee.js:75-76`；`docs/src/services/activity/agenda-relations.js:83-92`；`docs/src/components/governance/vote-widget.js:102-107`。
- **影响**：数据层风险已消除；视觉层没有新的结构问题。唯一残余是错误提示与议题卡脱节，多个议题同屏时用户不知道是哪一条失败。
- **建议方向**：保留单一校验器；把错误文案挂到对应议程卡内（或 toast 中带上议题名），不要只给一句服务端消息。
- **严重度**：P2（残余）
- **可能冲突**：无。

### U-13 资源读口已按支部分域，原「整表返回」不再成立
- **现象**：通用资源 list、`/bootstrap` 与多数语义路由都已走 `resourceRowsForActor`；党委未选支部时只返回支部目录/党委通知，不再返回支部业务整表。原前后端边界不一致的问题已闭环。
- **证据**：`server/routes/resources/index.js:111-117,568-573`；`server/routes/resources/branch-scope.js:66-77,180-200`。
- **影响**：读取路径不再跨支部泄漏；UI 侧党委在未选支部时看到的是目录/汇总，而不是空的业务表，符合「先选支部再进明细」。
- **建议方向**：把 `resourceRowsForActor` 保留为唯一读门；新增路由必须复用，避免重新开一条整表口。
- **严重度**：P2（残余）
- **可能冲突**：无。

### U-21 撤员已联动撤回授权，但界面把「移出工作组」做成了无确认的静默删行
- **现象**：数据层已在移除成员时把其 active grants 置为 `revoked`（原因 `membership-removed`），原「只置 removed 不撤授权」已闭环。但成员编辑器里的「移出工作组」是一颗红色 ghost 按钮，点击后直接从本地列表删行，没有确认、没有「将同时撤回 N 项授权」的说明，也不显示「待保存」状态。
- **证据**：`docs/src/services/core/auth.js:149-156`；`docs/src/components/governance/workgroup-member-editor.js:29,150-154`。
- **影响**：操作者可能以为只是把人移出分工，实际连带撤回全部操作授权；取消表单时删行又不落库，缺少反馈。这是页面上权限后果最重、交互处理最轻的动作。
- **建议方向**：加一次确认，明确「移除 X，并撤回 N 项操作授权」；行进入「待移除」态并提供撤销，保存时再统一提交。
- **严重度**：P1
- **可能冲突**：可能与 lens B 的「红字已经足够警示」冲突；lens A 会同意破坏性操作需要确认。

### U-10 平板/窄屏的真机几何已补：页签藏一半，390 首屏把行动列表推到 1.5 屏以下
- **现象**：768 宽时组织台页签滚区 704px、内容 1279px（约 5 个页签在屏外）；1024 时 960/1279；390 时组织台 358/1279（其余台 358/1203–1267）。只有右侧箭头提示溢出，没有溢出菜单。390 的概况页「条线」表转为卡式后高约 1000px，5 行数据把「待我处理」推到 y≈1517。
- **证据**：`docs/src/components/shell/tab-bar.js:268-271`；`docs/src/styles.css:4721-4746`；`docs/src/components/governance/work-overview.js:449-463,505-510`；上述为 Chromium 768×1024 / 1024×768 / 390×844 实测。
- **影响**：平板是快速查看的高频设备，却要横向滑动才能看到一半功能；手机上「进入即见待处理」被数据表转卡破坏，首屏只剩汇总和条线，行动项在 1.5 屏以下。
- **建议方向**：<1024 改为两行分组或「更多」溢出菜单，不只给箭头；<640 把条线表压成「条线 / 逾期 / 动作」三列紧凑行，或把「待我处理」提到条线表之前。
- **严重度**：P1
- **可能冲突**：可能与 lens A 的「横向滚动可接受、只要可聚焦」冲突；lens B 可能偏好单列长页的安静感。

### U-22 Chromium 已可用，page-sweep 能跑但 7 台全红；它不能再被当作「环境不可用」的豁免
- **现象**：本机 Playwright Chromium 可正常启动；实跑 `node --test test/page-sweep.test.mjs` 得到 16 tests / 7 pass / 9 fail。7 个工作台全部因 P7 字号离群失败（表头 12px、首列 14px，规范要求 13px），另有「支部分工」14 行未分页。
