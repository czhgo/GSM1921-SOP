# T-190 赋权整合闭环 — 设计文档

> 创建日期：2026-08-02 | 状态：待书记审批 | 关联：DESIGN_SYSTEM §一 原则7/8、COMMISSIONER_FRAMEWORK §赋权流程、T-189

## 一、背景与原则

书记（2026-08-02）提出两条重要设计原则（已沉淀 DESIGN_SYSTEM.md §一 原则 7/8）：

1. **同一套数据（One Source, Multi Entry）**：顺路产生的数据不单独填写，可保留多入口，但读写必须同一套数据。赋权是活动的副产物，应整合进活动数据流。
2. **降低填写负担（Low Friction Filling）**：可推导字段自动填充、完成即正向反馈、启动 ≤ 2 跳。

全仓审计发现赋权数据存在严重孤岛：

| 编号 | 问题 | 违反原则 |
|---|---|---|
| P0-1 | 书记"待赋权活动"统计读幽灵字段 `a.authorizedBy`（无写入点），恒失真 | 原则1 |
| P0-2 | 活动/专班子记录用 `prompt()` 双轨维护，与正式库割裂 | 原则1+2 |
| P0-3 | 专班解散赋权回收筛选 `r.scope`，但从不写该字段 → 永远回收不掉 | 原则1 |
| P1-1 | 项目角色 4 源并存（authorizations / activity.assignments / 静态 MOCK_TASKFORCES / mockDB.assignments），运行时新数据查不到 | 原则1 |
| P1-2 | 专班成员角色中英文混用（'深度参与者' vs 'deep'），权限匹配失效 | 原则1 |
| P1-3 | 组长/组织委员赋权待办无落地表单（authorize 仅书记工作台 2 处调用）→ 死待办 | 原则2+1 |

## 二、架构决策（书记已确认）

**一主源 + 一快照 + 双写 + 单读**

```
主源（运行时读写）   ：activity.assignments = [{personId, role:'organizer'|'deep'}]
                       taskforce.members   = [{personId, role:'organizer'|'deep'}]（统一英文编码）
审计快照（只增不改） ：localStorage 独立键 'sop_org_os_auth_audit'
                       （移出 docs 代码栈：不再作为 mockDB 实体，不 seed 种子）
统一写入口          ：AuthStore.authorize() = 写主源 + 追加快照 + 发通知（三合一）
统一读入口          ：_getProjectRole() = 读主源（活动/专班），删除静态回退
```

书记决策记录：
- 范围：先做赋权整合闭环
- 组长创建活动：创建时内联赋权（PersonPicker）
- 审计快照：保留但**移出 /docs** → 独立 localStorage 键 + 历史种子（auth-001~010）归档 .ctx/logs
- 未选人兜底：保留"为活动X赋权"待办，点击直达活动详情内联编辑

## 四、数据流

```
创建活动(组长) ──内联选 organizer/deep──▶ activity.assignments（主源）
                                          │
书记项目赋权 ──authorize()──▶ 主源更新 ──┼──▶ 审计快照(独立键) ──▶ 通知
组长事后补/改 ──authorize()/revoke()──▶ 主源更新 ──┼──────────────┘
组织委员专班赋权 ──authorize()──▶ taskforce.members ──┼───────────▶ 通知
专班解散 ──revoke 批量──▶ 主源清除 ─────────────────┘

读取：_getProjectRole 唯一读主源 → 访客分工页/书记统计/权限判断一致
```

## 五、验证方案

1. 组长创建活动内联选人 → 活动详情显示 organizer/deep 名单 + 被赋权人收到通知 + 不派发赋权待办
2. 组长创建活动不选人 → 仍派发赋权待办 → 点击直达活动详情内联补赋权
3. 书记项目赋权 → 写穿活动/专班主源 → 访客分工页可见 → 统计 pendingAuth 随之变化
4. 组织委员专班赋权 → 专班 members 英文编码 → 权限匹配生效
5. 专班解散 → 赋权回收 N 条 toast 出现 + 被赋权人权限失效
6. `sop_org_os_auth_audit` 键独立持久化，刷新不丢；authorizations 不再出现在 mockDB 序列化
7. 浏览器 console 无应用级 JS 错误
