# 汇报父键与反馈受众投影（批次 498）

## Why

- 一键汇报当前没有父键（不选活动/专班），卡点与请示无法按事项汇总；但个人汇报（学习、生活困难）没有工作组可挂，强制会逼人填假父键。支书裁定：**可选父键＋上下文自动带**。
- 「支部向党委报告」是独立对象 `ReviewRequest`（审批闭环、党委写门），不是一键汇报。支书裁定：**不并入，仅给入口链接**。
- 服务端 `GET /issues` 只按支部过滤：同支部任何成员可直连接口读到他人的内部汇报（带真实提交人）与被隐藏反馈。支书裁定：**内部汇报＝支书层＋当事人；隐藏反馈＝支书层＋处置人**。
- 宣传台「归档活动」与支书/组织者的活动关闭是两个写口，且按母本宣传委员只归档材料。支书裁定：**宣传台撤掉该动作**。
- 党委账号未选支部时部分写门仍回落 `br-b1`。支书裁定：**拒绝并提示先选支部**。

## What

1. **汇报父键**：`Issue`（kind=report）新增 `workgroupId` / `sourceType`（activity|taskforce）/ `sourceName` 快照；提交时可关联活动或专班，不选则为个人汇报。顶栏入口带可选选择器；从活动/专班详情页打开时按 URL 上下文预选。
2. **受众投影单一源**：`issues.js` 导出 `canReadIssue(row, viewer)`；前端全部读口（getAll/filter/getById/count）与服务端 `GET /issues` 共用同一判据。内部汇报只给支书层、汇报人、被请求人、被指派人；隐藏反馈只给支书层与处置人（含按角色指派）。
3. **党委报告入口**：一键汇报浮窗给一条「要报党委？去上报党委」链接（仅支书/副支书可见），对象不合并。
4. **宣传台撤归档**：移除「归档活动」按钮与写链，材料归档保留；活动归档仍由支书/组织者在活动详情办理。
5. **支部归属**：`ownBranch` 不再回落 `br-b1`；党委未选支部时写门拒绝，返回可读提示「请先选择支部」。

## Verification

- 新增 `issue-audience-projection.test.mjs`：普通成员读不到他人汇报与隐藏反馈；支书全量；被指派人可见；前端与服务端同判据。
- 新增 `report-workgroup-key.test.mjs`：父键随汇报落库并可回读；跨支部父键拒绝；个人汇报父键为空合法。
- 新增 `workgroup-branch-scope.test.mjs`：党委未选支部写工作组/活动被拒，提示含「选择支部」。
- 归档动作守卫：宣传台不再调用 `archiveActivity`。
- `npm run test:daily` 0 断言失败；`page-sweep` 16/16。

## Boundaries

- 不把 `ReviewRequest` 并入 Issue；不改审批状态机。
- 不强制所有汇报挂父键；不为个人汇报造虚拟工作组。
- 不扫描前端全部 `|| 'br-b1'`（存量 43 处属数据生命周期专项），本批只收服务端写门。
- 不改活动/专班工作组的父键规则。
