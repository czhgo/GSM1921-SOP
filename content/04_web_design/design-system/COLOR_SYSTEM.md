### 2.1 色盘总览

```
┌─────────────────────────────────────────────────────────────┐
│                    色彩系统架构                              │
│                                                             │
│  品牌统一层（Brand）    主色（Primary）                      │
│  ┌────────────────┐   ┌────────────────┐                    │
│  │ 党徽金 FFD700   │   │ 党建红 CE1126   │ ← 不可变合规底线   │
│  │ tab/强调边框/   │   │ 红系渐变 9 阶   │ ← 品牌语义         │
│  │ 主题党日/徽章   │   │ 主CTA/标题装饰  │                    │
│  └────────────────┘   └────────────────┘                    │
│                                                             │
│  角色识别层（Role/Accent）  状态层（Functional）              │
│  ┌────────────────┐   ┌──────────────┐                     │
│  │ 主题色（可自选） │   │ 完成绿/待处理琥珀/告警红/进行中蓝 │   │
│  │ 色条/标签/chips │   │ API青         │ ← 状态指示          │
│  └────────────────┘   └──────────────┘                     │
│                                                             │
│  中性色（Neutral）     表面色（Surface）                      │
│  ┌────────────────┐   ┌──────────────┐                     │
│  │ 白→黑 11阶灰度  │   │ 页面/卡片/浮层 │ ← 组件层级深度       │
│  │ 文字+边框+分割线 │   │ 悬停/激活态   │                     │
│  └────────────────┘   └──────────────┘                     │
└─────────────────────────────────────────────────────────────┘
```

> **主题色 / 功能色 / 品牌色三色区别（2026-08-14 裁决明确定义）**：
>
> | 层 | 名称 | 驱动 | 是否随用户自选 | 用途 |
> |----|------|------|--------------|------|
> | 品牌统一层 | **品牌色**（党徽金 `#FFD700` + 党建红 `#CE1126`） | 固定常量 | ❌ 不随 | 党徽、主 CTA、党务标签、标题装饰——横跨全站的身份/合规底线 |
> | 角色识别层 | **主题色**（各角色可自选） | `getAccentColors(role)` / 侧边栏「主题选择」 | ✅ 随（个性化覆盖） | 身份归属 + 个人偏好：tab 激活态、色条、角色标签、chips、主按钮、选中项、工作台内强调色 |
> | 状态层 | **功能色**（成功绿/警告琥珀/告警红/信息蓝） | 固定常量 | ❌ 不随 | 只表语义状态：完成/待处理/错误/信息提示——绝不用于身份或装饰 |
> | 中性层 | 灰度 + 表面色 | 固定常量 | ❌ 不随 | 文字层级、边框、分割线、卡片层级 |
>
> **使用铁律**：四层各司其职禁止混用——状态红、品牌红、主题红三者语义各异；同色相不同层按语境区分（§2.8 判例）。身份不再绑定固定色值（2026-08-14 裁决），角色识别一律走主题色体系。

> **四层职责（2026-08-08 裁决）**：品牌统一层（金色）横跨全站、不受主题色制约；角色识别层（主题色）可个性化、只管身份归属与个人偏好；状态层（功能色）只表语义状态；中性层只做层级。**四层各司其职，禁止混用**——这也是"金色/蓝色/主题色并存"问题的规范答案（详见 §2.8）。

### 2.3 辅助色（Accent）— 党徽黄系 + 角色识别色

#### 2.3.1 品牌统一层（党徽金）— 横跨全站、不受主题色制约

> **定义（2026-08-08 三审修正）**：金色是党建合规色（`--party-gold` 定义于 `:root`，不经角色派生链路），用于**全站统一视觉**场景。**但金不强制充当"主题色"**——主题色语义（tab 激活态、选中项、chips）回归角色识别层（§2.3.2/§2.8 ②），因金是品牌合规色、含义多、受对比度牵制反复变色（半透明偏淡→实色偏艳，均不被接受）。金色仅保留于：强调卡边框、主题党日类别、待办行动按钮、通知徽章、聚焦反馈。

| Token | 色值 | 色块 | 用途 |
|-------|------|------|------|
| `--party-gold` | `#FFD700` | ██ | **党徽金 · 品牌统一层基准** |
| `--party-gold-light` | `#FDE68A` | ██ | 党徽金浅调 |
| `--accent-gold` | `var(--party-gold)` | ██ | 别名（SVG 着色、装饰线） |
| 金黄文字 | `#A16207` | ██ | 金浅底/金底上的文字（2026-08-10 裁定"再黄一点"，由 `#B45309` 改，对比度达标） |
| 金浅底 | `rgba(255,215,0,0.12~0.14)` | ██ | 浅金色背景（类型徽章、图标底、待办次要按钮） |
| 金边框 | `rgba(255,215,0,0.35~0.45)` | ██ | 金色边框（强调卡、待办行动按钮、类型徽章） |

> **G3 裁定（2026-08-08 实测）**：金色按钮一律用**金浅底** `rgba(255,215,0,0.12)`，**禁用纯亮金实底** `#FFD700`——实测「去处理」纯亮金实底「过于艳丽，饱和度太高」，而 tab 的金浅底「因为有透明度，黄色非常舒服」。金浅底与 tab 激活态同源。
> **G3 裁定（边框）**：金色作为主题色时，普通按钮/标签**不加边框**，与其他主题色结构完全一致（「别的有他也有，别的没有他也必须没有」）；仅 visitor 品牌金待办行动按钮保留金边框（与详情按钮同页一致）。

**应用范围（固定，不得私自扩增）**：
1. ~~tab 激活态~~（2026-08-08 三审移出：回归角色识别层主题色渲染，见 §2.8 ②）
2. ~~tab 组标签~~（同上，随 tab 走主题色）
3. **可交互强调卡边框**：inspector 品牌活动卡 `border-left:3px solid var(--party-gold)`（品牌金边框，档位 1 卡片，见 [COMPONENT_SPEC.md](COMPONENT_SPEC.md) §4.2「五档语义表」档位 1；实现中 inspector.js 内联 `#EAB308` 为历史存量、不入权威色板，待收敛至 `var(--party-gold)`）
4. **主题党日系**：类别色（`ACTIVITY_CAT_COLOR['theme-party']`）
5. **待办行动按钮**：visitor「去处理/处理」金底
6. **通知/紧急徽章**：header 未读数、badge--gold
7. **聚焦反馈**：`.cs-select.is-open` 触发器边框、部分 input focus 金色 outline

**约束**：金色仅用于上述品牌统一场景；不得用于角色识别（色条/标签）、状态指示（完成/告警）、正文文字、以及任何"个人可选的强调/选中语义"（tab 激活态、选中项、chips 等一律用主题色）。

#### 2.3.2 角色识别色系（红橙黄绿蓝紫系统化）

> **设计原则**：每个角色一个独立色相，按职能分工分配色相，确保 8 种角色在关系网络图、角色卡片、日历图例等场景中可快速辨识。
>
> **色相分配逻辑**（按职能分工归类）：
> - 红色系（最深）→ 领导核心（党支书）
> - 石灰绿系 → 执行层（党小组组长，与支委分工配合）
> - 紫/蓝/琥珀系 → 支委三类（组织/宣传/纪检，横向协作）
> - 青/绿/灰系 → 项目执行层（组织者/深度参与者/普通参与者）
>
> ⚠️ **本表是身份标识场景的默认识别色，不是"主题色硬编码"**（2026-08-10 补充）：主题色已演进为一套**可选择的色盘**——侧边栏「主题选择」中所有角色均可从色盘自选主题色（2026-08-06 起），`resolveAccentRole` 优先读 localStorage 个性化覆盖（`docs/src/core/constants.js`）。本表仅约束**身份标识场景**（关系网络节点/角色卡片/日历图例的辨识色）；**主题色场景**（tab 激活态/按钮/标签/选中项/chips 等强调色）由个人自选色盘决定（见 §2.7 规则 + §2.8 ② 角色识别层）。2026-08-14 裁决强化：身份不再保留既有固定颜色设定——本表色值为默认识别色，任何角色均可经侧边栏「主题选择」自选覆盖，工作台强调一律走主题色。

### 2.7 主体色配色规则（给定主体主题色 X）— 打样样板

> **来源：**普通参与者界面视觉重设计打样（2026-08-01，批准）。本规则是"给定主体主题色 X 时如何搭配全页色彩"的可复用样板，其他角色改版按此规则推广。

**配色规则五条**：

1. **X 做工作台强调**：主按钮、标题装饰条、主要标签、**tab 激活态**均用主体色 X。tab 统一渲染方案即主题色三件套：浅底 `rgba(X,0.10~0.12)` + 边框 `rgba(X,0.30)` + X 文字（`tab-bar.js` 消费调用方 `accentColor`；2026-08-08 三审定稿，废除"tab+边框全金"）。
2. **品牌金做统一层**：可交互强调卡边框、主题党日、待办行动按钮、通知徽章用党徽金，全站一致、不受 X 制约。
3. **状态色全局统一**：完成绿 `#16A34A` / 提醒琥珀 `#D97706` / 告警红 `#EF4444`，所有角色一致。
4. **暖白底全局统一**：页面底色用暖白 `#FAFAF5`（替代偏冷的 `#F8F9FA`），衬托红金暖色系。
5. **灰只做中性**：灰度 `#6B7280` 降级为纯中性辅助——仅文字层级、边框、分割线，不再充当任何角色的身份色。

**打样实例（普通参与者）**：

| 层 | 色值 | 用途 |
|----|------|------|
| 品牌·党建红 | `#CE1126` | 主 CTA、标题装饰条、党务标签 |
| 品牌·党徽金 | `#FFD700`（配套：金黄文字 `#A16207` / 浅底 `rgba(255,215,0,0.12)` / 边框 `rgba(255,215,0,0.35)`） | 强调卡边框、主题党日、项目分工标签、考察成长元素、待办行动按钮 |
| 主题色 X | `getAccentColors(role)`（participant「金」默认即主题党日胶囊三件套：亮金底 `rgba(255,215,0,0.12)` + 金黄字 `#A16207` + 亮金边框 `rgba(255,215,0,0.35)`，2026-08-08 四审改，2026-08-10 再黄一点；见 §2.3.2） | **tab 激活态**（浅底 + 边框 + X 文字，2026-08-08 三审起回归主题色）、主按钮、标题装饰条、主要标签、选中项、chips |

| 底色·暖白 | `#FAFAF5` | 页面背景 |
| 中性·灰 | `#6B7280` | 文字层级、边框、分割线 |

**上下文隔离要点**：品牌红 `#CE1126`（标签语境）与告警红 `#EF4444`（数字/图标语境）语义不同，不得混用；金色浅背景文字一律用金黄文字 `#A16207` 保证对比度。

**角色色系与活动色系彻底分离**（2026-08-01 修复轮，决策"参与者/组织者/深度参与区分开，和活动类型的配色也要区分"）：

- **角色维度用冷色系**（人员 chips / 考察等级标签 / 日历执行人）——统一来自 `constants.js → ROLE_COLORS`：
  - 组织者对应天蓝 `#0369A1`、深度参与对应紫 `#7C3AED`、参与者对应中性灰 `#6B7280`（默认身份，呼应"没有标记就是普通参与者的标记"）、发起人对应靛蓝 `#4F46E5`。
- **活动类型维度用暖色系**（活动圆点 / 类型徽章 / 主题党日系）——统一来自 `constants.js → getActivityTypeColors()`：
  - 三会一课对应党建红 `#CE1126`、主题党日系（主题党日/共建/参访/座谈）对应党徽金 `#FFD700`。
- **金点描边约定**：亮金 `#FFD700` 圆点单独使用对比度不足（约 1.4:1），必须配套 1px 深色描边 `rgba(161,98,7,0.35)`；金底上的文字/数字一律用金黄 `#A16207`（`dotBorder`/`text` 字段已内置在 `_ACTIVITY_TYPE_BASE`）。
- **待办区去红**：待办卡片左缘色条用党徽金 `var(--party-gold)`，"标记完成"用状态绿 `#16A34A`；红色只保留品牌语义（主按钮、党务标签，tab 高亮已让位品牌金），避免红色过多、意义不明确。

**主操作回归角色主题色**：红色只保留语义场景（主按钮、党务标签），主操作按钮一律用角色主题色 X——需角色主题色时优先用 `bootstrapPage` 解构的 `accentRgba/accentBorder` 拼内联样式，避免新增 Tailwind 类变体。
**visitor 待办行动按钮金色**：`actionBtnStyle` 参数传金色系 `background:var(--party-gold);color:#A16207;`，待办详情「处理」按钮同金系；列表 ✓ 快捷完成按钮保持灰色中性（次要操作）。
**语义红保留清单**（不改）：超期/过期/打回/删除/必填星号/「必修」标签/解散专班（破坏性操作）等告警与危险语义。

### 2.8 颜色分类规则（品牌统一层 / 角色识别层 / 状态层 / 中性层）

> **背景（2026-08-08 反馈）**："金色/蓝色/主题色并存"看似无规律，实因全仓并存两套体系且未成文：一套是活动类别语义色（红/金），一套是功能/状态色（蓝/绿/琥珀/青）大量硬编码。裁定：**颜色必须有更合理的分类规则，四层各司其职**。

**四层分类总表**：

| 层 | 驱动 | 是否受主题色制约 | 代表色 | 职责 |
|----|------|----------------|--------|------|
| ① 品牌统一层 | `--party-*`（:root 常量） | ❌ 不受 | 党徽金 `#FFD700`、党建红 `#CE1126` | 全站统一视觉：强调卡边框、主题党日、待办行动按钮、主 CTA、党务标签、通知徽章 |
| ② 角色识别层 | `getAccentColors(role)` / 侧边栏「主题选择」 | ✅ 受（可个性化） | 各角色主题色 | 身份归属 + 个人偏好：**tab 激活态（2026-08-08 三审回归）**、色条、角色标签、人员 chips、左侧边线、主按钮、选中项、chips、工作台内强调色 |
| ③ 状态层 | `--functional-*` + 语义 Tailwind 类 | ❌ 不受 | 完成绿/待处理琥珀/告警红/进行中蓝/API 青 | 只表语义状态：完成、待办、告警、进行中、API 模式 |
| ④ 中性层 | `--neutral-*` | ❌ 不受 | 灰阶 | 文字层级、边框、分割线 |

**判定规则（遇到"这个边框该用什么色"时的决策路径）**：
1. 是**状态指示**（完成/待处理/告警/进行中/API）？→ 状态层 ③
2. 是**个人可选的强调/选中语义**（tab 激活态、下拉选中项、chips 选中态、主按钮、标签）？→ 角色识别层 ②（主题色）
3. 是**全站统一品牌视觉**（强调卡边框、主题党日、待办行动按钮、通知徽章、主 CTA）？→ 品牌统一层 ①（金）
4. 都不是 → 中性层 ④

**同色相跨层判例**（解决"颜色到底有没有规律"的困惑）：

| 色相 | 品牌统一层 | 角色识别层 | 状态层 |
|------|-----------|-----------|--------|
| 红 | `#CE1126` 党建红（主 CTA/党务标签） | 书记/副书主题色 `#B91C1C`（tab 激活态） | `#EF4444` 告警/超期/删除 |
| 金/琥珀 | `#FFD700` 党徽金（品牌） | 纪检委员 `#C2410C` | `#D97706` 待处理/提醒 |
| 蓝 | `--accent-blue`（一般装饰） | 组织委员 `#0EA5E9` / 宣传委员 `#2563EB` | `#3B82F6` 进行中/信息/高亮 |
| 绿 | — | 党小组组长 `#22C55E` | `#16A34A` 完成/成功 |
| 青 | — | 组织者 `#7DD3FC` | teal API 模式 |

**归档决策**：
- **首页 dashboard 定位为功能/状态色体系**（蓝=数据/进行中、红=主操作、金=主题党日、琥珀=待处理），**不接入个人主题色**（2026-08-08 确认）——首页是全局总览，状态色传达信息更准确。
- **首页统计卡四相语义色·定稿**（2026-08-10 两次裁定，最终版）：本月活动用蓝 `#3B82F6`（信息/载体）、活跃专班用亮金 `#F59E0B`（琥珀金，**参考工作台 tab 亮色呈现——底色必须是亮的：浅金底+亮金字**，告别深金 `#A16207`）、未读通知用红 `#DC2626`（待处理/告警语义）、我的考勤用绿/琥珀/红（状态语义，考勤三色称"很好"保留）——红蓝亮金三原色 + 考勤状态色的平衡组合。
- **主题色应用范围在工作台内可适当放宽**（2026-08-08）：工作台内 tab 激活态与强调色挂靠主题色；侧边栏选择器统一命名「**主题选择**」（浅色/深色模式与颜色选择同一排，2026-08-08 更名：称「主题」而非「工作台颜色」）。**每个角色 tab 各有各的主题色渲染**（`bootstrapPage → resolveAccentRole` 支持自选覆盖，2026-08-08 三审强调）。
- **「金」主题色即主题党日胶囊**（2026-08-08 四审定稿，原话"金色就应该和主题党日的胶囊颜色一致，那个我觉得很漂亮！"）：`ACCENT_COLORS.participant` 增配 `bg/border` 覆盖字段（亮金底 `rgba(255,215,0,0.12)` + 金黄字 `#A16207` + 亮金边框 `rgba(255,215,0,0.35)`），`getAccentColors` 优先消费覆盖；侧边栏色板「金」色块显示亮金 `#FFD700`。文字色仍守金黄 `#A16207` 保对比度（2026-08-10 裁定"再黄一点"，较原 `#B45309` 更黄），金不再因对比度牵制而变色。
- **存量收敛**：状态层现存约 69 处硬编码 Tailwind 类（`bg-green-50 border-green-200` / `bg-amber-50` / `bg-blue-50` / `#3B82F6` 等）本期**不动**，后续按本表逐项收敛，新增代码必须按四层分类取色。

**语义动作类与颜色对应法则（2026-08-08 指令 #1/#4）**：

> 背景：tab 激活态已随主题色，但确认赋权/发布通知/批复等按钮仍是硬编码红，党小组选中态与 radio 仍是原生样式——"改了 tab 其他没跟"。裁定：**颜色使用必须有全局对应法则**，用语义类统一收敛，新增代码禁止硬编码色值。

**按钮颜色三层（什么按钮用什么颜色）**：

| 按钮类型 | 语义类 | 规则 | 已落实示例 |
|---------|--------|------|-----------|
| 主操作 | `.btn-accent` | 主题色深化保白字对比度，禁用态 50% 透明 | 确认赋权、发布通知、确认设组长、批复、正式答复、创建活动、提交反馈 |
| 次级操作 | `.btn-accent-soft` | 主题色浅底 + 描边，hover 提亮 | 写入活动、评论（相对批复降级）、设党小组组长 |
| 中性动作 | 原灰系 | 不抢视觉，仅可点 | 取消、清除筛选、导出、关闭反馈 |
| 危险操作 | 状态红 `#EF4444` | 只用于破坏性语义 | 撤销、删除、驳回、解散 |

**选中/选择器主题色对应法则**：

| 组件 | 语义类 | 说明 |
|------|--------|------|
| 可选 chip（党小组/初始受众） | `.chip-option` + 选中 `.chip-accent-on` | hover 主题色提示，选中主题色实底 |
| 列表行选中（模板/子项/页码） | `.sel-accent-on` | 主题色浅底 + 主题色文字，无边框 |
| 单选 radio | `.radio-accent` | 15px 圆点，选中主题色填充（替换原生，2026-08-08 指令 #5） |
| 复选 checkbox | `.checkbox-accent` | `accent-color` 原生定制，勾选色随主题色 |
| 强调文字 | `.text-accent` | 步骤指示/重要文字 |
| hover 卡片 | `.tip-trigger[data-tip]` | CSS 零 JS 轻量 tooltip（提交人悬停等） |

**兜底规则**：以上语义类均以 `var(--app-accent, #B91C1C)` 兜底——6 个工作台经 `bootstrapPage` 注入 `--app-accent` 三件套（`--app-accent/-bg/-border`）随侧边栏自选主题色；归档/反馈/通知等非工作台页回退党建红 `#B91C1C`，保证任何页面可渲染。
