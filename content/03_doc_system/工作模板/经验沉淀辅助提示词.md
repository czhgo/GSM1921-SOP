# 经验沉淀辅助提示词

> **定位：** AI 驱动的经验提炼工具。人类提供原始材料，AI 完成全部提炼工作。
> **核心原则**：人类提供事实记录，AI 负责提炼其意义。
> **积木化设计（2026-08-05）**：提示词拆分为可复用积木，用时按场景排列组合，避免重复冗长。

---

# 第一部分：使用说明

## 你需要做什么

1. **收集原始材料**：微信聊天截图、工作群讨论、口头复盘录音转写、会议纪要草稿——任何记录了"做了什么、怎么做的、遇到什么问题"的材料
2. **选择积木组合**：根据下方对照表选择对应积木，按顺序拼装成一个完整提示词
3. **粘贴材料**：将原始材料粘贴到提示词的 `{材料}` 位置
4. **最小修改**：如果实际场景与积木预设的差异，按最小修改原则调整（见下方修改指南）
5. **提交给 AI**：让 AI 执行提炼，产出结构化的经验文档

## 场景 → 积木组合对照表

| 你的输入 | 使用场景 | 组合 |
|---------|---------|------|
| 活动结束后的群聊复盘 | 主题党日/品牌活动/参访等 | 积木 A + B1 + C1 + D1 + E |
| 专班阶段性讨论记录 | 专班运作中的经验 | 积木 A + B1 + C1（追加"专班协作效率"）+ D1 + E |
| 三会一课执行后的讨论 | 支部大会/党小组会/支委会/党课 | 积木 A + B2 + C2 + D2 + E |
| 考勤/发展党员/档案审查的沟通 | 纪检/组织委员日常工作 | 积木 A + B2 + C2（追加对应制度名称）+ D2 + E |
| 已有经验需要更新 | 之前沉淀过，新一轮实践后要迭代 | 积木 A（迭代输入）+ B3 + D3 + E |
| 混合场景（既有合规又有探索） | 如主题党日既涉及创新形式又涉及考勤合规 | 积木 A + B1 + C1（追加"合规风险点"）+ D1 + E |

## 最小修改原则

积木已经针对常见场景预设了关注维度和输出格式。只在以下情况修改：

- **追加关注维度**：你的场景有提示词未覆盖的特殊关注点（如"跨支部协作""经费管理"），在"关注维度"列表末尾追加一条
- **调整输出粒度**：默认输出"一条经验 = 一个可操作的做法"，如果你需要更粗或更细的粒度，修改"输出粒度"说明
- **指定已有经验**：使用迭代组合（B3/D3）时，必须粘贴已有经验原文

**不要做的事**：不要为了"更全面"而同时堆叠多个输出积木、不要自行修改输出格式、不要删减"按需正反两面论"要求。

## 输出到哪里

AI 产出的经验文档经人工审核后，写入 `content/insights/` 对应文件。写入时须遵守 H30.4 经验沉淀规则（结构兼容性、按需正反两面论、后推翻前规则）。

# 第二部分：积木库

## 积木 A：角色与输入材料（所有组合共用）

```
你是一位经验沉淀助手。你将从人类提供的原始工作材料中，提炼出可复用的经验知识。

## 输入材料

{在此粘贴微信聊天记录、工作群讨论、口头复盘转写、会议纪要等原始材料}
```

> 迭代组合：输入材料处依次粘贴「已有经验沉淀」与「新一轮实践材料」两段；角色句改为"你是一位经验沉淀助手。你将把新一轮工作实践与已有经验沉淀进行对比，识别验证、修正和新增，输出更新后的经验沉淀。"

## 积木 B：思考过程（按场景选一个）

### B1 探索·思考过程

```
## 你的思考过程

1. **还原事实**：从材料中提取"做了什么、怎么做的、结果如何"
2. **识别模式**：哪些做法反复出现？哪些问题反复碰到？哪些决策逻辑可以抽象？
3. **按需正反两面论证**：识别命题是否存在真正的对立方案，存在的必须同时回答"为什么是这样"和"为什么不是那样"
4. **标注边界**：每条经验只在特定条件下成立——什么条件下成立？什么条件下不成立？
5. **区分事实与推断**：材料明确记载的是事实，你从模式中推导的是推断。推断须标注"待验证"
```

### B2 合规·思考过程

```
## 你的思考过程

1. **还原事实**：从材料中提取"做了什么、制度要求是什么、执行与制度有无偏差"
2. **识别偏差**：实际执行与制度要求之间的差距——哪些是合理的灵活处理，哪些是风险点？
3. **按需正反两面论证**：识别命题是否存在真正的对立方案，存在的必须同时回答"为什么是这样"和"为什么不是那样"
4. **标注边界**：每条经验只在特定条件下成立——什么条件下成立？什么条件下不成立？
5. **区分事实与推断**：材料明确记载的是事实，你从模式中推导的是推断。推断须标注"待验证"
```

### B3 迭代·思考过程

```
## 你的思考过程

1. **逐条对照**：将新材料中的实践与已有经验逐条对比，不遗漏
2. **验证强化**：已有经验在新实践中再次得到印证的，标注新证据
3. **条件修正**：已有经验的适用条件被新实践缩小/扩大/改变的，标注修正
4. **新增发现**：新实践中出现的、已有经验未覆盖的模式，标注为新增
5. **推翻标记**：已有经验被新实践明确否定的，标注推翻及理由（后推翻前原则）
6. **正反两面**：对每个修正和新增点，仍需回答"为什么是这样"和"为什么不是那样"
```

## 积木 C：关注维度（探索/合规用）

### C1 探索·关注维度

```
## 关注维度

- 创新做法与效果
- 协作效率与沟通成本
- 可复用模式与推广条件
- 参与者反馈与参与度
```

### C2 合规·关注维度

```
## 关注维度

- 制度对照：涉及哪些制度条文？执行与制度有无偏差？
- 风险点：是否出现合规风险？如何规避？
- 流程优化：现有流程有无冗余步骤？哪些可简化但不影响合规？
- 补课机制：如有缺勤或遗漏，补课流程是否顺畅？
```

## 积木 D：输出格式（按场景选一个）

### D1 探索·输出格式

```
## 输出格式

对每个提炼出的经验点，按以下格式输出：

### 经验：<一句话概括>

- **适用场景**：<什么情况下用>
- **具体做法**：<怎么做>
- **为什么这样做**：<背后的逻辑>
- **为什么不那样做**（仅当存在真正的对立方案时填写）：<常见误区的反面论证>
- **边界条件**：<什么时候不适用>
- **信心等级**：<确信 / 待验证>（仅材料明确印证的标"确信"，推导的标"待验证"）
```

### D2 合规·输出格式

```
## 输出格式

对每个提炼出的经验点，按以下格式输出：

### 合规经验：<一句话概括>

- **涉及制度**：<哪条制度/规范>
- **实际偏差**：<执行与制度的差距，如无偏差写"无偏差">
- **具体做法**：<怎么做>
- **为什么这样做**：<背后的逻辑>
- **为什么不那样做**（仅当存在真正的对立方案时填写）：<常见误区的反面论证>
- **边界条件**：<什么时候不适用>
- **信心等级**：<确信 / 待验证>

## 注意事项（合规特有）

- 合规经验的"为什么不那样做"尤其重要——合规领域最常见的错误是"大家都这么做所以没问题"
- 对制度条文的引用必须准确，不确定的标注"待核实"
```

### D3 迭代·输出格式

```
## 输出格式

### 一、验证强化

> 已有经验在新实践中再次得到印证。

#### 经验：<已有经验的一句话概括>

- **已有表述**：<原文摘录或概括>
- **新证据**：<新实践中什么情况再次印证了这条经验>
- **强化结论**：<维持不变 / 收紧适用条件 / 放宽适用条件>

### 二、条件修正

> 已有经验的适用条件被新实践修正。

#### 经验：<已有经验的一句话概括>

- **原表述**：<原文摘录或概括>
- **原适用条件**：<之前认为的适用范围>
- **新实践情况**：<新实践中发生了什么不同的情况>
- **修正后适用条件**：<调整后的适用范围>
- **修正理由**：<为什么需要修正>

### 三、新增经验

> 新实践中出现的、已有经验未覆盖的模式。

#### 经验：<一句话概括>

- **适用场景**：<什么情况下用>
- **具体做法**：<怎么做>
- **为什么这样做**：<背后的逻辑>
- **为什么不那样做**（仅当存在真正的对立方案时填写）：<常见误区的反面论证>
- **边界条件**：<什么时候不适用>
- **信心等级**：<确信 / 待验证>

### 四、推翻

> 已有经验被新实践明确否定。

#### 经验：<已有经验的一句话概括>

- **原表述**：<原文摘录或概括>
- **推翻证据**：<新实践中什么情况明确否定了这条经验>
- **推翻理由**：<为什么原经验不再成立>
- **替代表述**：<如果有的话，用什么新经验替代>

## 迭代摘要

| 类别 | 数量 | 关键条目（一句话） |
|------|------|-------------------|
| 验证强化 | | |
| 条件修正 | | |
| 新增经验 | | |
| 推翻 | | |

## 注意事项（迭代特有）

- 不要为了"有变化"而强行修正——验证强化同样是有效的迭代结果
- 推翻必须基于明确证据，不能仅凭一次异常就推翻（除非异常本身揭示了结构性问题）
- 条件修正要写清楚"从什么变成什么"，不能只写"条件变了"
- 新增经验的标准与初版一致：可操作、有正反两面、有边界
- 如果新材料不足以与已有经验进行对比，直接说明"材料不足，无法迭代"
```

## 积木 E：执行摘要与通用注意事项（所有组合共用）

```
## 执行摘要

- **做得好的（可复用的）**：
  -
- **卡壳/出问题的（如实写）**：
  -
- **下次怎么改（具体，不要写"下次做好"）**：
  -

## 注意事项

- 不要编造材料中不存在的经验
- 经验应当是可操作的，不是空泛的原则
- 如果材料不足以提炼经验，直接说明"材料不足，无法提炼"
- 留出开放空间：如果材料暗示了某种模式但证据不足，标注为"待验证"而非确定结论
```

> 合规场景可将执行摘要前两问换用"制度执行到位的 / 存在偏差或风险的"措辞，语义相同。
