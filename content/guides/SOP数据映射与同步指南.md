# SOP 数据映射与同步指南

> **本文用途**：帮助书记在日常维护 Markdown 母本时，清晰地了解"改什么不会出事，改什么会崩系统"，从而安全、自信地推进 SOP 迭代。

---

## 一、核心钩稽逻辑 (Core Coupling Logic)

### 1.1 数据源识别

`index.html` 是一个 **AI 静态编译产物（单文件架构）**。它的所有业务数据（步骤文本、角色徽章、时间偏移、注意事项）并非运行时从 Markdown 动态加载，而是由 AI 编译代理在人工调用时一次性将 Markdown 母本"翻译"并硬编码进 HTML 中。

**数据流向（单向、人工触发）：**

```
流程指南/常见工作场景快速指南.md   ──编译代理──►   index.html (timeline-node 节点组)
流程指南/组织委员工作流程指南.md   ──编译代理──►   index.html (timeline-node 节点组)
流程指南/宣传委员工作流程指南.md   ──编译代理──►   index.html (timeline-node 节点组)
流程指南/纪检委员工作流程指南.md   ──编译代理──►   index.html (timeline-node 节点组)
```

编译代理依赖以下 Markdown 结构特征提取数据：

| 提取依据 | 在 Markdown 中的形式 | 示例 |
|---------|---------------------|------|
| **场景名称** | `## 【领域】场景名称` 格式的 `##` 级别标题 | `## 【活动建设】组织生活会` |
| **步骤序号** | 表格首列的 emoji 序号（`1️⃣`…`🔟`…） | `\| 会前准备 \| 1️⃣ 确定主题 \|` |
| **时间偏移（T-N/T+N）** | 表格"时间节点"列中的反引号代码块 | `` `[时间: T-7天]` `` |
| **角色分配** | 表格"负责人"列中的方括号标签 | `\[角色: 党小组组长\]` |
| **步骤描述文本** | 表格"具体操作"列 | `块块组长根据支委会部署确定会议主题` |
| **联系人** | 表格"联系人"列 | `储子禾/王峥旭/辛长乐` |
| **注意事项** | `#### ⚠️ 注意事项` 下方的 `- ✅` / `- ❌` 列表项 | `- ✅ 考勤为刚性考勤` |

---

### 1.2 字段映射 (Field Mapping)

每个 HTML `timeline-node` 节点对应 Markdown 表格中的**一行数据**，字段对应关系如下：

| HTML 属性 / 元素 | 对应 Markdown 列或文本 | 说明 |
|----------------|----------------------|------|
| `data-scenario="org-life"` | `## 【活动建设】组织生活会` 标题 | 场景 ID，snake-case 短字符串（如 `org-life`、`theme-party`），编译代理负责映射 |
| `data-domain="activity"` | 场景标题中的领域前缀（`【活动建设】` / `【组织建设】`） | 活动建设类→`activity`，组织建设类→`organization` |
| `data-role="leader"` | 表格"负责人"列中的 `[角色: 党小组组长]` | 见下方角色映射表 |
| `.tl-dot` 内序号数字 | 表格首列 emoji 序号（`1️⃣` → `1`） | 仅取数字 |
| `.badge-time` 内容 | `` `[时间: T-7天]` `` → 提取为 `T-7` | 编译代理截取时间标签中的相对时间 |
| `.js-expand-trigger` 标题文本 | 表格"步骤"列（`1️⃣ 确定主题`） | 仅取步骤名称 |
| `.js-expand-target` What 区 | 表格"具体操作"列 | 详细描述文本 |
| `.js-expand-target` Who 区 | 表格"负责人"列 + 表格"联系人"列 | 拼合为"角色 + 具体姓名" |
| 注意事项区 | `#### ⚠️ 注意事项` 下 `- ✅`/`- ❌` 列表 | 每个场景展示最多 5 条 |

**角色（`data-role`）映射表：**

| Markdown `[角色: ...]` 标签 | HTML `data-role` 值 | 对应 role-btn 按钮 |
|---------------------------|--------------------|--------------------|
| `[角色: 党小组组长]` | `leader` | 党小组组长 |
| `[角色: 组织委员]` / `[角色: 宣传委员]` / `[角色: 纪检委员]` | `commissioner` | 条条委员 |
| `[角色: 活动组织者]` | `organizer` | 活动组织者 |
| `[角色: 深度参与者]` | `deep` | 深度参与者 |
| 全体与会 / 无特定角色 | `all` | 全部场景（不过滤隐藏） |

## 二、同步安全区 (Easy to Sync — 低成本变更)

以下操作编译代理可以**极低成本、完美同步**到 HTML，书记可以大胆修改：

### ✅ 可安全修改的内容

| 操作类型 | 示例 | 编译成本 |
|---------|------|---------|
| **修改步骤的描述文本** | 将"通知到人"的具体说明改为更准确的措辞 | 🟢 极低：更新对应节点的 `.js-expand-target` What 区文字 |
| **修改联系人姓名** | 将"侯嘉嵘"更新为新任组织委员姓名 | 🟢 极低：更新对应节点 Who 区姓名 |
| **修改注意事项条目的文字** | 优化某条 `✅` 提示的措辞 | 🟢 极低：更新对应场景的注意事项区文本 |
| **调整步骤的时间偏移** | 将 `T-7天` 改为 `T-5天` | 🟢 极低：更新对应节点的 `.badge-time` 文本 |
| **在现有场景末尾追加一个新步骤** | 为【活动建设】组织生活会增加第13步 | 🟡 低：新增一个 `timeline-node` 节点，复制现有节点结构即可 |
| **修改「注意事项」条目的数量（±1～2条）** | 新增一条合规提示 | 🟡 低：直接在注意事项区追加 `<li>` 即可 |
| **修改合规模板文件名** | `党支部工作记录.docx` → 新版文件名 | 🟡 低：更新 What 区内的文件链接文字和 href |
| **修改场景的副标题描述** | 更新 `scenario-header` 内的灰色说明文字 | 🟢 极低：更新 `<span class="text-gray-400">` 内的文本 |

## 三、架构雷区 (Hard to Sync / Fragile — 高危变更)

以下操作如果由书记**直接修改 Markdown 母本**而不同步通知编译代理更新 HTML，将导致 HTML 状态机逻辑错误或数据不一致：

### 🔴 危险操作 — 会导致 HTML 状态机崩溃或渲染错误

| 危险操作 | 为什么会崩 | 正确做法 |
|---------|-----------|---------|
| **擅自改变时间锚点书写格式** | 如把 `` `[时间: T-7天]` `` 改写成"提前一周"或"活动前7天"，编译代理无法识别 `badge-time` 的相对时间标记，时间徽章将显示为空或原始文本 | 必须保持 `` `[时间: T-N天]` `` 或 `` `[时间: T+N天]` `` 或 `` `[时间: 活动中]` `` 三种固定格式之一 |
| **擅自增加 `[角色: ...]` 标签中的新角色类别** | 如新增 `[角色: 团支书]`，HTML `data-role` 不存在对应枚举值，该节点将被所有 role-btn 过滤器完全隐藏，用户永远看不到 | 必须先由书记告知书记/AI 扩展 role-btn 路由（新增按钮 + 过滤逻辑）再添加新角色标签 |
| **修改场景标题的编号格式** | 如把语义化名称标题改为纯数字编号标题，`data-scenario` 的 ID 映射将断裂，domain 过滤逻辑失效 | 场景标题必须保持语义化名称格式（如`## 【活动建设】组织生活会`），scenarioId 沿用 snake-case 短字符串 |
| **更改 `data-domain` 分类边界** | 将【组织建设】意见建议反馈从 `organization` 挪到 `activity`，domain-btn 过滤会把该场景路由到错误的分组 | 必须同步修改 HTML 中该场景所有节点和 `scenario-header` 的 `data-domain` 值 |
| **删除现有场景的中间步骤而不重新编号** | 删除【活动建设】组织生活会的步骤5（签到），但 `.tl-dot` 序号仍为 1-8，视觉上序号跳空，数据血缘断裂 | 删除步骤后必须同步重新编号所有后续节点的 `.tl-dot` |
| **在 Markdown 表格中合并多步骤行** | 将步骤6+7合并为一行，编译代理会生成一个节点覆盖两步，丢失原有两步的单独 `data-role` 归属 | 每个需要独立过滤的步骤必须单独一行 |
| **修改场景标题中的领域前缀** | 如将 `## 【组织建设】意见建议反馈` 误改为 `## 【活动建设】意见建议反馈`，编译代理据此前缀判断 `data-domain`，会导致场景路由到错误分组 | 场景标题必须保持 `## 【活动建设】...` 或 `## 【组织建设】...` 语义前缀，不得擅自改变 |

## 四、快速决策树 (Quick Decision Tree)

```
我想修改 Markdown 母本中的某些内容
│
├─ 是否只修改"具体操作/描述文字"列？
│   └─ YES → ✅ 安全，直接改，然后告知 AI 代理同步 HTML 文本
│
├─ 是否修改"时间节点"列的格式（如从 T-7 天改为"提前一周"）？
│   └─ YES → 🔴 危险，必须保持 `[时间: T-N天]` 格式
│
├─ 是否要增加一个全新的步骤？
│   ├─ 追加到场景末尾 → 🟡 低风险，复制最后一个节点结构
│   └─ 插入到中间 → 🟠 中等风险，后续步骤全部需要重新编号
│
├─ 是否要增加一个全新的角色类别？
│   └─ YES → 🔴 危险，必须先扩展 HTML role-btn 路由再写 Markdown 标签
│
├─ 是否要增加一个全新的场景（如【组织建设】新场景名）？
│   └─ YES → 🟠 中等风险，需在 HTML 中新增 scenario-header + N 个 timeline-node
│
└─ 是否只修改联系人姓名或注意事项文字？
    └─ YES → ✅ 安全，直接改，告知 AI 代理同步即可
```
