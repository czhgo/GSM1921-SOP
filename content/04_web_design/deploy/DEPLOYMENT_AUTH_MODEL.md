# 部署与认证场景模型

> 本文档定义系统的部署形态、登录态与登录门控的统一模型，作为侧边栏统一与全站登录跳转逻辑的权威依据。

## 一、问题缘起

系统存在多种部署形态与登录态，侧边栏与登录跳转逻辑在不同页面间存在不一致：哪些页面强制跳登录、哪些匿名可访、未登录时侧边栏显示什么、内部附件与公开外链的下载权限如何区分——此前缺乏统一模型，靠各入口分散实现。

本文档将这些「场景」拆成两个正交维度，统一约定侧边栏 footer 与登录门控的行为。

## 二、5 场景模型（两轴正交）

系统行为由两个正交维度决定，二者不可混为一谈：

- **轴一 · 部署形态**：决定「能否真正登录 / 数据存哪」
  - **静态托管**：GitHub Pages，`docs/` 直接部署，无后端。只能 mock，登录是「演示/开发绕过」；**有 about**（`about.html` 是公开门面「支部的故事」）。
  - **有后端**：Node 一体化（`server/` 同源）或计算中心对接。可真实账号登录 + API + 持久化；**无 about**（内部工具不需要公开门面）。
- **轴二 · 登录态**：决定「侧边栏显示什么」
  - **未登录**（访客）
  - **已登录 · 演示绕过**（mock：dev 卡片 / `?dev=ROLE` / 无后端时账号密码回退，无真实 token）
  - **已登录 · 正常**（api：账号密码 → 后端签发 token）

两轴笛卡尔积，去掉「静态托管下正常登录」这一不可能项，得到 5 个实际场景：

| # | 场景 | 部署 | 登录态 | 数据源 |
|---|------|------|--------|--------|
| S1 | 静态托管 · 访客 | 静态 | 未登录 | mock |
| S2 | 静态托管 · 演示登录 | 静态 | 已登录 · 演示 | mock |
| S3 | 有后端 · 访客 | 有后端 | 未登录 | mock |
| S4 | 有后端 · 开发绕过 | 有后端 | 已登录 · 演示 | mock |
| S5 | 有后端 · 正常登录 | 有后端 | 已登录 · 正常 | api |

「开发模式 vs 正常模式」同为「已登录」的两种方式——差异体现在数据源（mock vs api）与持久化，不影响侧边栏 footer。

## 三、侧边栏 footer 统一

所有页面（含静态壳 about/help）的侧边栏 footer 结构统一如下：

- **恒有**：帮助、字号切换、主题切换（浅色 / 跟随系统 / 深色 + 主题色板）
- **关于**：仅静态托管显示（有后端时隐藏）
- **退出登录**：仅已登录显示（未登录不显示登录引导，跳转由门控层触发）

各场景 footer 态：

| 场景 | 关于 | 退出登录 |
|------|------|---------|
| S1 静态 · 访客 | 显示 | 隐藏 |
| S2 静态 · 演示登录 | 显示 | 显示 |
| S3 有后端 · 访客 | 隐藏 | 隐藏 |
| S4 有后端 · 开发绕过 | 隐藏 | 显示 |
| S5 有后端 · 正常登录 | 隐藏 | 显示 |

## 四、登录门控四层模型

登录门控采用分层触发：

| 层 | 门控对象 | 未登录时行为 |
|----|---------|------------|
| L1 页面 | 工作台 `workspace/*` | 强制跳 `login.html` |
| L2 功能 | 一切「写入」操作（建活动 / 写支部文件 / 提交反馈等） | 触发跳登录（或弹登录引导） |
| L3 组件 | 一切「身份逻辑」组件（个人待办 / 个人考勤 / 身份标签 / 主题色） | 隐藏或显示「登录后可见」引导 |
| L4 下载 | 内部附件 vs 公开外链 | 内部附件需登录；公开外链无需登录 |

> 首页（`index`）为匿名可访问页面：匿名可见通知 / 日历 / 专班 / 活动的概览；点击任一组件跳工作台，再由 L1 工作台门控触发登录。登录目标当前为本地 `login.html`，后续对接北大 IAAA 单点登录（统一跳转 IAAA 网页）——IAAA 为登录落点的最终目标，接入前不改变门控触发条件。

## 五、下载情形（L4）

下载/查看分两类：

1. **公开外链**：官方文件（指向 12371.cn 等外部站点）→ 无需登录，新窗口打开。
2. **内部附件**：支部文件、宣传档案、考勤考察附件（`/api/v1/uploads`）→ 需登录（后端 `requireAuth`）。

支部文件的「可见」本身也需登录：匿名只看到「登录后查看」提示。

## 六、后端检测：构建时注入配置

侧边栏需要知道「静态托管 vs 有后端」以决定「关于」链接显隐，采用**构建时注入配置**，不做运行时探测：

- 新增 `docs/src/config/deploy.js`，导出 `DEPLOY_MODE: 'static' | 'server'`。
- GitHub Pages 部署时保持 `'static'`；Node `server/` 部署时注入为 `'server'`（注入机制见实现）。
- 侧边栏据此决定「关于」显隐；`getDataSource()`（mock / api）仍由登录态独立决定，二者不混淆。

## 七、代码落点

- `docs/src/config/deploy.js`（新增）：`DEPLOY_MODE` 常量
- `docs/src/components/sidebar.js`：footer「关于」按 `DEPLOY_MODE` 显隐；「退出登录」按登录态显隐
- `docs/src/core/bootstrap.js`：L1 页面门控（工作台强制跳登录）沿用，其余页面不强制
- 各写入功能 / 身份组件：按 L2 / L3 / L4 补登录引导或隐藏（逐处实施）
- `docs/src/components/header.js`：身份标签在未登录时隐藏（已实现，复核）
