# 品牌活动设计理念

> **定位**：品牌活动是活动的子类型（标签），不改变活动本身的数据结构。品牌认定在网页上由书记操作。品牌活动如需独立展示网页，将来可探索。

---

## 一、核心定义

品牌活动是支部长期培育、持续迭代的**动态工作项目**，非一次性事件。

### 1.1 四属性

| 属性 | 说明 |
|------|------|
| 持续性 | 跨学期/年度运营，非单次收场 |
| 成长性 | 萌芽 → 培育 → 成熟 → 标杆 四阶段 |
| 迭代性 | 执行 → 复盘 → 优化 → 再执行 |
| 体系性 | 方法论 + 资源库 + 人才梯队 |

### 1.2 品牌活动 = 活动的子类型

品牌活动不是独立实体，而是活动的标签/子类型。这意味着：

- **数据结构**：品牌活动复用现有 ActivityRecord 数据结构，仅增加一个 `isBrand: boolean` 字段
- **赋权逻辑**：品牌活动的赋权与普通活动一致，无需额外处理
- **视图逻辑**：品牌活动在现有视图中通过筛选条件展示，无需独立页面
- **品牌认定**：由书记在网页上操作标记，A/B 均可（书记审批或支委会讨论后书记标记）

**为什么不是独立实体？** 优先考虑简单模式——品牌活动本质上是"被认定的活动"，它首先是活动，其次才是品牌。独立实体会引入新的数据模型和 CRUD 流程，增加系统复杂度，而标签模式足以满足当前需求。如果品牌活动需要建设额外的展示网页（独立网页），将来可以探索。

### 1.3 品牌认定流程

品牌认定是**直接认定**，不是评分算法。支部根据活动的持续性、影响力、培育价值直接判断是否列入品牌活动。

| 步骤 | 操作者 | 操作 |
|------|--------|------|
| 1. 培育观察 | 支委/组长 | 识别有品牌潜力的活动 |
| 2. 讨论认定 | 支委会 | 讨论是否列入品牌 |
| 3. 网页标记 | 书记 | 在网页上操作标记 `isBrand = true` |

## 二、典型锚点案例

### 案例一：宣讲团

| 维度 | 内容 |
|------|------|
| **类型** | 对外输出型 |
| **培育路径** | 自组织萌芽 → 支委识别价值 → 给予资源扶持 |
| **核心特征** | 从零搭建、持续壮大、对外展示、可复制推广 |
| **关键经验** | 自下而上的生命力 + 支委的资源匹配 = 品牌孵化的最优路径 |

### 案例二：人生回望录

| 维度 | 内容 |
|------|------|
| **类型** | 内容生产型 |
| **培育路径** | 个人发起 → 团队扩展 → 制度化运营 |
| **核心特征** | 老教授深度访谈、跨学期滚动播出、形成内容资产库 |
| **关键经验** | 内容型品牌活动产生可累积的知识资产，其价值随时间递增 |

### 案例启示

1. **自发性 > 指派性**：最成功的品牌活动来自党员自发的兴趣和热情
2. **支委的角色是赋能而非指挥**：识别→扶持→制度化，而非设计→分配→检查
3. **跨类型融合是品牌活动的天然属性**：一个品牌活动往往跨越多个子类型
4. **品牌活动的"资产性"**：产生可复用、可传承的产出物

## 三、与决策树模型的关系

在决策树四层模型中，品牌不是 L1~L4 的任何一层，而是 L3（时长=长期活动）的一个可选子流程——品牌认定不再是活动的"属性维度"，而是长期活动发展到一定阶段后的"认定"。

**为什么品牌不是维度？** 因为品牌不是活动的起点，而是活动的结果。将结果设为起点，等于在活动尚未策划时就预设了它应该成为品牌——这是本末倒置。

## 四、未来探索方向

品牌活动如需独立展示网页（如品牌活动专区、品牌故事页面、Canvas 分享卡片），将来可探索。当前阶段，品牌活动通过标签筛选在现有视图中展示即可。
