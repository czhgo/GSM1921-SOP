# SOP 目录索引——各委员与党小组组长的操作规程

> 目录定位见 [DOC_MAP.md §五 目录作用表](../../03_doc_system/DOC_MAP.md#五目录作用表2026-10-24-立)。

## 作用

本目录存放**各角色「按什么流程做事」的操作母本**，回答「组织委员 / 宣传委员 / 纪检委员 / 党小组组长 / 普通成员分别在什么场景、按什么步骤、交接给谁」。

## 不负责什么

- 不写角色权限矩阵与键级口径——归 [SYSTEM_ROLE_PERMISSION.md](../SYSTEM_ROLE_PERMISSION.md)。
- 不写组织形态与委员体系的设计论证——归 [COMMISSIONER_DUTY_FRAMEWORK.md](../COMMISSIONER_DUTY_FRAMEWORK.md)。
- 不写系统实现、页面流程与 AI 协作方法——归 `04_web_design/`、`05_ai_coding/`、`docs/`。
- 不存历史会议与上级文件原文——归 `01_strategy/references/`。

> **七份的分工**：`INDEX.md` 是导航层（不写流程）；六份正文按角色分工——组织 / 纪检 / 宣传三条「条条」线、党小组组长「块块」线、成员场景速查、以及支委与党小组的定责说明。跨 SOP 的公共规则（通知发布、考勤、归档等）只在《常见工作场景快速指南》的公共规则表中定义一次，其余 SOP 引用而不另立口径。

## 权威源与派生

- **权威源**：六份 SOP 正文是各角色操作的母本；其中公共规则以《常见工作场景快速指南》的公共规则表为唯一权威。
- **INDEX 的关系**：`INDEX.md` 只做三件事——列出 SOP 与责任人、提供共享术语、对账物理文件是否全部登记；术语定义只在 INDEX 写一次，各 SOP 引用不重复定义。
- **派生**：系统帮助页与工作台流程文案是 SOP 的派生表达，不得反向覆盖母本；权限口径仍以 `SYSTEM_ROLE_PERMISSION.md` 为准。

## 知识流向

`01_strategy/` 的战略与 `02_institution/` 的组织设计 → 在本目录写成各角色可执行 SOP → 派生出系统流程、待办与帮助文案（`04_web_design/`、`docs/`）→ 执行中发现的场景缺口 → 先改公共规则表 / 对应 SOP，再同步 INDEX 与系统。

## 是否保留原始材料

不保留。历史会议与上级文件原文在 `01_strategy/references/`；执行过程中的评议与证据在 `.ctx/logs/`、`.ctx/evidence/`。

## 维护触发器

- 新增、删除或重命名任一 SOP 或 INDEX；
- 角色职责、交接链或公共规则变更（须一改具改到所有引用处）；
- `INDEX.md` 的术语、SOP 清单或关联字段变更；
- `SYSTEM_ROLE_PERMISSION.md` 或 `COMMISSIONER_DUTY_FRAMEWORK.md` 的职责口径变化。
