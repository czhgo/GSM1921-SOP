# Lens B — design-with-taste

> 审查口径：Simplicity（主次与渐进披露）/ Fluidity（空间连续与动效）/ Delight（选择性强调与空态）。
> 只判「这一屏应该先看什么、什么该退后」，不复述控件级规范。
> 审查时间：2026-10-19。证据均指向当前工作区代码，不引用 lens A / lens C 结论。

## 深审发现

### U-01 「待我处理」计数不含「待答复」周报
- **现象**：全局概况的「待我处理」区条数与结论带里的「待答复」不是同一集合。`_buildActionItems()` 只收待办组、文件确认、汇报请求/我的汇报、活动、专班、条线缺口；支书待审周报只进入第四个指标「待答复」，没有进入「待我处理」列表。于是标题说「待我处理」，溢出行「共 N 项」却不含周报待审。
- **证据**：`docs/src/components/governance/work-overview.js:128-135`（四指标定义）、`:431-435`（`totals.actions = actionItems.length`）、`:658-772`（actionItems 组装，无 `getSecretaryPendingReports`）、`:612-617`（周报待审只写入 `answerCount`）；`docs/src/entries/tabs/secretary/todo-tab.js:363`（周报待审在待办页另有独立区）。
- **影响**：用户看到「待答复 3」和「共 6 项 · 去待办」会默认这是同一批事；实际两处口径不同。对支书的高频首屏，这会造成「我处理完了，为什么数字还在」的二次核对成本。
- **建议方向**：二选一——把待审周报作为 `kind: 'report'` 纳入 actionItems，或把该区标题改为「待办与缺口」并把「待答复」做成同区筛选；不要继续用两个名字说两套集合。
- **严重度**：P2
- **可能冲突**：lens A（列表/计数一致性）

### U-02 「党员结构」标题口径
- **现象**：审计底表指向的卡片已不存在。`secretary/overview-tab.js` 现仅 32 行，整体委托三层骨架；三层是「结论带 / 条线 / 待我处理」，`docs/src` 已搜不到「党员结构」标题，原四阶段分布也不再出现在概况首屏。
- **证据**：`docs/src/entries/tabs/secretary/overview-tab.js:1-32`；`docs/src/components/governance/work-overview.js:483-511`（三层 DOM，无结构分布卡）；`docs/src` 内 grep「党员结构」0 命中。
- **影响**：原误读入口消失，首屏主次由「逾期 / 待我处理」承担，符合渐进披露；本条不再有视觉风险。
- **建议方向**：结项。若未来把四阶段分布放回概况，标题必须写成「队伍结构（含积极分子 / 发展对象 / 预备党员）」，不得复用「党员结构」。
- **严重度**：P2
- **可能冲突**：无

### U-04 纪检考勤：两级拆分后仍有平权竞争
- **现象**：已拆成「考勤 / 补课」一级分段 + 「确认与录入 / 数据查看」二级视图，方向正确。但「确认与录入」内仍是三张平权卡（待确认考勤、出勤申诉、会议考勤录入），会议卡把「上传位按会议类型分」在同一屏讲了两次；「数据查看」把矩阵与全量总表两张大表纵向串联，矩阵区又用「活动下拉 + 活动名搜索 + 起止日期」四种控件表达三类筛选；表格卡顶部并排 4 个等权低频动作（导出 CSV / 出勤率汇总 / 打印 / 提交支委会），没有唯一主动作。
- **证据**：`docs/src/entries/tabs/disc/attendance-tab.js:181-198`（两级视图与三卡顺序）、`:825-835`（`<p>` 与 `<details>` 重复同一口径）、`:1085-1094`（活动下拉 + 名称搜索 + 两个日期同权）、`:1193-1198`（4 个 `btn-outline` 等权）、`:609-614`（卡头常驻 4 个计数，其中「出勤自动确认」不可操作）。
- **影响**：纪检每天的第一动作应是「确认异常」，现在却要和「录会议考勤」「申诉」「导出」争夺首屏注意力；数据视图的四种筛选用两套方式说同一件事，用户要先猜哪套生效。
- **建议方向**：确认队列设为 process 视图唯一主角；会议录入降为页尾折叠或二级入口；申诉无数据时不渲染；矩阵筛选合并为「活动 + 时间区间」一套并删掉重复的名称搜索；表格卡四个低频动作收进一个「导出 ▾」菜单，主动作只留「提交考勤统计至支委会」。
- **严重度**：P1
- **可能冲突**：lens A（筛选/表单规范）、lens C（视觉层级）

### U-05 专班管理：三视图已拆，详情六分区仍平铺
- **现象**：顶层已拆成「专班工作组 / 活动工作组 / 报名总表」，原三类对象混排大幅缓解。残留问题在详情面板：打开一个专班后同时平铺 6 个同权分区（成员与授权、任务与产出、历史分工、核验与代录、报名与记录、收尾与复盘），其中「历史分工」「核验与代录」是一次性迁移/清理对象，却与核心「任务与产出」同字号同分隔；卡片上「撤销并删除」与「启动专班」并排同重，删除前连弹两次原生 `window.confirm`。
- **证据**：`docs/src/entries/tabs/org/taskforce-tab.js:414-440`（6 分区同权）、`:1331-1334`（主/破坏动作并排）、`:276-283`（两次 `window.confirm`）；就地展开位置见 `:454-464`（这点是对的）。
- **影响**：进入专班后第一眼无法判断「我现在该做什么」；低频治理块占据与核心任务相同的阅读位；删除动作使用浏览器原生对话框，视觉上脱离主题，也打断「这个工作台是一个空间」的感觉。
- **建议方向**：详情首屏只留「任务与产出 + 成员与授权」；历史分工 / 核验与代录折叠为「历史迁移」；破坏动作收进「更多」并与主按钮拉开距离；两次 `window.confirm` 换成既有 `components/ui/modal.js` 的确认弹层。
- **严重度**：P1
- **可能冲突**：lens A（确认弹窗规范）、lens C（按钮主次）

### U-06 支部管理：长页已拆，目录页主色不唯一
- **现象**：原「支部档案 + 换届向导 + 部署自查」长页已拆：`branches-tab.js` 只剩目录表，配置 / 向导 / 部署自查移到独立 `branch-config.html`。目录页残留问题是一屏出现 N+1 个同主色按钮：页头「新建支部」是 `btn-accent`，每行「支部设置」也是 `btn-accent`，旁边再跟一个「查看该支部」。实跑 page-sweep 还读到该表表头 12px、首列 14px（期望统一 13px），说明首列强调是意外的而不是设计的。
- **证据**：`docs/src/entries/tabs/party-committee/branches-tab.js:32`（新建支部 `btn-accent`）、`:60`（行内 `btn-accent` + `btn-outline`）；`docs/src/entries/pages/branch-config-entry.js:167-173`（配置页挂载）；实跑 `node --test test/page-sweep.test.mjs` 的 P7 读数：`支部管理` TH 全部 12px、TD「光华管理学院本科生党支部本科生」14px。
- **影响**：页面级主色不再唯一，用户会犹豫「先点哪一个设置」；表格三级字号（12 / 13 / 14）让「第一列最重要」变成偶然结果。
- **建议方向**：主色只留给页级「新建支部」；行内「支部设置」降为 `btn-outline` 或文字链接，「查看该支部」降为行尾次级链接；表头与数据格统一 13px，靠字重而非字号建立首列层级。
- **严重度**：P2
- **可能冲突**：lens A（一屏一个主按钮 / 字号档）、lens C（视觉层级）

### U-08 组长「本组活动」：范围已说清，筛选仍要筛两次
- **现象**：范围文案已按支书口径改名并拆成两组：「本组创建 / 承办 · 可写入」与「可见活动（只读）· 支部级 / 定向下发」，原「本组活动含支部其他活动」的误读已消除。残留的是同一页两条列表各接一套检索条（同一组 keyword / facets、两个 `stateKey`），数据超过 8 行时上下出现两条几乎相同的筛选行；顶部说明句又与两组标题重复表达同一件事。

- **影响**：用户回答「本月本组有哪些活动」要维护两套筛选状态；首屏三处说同一件事，增加噪音。

### U-23 活动材料闭环：流程终点没有「房间」
- **现象**：全站页面清单中没有「活动材料闭环」承载面；支委会的「要求组织者复盘」只能进入单场 `activity.html` 操作，跨活动「哪些场次材料 / 复盘未收口」没有一张清单。帮助文档把终点拆给「活动详情 + 宣传台档案归档」，但没有任何一屏能回答「还差哪几场」。
- **证据**：`docs/` 根页面清单（17 个：about / activity / archive / branch-config / feedback / help / index / login / messages / notice / party-committee-meeting / person / search / settings / taskforce / thought-report / wizard + 7 个工作台，无闭环页）；`docs/src/entries/pages/activity-entry.js:247-267`（追加复盘仅嵌在单场详情）；`.ctx/REVIEW_QUEUE.md:349`（B-3 仍未建）。
