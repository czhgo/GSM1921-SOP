## 二、风险明细（供日后特批修复，本次不改）

> 根因同源：work-overview.js 每次动作都执行 `container.innerHTML = …` 全容器重建（211）后重绑（238），且未对概况内唯一文本输入域（B1「请我汇报」行内输入）做任何草稿保态。折叠/下钻为「重建式往返」而非判据①要求的「CSS 隐藏不重建」。

- **R-1｜同容器其它表单提交导致本行草稿丢失**（判据③）
  - 文件:行：work-overview.js:306-315（提交处理）+ 211（重建）
  - 现象：存在 ≥2 条「请我汇报」请求时，在 A 行输入未提交内容，随后提交 B 行 → rerender 全量重建 → A 行未提交草稿丢失。A 表单在「未提交成功」下被重置。
  - 最小修法建议：模块级草稿表 `_reqDraftByIssue = {}`（input 事件存值；渲染回填仍存在于请求列表中的 issue；该 issue 提交成功或从列表消失时清除）。改动集中在 work-overview.js 约 +15 行。

- **R-2｜卡点区「确认收到」刷新触碰汇报表单 DOM**（判据②）
  - 文件:行：work-overview.js:105（按钮）、318-324（处理）、322（rerender）、211（重建）
  - 现象：在 B1 输入草稿未提交，点击下方卡点区「确认收到」→ 全容器重建 → 草稿丢失。判例（#wf-form-zone 独立于列表 / 纪检考勤 CSS 保态）要求的「列表刷新不触碰表单 DOM」未满足。
  - 最小修法建议：同 R-1 草稿表回填即可覆盖（或在 R-1 修复前提下把 B1 区卡片拆为独立渲染单元，仅重建自身卡片）。

- **R-3｜在办下钻-返回往返丢失概况草稿**（判据①③）
  - 文件:行：work-overview.js:165/181（下钻钮）、327-340（_woDetail+rerender）、49-52（详情路由）、378-381（返回重建）
  - 现象：B1 有草稿 → 点任一在办条目下钻详情 → 点「← 返回工作概况」→ 概况整容器重建，草稿消失。该往返属同页「展开/收起」，未提交内容因重建丢失。
  - 最小修法建议：方案甲＝R-1 草稿表回填；方案乙（更贴判例形态）＝下钻详情改为「已渲染节点的 CSS 显隐切换」（容器保留概况 DOM），需特批改造受保护组件时评估。

- **登记提示（非判据红线，宽口径记录）**：B4/B5/C1 属导航类（切 tab 离开概况），B1 草稿随导航离开丢失为常规交互可接受；若书记要求跨 tab 草稿保态需另行立项（超出 P12 只读复查范围）。
