# 工作台视觉语言与条目交互 Spec

## Why

功能已经到位，但工作台三页（全局概况 / 待办 / 支委会）仍像线框：标题与行标题同重、表头与正文同色、红色同时承担主题与错误、条目动作没有统一语法。根因不是「缺装饰」，而是缺一套可执行的**视觉语法、颜色语义、行型交互与前置卡**。

## 研究结论：过去的设计取向是什么

本仓不是没有审美取向，而是取向分散在原则里、没有被翻译成「这一屏怎么做」：

| 已有取向 | 出处 | 对本次的含义 |
|---|---|---|
| 清洁优先：纯色优先、扁平优先、留白优先 | DESIGN_SYSTEM §一 原则 1 | 不靠渐变、玻璃、重阴影；靠字号、留白、色调分区 |
| 哑光质感：低饱和中性底，拒绝高光镜面 | §一 原则 3 | 工作台保持纸白/暖灰，不做「数据驾驶舱」 |
| 色彩克制：每页主色 ≤ 2 种，功能色只表状态 | §一 原则 4 · §2.8 | 一个角色主题色 + 功能色状态；不新增装饰色 |
| 四层颜色各司其职 | §2.8 · §2.9 | 主题色管行动/选中/身份；功能色管状态；中性管结构 |
| 纯展示行不得有 hover 伪装 | §4.2 · §10.4 | 行是否可点必须先判行型，不能一律加 hover |
| 小字号衬线曾全仓撤回 | DESIGN_METHODOLOGY §1.5 | 不用小字衬线制造「精致感」；标题才用宋体 |
| 同页左边条不得多色 | DESIGN_METHODOLOGY §1.5 | 不用彩色左边条分区；分区靠留白与标题层级 |

**推荐方向：静雅公文（哑光克制）**。不是把页面做得更花，而是把「公文/简报」的秩序感做足：纸白底、墨色正文、一个角色主题色、功能色只标状态；用字号差、数字尺度、表头底色、章节留白和细分割线建立层级。它与过去七条取向一致，不引入新的视觉体系。

## 当前「不美」的具体病灶

1. **结论带没有重心**：`在办 230 逾期 67 待我处理 29 待答复 2` 全部同字号同字重，230 最大却最不重要；没有分隔、没有主次。
2. **卡片红边滥用**：待办、支委会会议卡出现整圈红边，红色既像主题色又像错误色，用户不知道它在报警还是在选中。
3. **表头与正文同重**：表头没有底色、没有字号差，扫读时找不到列边界。
4. **章节标题与行标题同字号**：都是 14px/700 与 14px/500，层级压缩，页面像一张平铺的清单。
5. **动作没有主次**：同一行出现「去处理 / 待汇报」两个彩色按钮，或「改派 / 撤销」两个等权文字，用户要读两遍才决定点哪个。
6. **状态只是文字**：支委会「待召开」、成员「在任/空缺」没有状态形态，和普通单元格混在一起。
7. **列表行像浮动文字**：行与行之间缺少稳定的分隔与节奏，扫读时容易串行。
8. **图标与箭头不成体系**：有的动作有箭头，有的没有；有的按钮有图标，有的没有，动作识别成本不稳定。

## What Changes

- **视觉语法**：把「字号 / 字重 / 颜色 / 图标 / 间距 / 边框底色 / 动效」各自承担什么信息写清，新增 §4.23。
- **颜色语义**：新增 §2.10「颜色四问 + 明暗档」；**BREAKING**：逾期从红改为琥珀（warning），红色只留给阻断/失败/删除。
- **行型交互**：扩展 §10.4 为「导航行 / 动作行 / 选择行 / 展示行 / 主从行」五类，写清整行是否可点、用什么元素、动作如何并存。
- **三页视觉刷新**：全局概况、待办、支委会按「静雅公文」重做层级；首页工作组卡同步。
- **UI 前置卡**：在 `CLAUDE.md` 热层与 `DESIGN_SYSTEM.md §0` 各放一张 10 问卡，改界面前必答。
- **守卫**：新增颜色语义、行交互、焦点/动效守卫；1440 与 390 截图复核。

## ADDED Requirements

### Requirement: 视觉语法单一源

`DESIGN_SYSTEM.md` SHALL 新增「视觉语法」一节，逐项说明字号、字重、颜色、图标、间距、边框底色、动效各自承担什么信息，并给出反例。

#### Scenario: 新增一个区块
- **WHEN** 开发者新增一个区块
- **THEN** 能按视觉语法表回答：标题用哪档字号、正文用哪档、状态用什么颜色、动作用什么形态、分区靠留白还是边框

### Requirement: 颜色四问与明暗档

颜色使用 SHALL 先回答四问：**是行动 / 是状态 / 是身份 / 是结构**；再按「明暗档」选择实底或淡底。

- 行动 → 主题色：主 CTA 用实底白字；次级行动用淡底深字。
- 状态 → 功能色：状态徽章/提示条用淡底深字；只有阻断/失败/删除确认可用实底白字。
- 身份 → 角色识别色：只用于身份标识，不用于按钮和状态。
- 结构 → 中性色：文字、边框、分割线、禁用。

#### Scenario: 逾期与错误同屏
- **WHEN** 页面同时出现「逾期」与「删除失败」
- **THEN** 逾期用琥珀 warning 的淡底深字；删除失败用红色 error；两者不共用同一色相与形态

#### Scenario: 支书主题色本身是红色
- **WHEN** 当前角色主题色为红
- **THEN** 主题色只出现在主 CTA、选中态、焦点与身份标识；逾期仍用琥珀，错误仍用红但只出现在状态徽章/确认按钮

### Requirement: 行型交互矩阵

`DESIGN_SYSTEM.md` §10.4 SHALL 定义五类行型与交互边界：

| 行型 | 整行可点 | 元素 | 主行动 | 次行动 | hover / 焦点 |
|---|---|---|---|---|---|
| 导航行 | 是 | `<a>` 或 `<button>` | 打开目标 | 无，或一个行尾「更多」 | 有 hover，有 focus-visible |
| 动作行 | 否 | `<div>` + 末列按钮 | 一个明确按钮 | 其余进「更多」 | 行不 hover，按钮有 |
| 选择行 | 是 | `<button>` | 选中/取消 | 无 | 有 hover，有 focus-visible |
| 展示行 | 否 | `<div>` | 无 | 无 | 无 hover、无 pointer |
| 主从行 | 是（仅选中） | `<button>` | 选中并在右栏显示 | 一个行内动作 + 「更多」 | 有 hover，有 focus-visible |

#### Scenario: 动作行里放按钮
- **WHEN** 一行同时有「改派」和「撤销」
- **THEN** 行本身不可点；「改派」为主行动（主题色文字），「撤销」为危险文字；不得两个都做成同权重按钮

#### Scenario: 主从行里点行与点按钮
- **WHEN** 用户点待办行本身
- **THEN** 只切换右栏详情，不触发行内动作；点行内「去处理」时 `stopPropagation`，只执行该动作

### Requirement: 工作台三页视觉层级

全局概况、待办、支委会 SHALL 按「静雅公文」建立层级：

- 结论带：数字 26–28px/600，标签 12px/500；四项之间用细竖线分隔；逾期用琥珀、待我处理用主题色、其余中性。
- 章节头：14px/700 宋体 + 12px 计数/说明；与内容之间留 12px；不使用整圈彩色边框。
- 表头：`--neutral-50` 底 + 12px/600 中性字；正文 13px；首列 14px/500。
- 状态：统一用淡底深字徽章；不使用裸文字表示状态。
- 动作：每行最多 1 个主行动 + 1 个「更多」；主行动为主题色文字或 `btn-accent-soft`。

#### Scenario: 打开全局概况
- **WHEN** 页面加载完成
- **THEN** 第一眼落在「逾期/待我处理」而非「在办 230」；条线表有表头底色；待我处理卡没有整圈红边

#### Scenario: 打开支委会
- **WHEN** 页面加载完成
- **THEN** 两张表的表头有底色；「在任/空缺/待召开/已留存」是状态徽章；「改派」与「撤销」主次分明

### Requirement: UI 前置卡

`CLAUDE.md` 热层与 `DESIGN_SYSTEM.md §0` SHALL 各有一张 10 问 UI 前置卡；任何改界面的任务在写代码前 SHALL 逐条回答。

10 问：
1. 这一屏唯一的主动作是什么？有没有第二个同等权重的主按钮？
2. 每个颜色属于哪一层：行动 / 状态 / 身份 / 结构？
3. 每个色块是实底还是淡底？为什么？
4. 每个条目是哪一种行型：导航 / 动作 / 选择 / 展示 / 主从？
5. 可点行用的是 `<a>`/`<button>` 吗？焦点可见吗？
6. 行内动作是否超过 1 主 + 1 次？其余是否进「更多」？
7. 标题 / 正文 / 次级 / 标签是否只用了规定字号档？
8. 空态、加载、错误是否各有一句话和一个下一步？
9. 1440 与 390 都看过吗？有没有横向溢出？
10. 删掉一半装饰后，信息是否更清楚？

#### Scenario: 开始一个 UI 任务
- **WHEN** AI 准备改工作台界面
- **THEN** 先在回复或 spec 中给出 10 问答案；答不出第 1、2、4 问时不得动笔

### Requirement: 设计守卫

系统 SHALL 新增守卫，至少覆盖：

- **颜色语义**：逾期不得用 error 红；功能色不得用于主按钮；主题色不得用于状态徽章。
- **行交互**：可点行必须是 `<a>`/`<button>` 或带 `data-interactive` 的原生控件；纯展示行不得有 `cursor:pointer` / hover。
- **焦点与动效**：可交互行必须有 `:focus-visible`；禁止 `transition: all`。
- **前置卡**：`CLAUDE.md` 与 `DESIGN_SYSTEM.md §0` 必须含 10 问卡；缺一即红。

#### Scenario: 新增一条可点行
- **WHEN** 新代码写了 `div` + click 处理器
- **THEN** 守卫报红并指向 `list-row` 的 `interactive` / `href`

## MODIFIED Requirements

### Requirement: 颜色角色 → 令牌映射

§2.9 映射表 SHALL 把「逾期 / 超期」从 `--functional-error` 改为 `--functional-warning`；`--functional-error` 只保留给阻断、失败、删除、驳回。

### Requirement: 可点击性规范

§10.4 SHALL 从四条零散规则扩展为五类行型矩阵，并与 `list-row` 的 `interactive` / `href` 实现对齐。

## REMOVED Requirements

### Requirement: 整圈彩色边框表示强调

**Reason**：整圈红边同时像主题色、错误色和选中态，用户无法判断语义；且与「纯展示行不加边框」冲突。
**Migration**：强调改用章节头计数、左侧 2px 单色规则或状态徽章；卡片回到中性 hairline。

### Requirement: 同一行多个等权彩色按钮

**Reason**：用户需要读两遍才能决定点哪个；颜色越多，主行动越不突出。
**Migration**：每行保留 1 主 + 1 次；其余进「更多」；危险动作只在确认时用实底红。
