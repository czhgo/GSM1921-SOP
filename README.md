## 🗺️ 仓库版图（核心）

这是一个"**静态编译交互视图 + 制度引擎**"中台产品。各部分职能如下：

### 🧠 `/src` — 系统的大脑（原生 ES Modules 架构，v8.3+）

```
src/
├── domain.js         # 领域层：Activity 数据契约（JSDoc typedef）、can() 权限函数、mockDB
├── service.mock.js   # Mock 服务层：createActivity()，600ms 模拟延迟，10% 随机错误注入
├── service.runtime.js # 运行时插槽：BranchService 统一出口，USE_MOCK 开关，未来 Supabase 替换点
└── main.js           # 主状态机：STATE 枚举、appState、setState()、renderUI()、防竞态 reqId
```

> **架构依赖铁律（Domain → Service → Runtime → Main）**，UI 层只能通过 `renderUI(state)` 驱动，严禁直接写 DOM。

### 🖼️ `index.html` — 系统的前端壳体

Apple Liquid Glass 设计语言的完整 UI 资产。包含：
- 左右分栏布局（侧边栏 + 主内容区）
- 领域/角色双维度筛选器
- 时间轴节点（推演工作台）+ 检查器面板
- 响应式侧边栏（移动端 CSS Transform 收起）

## 🔧 这个仓库是怎么工作的？

**你所看到的所有指南和模板，都不是手写维护的。** 本仓库运行"**双轨制**"：

- **人工面板（你正在看的这层）**：所有流程指南、速查卡、申报模板，用简洁中文写成，照着做就行。
- **后台控制逻辑（`.vibe_context/` 文件夹）**：AI 协同工作引擎的状态机和规则文件，供书记和 AI 代理维护，普通使用者无需关心。

**技术架构（v8.3 起）**：`/src` 目录采用原生 ES Modules 分层架构，`index.html` 为纯前端壳体，GitHub Pages 无需构建工具即可部署，未来可平滑接入 Supabase 后端。

每次你通过反馈卡提交痛点，书记调整后台规则，AI 引擎会在几分钟内**把所有相关文档一次性改好，不遗漏，不矛盾，有日志可查。**
