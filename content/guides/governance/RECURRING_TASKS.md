# 经常性工作管理机制

> **audience**: [人机] | **date**: 2026-05-02 | **status**: 规划阶段

---

## 一、总则

本项目存在若干需要定期执行的持续性维护工作。若缺乏系统化的唤醒机制，这些工作容易被遗忘，导致文档腐化、状态漂移和技术债务积累。

本机制设计一套基于时间周期的自动唤醒提醒系统，覆盖识别、调度、通知、执行、验证全链路。

## 三、自动唤醒机制设计

### 3.1 架构

```
┌──────────────────────────────────────────────────┐
│                  TIMESTAMPS.md                     │
│  ┌────────────┐  ┌────────────┐  ┌────────────┐  │
│  │ last_W1    │  │ last_M1    │  │ last_Q1    │  │
│  │ 2026-05-01 │  │ 2026-04-15 │  │ 2026-03-01 │  │
│  └────────────┘  └────────────┘  └────────────┘  │
└────────────────────────┬─────────────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────────────┐
│            SCHEDULER (调度逻辑)                     │
│                                                    │
│  check_recency() → 对比当前时间与 last_* 时间戳      │
│  if (now - last_W1) > 7天 → 触发 W1                │
│  if (now - last_M1) > 30天 → 触发 M1               │
│  if (now - last_Q1) > 90天 → 触发 Q1               │
└────────────────────────┬─────────────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────────────┐
│              DISPATCHER (分发逻辑)                  │
│                                                    │
│  根据任务编号 → 查找对应 Agent → 生成 next_prompt   │
│  在 .ctx/ 中写入 PENDING_TASKS.md 待办列表          │
└────────────────────────┬─────────────────────────┘
                         │
                         ▼
┌──────────────────────────────────────────────────┐
│           EXECUTION (三步工作流闭环)                │
│                                                    │
│  规划 → 执行 → 验证 → 更新 last_* 时间戳 → 记账     │
└──────────────────────────────────────────────────┘
```

### 3.3 唤醒触发方式

| 方式 | 适用 | 实现 |
|------|------|------|
| **会话入口检查** | 每次新对话开始时 | `copilot-instructions.md` 前置指令：读取 TIMESTAMPS.md → 检查到期任务 → 若存在到期任务则优先汇报 |
| **手动检查指令** | 用户主动触发 | `/check-recurring` → 执行 SCHEDULER 逻辑并输出到期列表 |
| **GitHub Actions（远期）** | 全自动月级/季级任务 | cron 触发 workflow → Agent 自主执行 → 更新日志 |

### 3.4 通知策略

| 到期天数 | 级别 | 行为 |
|---------|------|------|
| 到期前 3 天 | 提醒 | 下次 AI 会话开头显示"即将到期" |
| 到期当天 | 警告 | 标记为 ⚠️ overdue pending |
| 到期后 7 天 | 升级 | 在 CLAUDE.md §八 中追加为短期规划任务 |
| 到期后 30 天 | 紧急 | 标记为 🔴 管理漏——写入存档以便追责追溯 |

## 五、维护与演进

- 每次新增周期性任务时，同步更新本文档 §二 + TIMESTAMPS.md 追踪表

- 季度审查时评估周期性任务的执行质量和覆盖完整性
