# Phase 2：急救四项与首页活动风采

## Why

三路审计（web-design-guidelines / design-with-taste / frontend-design）在 Phase 1 后留下的 P2 清单中，有四项属于「用户会误以为系统坏了」；首页「活动风采」则是名实不符最明显的区块：叫风采，却没有一张图，渐变底、蓝色 hover、整卡上浮同时存在。

本批先把这五件事做完，避免继续用装饰掩盖结构问题。

## 用户裁定（2026-10-19）

1. **下一批主攻**：急救包 + 首页重构。
2. **活动风采最终形态**：保留「活动风采」定位，做**真图位**；不改成「近期活动」。
3. **页标题统一范围**（后置）：定规范 + 四页重点（概况 / 待办 / 支委会 / 首页），其余触达即迁。
4. **零值口径**（后置）：零是事实就保留；只隐藏「整行全是 —」与 0/0。

## 本批范围

### 1. P2-4 日历小字对比度

- 证据：`styles.css` `.cal-cell-compact .cal-activity-tag` 为 `0.625rem`（10px），`calendar.js` 标签字色为 `color-mix(... 60%, #000)`，实测对比度 3.73:1。
- 修法：紧凑日历标签与任务标签统一到 **11px（0.6875rem）**；标签字色压深到 **72% + #000**，使浅底标签达到 4.5:1。
- 不改：日历格子尺寸、事件密度、类型色相。

### 2. P2-5 个人考勤空态

- 证据：`dashboard/stats.js` 在 `myTotal === 0` 时只显示「—」，没有任何说明。
- 修法：数值仍为「—」，标签改为「个人考勤（本月无记录）」；弹窗空态文案保持。
- 不改：出勤率口径、颜色阈值、可点卡行为。

### 3. P2-14 选人面板遮挡与双层遮罩

- 证据：`person-picker.js::_positionPanel` 向上展开时 `top` 允许到 8px，会盖住 56px 顶栏；触发按钮在 `modal.js` 弹窗内时，picker overlay（0.3 黑）叠加在弹窗遮罩（0.35 黑）上，形成双层遮罩。
- 修法：
  - 向上展开时 `top` 不低于顶栏底部 + 8px，并同步收缩面板高度。
  - 触发按钮位于 `[role="dialog"]` 内时，picker overlay 改为透明点击捕获层（不再叠加第二层黑）。
- 不改：焦点陷阱、Esc 回焦、40px 行高、无头像规则。

### 4. P2-15 非交互卡片 hover

- 证据：全局 `.card:hover` 改 `border-color: var(--primary-300)`，纯展示卡也被误认为可点；现有 `card--static` 是逐卡打补丁。
- 修法：默认 `.card:hover` 不再变色；新增 `.card--interactive:hover` 与 `cursor: pointer`，只给确需点击的卡（本批：首页个人考勤卡）。`card--static` 保留为兼容标记。
- 不改：卡片边框、圆角、阴影基线与页面布局。

### 5. 首页「活动风采」真图位

- 证据：`dashboard/gallery.js` 有 8 种类型渐变、`group-hover:text-blue-700`、`hover:-translate-y-1`；`imageRecords` 已有活动照片（`activityId` + `filePath`/`base64`），但首页从未读取。
- 修法：
  - 卡片改为白卡：顶部 16:9 真图位 + 下方类型 / 标题 / 日期 / 状态。
  - 图片源复用 `imageRecords`：同一活动取最新一张未作废照片；无图时显示中性占位（类型图标 + 「暂无活动照片」），不生成假图、不用渐变冒充图片。
  - 服务端图片经鉴权取 blob 后显示；无 token 或加载失败时回退占位。
  - 去掉蓝色标题 hover、整卡上浮；保留整卡点击进入活动详情。
- 不改：`galleryFeatured` / `galleryPinned` 排序与收录权；首页区块标题仍为「活动风采」。

## 第二批（2026-10-19 · 本批执行）

### 1. 页标题统一（四页重点）

- 单一层级：**H1 = 顶栏品牌**（全站唯一）；**H2 = 当前 tab 的页面标题**；**H3 = 分区 / 卡片标题**；更深层才用 H4。
- 统一组件：`components/shell/page-frame.js::renderTabHeader`（输出 H2 + 可选说明 + 可选动作）。
- 四页重点：
  - 全局概况：新增 H2「全局概况」；条线 / 待我处理由 H4 升为 H3。
  - 待办：新增 H2「待办」；「待答复与未读通知」由 span 升为 H3；「我的待办」与详情标题保持 H3。
  - 支委会：H2「支委会」改走统一组件；两支卡头保持 H3。
  - 首页：删除与 H1 同名的组织名 H2 与重复党徽；区块标题升为 H2；风采卡标题降为 H3。
- 其余页签触达即迁，不在本批一次性改 60+ 文件。

### 2. 零值处理

- **零是事实**：数值型表格单元格中的 0 照常显示，不再用 `—` 代替（如概况条线「在办 / 逾期」）。
- **缺数据才是 —**：没有值、未填报、无截止等继续用 `—`。
- **禁止 0/0**：分母为 0 时用 `—` 或文字说明，不显示「0/0 · 0%」。
- **整行全 — 不渲染**：一行所有业务字段都为空时，该行不出现。
- 写入 DESIGN_SYSTEM §4.26，作为后续新表的默认口径。

### 3. 数字对齐与状态列去重

- 数字列统一 `is-numeric`：**右对齐 + `tabular-nums`**；表头与单元格同时声明。
- 表头统一补 `scope="col"`（P2-1，同批顺手收口）。
- 状态列去重：
  - 支委会「状态」列：全部为「在任」时整列隐藏；出现「空缺」时显示。
  - 党小组「状态」列：全部为「在册」时整列隐藏；出现「已解散」时显示。
  - 隐藏用 `is-redundant`（`display:none`），不删除源码列，避免表头与卡片行结构分叉。

### 4. 卡片边界（P2-7 · sample-diff-learning）

本项最初被写成「一页一张主卡」，经支书用「跨组详情应当拆」这一样本纠正，记录为一次 diff：

| 字段 | 内容 |
|---|---|
| **AI 假设** | 「同款白卡」= 卡片太多 ⇒ 每页只留一张主卡，次级区全部改 hairline。 |
| **人类意图** | 白卡可以分开；判据不是数量，而是**排布是否符合工作 / 阅读单元**；跨组详情四个块应拆成并列卡。 |
| **分歧类型** | `scope_narrowing` + `priority_inversion`：把「分组错误」窄化成「数量过多」，并倒置了「阅读单元」与「卡片数量」的优先级。 |
| **泛化规则** | `若 blockA 与 blockB 的主行动 / 主问题不同 → 必须是两个独立容器；若相同 → 可合并。` 禁止卡中卡。 |
| **落点** | DESIGN_SYSTEM §4.2「卡片边界判据」；党小组「跨组进展」拆成四张并列卡。 |

**本批只改这一处**：概况 / 待办 / 支委会的卡片分别对应不同任务，保持分开；首页四张卡也保持分开。不做「一页一张主卡」的全局收敛。

## Acceptance

- 390 / 1440 下日历紧凑标签可读，浅底标签对比度 ≥ 4.5:1。
- 个人考勤为 0 时，卡片明确说明「本月无记录」。
- 选人面板不遮顶栏；弹窗内打开时只有一层遮罩；键盘路径不回归。
- 非交互卡片 hover 不再出现主题色边框；个人考勤卡仍可点且有 hover 反馈。
- 活动风采：有照片显示真图，无照片显示中性占位；无渐变、无蓝 hover、无上浮。
- 四页重点各只有一个 H2；首页不再有与 H1 同名的 H2 和重复党徽。
- 概况条线 0 值显示为 0；不再出现 0/0；数字列右对齐且等宽。
- 支委会 / 党小组状态列在全部正常时隐藏，异常时出现。

## Non-goals

- 不改 `imageRecords` 数据模型与上传接口。
- 不在本批做全站页标题迁移、零值全站治理、数字对齐。
- 不改后端 API、权限与审批链。
