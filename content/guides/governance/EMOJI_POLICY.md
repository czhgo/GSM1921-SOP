# Emoji 使用规范

> **audience**: [人机] | **last_updated**: 2026-05-02 | **enforcement**: 强制

---

## 一、总则

本规范定义 Org OS 仓库中 Emoji 的使用边界，确保界面文本纯净的同时，保留人类可读文档中必要的情感表达与紧急程度标识。

核心原则：**网页零 Emoji，文档有限度使用。**

---

## 二、禁用范围

### 2.1 绝对禁止

以下位置**严禁出现任何 Emoji**：

| 位置 | 原因 |
|------|------|
| `index.html` 中的所有可见文本内容 | 网页界面必须纯净，无特殊符号 |
| `docs/src/styles.css` 中的 `content` 属性值 | CSS 生成的可见装饰 |
| `docs/src/*.js` 中的用户可见字符串和 console 输出 | 运行时界面 |

### 2.2 HTML 结构注释例外

`index.html` 中的 `<!-- -->` 注释块允许使用分隔符符号（如 `═`），用于标记模块边界——此类为 ASCII 装饰，非 Emoji。

---

## 三、允许使用范围

### 3.1 [人] 角色文件

完全允许 Emoji 用于：
- 文档标题装饰（如章节标记）
- 紧急程度标识（如优先级指示）
- 强调关键信息
- 表格中的状态标记

**示例文件**：
- `content/references/模板库/活动复盘/README.md` — 现已按网页接口标准清理，后续新参考文件可保留 Emoji
- 新创建的、仅面向人类的参考文档

### 3.2 [人机] 角色文件

允许在以下场景**有限度**使用 Emoji：

| 场景 | 允许的 Emoji 类型 | 示例 |
|------|------------------|------|
| 紧急程度/优先级标识 | 功能性指示符（⚠️） | CLAUDE.md 钩稽断链告警 |
| 表格状态栏 | 状态标记（✅/❌） | ARCHITECTURE.md Agent 注册表 |
| 代码注释中的警示 | 告警标记（⚠️） | 源代码中的 TODO/FIXME |

### 3.3 [AI] 角色文件

| 文件类型 | Emoji 策略 | 理由 |
|---------|-----------|------|
| Agent 定义文件（`agents/*.agent.md`） | 允许功能性 Emoji（✅/❌/⚠️） | 状态标记有助于快速识别 Agent 状态 |
| Skill 定义文件（`skills/*/SKILL.md`） | 允许功能性 Emoji（✅/❌/⚠️） | 同上 |
| 运行时上下文文件（`.ctx/CONTEXT.md`、copilot-instructions.md） | 禁止任何 Emoji | 纯文本最小化 token 消耗，确保指令解析准确性 |
| 系统快照文件（`.ctx/SNAPSHOT*.md`） | 允许功能性 Emoji | 状态标记有助于人类快速审阅 |
| 执行日志文件（`.ctx/logs/*.md`） | 允许功能性 Emoji | 日志行首状态标记提升可读性 |

### 3.4 禁止的装饰性 Emoji

即便在 [人机] 文件中，以下**纯装饰性** Emoji 禁止使用：

- 💡（灯泡 — 用"提示"替代）
- 🗺️（地图 — 用"导航"替代）
- 📚📖（书本 — 用"文档"替代）
- 🌟⭐（星星 — 用"推荐"/"重点"替代）
- 🎯（靶心 — 用"目标"替代）
- 📊（图表 — 用"数据"/"统计"替代）
- 🔑（钥匙 — 用"关键"替代）
- 💡（灯泡 — 用"建议"替代）
- 🔗（链接 — 用"参考"/"详见"替代）
- 👤（人物 — 用"负责人"/角色名替代）
- ⚡（闪电 — 用"快速"/"时效"替代）
- 📝（备忘录 — 用"记录"/"说明"替代）
- 🗂️（文件夹 — 用"归档"/"分类"替代）
- 📌（图钉 — 用"对比"/"区分"替代）

## 四、功能性 vs 装饰性 判定标准

| 类型 | 定义 | 判定方法 | 处理 |
|------|------|---------|------|
| **功能性 Emoji** | 承载不可替代的信息语义，删除后信息丢失 | 删除后能否用 ≤3 个中文字符替代？ | 允许 |
| **装饰性 Emoji** | 纯视觉点缀，删除后不影响信息传递 | 删除后能否用 ≤3 个中文字符替代？ | 禁止 |

### 功能性 Emoji 白名单

| Emoji | 语义 | 允许位置 | 替代方案（不允许时） |
|-------|------|---------|---------------------|
| ⚠️ | 警告/告警 | [人机] 钩稽关系、代码注释 | `[警告]` |
| ✅ | 完成/通过/可用 | [人机] 表格状态栏 | `[Y]` / `[通过]` |
| ❌ | 失败/禁止/不可用 | [人机] 表格状态栏 | `[N]` / `[禁止]` |
| 🔜 | 即将/下一步 | [人机] CLAUDE.md 状态 | `[下一步]` |

## 五、网页内容特别规定

"网页内容"定义为：`index.html` 加载渲染后，在浏览器视口内可见的**所有文本节点**。

### 5.1 SVG 图标不受限制

`index.html` 中内联的 SVG 元素（`<svg>`）和通过 CSS 绘制的图形组件不在 Emoji 限制之列。

### 5.2 角色侧边栏图标

角色侧边栏卡片中的图标必须使用内联 SVG（当前已实现），禁止使用 Emoji 字符作为角色图标。

---

## 六、执行与审计

### 6.1 新增文件审核

创建任何 `.md` 文件时，按以下流程审核 Emoji 使用：

1. 判定角色：[人] / [人机] / [AI]
2. 若是 [人机]，逐项检查 Emoji 是否为功能性（§四白名单）或装饰性（§3.3禁止列表）
3. 装饰性 Emoji 全部移除，用中文替代

### 6.2 定期扫描

| 扫描对象 | 命令 | 频率 |
|---------|------|------|
| index.html | `grep -rP "[\x{2600}-\x{27BF}\x{1F300}-\x{1F9FF}]" index.html` | 每次部署前 |
| CLAUDE.md | 目视审查 §八 优先级列 | 每次更新后 |
| content/SOP/*.md | 随机抽检 | 月度 |

---

## 七、违规处理

- 网页中发现 Emoji：P0 级缺陷，立即修复
- [人机] 文件中发现装饰性 Emoji：下个编辑周期自然替换
- [人] 文件中 Emoji：不限制，尊重人类阅读习惯
