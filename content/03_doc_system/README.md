> 目录定位见 [DOC_MAP.md §五 目录作用表](DOC_MAP.md#五目录作用表2026-10-24-立)。

## 作用

本目录存放**知识类型 3：全仓库文档系统管理的技术方法**，回答「文档怎么治理、术语怎么用、导航在哪、判例怎么编号」。

## 不负责什么

- 不写支部战略、制度与 SOP 正文——归 `01_strategy/`、`02_institution/`。
- 不写前端设计、数据模型与部署规范——归 `04_web_design/`。
- 不写 AI 协作方法正文——归 `05_ai_coding/` 五个分篇。
- 不写判例正文——判例在各域 `CASES.md`，本目录只维护总索引。

## 权威源与派生

- **权威源**：`OPERATIONS_GUIDE.md`（规范条文）、`TERMINOLOGY.md`（术语定义）、`ARCHITECTURE.md`（架构与单一事实源）、`DOC_MAP.md`（导航）。
- **派生/索引**：本 README 与 `CASES_INDEX.md` 都是索引；`DOC_MAP §二` 的文件总览从各层正文派生，不反向定义正文。
- **跨目录引用**：各层 `README.md` 与本目录 `DOC_MAP` 互指；判例编号与分职规则以 `OPERATIONS_GUIDE §32` 为准。

## 知识流向

全仓文档与逐批过程（`.ctx/logs/`）→ 治理经验在 `OPERATIONS_GUIDE.md` 沉淀为规则 → 结构变化登记进 `ARCHITECTURE.md §十` → 导航更新 `DOC_MAP.md` → 判例取号登记进 `CASES_INDEX.md` 并落各域 `CASES.md`。

## 是否保留原始材料

不保留。过程原文在 `.ctx/logs/`（月度执行/决策日志），真机证据在 `.ctx/evidence/`；本目录只存规则、导航与索引。

## 维护触发器

- 新增、删除或重命名本层文件；
- 文档权威层级、分职规则或判例编号规则变更（`OPERATIONS_GUIDE`）；
- 目录结构、单一事实源或服务目录变更（`ARCHITECTURE`）；
- 任一层新增/删除文件导致 `DOC_MAP` 导航需要同步。
