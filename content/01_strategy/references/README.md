## 作用

本目录是**上级文件与支部历史材料的只读存档**，回答「这条制度或战略的依据原文在哪」。

## 不负责什么

- 不写结论、不写规范、不写 SOP——加工后的结论在上级目录 `01_strategy/` 与 `02_institution/`。
- 不改写、不摘要、不转写原文——原件保持原样。
- 不承担版本管理结论——哪一版现行由使用方在正文中注明。
- 不放系统设计与 AI 方法材料。

## 权威源与派生

- **合规文件是上游原文**：`02_institution/sop/` 各流程的溯源以此为准；原文本身即依据，本 README 只做索引，不解释条文。
- **历史会议材料是档案**：只证明「当时讨论过什么」，不构成现行制度；引用时须在正文写清日期与文件名。
- **建设探索是参考**：可启发思路，不作为制度或战略结论的直接依据。
- **加工关系**：结论一律写在上级目录（`01_strategy/SECRETARY_DIRECTIVES.md`、`DEVELOPMENT_PATH.md`）或 `02_institution/`，**不回写本目录**。

## 知识流向

上级机关发布文件 / 支部召开会议 → 原件原样存入本目录 → 由 `01_strategy/`、`02_institution/sop/` 在正文中按文件名溯源引用 → 使用中形成的结论留在上级目录；本目录只增不改。

## 是否保留原始材料

**保留——本目录就是原始材料保留地**（合规文件、历史会议材料、建设探索三类）。只读：修改、替换、删除或转格式须按仓库授权流程申请；日常不加工、不做摘要。

## 维护触发器

- 新增上级文件或新的历史材料；
- 原文被上级机关更新（新增版本，旧版保留并在文件名或正文注明）；
- 子目录增减或文件改名（须同步更新上级 `01_strategy/README.md` 与 `DOC_MAP`）；
- 某份材料被正式认定为现行依据或废止（在上级正文注明，不改原件）。
