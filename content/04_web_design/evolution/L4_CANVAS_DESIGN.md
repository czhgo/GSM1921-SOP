# L4 支部工作地图设计稿 v1.2

> **定位**：书记 2026-09-03 对 v1（流程画布/泳道）的纠偏——支部工作不是「串行流程泳道」，而是**并行常态工作线的组织**。L4 的正确语义 = **支部工作地图**：
> ① 按**党内制度条线**给"工作"分类（书记认可方案一）；② 每类下模块分**默认功能**（制度必备）与**可勾选的额外功能**（支部自选）；③ **模块是可打包的工作包，核心问题是"分配给谁人"（分工）**。
> v1.2（书记裁决）：① 先细化「组织生活」「发展党员」两类为模块级，其余五类保持一级；② 负责人粒度 = 角色 + 可到具体人；③ 入口 = 党委台主编排 + 书记台只读。
> 本稿只定义分类学与目录草案 + UI 形态方向；编码待目录校验后拆分。
> **受众**：[工程师]+[AI] + 书记（分类/分工裁决人）

## 一、工作分类学草案（书记认可框架：党内制度条线）

| 大类（T1 用语） | 模块（系统对应） | 属性 | 默认负责人 |
|---|---|---|---|
| **一、组织生活** | 支部党员大会 / 支委会 / 党小组会 / 党课（三会一课） | 默认（制度必备） | 书记 / 副书记 / 党小组组长 |
| | 主题党日 | 默认 | 书记 |
| | 组织生活会 + 民主评议党员（年度） | 默认 | 书记 / 纪检委员 |
| **二、发展党员** | 入党申请与积极分子确定 / 培养考察（考察记录） / 发展对象确定与公示 / 预备党员接收与转正 / 思想汇报收缴 | 默认（制度必备） | 组织委员（牵头）/ 书记 |
| **三、党员教育管理** | 党员台账与组织关系 / 党费收缴（如适用） | 默认；党费=支部酌情 | 组织委员 |
| **四、纪律与作风** | 组织生活考勤（出席台账）/ 活动参与考察（工作量）/ 提醒谈话（记录） | 默认 | 纪检委员 |
| **五、宣传教育** | 宣传记录（公众号/阵地）/ 思想动态收集 / 学习材料推送 | 默认 | 宣传委员 |
| **六、专班与专项** | 专班（支部自创制度）/ 主题教育专项 / 共建座谈 | **额外（支部自选）** | 按需指派（角色或具体人） |
| **七、党委协同** | 支部上报审批（发展节点/活动报备）/ 党委下发通知 / 支部档案备案 | 默认（两级治理） | 书记 |

> 注：默认/额外依据 = 党内制度性要求（T1）vs 支部自选动作；负责人为**默认**，均可调整指派（可到角色，也可到具体党员）。

### 1.1 细化·一类 组织生活（模块级，书记 2026-09-03 优先细化）

| 模块 | 制度节奏（T1） | 系统既有能力 | 默认/额外 | 默认负责人 |
|---|---|---|---|---|
| 支部党员大会 | 每季度 ≥1 次 | calendar 场景 branch-party-meeting + 大会议程 agenda + 票决（发展票决在此） | 默认 | 书记主持 |
| 支委会 | 每月 ≥1 次 | calendar 支委会 + agenda（讨论文件/待讨论名单）+ 线上异步表决 | 默认 | 书记主持 |
| 党小组会 | 每月 ≥1 次 | 党小组活动（组长 write-tab/党小组会议场景） | 默认 | 党小组组长（角色=组长组，天然到角色下的人） |
| 党课 | 每季度 ≥1 次 | 党课场景 party-lecture | 默认 | 书记（可到人：主讲/组织者） |
| 主题党日 | 每月（支部规范） | L3 `theme-party-day` 块（S4 入口守卫已建） | 默认 | 书记 |
| 组织生活会 + 民主评议党员 | 年度 | 年度活动 + 评议（**民主评议明细待建**） | 默认 | 书记 + 纪检委员 |

> 组织生活 = 六模块。三会一课/主题党日/评议均制度必备（默认开）；模块的**表单条目/产出块**继续由 L3 manifest 承载（主题党日块已成例，三会一课子会/评议按同法续建）。

### 1.2 细化·二类 发展党员（模块级 = 环节链）

| 环节模块 | 系统既有能力 | 默认/额外 | 默认负责人 |
|---|---|---|---|
| 入党申请与积极分子确定 | development-tab 管线 + 支委会确定 | 默认 | 组织委员牵头 / 书记把关 |
| 培养联系人指派 | **到人**（每名积极分子 2 名培养联系人）——**培养联系人体系待建** | 默认 | 组织委员指派（典型"可到人"场景） |
| 培养考察写实 | inspection 考察记录（按季写实）——**联系人与写实关联待建** | 默认 | 培养联系人（到人） |
| 思想汇报收缴 | thought-report（思想汇报登记） | 默认 | 组织委员 |
| 发展对象确定与公示 | development + 支委会票决 + 公示 | 默认 | 组织委员牵头 / 书记 |
| 预备党员接收（支部大会票决） | agenda 发展票决 + calendar | 默认 | 书记主持 |
| 预备期考察与转正 | development 阶段推进 + 转正票决 | 默认 | 组织委员 + 书记 |
| 上报党委审批（发展节点） | party-committee 上报审批（发展节点批驳已支持） | 默认 | 书记（向上级党委） |

> 发展党员 = 八环节模块（制度必备、默认全开，按环节推进而不是并行）。**能力缺口**（诚实标注）：培养联系人体系（到人）、联系人写实关联、民主评议明细、党费——未在既有系统内，属"待建工作包"，可后续按 L3 manifest 方式补齐，不在本次地图 UI 范围。

---

### 模块 = 工作包（三要素）
每个模块卡表达三件事：
1. **是什么**（manifest 目录：inputs 表单条目 + 产出块，L3 已建立）；
2. **开不开**（默认开/额外勾选 → config 启停，L3 workflowBlocks 语义）；
3. **谁负责**（负责人指派 → **新增** config 维度，见 §三）。

## 二、UI 形态方向（替代 v1 泳道）

```
┌─ 支部工作地图 ────────────────────────────── [保存] [恢复默认]
│
│ 一、组织生活
│   [支部党员大会] [支委会] [党小组会] [党课] [主题党日]   ← 制度必备（红点）
│   负责人：书记 · 副书记 · 三组长
│
│ 二、发展党员          牵头：组织委员
│   ☐ 入党申请 ☑ 培养考察 ☑ 发展对象 ☑ 预备接收/转正 ☑ 思想汇报
│                       ← ☑ 默认开；☐ 勾选开（额外）
│
│ 六、专班与专项        （支部自选）
│   ☐ 专班  ☐ 共建座谈   ← 默认全关，支部需要才勾
│
│ 七、党委协同          负责人：书记
│   [上报审批] [下发通知]  [支部档案]
└─────────────────────────────────────────────
```

- **分类即横条**（党内制度条线七类），条内模块卡/chips。
- 卡元数据：制度来源点（红=必备、金=自选）+ 负责角色名（可点指派）。
- **无强顺序、无泳道、无连线**——并行职责一眼见；协调关系用模块卡内的"产出"标签表达（见 §四），不画装饰线。

## 三、分工指派（书记核心问题：模块打包分配给谁人）

- **数据**：`config.workforce`（支部分工表）新增，形如 `{ moduleAssignments: { [moduleId]: { ownerType: 'role'|'person', ownerId: 'org-commissioner'|'p3' } } }`（缺省=按目录默认负责人）。
- **判定默认值**：按目录草案默认（组织委员→发展党员 等），支部可改（如把发展党员临时指派给副书记代办）。
- **落点**：指派后，该模块的待办/入口在负责人工作台出现（复用 secretaryId/role 关联 + 待办派生机制，不新建权限体系）。
- 协调：同一模块归属一人牵头，产出块可多人协作（活动产出的考勤归纪检确认等，走既有 handoff/产出块）。

---

## 四、协调关系表达（不画线）

模块卡内一行小字标签列出"产出交接"：如 主题党日卡 → `产出：考勤→纪检 · 宣传→宣传委`（复用 L3 outputs 声明 + OUTPUT_BLOCK_DEFS）；发展党员卡 → `产出：考察→组织委员`。交接仍由既有 services/handoff/review 通道执行——地图只展示"谁产什么交给谁"，不新增执行。
