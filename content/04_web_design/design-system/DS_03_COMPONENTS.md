## 四、组件规范

> **定位：** 本节是系统**组件规范**（按钮/卡片/输入框/侧边栏/导航/模块标签/角色/嵌套/日历图例/数据展示/图标/交互载体/选人/状态徽章/意见反馈）。写组件优先查本节。

#### 变体族谱（2026-09-30 立 · 支书裁定「**全面归一**」）

> ⚠ **2026-10-19 起，动作按钮收口为 §4.1.1 的「四类 + 两档」**；下表 8 族保留作沿革与存量映射——
> `.btn-ghost` / `.btn-neutral` / `.btn-action-*` 均为**存量类**，**新代码不得使用**；`.btn-tab` 只做页签/分段，**不属于动作按钮**。

**全站 `<button>` 只准用这 8 族**（单一源＝`docs/src/styles.css`「按钮族谱补全」段；机检＝`button-system-guard::B4` 棘轮）：

| # | 族 | 类 | 语义 | **随主题色？** | 尺寸 |
|---|----|----|------|------|------|
| 1 | 主操作 | `.btn-accent` | 实底主题色（发布 / 提交 / 确认） | **随**（主操作） | 按本节四档/五档取 |
| 2 | 次主操作 | `.btn-accent-soft` | 主题色软底（次级确认 / 保存并继续） | **随**（主操作） | 同上 |
| 3 | 微操作 | `.btn-action*` | 行内小动作（撤销 / 全选 / 清除） | 固定（中性） | **档1 25px** |
| 4 | **中性** | `.btn-neutral` | 灰底实心（默认按钮 / 取消） | 固定（中性） | 同上 |
| 5 | **描边** | `.btn-outline` | 白底 ＋ 灰描边（弱强调） | 固定（中性） | 同上 |
| 6 | **文字** | `.btn-ghost` | 透明底文字按钮（低频 / 轻量） | 固定（中性） | 同上 |
| 7 | **危险** | `.btn-danger` | 功能红**软底**（删除 / 驳回 / 通知纪检） | **固定**（功能色） | 同上 |
| 8 | 命名族 | `.btn-md*` / `.btn-tab*` | 规模 / 页签族（另有自身尺寸口径） | 页签**随**（选中态）· 规模固定 | 自身口径 |

> **⚑ 2026-10-01 支书裁定（判据·甲，**本条为现行权威**）**：**只有三类随主题色**——
> **① 主操作（族 1 / 2）· ② 选中态（tab / chip / 列表行 / 分段钮的激活态）· ③ 本人标识（头像 / 「我的」行 / 本人首字块）**；
> **其余一律固定**——**成功 / 警告 / 危险 / 信息（功能色系）** 与 **活动类别色** 都**不随主题色变化**。
> 判据写成可判句：**换支部主题色后，该元素是否应当变色？**「应当」⇒ 走 `--app-accent*` 三件套（三类之一）；
> 「不应当」⇒ 走功能色 / 中性阶 / 品牌统一层 / 类别色，**不得借 `--app-accent`**。两向都**不得互串**
> （§2.9 角色-令牌表：同一行内不许混用别行令牌）。
> 支书原话：「**我没有要求过一屏只允许一枚实底**；……**这个 button 的问题最大的要求就是——能不能识别出哪些是应该随着主题色的变化而变化的**」「甲：主操作 + 选中态 + 本人标识 三类随主题」。

- **不许手写**：新增按钮**必须**落上表之一；未入族者计入 `button-system-guard::B4` 的「未入语义族」台账，**只许降不许升**（基线＝批次 297-1 实测 454 ⇒ **批次 297-2 全站归一后为 `0`**，棘轮已锁死）。
- **色一律走令牌**（不落 hex，受 `hex-hardcode-guard`）；**尺寸**仍由各页按本节的四档 / 五档给出（**族只管语义外观，尺寸另算**）。
- **沿革**：本表 1–3 ＋ 8 为既有；**4–7 为 2026-09-30 新立**（支书裁「新立 4 族（中性 / 描边 / 文字 / 危险）」）。**批次 297-2 已全站归一**（`B4` 454 → **0**；临时进 `DYNAMIC_SELECTOR_WHITELIST` 的 4 条族谱基线条目**已按承诺删除**，`Z2/Z3` 僵尸检查复绿）。

#### 何时用哪族（2026-09-30 批次 297-2 立；**同日「拨乱反正」改准**）

> **⚑ 拨乱反正（支书 2026-09-30 原话）**：「**我没有要求过 一屏只允许一枚实底**；此外我认为这个 button 的问题**最大的要求就是——能不能识别出 哪些是应该随着主题色的变化而变化的**。」
>
> ⇒ **原判据「一屏对比度最高的按钮只允许一枚」与「同一 class 同屏 ≥2 次者一律不得实底」系 AI 误读，本条作废**；据此做出的「重复出现 ⇒ 降为淡底」降级**一并列为待裁**（见 `.ctx/REVIEW_QUEUE.md`）。
>
> **现行判据只有一条**：**每个按钮都要能判定它「随主题色变化」还是「固定语义色」**——随主题色者走 `--app-accent` 系（族 1 / 2）；固定语义者走**功能色系**（族 7）或**中性色系**（族 4 / 5 / 6）；**组件自带强调色状态者（如页头 tab 的 `--tab-accent`）保留其原有模式**，不并入通用族。

| 情形 | 归族 | 判据 |
|---|---|---|
| **随主题色变化** 的主行动 | `.btn-accent`（实底） | 换支部主题色后**应随之变色** |
| **随主题色变化** 的次行动 | `.btn-accent-soft`（淡底） | 同上，弱一档 |
| **固定语义**（不随主题色）的普通动作 | `.btn-neutral` / `.btn-outline` / `.btn-ghost` | 换主题色后**不应变** |
| 分段 / 视图切换 / 页签（**含页头 tab**） | 各自**命名族** / 组件自有类 | 自己带强调色状态者**保留原模式**（2026-09-30 支书：「把这些页头 tab 恢复到之前的模式」） |
| 中性（取消 / 返回 / 普通工具） | `.btn-neutral`（灰底实心） | 原形态＝灰底实心系 |
| 白底 ＋ 灰描边（弱强调 / 筛选 / 导出 / 打印） | `.btn-outline`（**改准：中性描边**，非主题色描边） | 原形态＝白底 ＋ `border-gray-200` ＋ 灰字 |
| 纯文字（轻量 / 低频 / 关闭） | `.btn-ghost` | 原形态＝无底色无边框 |
| 行内微操作（撤销 / 全选 / 清除） | `.btn-action*` | 尺寸档 1 |
| 删除 / 驳回 / 通知纪检 | `.btn-danger`（软底）；**实底红**用 `.btn-danger-solid`（族 7 的实底变体） | 功能红系 |
| 分段 / 视图切换 / 页签 | `.btn-tab*` | 原形态＝`*view-btn` / `*seg-btn` / `*chip` / `page-btn` / `lf-btn` |

- **rule H（私有类处置）**：样式**只写在 `styles.css` 私有规则里**的按钮（如 `.page-btn` / `.vote-btn`），**族类是样式的单一源、私有类只当标识**——私有规则改写为「族类 ＋ 私有类」组合选择器（如 `.btn-tab, .page-btn { … }`），实现层 class 串补上族类。**不得让私有类继续自成一套外观**（同 `D-647`）。
- **页头编排（Q3 落地）**：页头**只留 1 枚本台主 CTA**；**跨台通用动作**（如「一键汇报」，现常驻 5 台页头）**收进全局固定位**（顶栏/侧栏），不得每台各放一枚。
- **迁移不得动 hook 类与尺寸类**：`id` / `data-*` / 语义 hook（`.page-btn` / `.vote-btn` / `.wo-*` / `#att-form-submit` 等，JS 与真机守卫依赖）**逐字保留**；尺寸类（`px-* / py-* / text-xs|sm` 等）**照旧**（族只管语义外观，尺寸另算）。

#### 操作可见性（2026-09-30 立 · 支书原话：「**这些有操作能力的字段应该有一定的设计，如果不是边框，就应该用一定的颜色**」）

> **一句话**：**凡具操作能力者，必须给出可见的可交互标识——「边框」或「颜色」二者至少其一**。**不得以「裸文字」呈现**：无边框、无底色者会被读成说明文字，用户找不到入口（`cursor:pointer` 也**不构成**可见标识——触屏没有指针）。

| 情形 | 允许的做法 | 可复核判据 |
|---|---|---|
| 中性操作（改名 / 编辑 / 查看 / 移出） | `.btn-neutral` 或 `.btn-outline`（**边框**） | class 串含二者之一 |
| 主操作 / 危险操作（发布 / 提交 / 删除 / **解散**） | `.btn-accent` / `.btn-accent-soft` / `.btn-danger`（**颜色**） | class 串含其一 |
| 微操作（撤销 / 全选 / 清除） | `.btn-action*`（**自带底色**） | 尺寸档 1 |
| 分段 / 页签 / 翻页 | 命名族（**自带选中态底色**） | — |
| **允许「裸文字」的例外** | ① **行式载体**（整行可点：`w-full`｜`flex-1` ＋ `text-left`，如「今天 · 全部 ›」「前往待办 ›」）② `sr-only` ③ **纯导航**用 `<a>` 文字链接 ④ 与主操作**并排**的「取消 / 关闭」 | 逐条可判 |

- **口径**：`.btn-ghost`（文字族）**不得用于「并列的实体操作」**（改名 / 解散 / 编辑 / 删除这类逐行操作）——它保留给上表例外四类。**存量按按钮族谱同法分批迁移**（先立判据、后逐屏收敛）；本批**只落判据 ＋ 修支书点到的两枚**（`secretary/group-progress-tab.js` 的「改名」→ `.btn-outline`、「解散」→ `.btn-danger`）。**守卫待迁移到一定比例后再立**（避免一次推翻 200 余枚文字族）。
- **同批去冗余**：**同一句计数不得出现两遍**（本批实例＝同一屏既出 `div`「共 16 场」又出 `span`「共 16 场 · 第 1 / 2 页」）⇒ **计数只留一处**：`list-filter.js` 的 `.lf-count[role=status][aria-live=polite]`（分页文案并入本行），`pager.js` **只出翻页钮**。

#### 尺寸四档（**在force口径** · 可机检）

> **全站按钮高度只许落四档之一**。单一源＝`docs/src/styles.css` COMPONENT: Button 段「按钮尺寸规范」（**支书指令 2026-08-06**：全站一次规范，**同一界面按钮高度差距不过大**）：
>
> | 档 | 高度 | 实现 | 用在哪 |
> |---|---|---|---|
> | 档1 微操作 | 25px | `.btn-action` ＋ `.btn-action-{red,green,amber,orange,gray}` | 表格行内 / 列表项内操作 |
> | 档2 默认 | 30px | `text-xs px-3 py-1.5`（或 `.btn-md`） | 卡片内 / 模态内独立按钮 |
> | 档3 行内对齐 | 34px | `text-xs px-3 py-2` | 与 `input-flat` / `select` 同一 flex 行 |
> | 档4 主 CTA | 34px | `text-sm px-4 py-1.5`（带边框）/ `py-[7px]`（无边框） | 表单主提交 / 页面主操作 |
> | 档5 低频操作 | 32px | `h-8 px-3` ＋ `text-xs` | 导出 / 打印 / 分页等低频钮（**U5b 2026-09-07 支书批准**：与分页钮、下拉**同高同 border 家族**） |
>
> **机检判据**（守卫 `button-system-guard` B2）：每个 `<button>` 的 `class` **须命中五档之一或命名族**（`.btn-action*` / `.btn-md*` / `.btn-tab*` / `.btn-accent*`）；否则＝**第六种高度**，判红。
> **例外**（非按钮，不判）：① `sr-only` 隐藏语义按钮；② **无纵向内边距者**（`py-` 缺席 ⇒ 高度由行高 / CSS 定：含纯文字动作如「全部 ›」，以及 `.btn-action` 等 CSS 族）；③ **行式载体**（`w-full`｜`flex-1` ＋ `text-left` 的整行可点条目，归 `§4.19`）；④ **CSS 命名族**（类名已在 `styles.css` 定义且名带 `btn`/`chip`，如 `.ref-doc-action-btn` / `.page-btn` / `.vote-btn` / `.chip-option`）——守卫**实读 `styles.css` 核验存在**，**不按名字猜**。
> **⚠ 口径更正（批次 288）**：本节早前曾写作「`.btn` ＋ 四变体（primary / secondary / ghost / danger）、40px / 36px 两档」——经查 **`.btn` 与 `.btn--*` 在 `styles.css` 中并不存在**，该表指向**未实现的类名**，故**按在force四档＋档5更正**（上表）。同因，早前「316 个／147 个越轨」系**错口径 ＋ 正则缺陷（`py-\[7px\]\b` 的 `\b` 永不成立）**所致；补入 U5b 档5 后**真值＝86 个**（2026-09-29 实测）。
> **执行**：**已全站归零（批次 290，2026-09-29）**。归位路径：错口径 316 → 真值 103（批次 288）→ 补 U5b 档5 与档1 等值写法 86（289）→ 命名族校验 ＋ 假阳性修正 63 → 归位 `text-sm px-4 py-2`（≈38px，越两档）等真越轨 **8 → 0**。**棘轮上限已锁死为 0**：此后**任何**新按钮都必须落档，零容忍。

> CSS 实现见 `docs/src/styles.css`。**装饰性禁令**：禁止 `linear-gradient`（纯色优于渐变）、`box-shadow`（扁平化不需要）、`transform: translateY(-Npx)`（上浮效果违反扁平原则）、`transform: scale()` 过大值（缩放反馈过于花哨）。**功能性允许**：`transform: scale(1.02)` 等微交互反馈、`transform` 用于 SVG 动画绘制（如 stroke-dashoffset 渐进绘制）。区分标准：transform 不得用于"装饰性动画"（如装饰性弹跳、缩放重影），但允许用于"功能性反馈"（如按钮点击微缩、SVG 动画绘制方向）。

#### 4.1.1 按钮四类决策表（2026-10-19 立 · 动作按钮单一源）

> **一句话**：动作按钮只有四类，先判「这是不是页面主路径」，再选类；**没有第五种「文字按钮」**。

| 类型 | 外观 | 用在哪 | 不用在哪 | 例子 |
|---|---|---|---|---|
| **主操作** `.btn-accent` | 实底主题色 + 白字 | 提交 / 发布 / 确认等**主路径**；**每屏最多 1 个** | 行内动作、并列操作、第二个同等权重动作 | 「发布通知」「提交报名」「确认生效」 |
| **次操作** `.btn-outline` | 白底 + 中性描边 | 普通动作、取消、展开、管理、筛选 | 页面唯一主路径（应与主操作区分） | 「取消」「展开全部」「管理成员」「筛选」 |
| **强调次操作** `.btn-accent-soft` | 主题色淡底 + 描边 + 深字 | 高频但**非页面主路径**的行内动作（去处理 / 去催办 / 设改） | 每屏唯一主操作、危险动作 | 「去处理」「去催办」「设 / 改」 |
| **危险** `.btn-danger` | 红淡底 + 红描边 | 撤销 / 删除 / 解散 / 驳回 | 普通编辑、确认弹窗的最终确认 | 「撤销」「删除」「解散」「驳回」 |
| 危险·实底 `.btn-danger-solid` | 实底红 + 白字 | **只给确认弹窗**的最终确认 | 页面内普通动作、行内动作 | 确认弹窗「确认解散」 |

- **没有第五种「文字按钮」**：行内动作一律有**可见边界**（描边或淡底）；纯导航 / 帮助用 `<a>` 链接，不用 `<button>`。`btn-ghost` 不再作为动作按钮类型（存量只降不升）。
- **默认尺寸两档**：常规 **32px**（`.btn-md`，四类动作按钮默认）；紧凑 **28px**（`.btn-sm`，行内紧凑动作）。`.btn-md` 只是常规尺寸别名，**不是独立视觉族**。
- **页签 / 分段控件**用 `.btn-tab`（30px），**不计入动作按钮**。
- **工作台 tab 豁免**：支书 / 组织 / 宣传 / 纪检 / 组长 / 成员六台顶部 tab（`tab-btn` / 作为页签使用的 `btn-tab`）**保持现状**，不改尺寸、底色、选中态。

### 4.2 卡片（Card）

#### 规范

| 属性 | 值 |
|------|-----|
| 背景 | `background-color: var(--surface-card)` (纯白 `#FFFFFF`) |

> **点缀色作数值（2026-10-28）**：点缀色作数值时**必须满足大字 3:1**（`.metric-band__value` 为 24px/600 ⇒ WCAG 大字档 3:1），**否则退回正文色 `--neutral-800`，只留图标着彩色**。实测：`--status-success` 对白卡 2.54:1 ⇒「个人考勤」的「良好」档数值用 `--neutral-800`（14.68:1）、绿色只留在 `.stat-icon-tint`（`aria-hidden` 装饰件）；其余档位 warning-text 7.09 / error 3.76 / neutral-500 4.83 均 ≥3:1，数值与图标同色。

#### 列表项白底原则

列表项/卡片一律白底，不设背景色，不加边线。类型区分仅靠圆点颜色，背景色是重复表达。灰色背景容器一并清除，改为透明底，卡片间分隔靠间距（gap）。

**豁免**（保留背景色）：通知 badge 未读标记、侧边栏选中项高亮、日历当日格子标记、登录页品牌色区域、header 品牌色区域。

#### 边线语义（Border-Left Semantics）

**适用范围**：卡片/区块级元素（容器）。**列表项（行级元素）仍遵循"列表项白底原则"不加边线**——行内区分靠圆点，容器级区分靠边线，两层不混用。

**五档语义表**：

| 档位 | 样式 | 语义 | 典型场景 |
|------|------|------|---------|
| 0. 中性 | 纯白卡，无边线 | 常规内容容器 | `card rounded-xl p-5` 默认态（圆角 `--radius-md` 12px / 内边距标准档 20px） |
| 1. 可交互高亮主卡 | 白卡 + `border-left: 4px` **品牌金** | 可点击进详情/当前聚焦项，**必须有 hover 反馈** | `.inspector-card`（inspector.js 活动卡，品牌活动卡 `var(--party-gold)` 金边框；实现内联 `#EAB308` 为历史存量，见下方用色来源注） |
| 2. 角色职责核心卡 | 白卡 + `border-l-4` 角色主题色 | 该角色职责范围内的核心卡/详情面板（角色识别，保留主题色） | 考勤概况（支书红）、专班详情（组织委员）、纪检面板（橙）、访客金色 |
| 3. 引述/要点块 | 浅底色 + `border-left: 3px` 主题色 | 引述、对立观点、要点提示 | help 页 `--help-party-red` 引述块、about 模块说明卡 |
| 4. 嵌套/时间线 | `border-left: 1-2px` 灰色（`--neutral-200`） | 层级嵌套、时间线、子项缩进 | issue-detail 嵌套、专班列表子项 |

**用色来源**：
- 可交互强调卡（档位 1）：**品牌金** `var(--party-gold)`（品牌统一层，色值权威见 §2.3.1）
- 角色职责核心卡（档位 2）：`--color-identity-<role>`（主色 / 左条 / 圆点；与 `ROLE_COLORS` 同值）——属身份色层，**只作小面积**，不替代主题色
- 品牌/活动色：党徽金 `var(--party-gold)`（inspector 品牌卡边框；实现中 inspector.js 内联 `#EAB308` 不入权威色板，待收敛至 `var(--party-gold)`）
- 嵌套灰色：`--neutral-200`

**硬性规则**：
1. **每条边线必须有语义**：可交互/强调/角色归属/引述/嵌套，五者之外不得加边线
2. **可交互必 hover**：档位 1 的卡片必须有 hover 加深反馈（`border-color` 加深或背景偏移），符合 web-design-guidelines "Interactive states increase contrast"
3. **宽度层级**：强调 4px > 引述 3px > 嵌套 1-2px，不可倒挂
4. **纯展示卡不加 hover 伪装**：档位 2/3 的卡不可点击，也不要加"看似可点"的 hover 效果

#### 卡片边界判据（2026-10-19 立 · P2-7 修订）

> **一句话**：卡片的数量不是判据；**两个区块是否对应不同的用户任务 / 阅读单元**才是判据。

| 情形 | 处理 |
|---|---|
| 两个区块回答**不同问题**或触发**不同动作**（如「组员汇报」vs「活动复盘状态」） | **拆成两张并列卡** |
| 两个区块是**同一任务的前后步骤**（如「日期选择 + 当日列表」） | 可合为一张卡，用 H3 + hairline 分隔 |
| 卡内再出现完整卡（**卡中卡**） | **禁止**；要么拆成并列卡，要么降为 hairline 分区 |

**Boolean 判据**：`若 blockA 与 blockB 的主行动 / 主问题不同 → 必须是两个独立容器；若相同 → 可合并。`

**正例**：党小组 tab 的「跨组进展」拆成四张并列卡——选择党小组 / 组员汇报 / 活动复盘状态 / 活动与考勤，各回答一个问题。
**反例**：四张子卡套在一张外包卡里，形成卡中卡；读者看到的是「一个巨大的框」，而不是四个可分别阅读的单元。

### 4.3 输入框（Input / Select）

#### 规范

| 属性 | 值 |
|------|-----|
| 背景 | `var(--neutral-0)` |
| 边框 | `1px solid var(--neutral-200)` |
| 圆角 | `8px`（`--radius-sm`） |
| 高度 | **单档 38px**（`.input-flat` / `.input-flat.text-xs` / 下拉触发器 同高：`padding: 10px` + 行高 16px + 边框 2px）；表格行内编辑位可用 `.input-flat-sm`（`6px 12px`，字号同档） |
| 内边距 | `10px 16px`（输入框）/ `10px 12px`（下拉触发器）；表格行内编辑位 `6px 12px` |

#### Select 统一规则

**废弃**：select 默认方框样式（浏览器原生下拉箭头外观）。

**统一采用**：`select.input-flat` 样式，与 input 输入框完全一致：
- 移除原生下拉箭头（`appearance: none`）
- 添加自定义 SVG 下拉箭头（12px，灰色，右侧 14px 偏移）
- 聚焦时箭头变为主色（红色）
- 右侧内边距 `36px`（为箭头留空间）

> CSS 实现见 `docs/src/styles.css` 的 `.input` 和 `select.input-flat` 选择器。

**交互增强**：`select.input-flat` 由 `custom-select.js`（S2）自动增强为自定义圆角下拉（`.cs-select` + `.cs-trigger` + `.cs-menu`），原生 select 作为值载体保留（`data-cs-enhanced` 防重；bootstrap 全局 MutationObserver 覆盖动态渲染）。增强后：
- 触发器外观与 `input-flat` 完全一致（圆角 `--radius-sm`、边框 `--neutral-200`、聚焦时只把边框变主题色，不出外环）
- 菜单选中项用主题色（背景 `var(--app-accent-bg)`、文字 `var(--app-accent)`，跟随当前用户主题色，与 tab 激活态同档同源）
- 智能定位（向上/向下翻转、视口 clamp）；选项超 10 条自动内嵌搜索

**弹层统一基准（2026-08-08）**：所有"选择类弹层"（`.cs-menu`、`.status-badge-popover`）统一：圆角 `--radius-sm`、阴影 `--shadow-dropdown`、选中色用主题色（`var(--app-accent-*)` 三件套，bootstrap 按 accentRole 注入）；禁止各自另设圆角/阴影/选中色。

#### 输入组件统一原则

所有 `<input>`/`<select>`/`<textarea>` 使用 `input-flat` 体系，禁用内联 Tailwind input 样式（如 `border border-gray-200 rounded-lg px-3 py-2 focus:border-red-300` 等）。紧凑场景使用 `input-flat-sm`，多行文本使用 `textarea.input-flat`。**唯一出口自 2026-11-01 起＝`components/ui/forms.js`**（布局中立 `textInput` / `selectInput` ＋ 带 label 的 `textField` / `selectField` / `dateField`），新代码不得直接手写裸 `input-flat`；细则见 §12.15 SD-56。

> **口径变更（2026-09-14 支书裁定「折中」值）——全站并为一档：正文 13px、控件 38px。**
> 支书原话：「考勤、考察的人作为第一列的表格字体都很小，搜索框和筛选器的组件都很小。而同一页的表单字体却又很大……**全部统一，但是目前表格与筛选器太小；表单太大。可以折中一下！**」
> 并档后：严格说只剩**一档**（38px / 13px），外加一个「表格行内编辑位」保留较小内边距（`.input-flat-sm`，字号同档）。

> **尺寸/字号单一源**：
> ① **唯一档位**——正文 13px、控件 38px：`input-flat` / `input-flat text-xs`（`.text-xs` 只是历史类名，**不再是更小一档**）/ 原生与增强下拉 / `.lf-btn` / `.data-table` 正文，全部同档；表格内嵌 `.input-flat-sm` 仅保留较小内边距（6px 12px），字号同档 13px；
> ② **禁止**「自制 Tailwind 控件」再出现（`rounded-lg border border-gray-200 px-2 py-1.5 text-xs bg-white` 一类）；
> ③ **禁止**在 `input-flat` 上叠尺寸类（`py-1.5` / `p-2` / `text-sm` / `rounded-lg`）——会覆盖单一源口径；
> ④ **禁止** `text-[11px]`/`text-[10px]` 控件字号（与规范 Caption 档冲突）；现存项登记为基线，**新增即红**——守卫 `server/test/control-font-guard.test.mjs`（含 `text-[9px]`：§4.3 原文未点名 9px，按同一条「控件单档 13px」纳入，全站现存 0 处）；
> ⑤ 同一 tab 内同一层级（工具条筛选/表单正文）的控件必须同档同字号——并档后此项自动成立；
> ⑥ **高度算式显式**：控件高 = 上下内边距 + **显式行高** + 边框，五处载体（输入框 / 原生下拉 / 增强下拉触发器 × 带不带 `.text-xs` 类名）同一算式——`10+10+16+2 = 38px`。**行高必须由 `docs/src/styles.css` 声明，不得靠 UA 默认或 Tailwind CDN 的 `text-*` 工具类提供**。守卫 `server/test/filter-row.test.mjs::D1 / D2`。
> ⑦ **表格正文与筛选器/表单同档**：`.data-table` 字号 13px、行高 1.25rem（行高 20px + 上下内边距 8px = 36px 行高）；Caption/徽标（`text-xs` 12px）不在本口径内，仍可用于状态徽标等附注文字。

**控件选型判断规则（先判「取值能否穷举」，再判「单选还是多选」）**

### 4.6 模块标签（Module Tab）

#### 排序原则

标签按**增量 > 存量**排列：增量（产生新数据的操作）排在存量（查看已有数据）之前。增量内部和存量内部的具体顺序需具体分析。日历与写入同属增量（均涉及带时间戳的待办数据），应合并在同一标签。

#### 功能融入优于独立

辅助性功能融入主功能 tab，不独立成 tab。判定标准：该功能是否依赖主功能的数据上下文？若是，则融入主功能 tab 作为子区块；仅当功能完全独立、不依赖主 tab 上下文时才独立成 tab。

已落实案例：经验沉淀融入监督复盘（督促清单）、追踪看板融入专班管理（活动进度）、专班工作量融入项目看板。

#### 职责有入口

角色有职责就必须有系统入口。如果制度文件（如支委与党小组定人定责定岗说明.md §二 党小组组长职责表）定义了某项职责，但系统中无对应操作入口，则视为功能缺失，需补全。

已落实案例：党小组组长复盘反馈职责→新增复盘提交 tab。

#### 视角正交

同一数据可从不同视角查看，不重复操作入口。视角不同不等于功能重叠——操作入口按赋权范围约束分布，只读视图可全局共享。

已落实案例：人全景（以人为中心）只读 vs 常设赋权（以项目为中心）写入，两入口互补不重叠。

#### tab 命名一致性（2026-09-27 立 · 命名裁定成文 · 单一源）

> **口径**：**同一语义组件跨台必须同名**——同一功能、同一组件、同一数据，在各角色工作台**必须用同一个 tab 名**，不得因「这台先写、那台后写」各起一名。**tab 名的差异只能由「职责不同」支撑，不得由「实现历史」支撑**：若两台显示名不同，必须能**指认二者职责 / 视角层级的实质差异并引母本**；指不出实质差异者，一律**收敛为同名**。

**「人 × 项目」矩阵＝宽表单一源（2026-09-14 支书裁定）**

> 支书原话：「活动的考勤考察，还是以 long form 为主，也就是每人次一行。wide form 是不是一个更加简明的表现方式呢？人和活动/专班/别的……分离开后，其实存在一种**转置**方式！第一列是人的话，就可以展示他参加的项目；如果第一列是项目，那就可以看有哪些人。这是一个**很全局性的**需要思考和改进工程！」
> 支书裁定：① **宽表默认**（long form 降为「明细 / 导出」下钻）；② 矩阵**推广到其它二元关系域**（支部分工、专班报名总表、表态汇总）。

凡「人 × 项目」这类**二元关系**（考勤、考察、支部分工、专班报名总表、表态汇总）一律走单一源组件 [components/ui/relation-matrix.js](file:///d:/GitHub/GSM1921-SOP/docs/src/components/ui/relation-matrix.js)：

1. **转置双视图**——`byPerson`（行＝人，列＝项目，看「某人参加了哪些」）与 `byItem`（行＝项目，列＝人，看「某项目有哪些人」）**互为转置**：同一份数据、同一 cell 口径，切换只换视角，不是两张表；
2. **项目维列上限 6**（`MATRIX_COL_LIMIT`）——项目（活动/专班/工作项）随年份无限累积，列不能无限长；超限时给「**显示全部 N 项**」一键展开（展开态按 `stateKey` 记忆，跨重渲染不丢），行维保持全量；
3. **横向滚动 + 首列吸附**（`overflow-x-auto` + `sticky left-0`）——桌面 / 宽表横向滑动时维度名不丢；≤640px 不靠横滑，改按第 9 条堆叠；
4. **筛选归调用方**（活动名/时间区间/姓名/分面），组件只负责「列取哪几项 + 转置 + 展开」——筛选是各域口径，矩阵是共同载体；
5. **载体不另造样式**——表格用 `.data-table`，展开钮用 `.lf-btn`（全站单档 38px/13px），不为矩阵新增类族（`styles.css` 属禁改文件）；
6. **默认视图＝宽表**（long form 的定位改为「明细 / 导出 / 打印」下钻）；
7. **人维分页**——`MATRIX_ROW_LIMIT = 10`（每页 10 人），`cfg.rowLimit` 可配、**0＝不分页**；人维无论落在行（按人）还是列（按项目）都按同一页切片，页控件走 `components/ui/pager.js::pagerHtml`（翻页标记单一源，见 §4.10「翻页标记单一源」）；
8. **`cfg.cellClass(pid, iid)` 单元格附加类钩子**——单元格语义经既有语义类复用（如表态矩阵的「异议」红底 /「未投」灰字复用 `.vs-object` / `.vs-none`），**不为矩阵新增样式类族**。
9. **窄屏堆叠＝同一关系行的响应式形态（2026-10-21 Task 7 / B-499-10）**——矩阵表与引擎表共用 `data-responsive="cards"`：≤640px 时 thead 隐藏，每行成为一张卡（`byPerson`＝一人一卡、卡内「项目名·状态」；`byItem`＝一项一卡、卡内「姓名·状态」），行表头（`tbody th`）作卡标题，每个 `td` 用 `data-label`（当前可见列名）作字段名。**这不是卡片矩阵**：仍是同一张表、同一份数据、同一 cell 口径（含 `—`、状态徽标、下钻），只是响应式重排；转置、列上限 6、显示全部、人维分页全部保留。卡式行内 `sticky` / `min-width` 必须清零（`styles.css` 单一源），容器不限高、不再表内横滚；桌面 ≥1024px 仍是原宽表 + 首列吸附。

### 4.11 图标规范

图标是组件的一种特殊形态，本节规定其格式与标准。

#### 4.11.1 格式要求

- **必须使用 SVG**（内联或 `<img>`）
- **禁止使用**：Emoji（如 🔍 → `<svg>...</svg>`）、PNG 图标、Icon Font

#### 4.11.2 SVG 图标标准

| 属性 | 值 |
|------|-----|
| 尺寸 | `18px × 18px`（标准）/ `24px × 24px`（大图标） |
| 描边 | `stroke="currentColor" stroke-width="2"` |
| 填充 | `fill="none"`（线性图标）/ `fill="currentColor"`（实心图标） |
| 圆角 | `stroke-linecap="round" stroke-linejoin="round"` |

#### 4.11.3 图标使用示例

```html
<!-- 内联 SVG（推荐） -->
<button class="module-tab">
  <svg width="18" height="18" viewBox="0 0 24 24" fill="none"
       stroke="currentColor" stroke-width="2"
       stroke-linecap="round" stroke-linejoin="round">
    <rect x="3" y="4" width="18" height="18" rx="2" ry="2"/>
    <line x1="16" y1="2" x2="16" y2="6"/>
    <line x1="8" y1="2" x2="8" y2="6"/>
    <line x1="3" y1="10" x2="21" y2="10"/>
  </svg>
  <span>工作台</span>
</button>
```

### 4.12 交互载体决策规范

> 指令"适用悬浮表单的场景有点受限，下拉选择和表单出现的位置值得深究"。系统录入/操作按场景判定载体，防止"所有表单都内联在页面"或"所有操作都弹窗"两极化。

四种载体按场景判定：

| 载体 | 适用场景 | 判定要点 |
|------|---------|---------|
| 悬浮表单 | 轻量录入（≤3 字段）；需要上下文锚定的主录入（如写入活动） | 录入动作，字段少或主流程 |
| 就地展开 | 以「查看」为主 + 快捷操作 | 读为主，不破坏页面常驻结构 |
| 内联面板 | 页面主流程长表单（多字段、多步骤） | 常驻、需要持续可见 |
| 跳转 | 整页级操作 | 独立页面 |

**已落实案例**：
- 支书「写入活动」→ 悬浮表单（`openModal` 720px，Step1 选模板 → Step2 填表单），提交成功关闭悬浮 + 列表刷新（2026-08-05）
- 组长工作台「添加记录」→ 就地展开（查看为主 + 快捷录入）
- 纪检批注 → 悬浮表单（`openFormModal`）

**筛选行载体（2026-09-14 补；2026-10-20 按 D-738 改准）**：筛选器不属上表四种载体，单独定则——关键词用紧凑档输入框，每个可枚举维度默认用**一个下拉**（首项「全部」）；人维表（`personFacets`）可按 §4.28 用引擎 `facetStyle:'chip'`；仅互斥视图切换才用分段钮；**禁止页面自写 chip 承担筛选**（详见 §4.3「筛选行规范」与 §4.28）。

### 4.13 选人规范（PersonPicker）

> "我们人太多了"——全支部约 50 人，select 罗列人名不可搜索、不可分组，选择成本高。

**硬性规则**：
1. 凡选择「具体人」，一律使用 `PersonPicker`（自带姓名/学号搜索 + 党小组分组 tabs + 单选/多选）
2. **禁止用 select 下拉罗列人名**
3. 表单内选人同样走 PersonPicker（嵌入表单渲染）
4. 候选范围过滤用 PersonPicker 的 `filter` 选项（如排除支委），不得预生成 select option

**例外：「任命 / 指派到人」可用下拉（2026-09-14 支书裁定）**

> 判据是**语义两分**，不是载体偏好：**「选名单里的成员」**（参与人、流出对象、批量处理、候选人）→ 必走 PersonPicker；**「把某职责任命/指派给谁」**（任命支书、分工到人、落实责任人）→ 允许下拉。理由有二：① 指派类字段常是**混合取值**（「支委角色」或「具体成员」二选一），PersonPicker 只表达「具体人」，硬换会丢掉「按角色指派」这一档；② 任命类候选集合小且需并列显示「现任/发展阶段」等旁注，下拉反而读得更快。

**已登记例外（全站共 3 处，守卫 `filter-row.test.mjs::S9` 锁白名单）**：

| 位置 | 语义 |
|------|------|
| `components/governance/org-setup-wizard.js` | 换组织向导内任命 |
| `entries/tabs/secretary/workforce-panel.js` | 支书台分工到人（支委角色 或 具体成员） |
| `components/governance/resolution-followup-manager.js` | 决议落实「责任人」（与分工同口径） |

**已落实案例**：工作组成员授权选人（原「项目赋权」；原 select 罗列人名 → PersonPicker 搜索选择，2026-08-05）。

#### 实现态不入产品话面（2026-09-29 立 · 支书裁定）

- **原则**：数据源（`mock` / `api`）、`sessionStorage` token 有无、判定段号、内部 id、代码版本戳……这些是**实现态**，**不得摆成用户可见的「字段」**。用户要的是**能感到的事实**（如「顶栏组织名是什么、凭什么是它」），不是「系统现在跑在哪个模式」。
- **判据（Boolean）**：`visible_to_user(field) == false` 若 `field ∈ {数据源, token 有无, 段号/内部枚举值, 内部 id, 版本戳}`。
- **落点**：设置页「当前归属」卡（本批由「当前形态 · 归属判定」精简而来，只留**组织名 ＋ 归属依据**）；段标签本身也去掉了代码标识符（`HEADER_SEGMENT_LABELS` 改为人话）。
- **边界**：机关/调试态若要留自查位，**不得**混在常规设置页里（本批选择**精简**而非另立调试面）。

#### 表格 / 矩阵：说明段与列宽（2026-09-29 立 · 支书裁定）

- **说明段**：表格 / 矩阵**不得配「行＝…；列＝…；徽标＝…」式说明段**（行列结构由**表头**自明）。真正非自明的图例（如「状态取**就高不就低**」）改落**表头 `title` 悬浮**。
  - **判据（Boolean）**：`has_explainer_paragraph(table_host) == true` ⇒ 违规；允许的例外只有**与控件绑定的功能提示**（如「列＝最近 6 项」随 `显示全部` 切换出现）。
- **列宽**：矩阵单元格信息量小（状态色块 / 「—」）时**列须按内容定宽**——`.data-table` 基类 `width:100%` 会把列**拉伸填满**；矩阵一律加 `.rm-table`（`docs/src/styles.css`：`.data-table.rm-table { width: auto }` ＋ 横向内边距收窄）。
  - **判据（Boolean）**：`cell_info_density(column) << column_width` ⇒ 违规（应 `width:auto` 或换更紧凑的展示形态）。
- **单元内容**：台账类矩阵的 cell 用**状态小色块**（`2.5×2.5` 圆点，色取状态色白名单 `bg-*-600`），**全文进 `title`**（本批据此**改裁**批次 41「cell＝徽标 ＋ 篇数小字」——支书 2026-09-29 评「每一列这么宽…没有更高效的展示视图嘛」⇒ 选「紧凑化」）。

#### 能自动的交接，一律自动（2026-09-29 立 · 支书裁定）

- **原则**（支书逐字）：「**需要自动交接的 都要实现自动交接才对！不需要额外费口舌**」⇒ 凡「数据交接」类（一方交、一方存档）**发起即完成**，**不得**要接收方再点一次「确认接收」；**留痕仍在**（`createdAt` / `confirmedAt` / `confirmedBy: 'system'`）。
- **判据（Boolean）**：`is_data_handoff(type) == true` ⇒ `auto_confirm(type) == true`；`is_todo(type) == true`（如「补课需求回执」＝要人去办事）⇒ 仍 `pending`。
- **单一源**：`docs/src/services/governance/handoff.js::AUTO_CONFIRM_TYPES`（**两形态同源**：前端 mock 与 `server/routes/resources/semantic-routes.js` 都读它，不得各写一份）。
- **配套**：既然不再需要人工确认，**也不得**再写「到某处点确认接收」「（提交后此处给出指路）」那类**空态解释**（同属「此地无银」）。

### 4.16 组件设计原则

> 与本节 4.1~4.15 既有组件规范互补——既有条目规定组件"长什么样"（规格表），本节记录组件"为什么这样设计"（布局/交互论证与判例）。论证与判例档案见 [DESIGN_METHODOLOGY.md](../evolution/DESIGN_METHODOLOGY.md)。

**主页布局：2+1 排布**：上方两列（通知+招募）+ 下方全宽（日历），信息层级清晰。三等分布局不适合信息层级不同的内容——通知和招募是快速浏览型，日历是深度交互型，不应争夺同样的视觉空间。

**侧边栏交互：overlay 优于挤压**：桌面端侧边栏展开时挤压主内容区（margin-left）会导致内容重排。overlay 不影响主内容区的布局计算，用户可以在侧边栏打开的同时继续阅读主内容。挤压模式则迫使主内容区重新计算宽度，造成视觉跳动。

**浮层 hover / 进场：渐入优于突现**：`transition`（`box-shadow` / `opacity`）渐入而非瞬间出现。突兀的视觉变化会打断用户的阅读流。⚠ **适用范围经 §4.19 收敛为「浮层」**——平地卡片/面板一律无阴影，卡片 hover 只改 `border-color`（§4.2 规范表 + 硬性规则 4「纯展示卡不加 hover 伪装」），不再渐入阴影。

**标题应统领卡片而非内嵌于卡片**：h2 标题被包裹在 `div.card` 内部时，视觉上卡在"中不溜"的位置——既不在页面顶端，也不在卡片核心内容区。标题是"这是什么页面"的宣言，卡片是"在这里能做什么"的容器——两者不应混为一谈。

**反馈系统作为独立子页面**：一个功能如果值得被单独提及（如 header 中的独立链接），那么它很可能值得一个独立的子页面。把它塞进边角等于在暗示"这个功能不重要"。

**侧边栏即全局导航**：每新增一个子页面都应同步在侧边栏中新增导航项。侧边栏是用户在多页面系统中的"地图"——岔路越多，地图越不能缺页。

### 4.17 快速导航矩阵形态

**矩阵形态**：多角色 × 功能域导航用紧凑表格表达——行对应功能域、列对应角色，六类角色列等宽平级、支书列置后，公共页面独立为表上贯通横条；功能 chip 用 `<a>` 跳转（带 `:focus-visible`）。对比按角色分组的卡片网格：网格信息全但无层次、无关系、无视觉锚点；矩阵用双轴编码把"谁有什么功能"压缩进一张表，空格子以淡色填充弱化空洞。

**扁平化落点**（全仓库适用）：主持角色不得置于最高/最中心；所有角色列完全等宽、同样式、平级。行归并按"同域归并"而非"同角色归并"——考勤+考察→「考勤与考察」行、活动+专班→「活动与专班」行（专班不得与统筹合并）；**合并行标签必须保留"与"字**，省略后行名失去并列语义。

**为什么不是"每角色一张卡片的平铺网格"**：纯罗列无法表达导航关系。平铺把信息全部摆出但没有关系表达，用户仍需自行拼装"哪个角色有哪些功能"；矩阵把关系编码进行列结构，一眼可查、可横向比较。网格形态在导航项不可正交切分时仍可用（如单角色站点），不构成全盘否定。

**生效条件**：导航项可按"角色 × 功能域"两轴正交切分的多角色系统（组织内部管理系统、多岗位后台）。单角色站点、或导航项无法正交切分时，卡片/列表形态仍适用。

> **关联**：最小三成本（[DESIGN_METHODOLOGY.md](../evolution/DESIGN_METHODOLOGY.md) §1.3.1）、H40.1 概念命名守则（扁平化）、web-design-guidelines（语义 `<a>`/focus-visible）

### 4.18 界面文案（Copy）规范（2026-09-24 立 · 阈值全部来自实测）

> **来源**：支书 2026-09-24 原话——「我需要补充一个设计上**最大的问题**就是【**字很多！！**】很多新界面**字都很多**！！」。
> 本节**不凭感觉立规**：所有阈值取自一次可复现的**全站真机取证**（7 个工作台 × 全部 tab ＋ 12 个独立页 = 79 屏，
> 在**真实渲染的 DOM** 上量「可见文案字符数 / 可操作控件数」；量测口径见 §4.18.5）。
> 本节只约束**界面文案（Copy）**，不约束字号 / 配色 / 布局骨架——那是 §三 / §二 / §六 的事。

**全部落在 2026-09-10 ~ 09-24**，其余为名单 / 计数类数据块）。上表与这两个数字是**阈值推导的取证底稿**，保留改前取值；

#### 4.18.2 硬规则（逐条给判据，判据一律写成**真机 DOM 谓词**）

| # | 规则 | 判据（能判红） |
|---|---|---|
| **C1** | **面板/卡片导语 ≤ 60 字**，其后直接是控件或数据 | 卡片内**首个**文本块的 `[...textContent.replace(/\s+/g,'')].length ≤ 60`。超 60 ⇒ 改为「一行摘要（≤60）＋ `<details>` 折叠全文」 |
| **C2** | **单个连续说明段 ≤ 80 字**；超 80 必须拆段或折叠 | 任一**不在关闭的 `details` 内 / 非 `summary`** 的块元素 `textContent` 去空白后 `> 80` ⇒ 红（全站实测仅 16 条离群：12 条界面文案的提交日期全在 2026-09-10 ~ 09-24，另 4 条是数据块） |
| **C3** | **禁止同屏复述**：同一句话不得在标题 / 副标题 / 提示句里说三遍 | 同屏内**归一化后（去空白、数字→N）相同**且 `≥15` 字的文案块出现 `≥2` 次 ⇒ 红。允许的确切例外：分页/列头等**结构性重复**（如每行状态徽标） |
| **C4** | **每屏「文案 ÷ 控件」≤ 12**；12–20 须逐屏登记理由；>20 必须改造 | `可见文案字符 ÷ 页内 button/a/input/select/[role=button]/[role=tab] 可见个数`。12 = p75，20 ≈ 实测比值排行第 8 名 |
| **C5** | **单句括注 ≤ 2 个**（`（…）` 计数，含半角 `(...)`） | 单块内 `（` 出现 `≥3` 次 ⇒ 红（全站实测 7 处；最重一段 359 字含 5 个括注） |
| **C6** | **空态/错误态 ≤ 30 字**，只写「为什么空 ＋ 下一步动作」，不写安慰话 / 承诺 | 空态容器（`.is-empty` / 「暂无 / 还没有」起始的块）文案 `> 30` 字 ⇒ 红（全站实测 4 处、最长 38 字）。**空态只从 `docs/src/components/ui/empty-state.js::emptyStateHtml` 出**（`variant: 'panel'｜'inline'｜'table'`），不再手写；机检＝`copy-guard::E1/E2` |

#### 4.18.3 硬规则（制度与口径类）

| # | 规则 | 判据 |
|---|---|---|
| **C7** | **制度原文不进界面**：制度母本（`content/02_institution/**`、`content/01_strategy/references/**`）的整句不得搬进页面 | 界面文案与制度母本存在 **连续 ≥20 字**子串重合 ⇒ 红，必须改写成一句口径 ＋ 指向 `docs/help.html` 对应锚点的链接（**信息不丢，只搬家**） |
| **C8** | **口径说明允许就地折叠，但不允许只在界面里存在一份**：折叠区内容必须与 help 的对应小节口径一致 | 折叠文案若属**制度口径**，须在 `help.html` 有同义段落（改口径时两处同改；单处出现即视为孤本） |

#### 4.18.4 允许风格与推荐句式

- **摘要句式**：先给**结论**（谁的本位 / 能不能做），再给操作。示例：「**本位＝党小组组长**（办活动⇒党小组承办）。」
- **折叠标题**：名词短语 + `▾`，如「上传位口径与应到计算规则 ▾」「支书为何可介入 ▾」「身份边界 ▾」。**禁止**「更多」「详情」这类无信息标题。
- **括注去处**：批次号 / 裁定日期 / 单一源代码位（如「policy recorderByType」）**一律进折叠区**；摘要行留给用户看得懂的话。
- **指向 help**：界面里只留一句 ＋ `<a href="./help.html#锚点">见帮助 · 某某</a>`，不复制正文。

#### 4.18.5 取证口径（可复现）

量测方式：Playwright headless，逐台登录 → 逐 tab 点击 → 在真实 DOM 上遍历文本节点。计入「可见文案」＝
文本节点满足「父链不含 `button/[role=button]/[role=tab]/input/select/textarea/option/label/table`（表格数据格）/
`nav/.tab-bar/.sidebar/header/footer`/`.visually-hidden/.skip-link`」且**父元素可见**、且**不在关闭的 `details` 内**
（折叠内容不计入视线，与「读不完」的实际体验一致）。「控件数」＝可见的
`button/a/input/select/textarea/[role=button]/[role=tab]` 个数。

> **为什么「每屏文案总字数」不设硬阈值**：实测最重的几屏，其字数**主要来自运行时数据而非界面文案**
> （如「活动监督复盘」1161 字里 8 成是成员提交的复盘正文；「通知发布」852 字里 459 字是通知正文）。
> 总量阈值会把**数据面**误判为文案问题 ⇒ 总字数只作**人工普查项**（每季度全站排名一次），不进 lint。
> 同理，**「新界面比老界面字多」不作规则**：按 tab 新旧分组取证时结论随切分阈值摆动（见执行日志），不是一个稳定命题。

> **关联**：§3.3.1 标题语义层级（复述的源头常常是标题层）、§4.16 组件设计原则、
> [DESIGN_METHODOLOGY.md](../evolution/DESIGN_METHODOLOGY.md)（判据论证）、`docs/help.html`（长文的正规去处）

### 4.19 形状 · 边框 · 阴影档位表（2026-09-27 立 · 补「标准缺档」）

> **为什么要立这一节**：§4.2 规定卡片「边框 1px / 圆角 12px / 阴影 无」，§4.3 规定控件圆角 8px，§4.9 规定
> 日历色块圆角 3px——**但没有一张「元素类 → 圆角/边框/阴影」的总表**，且 §4.2 与 §4.16（卡片 hover 阴影）
> 互相冲突。于是同一类元素各自取档（真机量测：**徽标**同时出现 `rounded-full` 与 `rounded-md`(6px)；
> 同页**卡片**用「无边框+阴影」，而**自定义卡/行块**用「有边框+无阴影」——支书实报的「有的方硬、有的圆软」
> 即此处）。本节把三档写成表，并**消解上述两处冲突**。

| 元素类 | 圆角 | 边框 | 阴影 |
|---|---|---|---|
| 卡片 / 面板（`.card`） | `--radius-md` 12px | `1px solid --neutral-200` | **无** |
| 弹窗 / 浮层容器 | `--radius-lg` 16px | 1px `--neutral-200`（或语义色） | `--shadow-dropdown`（**平地唯一允许的阴影去处**） |
| 控件（输入框 / 下拉触发器 / 筛选钮）· 按钮 · **内嵌行块**（卡片内小卡 / 列表行块） | `--radius-sm` 8px | 控件 / 按钮 1px `--neutral-200`（或语义色）；**内嵌行块无边框**（§4.2「列表项白底原则」） | 无 |
| 徽标 / 胶囊 / 圆点 / 头像 | `rounded-full` | 视语义（状态徽标可带 1px 同色系） | 无 |
| 表格 | 0（无圆角） | 表头行线 1px `--neutral-200`、数据行线 1px `--neutral-100` | 无 |
| 分页钮（明载例外） | `--radius-sm` 8px | 1px `--neutral-200` | 无 |

**判据与消解（逐条可核）**：

1. **「同一类元素同一圆角档」的机器化口径＝`class` 里的圆角工具类只能取本表档值**。全站实测
   `class="card …"` **134/134 都取 `rounded-xl`（12px）**⇒ 卡片圆角本就统一；不统一发生在
   **徽标**（主流 `rounded-full` vs 少数 `rounded-md` = 6px，11 处）与**内嵌行块 / 小按钮**
   （主流 `rounded-lg` = 8px vs 少数 `rounded-md` = 6px）⇒ 处置：**越档值归到最近档**（徽标→pill、块/钮→8px），
   **不新造第 4 种档**。（Tailwind 尺规：`rounded-md`=6px、`rounded-lg`=8px、`rounded-xl`=12px，
   与 `--radius-sm/-md/-lg` 一一对齐，故表内只写两套等价命名。）
2. **阴影只归浮层**：§4.1「装饰性禁令：禁止 `box-shadow`」＋ §4.2「卡片阴影 无」＋ §5.3「禁止 box-shadow
   发光扩散」三处一致 ⇒ **平地（卡片/面板/行块）一律无阴影**，`box-shadow` 全站只留给**浮层**
   （`--shadow-dropdown`、tooltip、focus 环）。此前 `.card` 带 5% 阴影、而同页「白底+边框」的自定义卡
   无阴影 ⇒ 两种质地并存（＝「方硬 / 圆软」）⇒ 本批把 `.card` 收敛为本表第一行。
3. **§4.16「卡片 hover 渐入阴影」条款废止、适用范围限定为浮层**——它与 §4.1/§4.2/§5.3 直接冲突，且
   §4.2 硬性规则 4 明写「纯展示卡不加 hover 伪装」⇒ 平地卡片不得用 `box-shadow` 做 hover 反馈；
   `.card--interactive:hover` 按 §4.2 规范表只改 `border-color`（不移位、不加阴影）；默认 `.card:hover` 不变色。
4. **边框层级**：容器卡 1px 中性边框；**行级元素（列表项 / 卡片内行块）不加边线**（§4.2「列表项白底原则」）；
   强调/角色/引述边线仍按 §4.2「边线语义」五档表（宽度 4 / 3 / 1-2px 不可倒挂）。

> **关联**：§4.2 卡片（本表的权威行）· §4.3 输入框单档 · §4.10 数据展示与分页控件 · §5.3 禁止动效 ·
> 研判见 [DESIGN_METHODOLOGY.md](../evolution/DESIGN_METHODOLOGY.md)

### 4.20 表格与列表（2026-10-18 立 · 四类载体单一源）

> **为什么单立一节**：§4.10 回答「有哪些视图」、§4.10.1 回答「什么数据格式用哪种视图」，但**同一块数据仍可能在
> 「表格 / 矩阵 / 台账 / 卡片」之间随手挑**，并出现手写 `<table>`、同屏两种主载体、用卡片堆叠代替字段分组等回潮。
> 本节把四类载体的**适用判据、阈值、交互与窄屏口径**一次写清；新增区块先按本节选载体，再按 §4.10 接单一源组件。

#### 4.20.1 选择四问（按顺序问，前一问答「是」即停）

| 顺序 | 问题 | 答「是」→ 载体 |
|---|---|---|
| 1 | 对象是否需要**逐行对比**（同一组字段、一行一个对象）？ | 数据表（`.data-table`） |
| 2 | 是否存在**两维交叉**（人 × 活动 / 项目 / 期次；单元格是关系而非字段）？ | 关系矩阵（`.relation-matrix`） |
| 3 | 是否**时间序、只读、不可排序**（记录发生即留痕）？ | 台账 / 时间轴 |
| 4 | 是否**少量异构对象**（每项字段不同、以整体阅读为主）？ | 卡片列表 |

四问全「否」⇒ 回到 §4.10.1 重新判断数据格式，**不得默认用表格**。

#### 4.20.2 四类载体

**① 数据表（`.data-table`，经 `components/ui/list-filter.js`）**

- **适用**：第一列是对象（人 / 活动 / 事项 / 记录），需要逐行比较同一组字段。
- **阈值**：行数 **> 8**（`SEARCH_FILTER_MIN_ROWS`）必须出现检索条；每页 10 条，页数 > 1 显示翻页控件（`pageSize: 0` 仅限有界小表）。
- **列序**：第一列＝对象标识；中间列＝可比字段；**行动作固定放末列**。
- **状态**：空态一句话（如「无匹配记录」），**只从 `empty-state.js` 出**——表格空行走 `emptyStateHtml({ variant: 'table', colspan })`（`list-filter` / `relation-matrix` 已内置），不再手写 `<tr class="is-empty">`；加载态由承载页在数据到达前给出占位文本，**不得把空数组渲染成空态**。
- **窄屏**：承载容器提供 `overflow-x-auto` 横向滚动；需要固定身份列时，首列声明 `sticky left-0`（列级特例，样式仍归 `.data-table`）。**≤640px 可切卡式行**（`responsive: true` / `data-responsive="cards"` ＋ 每格 `data-label`）：一行一卡、字段名在值前；打印时由 `@media print` 恢复为表格。

**② 关系矩阵（`.relation-matrix`）**

- **适用**：两维交叉（人 × 活动 / 项目 / 专班 / 期次），单元格表达「状态 / 动作」，不是一行对象的字段集合。
- **形态**：`relation-matrix.js` 的 `byPerson` / `byItem` 互为转置；同一份数据、同一 cell 口径。
- **单元格**：只放状态徽标、计数或可下钻动作；长说明不进单元格。
- **分页**：矩阵不做业务行的无限翻页——列维超过 **6 项**用「显示全部 N 项」展开（展开态按 `stateKey` 记忆）；人维沿用 `MATRIX_ROW_LIMIT`（缺省每页 10 人，`rowLimit: 0` 取消），与 §4.10 单一源一致。新矩阵不得另写分页标记。
- **窄屏（≤640px）**：**堆叠为卡式行**——同一张表加 `data-responsive="cards"`，thead 隐藏，每行一卡（行表头作卡标题，每格用 `data-label` 显示当前可见列名）；**矩阵窄屏堆叠＝同一关系行的响应式形态，不算卡片矩阵**（仍是同一份数据、同一 cell 口径，转置 / 列上限 / 分页不变）。卡式行内 `sticky` / `min-width` 清零，页面主体不得横向溢出；桌面 ≥1024px 仍是宽表 + 首列 `sticky left-0`。

**③ 台账 / 时间轴**

- **适用**：时间序、只读、不可排序；记录「谁在什么时候把什么改成了什么」，只增不改。
- **分组**：按日期分组（同日多条归一组）；组内按时间倒序。
- **单条内容**：时间、变更前后（或动作）、记录人；撤销/更正以新记录留痕，不覆盖原行。
- **交互**：只提供筛选与下钻；不提供列排序、不提供行内改字段。

**④ 卡片列表**

- **适用**：**少于 12 项**、对象异构（每项字段不同）、以整体阅读为主。
- **形态**：一对象一卡；可交互卡片保留边框与既有 `.card` 语义，纯展示卡不加 hover 伪装（§4.2）。
- **分页**：不分页；超过 12 项先回到四问，改用数据表或矩阵。
- **空态**：一句话说明「当前没有什么、去哪里新增」，不铺插图与长说明。

#### 4.20.3 禁止

1. **手写 `<table>` 绕过 `.data-table`**：表格标记只允许来自 `list-filter.js` / `relation-matrix.js` 及 §4.10 已登记的例外实现。
2. **同一屏混用两种主载体**：一张卡内不得同时以表格和卡片列表承载同一批对象；下钻明细除外。
3. **用卡片堆叠替代字段分组**：字段可逐行比较时用表格，不把每个字段拆成一张小卡。
4. **表格里放长说明段**：说明文字放表格外的提示条或帮助页；单元格只放值、状态与动作。

#### 4.20.4 交互口径

- **检索 / 分面**：关键词输入 + 每个可枚举维度一个下拉（首项「全部」）；阈值未达不渲染检索条；筛选后页码归 1。
- **分页**：统一走 `components/ui/pager.js::pagerHtml`；计数与「第 x / y 页」只在 `list-filter` 状态行出现一次。
- **行点击**：整行可点击时须有明确落点；行内动作按钮 `stopPropagation`，不得触发行跳转（§10.4）。
- **行动作**：固定末列；危险动作二次确认；纯展示行不得出现伪按钮。
- **键盘可达**：可点击行/卡须可聚焦（`tabindex="0"` 或原生控件），Enter / Space 等效；禁用控件用 `disabled`，不用 `div` 模拟。
- **空态 / 错误态**：空态一句话；读取失败给出「读取失败 + 重试」，不得静默显示为空。
- **窄屏**：表格 ≤640px 可切卡式行（`data-responsive="cards"`），矩阵可堆叠（同一关系行的响应式形态）；未切卡式的表仍在自身容器内横向滚动、首列固定；卡片列表单列；不得把表格强行压成两列。

#### 4.20.5 实现对照表

| 载体 | 现有组件（单一源） | 代表页面 |
|---|---|---|

#### 4.20.6 矩阵不适用于「人员 × 工作组」

**判据（布尔）**：只有当第二轴是**可重复的事件 / 任务实例**，且每个单元格表达「这个人在这个实例上的状态」时，才用关系矩阵。若第二轴是**协作结构**（工作组 / 专班 / 党小组），单元格只表达「是不是成员、什么角色」，那是**成员关系**，不是二维状态网格。

- **人员 × 活动**：矩阵成立——每场活动是一个实例，单元格是出勤/表态/考察状态。
- **人员 × 工作组**：矩阵不成立——工作组是协作载体，人员与它的关系是「组织者 / 深度参与者 / 普通参与者」的成员关系；正确载体是**工作组名册**（按组列成员与角色）或**人员详情的工作组记录**。
- **考察的入口**：考察的入口是工作组详情内的成员表；跨组比较用**数据表**；「人 × 活动」矩阵只能作为活动工作组的派生视图，不能脱离工作组存在。
- 需要跨组审计时，用**数据表**列「人员 / 工作组 / 角色 / 状态 / 加入时间」，不要画成全站人员 × 全站工作组的稀疏大矩阵。
- 反面判例：把「谁在哪个工作组」画成矩阵，会出现大量空格、角色值挤在单元格里、无法表达加入/移出时间——这是载体错配，不是信息量问题。

> **关联**：§4.20.2 关系矩阵 · §4.20.3 禁止 · `COMMISSIONER_DUTY_FRAMEWORK.md` §A.4（活动工作组 / 专班工作组）

#### 4.20.7 表格内部三类行型

表格与台账的「行」不是同一种东西。先认行型，再选载体；同一张表内不得混用两种行型。

| 行型 | 判据 | 渲染模块 | 行内约束 |
|---|---|---|---|
| **对象行** | 同一组字段、一行一个对象，需要逐行对比 | `components/ui/data-table.js`（经 `list-filter` 表格模式） | 首列对象标识、末列动作；单元格只放值 / 状态 / 动作 |
| **关系行** | 两维交叉，单元格表达「这个人在这个实例上的状态」 | `components/ui/relation-matrix.js` | 互为转置；项目维列上限 6；人维每页 10；首列吸附 |
| **留痕行** | 时间序、只读、只增不改，记录「谁在什么时候改了什么」 | 台账 / 时间轴（既有留痕区块） | 按日期分组、组内倒序；不排序、不行内改字段 |

**硬约束**：

1. 新增重复行（标题 + 次级 + 一个动作）必须用 `components/ui/list-row.js`；不得手写 `div` + `border-b` + `py-2.5` 的行容器。
2. 新增逐行对比表必须用 `components/ui/data-table.js`；不得手写 `<table>` 或 `<td>` 内边距。
3. 新增两维交叉必须用 `components/ui/relation-matrix.js`；不得用卡片矩阵或稀疏表格冒充。
4. 留痕行只读；更正以新记录留痕，不覆盖原行。
5. **矩阵窄屏堆叠不算卡片矩阵**（2026-10-21 Task 7）：≤640px 时矩阵仍是同一张表加 `data-responsive="cards"`，一行一卡是**关系行的响应式形态**；不得因此另写一套「人 × 项目」卡片渲染，也不得把矩阵拆成互不相关的小卡。

### 4.21 间距五档与组件采用矩阵（2026-10-18 立 · 单一源）

> **为什么单立一节**：间距此前只有页面里的零散工具类，没有档位表，也没有「谁用哪一档」的矩阵，
> 于是同一屏出现 `p-[14px]`、`gap-[10px]`、`mt-[6px]` 三种自由值。本节把间距收成 **4 / 8 / 12 / 16 / 24**
> 五档（令牌单一源＝`docs/src/styles.css` 的 `--space-*`），并规定每个组件族只取一个档位。

#### 4.21.1 五档定义

| 档位 | 令牌 | 值 | 用途 |
|---|---|---|---|
| 1 | `--space-1` | 4px | 行内元素之间（图标与文字、徽章与标签） |
| 2 | `--space-2` | 8px | 行内与行纵向（列表行上下内边距、次级信息与标题之间） |
| 3 | `--space-3` | 12px | 卡片内（卡内元素间距、紧凑卡内边距） |
| 4 | `--space-4` | 16px | 标准卡内边距与区块间距 |
| 6 | `--space-6` | 24px | 页面区块间距 |

行高另有语义档：`--row-compact`（32px）/ `--row-standard`（40px）/ `--row-comfortable`（48px）。
字号不另造第二套：标题 14px、次级 12px 复用既有 `--text-base` / `--text-sm`。

#### 4.21.2 组件采用矩阵（每个组件族只取一个档位）

| 组件族 | 唯一档位 | 采用方式 |
|---|---|---|
| 页面区块 | 24 | `.stack-page`；页面级区块之间 |
| 标准卡 | 16 | `.card-standard`；卡内元素间距沿用 `.stack-card` 的 12 |
| 紧凑卡 | 12 | `.card-compact`；通知 / 待办等高频卡 |
| 列表行 | 12 | `.list-row` 的横向与行间；纵向 8 属行高构成，不另立档 |
| 选人面板行 | 4（纵向）/ 12（横向） | `.person-picker-item`；两级文字 + 40px 行高硬档，纵向取 4 才不撑高 |
| 表格单元 | 12 | `.data-table th/td` 的横向；纵向 8 属行高构成，不另立档 |
| 表单字段 | 8 | 字段与标签 / 错误提示的纵向间距 |
| 徽章 | 4 | 徽章内与徽章 / 文字之间 |
| 按钮 | 不取本表档位 | 尺寸与内边距由 §4.1 按钮语义族统一，本表不重复定义 |

同屏出现标准卡与紧凑卡时，厚度只允许差一档（16 与 12）；不出现第三种厚度。
页面骨架工具类：`.stack-page`（24）→ `.stack-section`（16）→ `.stack-card`（12）；
行内小间距用 `.gap-inline`（4）。

**数字卡不另立厚度档（2026-11-01 批次 523 立）**：数字卡（`.stat-card`）＝**两行**（数值 ＋ 标签），
无记录时数值位显示「—」，**不得加第三行注记**（如「本月无记录」）；卡内边距只由调用点 `p-4`（16px）给出，
组件自身不再叠加上下内边距，**卡高 ≤80px**（桌面与 390 同值；手机上两行卡合计 176px ＝ 2×80 ＋ 16 间距）。
结构细则见 §4.2「数字卡」与 §4.29 S-1，守卫 `ui-home-hero::E7`。

#### 4.21.3 禁止

1. 新代码不得出现 `p-[14px]`、`gap-[10px]`、`mt-[6px]` 一类自由间距值；只能引用 `--space-*` 或本表的语义类。
2. 不得用行内 `style="padding: …"` 绕开档位；组件样式只写在 `styles.css`。
3. 不得为单个页面新增第六档；确需新档时先改本节与令牌，再改页面。
4. 存量自由值按抽样清单分批迁移；守卫 `server/test/spacing-scale-guard.test.mjs` 按「只降不升」基线看住总量。

### 4.23 视觉语法（2026-10-18 立 · 七类信息载体单一源）

> **为什么单立**：§三 / §四 分别给了字号与组件，但「这一处该靠什么建立层级」没有一张总表——
> 于是同一屏里用色块、图标、加粗、边框同时争抢注意力，页面看起来「花」而不是「清楚」。
> **总则：文字、颜色、组件、字体、排版、图标都是信息载体，不是装饰**——任何一处样式选择都要能回答
> 「它承载了什么信息」；答不出就删掉。

| 信息维度 | 承担什么 | 允许档位 | 反例 |
|---|---|---|---|
| **字号** | 层级与扫读顺序 | 标题 14 / 16 / 20；正文 13；次级 12；标签 11 | 正文用 11px；同一层级出现第三种字号；靠小字衬线制造「精致感」 |
| **字重** | 同一字号内的主次 | 700 章节标题；500 行标题 / 表头；400 正文 | 整页 700；正文加粗代替层级；同一行标题时而 500 时而 700 |
| **颜色** | 行动 / 状态 / 身份 / 结构（§2.10 四问） | 行动＝主题色；状态＝功能色；身份＝角色色；结构＝中性色 | 逾期用 error 红；功能色上主按钮；主题色做状态徽章；整圈彩色边框 |
| **图标** | 动作与状态的识别 | 同一动作同一图标；尺寸随字号档；只作动作 / 状态前缀 | 装饰性图标；同义动作三种图标；图标替代文字导致语义不明 |
| **间距** | 分组与阅读节奏 | `--space-1/2/3/4/6`（§4.21 五档） | `p-[14px]` / `gap-[10px]` / `mt-[6px]` 一类自由值；靠重复边框分组 |
| **边框 / 底色** | 结构分组与强调 | 结构用中性 hairline；强调用单色规则（左侧 2px、计数徽章、状态徽章） | 整圈红边；同页多种左边条颜色；用底色代替分组 |
| **动效** | 状态变化的提示 | 150–250ms，只动 `transform` / `opacity` | `transition: all`；长时动画；为装饰加循环动效 |

**一句话口径**：字号定层级、字重定主次、颜色定语义、图标定识别、间距定分组、边框底色定结构、动效定反馈；
七者各司其职，**不得互相顶替**（例如用颜色代替字号层级、用图标代替状态文案）。

> **关联**：§2.10 颜色四问 · §3.2 字号层级 · §4.19 形状 / 边框 / 阴影 · §4.21 间距五档 · §5 交互反馈

### 4.24 帮助注释（Help Note · 2026-10-19 立）

> **一句话**：帮助注释＝**一句正文 + 一个链接**；正文只说明「这一屏怎么用」，长口径进 `help.html`。

| 项 | 规定 |
|---|---|
| 正文 | **≤ 1 句**；12px 中性灰（`--neutral-500`）；`display:block` |
| 链接 | **恰好 1 个**；全站单一链接色 `--color-link`（＝主题 soft-text）；**600 字重 ＋ 尾随箭头 ＋ 10% 主题淡底 hover** 作非颜色线索（SD-49：无文本下划线）；文案统一「见帮助 · <主题>」 |
| 位置 | 主对象**之后**或折叠内（§10.5「说明后置」） |
| 统一类 | `.help-note`（容器）＋ `.help-note__link`（链接） |

**正例**：

```html
<p class="help-note">组长 / 副组长由成员档案派生；行内「设 / 改」任命或撤销。<a class="help-note__link" href="help.html#party-group">见帮助 · 党小组与组长</a></p>
```

**反例**：同一页两种链接风格并存——一处手写 `text-sky-600` 蓝链，另一处灰字带下划线链；读者无法判断哪一个是「帮助」。

- 页面**不得**再手写 `sky-600` / 下划线灰链等第二种链接风格；新页面一律用上述两个类。
- 长口径（制度原文、完整流程、字段定义）**只进 `help.html`**，界面只留一句 + 链接。

> **关联**：§4.18 界面文案 · §10.5 首屏浏览顺序 · `docs/src/styles.css`「帮助注释」段

### 4.25 标题层级与文档大纲（2026-10-19 立）

> **一句话**：**H1 只在顶栏出现一次；每个 tab 一个 H2；分区 / 卡头用 H3**。标题层级是阅读顺序，不是字号装饰。

| 层级 | 用在何处 | 约束 |
|---|---|---|
| **H1** | 顶栏品牌（组织名） | 全站唯一；页内容不得再写一遍同名组织名 |
| **H2** | 当前 tab 的页面标题；首页区块标题 | 每个 tab **恰好 1 个**；统一用 `components/shell/page-frame.js::renderTabHeader` |
| **H3** | 分区 / 卡片标题 | 卡头统一 H3；不得从 H2 直接跳到 H4 |
| **H4** | 卡内再嵌套的分区 | 仅更深一层；不得用来冒充页面标题 |

**硬性规则**：

1. **一个 tab 只有一个 H2**：标题文案与页签名一致；不得用两个 H2 分别做「页名 + 主对象名」。
2. **不重复同一文案**：同一层级出现两次同名标题即判「繁」；首页不得再出现与 H1 同名的组织名 H2。
3. **主对象先于说明**：首个标题之后先放主对象；说明行、帮助注释一律后置（§10.5）。
4. **首页 hero 豁免（2026-10-28 支书裁定：保留 hero，改规范）**：首页 hero 允许 48px 党徽 ＋ 居中标题，但**仅限**两种状态——① 未登录 / 访客态；② 首屏无待办（个人待办为 0）。登录且有待办时，hero 降为辅助信息：组织名由顶栏 H1 承担，hero 不再作为第一重音。层级次序固定为：顶栏 H1（组织名）→ 区块 H2（如「近期活动」）→ 卡头 H3；区块标题用 H2，区块内的卡片标题用 H3。本豁免不与 §4.25 其它规则冲突；除此两种状态外仍按原规则判。
5. **其余页签触达即迁**：新页面 / 改到的页面必须按本表；不得为了「统一」一次性重写 60+ 文件。

### 4.26 零值与空行（2026-10-19 立）

> **一句话**：**0 是事实就显示 0；— 只表示缺数据；0/0 与整行全 — 都不出现。**

| 场景 | 规定 | 例 |
|---|---|---|
| 真实零值 | 显示 `0`，可用弱化色 | 条线「在办 0」、统计卡「本月活动 0 场」 |
| 缺数据 | 显示 `—` | 未填报的截止日期、无卡点 |
| 分母为 0 | 显示 `—` 或一句说明，**禁止 `0/0`** | 个人考勤无记录 → `—` + 「本月无记录」 |
| 整行全 `—` | **不渲染该行** | 全字段为空的历史记录 |

**判据**：写渲染代码前先问「这个 0 是事实还是缺数据？」——事实留 0，缺数据用 —；不得把二者混成同一个占位符。

> **关联**：§4.2 卡片 · §4.25 标题层级 · `docs/src/components/governance/work-overview.js`（条线 0 值）· `docs/src/components/dashboard/stats.js`（考勤空态）

#### 4.27.1 危险动作盘点（2026-10-28 立 · 美学专项 Task 6）

> **一句话**：**危险动作必须离开正文流、进入确认面；确认面须含「做什么 / 影响范围 / 可否恢复」三段**（规范编号 **SD-53**）。
> **适用**：归档、删除、作废、解散、移除成员、撤销、驳回、清空、覆盖、恢复默认等**破坏性或不可逆**动作；「保存 / 提交」一类非危险动作不在其列。

**三段判据**（三条全为真才算合格）

1. **做什么**：标题是一行动词（删除 / 归档 / 解散 / 撤销 / 拒绝），不写「确定吗？」。
2. **影响范围**：写清哪些行 / 人 / 记录会变；跨对象联动（待办、通知、材料、权限）要点名。
3. **可否恢复**：可恢复给出撤销路径（在何处回查 / 如何回退）；不可恢复（删除、解散、覆盖）明写「不可恢复」。

**统一入口**：`docs/src/components/ui/modal.js::confirmDanger`——复用既有 `_mustPressConfirm` 的「必须点按钮才能关」机制，主按钮 `.btn-danger-solid`（危险确认专用），**不新增第二套弹窗组件**；`docs/src` 内原生 `confirm(` 与 `data-confirm` 已清零（`data-adapter` 的业务方法 `.confirm(id)` 不属于对话框，不在其列）。

### 4.28 筛选形态选择（2026-10-20 立 · 阈值来自名册判例）

> **判例**：`.ctx/logs/archive/2026-10/UI_AUDIT_R3.md` 判例⑥——名册 4 组 chip 约 20 个按钮，390px 占 6–7 行，首屏看不到第一名成员。

| 形态 | 何时用 | 何时不用 |
|---|---|---|
| 搜索 | 取值**不可穷举**（姓名 / 学号 / 标题 / 正文 / 地点） | 取值可穷举时不要用搜索代替枚举 |
| 下拉 | 取值**可穷举且单选**；**筛选项 > 6**，或平铺后**占屏 > 2 行**；活动类表（`activityFacets`） | 取值只有 1 种（该维度直接隐藏） |
| chip | ① 人维表（`personFacets`，值集小且稳定，现行裁定 D-738）；② 表单内枚举多选（受众 / 类型）；③ 已选条件回显（可逐个删除）；④ 纯展示标签（不可点） | 活动类表与长值集维度；页面自写 `.chip-option` 绕过引擎 |
| 分段钮 | 互斥视图切换（按活动 / 按人；人视图 / 项目视图） | 不作筛选，不承载多选 |

**阈值与判据**

1. **> 6 或 > 2 行 ⇒ 下拉（默认）**：同一页筛选控件合计超过 6 个，或平铺后桌面超过 2 行、390px 超过 3 行，默认改「搜索 + 下拉」。**名册已由 2026-10-20 支书判例⑥专项裁定**：成员名册改「搜索 + 党小组/阶段/在册状态 三个下拉」，**D-738 的人维 chip 规则不再适用于名册**；其它人维表仍按 D-738，若与阈值相抵须先发起专项裁定，未裁定前不得逐页自改。
2. **> 8 行才出筛选行**：列表行数不超过 8 行不渲染筛选条（`SEARCH_FILTER_MIN_ROWS`，与 §4.20.2 同口径）。
3. **搜索与维度并存**：表格类列表必须同时提供关键词搜索与维度下拉；搜索框不替代维度。
4. **已选条件折叠**：回显 chip 超过 6 项时折叠为「已选 N 项」，不得继续平铺。
5. **引擎单一源**：chip 只能由 `list-filter.js` 按 `facetStyle: 'chip'` 渲染，页面侧不得自写胶囊类。

> **与 §4.3 / §4.12 的关系**：§4.3「筛选行禁止 chip」一句已被 2026-10-01 支书裁定推翻（D-738），现行边界以本节与 D-738 为准；§4.3 / §4.12 的旧句按本批同源改准，不再作为禁 chip 依据。

## 十二、组件层执行口径（2026-10-23 批次 505 · 现行）

> 本节是支书 2026-10-23 九条 UI 判例的执行口径；与 §3.2 / §4.1 / §4.3 的旧尺寸表冲突时，**以本节为准**（旧表保留作沿革）。
> 机检＝`server/test/ui-control-system-guard.test.mjs`；真机抽检＝`page-sweep`。

### 12.1 控件（唯一源）

| 项 | 标准 | 紧凑 |
|---|---|---|
| 类 | `.input-flat` | `.input-flat-sm` |
| 高度 | 38px | 32px |
| 内边距 | 10px 16px | 7px 12px（含 1px 边框） |
| 字号/行高 | 13px / 16px | 13px / 16px |
| 描边 | 1px `--neutral-200` | 1px `--neutral-200` |
| 圆角 | 8px（`--radius-sm`） | 8px |
| focus | 只把边框变主题色（`outline: none`、`box-shadow: none`，单信号；鼠标与键盘一致） | 同左 |
| 日期控件 | 所有 `.input-flat[type=date…]` 钉 38px | 所有 `.input-flat-sm[…]` 钉 32px |

- 控件上**禁止**叠加 `text-sm` / `rounded` / `rounded-lg` / 无颜色 `border`。
- 搜索类输入（`person-picker-search` / `help-search-input` / `cs-search-input`）必须与上表同描边、同 8px 圆角、同输入族焦点口径；它们是**登记在案的白名单**，新增白名单须给理由。白名单控件不得用页面内联样式另立一套焦点外观。

### 12.2 按钮（外围—内围）

**强度按结构位置，不按「主/次」：**

| 位置 | 族 | 外观 |
|---|---|---|
| 最外围（页头 / 空态主行动 / 弹窗主行动） | `.btn-accent` | 主题色实底 + 白字 |
| 内围（卡片 / 区块内） | `.btn-accent-soft` | 浅主题底（≥12% 主题色，不得近白）+ 深主题字 `--app-accent-deep` + 同色 1px 描边 |
| 工具位（行尾 / 筛选 / 次级） | `.btn-outline` | 白底 + `--neutral-200` 描边 + `--neutral-700` 字 |
| 行内辅助（更多 / 展开） | `.btn-ghost` | 无框文字 |

- **禁止**「白底 + 主题色文字」的按钮形态。
- 尺寸：标准 **36px**（accent / accent-soft / outline / neutral / danger / md）、紧凑 **32px**（ghost / tab）、小号 **28px**（sm / action）；与 38px 输入框同排的主行动可 38px。

### 12.11 状态语言（批次 508）

一个控件只回答五个问题，且五态**视觉正交**（可同屏并辨）：

| 问题 | 态 | 载体 | 禁止 |
|---|---|---|---|
| 我现在在这里吗 | **selected**（持续） | 主题 soft 三件套：`--app-accent-soft-bg` + `--app-accent-soft-text` + 左条 `inset 3px 0 0 var(--app-accent)` | 用 `--surface-hover/--surface-active` 表达选中 |
| 我正按着吗 | **active**（瞬时） | 中性灰 / 主题 `activeBg` / 党建红 `--party-red-active` | 与 selected 共用令牌 |
| 我能点吗 | **hover** | `--surface-hover` 或主题 `hoverBg`，仅颜色 | 位移 / 阴影 / 缩放 |
| 我填对了吗 | **invalid** | 红边 + toast 文案（不新增内联错误行） | 仅靠颜色不配文案 |
| 我能改吗 | **disabled / readonly** | 禁用＝浅灰底灰字；只读＝透明边浅底 | 用 `opacity` 混作两态 |

- **侧边栏是唯一豁免**：`.module-tab.active` 保留浅灰；其余选中一律主题 soft。
- 实例：`.list-row[data-selected]`、`.cal-cell-large.selected`（桌面/移动同源）、`.subtab[aria-selected]`、`.cs-option:focus-visible`、`.status-badge-option.is-active`、支委会步骤条当前步。
- 实底按钮 hover＝第 9 个主题 token `--app-accent-strong-hover`（同色相加深），**不得落灰**。
- 守卫：`hover-state-guard` / `theme-palette-guard` · 判例：CASE-DESIGN-004（SD-25）/ CASE-DESIGN-005（SD-26）

### 12.12 字段外壳（批次 508）

输入类控件（input / select / textarea / 日期 / 搜索）共用一个外壳，五个问题同一个答案：

| 态 | 边框 | 底 / 字 | 备注 |
|---|---|---|---|
| 静置 | 1px `--neutral-300` | 白底、`--neutral-800` | — |
| 悬停 | 1px `--neutral-400` | 不变 | 仅 `@media (hover:hover)` |
| 活动（鼠标或键盘） | 1px `--app-accent`，`outline: none`，`box-shadow: none` | 不变 | **只变边框；不出近黑外环，不叠 3px 浅晕** |
| 焦点环 | 输入族不出环（只变边框，`outline: none`） | — | 按钮 / 链接族见 DS_04 §5.8：一条 `outline: 2px solid var(--app-accent)`（offset 1px），几何同源 |
| 禁用 | 1px `--neutral-200` | 浅灰底、灰字 | 真不可用 |
| 只读 | 透明边 | 浅底、正文色 | 可读可复制 |

- 禁止「金边 + 黑环」双答；**禁止同一控件同时出 `:focus` 的 `box-shadow` 环与 `:focus-visible` 的 `outline` 环**——键盘聚焦时两者同时命中，会画成两个环（2026-10-28 实测：outline 2px 主题色 ＋ box-shadow 3px soft-bg）。
- **选择器统一**：原生 `<select>` 一律经 `enhanceSelects` 增强，面板与页面同一套 token；原生控件只作值载体。
- **大选项集一般化框架**：搜索（`data-cs-search`）、近期优先（`data-cs-priority="recent"`）、分批渲染（`data-cs-limit`）、空态「没有匹配项」；选人继续走 `person-picker`。
- 守卫：`field-shell-guard` / `ui-focus-ring` / `ui-control-system-guard`（FOCUS-1…3：双环检测 + 搜索框同环 + 环对比度）· 判例：CASE-DESIGN-006（SD-27）/ CASE-DESIGN-007（SD-28）/ CASE-DESIGN-008（SD-29）

### 12.13 动效令（批次 508，2026-10-31 P10 三档化）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--motion-feedback` | 120ms（80–120） | 小范围颜色 / 边框 / hover / press |
| `--motion-enter` | 200ms（160–240） | 入场、页签淡入、浮层淡入 |
| `--motion-exit` | 180ms（160–240） | 淡出、浮层关闭、旧内容退场 |
| `--motion-emphasis` | 280ms（240–320） | **仅一次性提示**：高亮褪去 / 进度条 / toast |
| `--ease-standard` | `cubic-bezier(.2,.6,.36,1)` | 常规 |
| `--ease-enter` | `cubic-bezier(.22,.61,.36,1)` | 入场 |

- 旧名 `--motion-fast / --motion-base / --motion-slow` 与 `--transition-*` 保留为别名，分别映射反馈 / 进入 / 退出档。
- 可复用类：`.motion-enter`（opacity + transform）、`.motion-collapse`（`grid-template-rows` 0fr→1fr）、`.motion-press`（内阴影）。`.motion-scale-in` 已删除（等比 `scale()` 属「太 fancy」）。
- **只允许过渡** `opacity / transform / color / background-color / border-color / box-shadow`；禁止 `height/width/max-height/min-height/padding/top/left/margin` 与 `transition: all`。
- 折叠用 `grid-template-rows` 取代 `max-height + padding`；进度用 `transform: scaleX()` 取代 `width`。
- 不写裸毫秒（`0s` 除外）；循环动画用 `calc(var(--motion-emphasis) * N)` 表达周期。
- `prefers-reduced-motion` 下 `transition-delay / animation-delay` 归零。
- 关于页 `about.css` 的 0.9–1s 叙事长时长与 `rotateX` / `clip-path` / `scale()` **只登记不改**，不得扩散到产品页。
- 守卫：`motion-guard` M1–M10（全 CSS + JS 内联 + 滚动出口）· 判例：CASE-DESIGN-009（SD-30）
