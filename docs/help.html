1.2 权限体系

系统权限不是"给你一个账号就什么都能做"，而是赋权关系链——谁给你赋的权，你就在谁的赋权范围里干活。三个视图模式，界定"能看什么"：

模式谁使用能看到什么能修改什么
管理模式角色对应的管理者自己角色的工作台自己角色的数据
管理者只读赋权者查看被赋权者被赋权者的工作台无
成员只读未选择角色的参与者统一信息流面板无

写入范围界定"能改什么"：

写入范围授权人享有角色
职能写入天然权限组织委员 / 宣传委员 / 纪检委员（各自板块）
活动写入天然权限党支书 / 党小组组长
活动写入（需赋权）党小组组长组织者 / 深度参与者
专班发起天然权限党支书 / 党小组组长 / 三委员
专班招募统筹天然权限组织委员（唯一节点）

关键约束：

  • 创建活动仅限党支书和党小组组长；党小组组长可独立创建，须报书记知情同意；组织委员协调的是专班（招募统筹），不是活动
  • 纪检委员考勤数据与组织委员通用同源
  • 宣传委员不可自行招募宣传专班，赋权操作统一归口组织委员
  • 三委员之间可相互查看（只读），但不可修改彼此的工作
  • 从首页进入管理页面时自动设为只读模式

二这个系统在干什么

这个系统是北京大学光华管理学院本科生党支部的数字化管理工具。它要解决的核心问题是：党支部工作如何从"人治"走向"制度治理"？支委换届频繁，经验随人走、制度随人变；新支委上任后需要数月摸索才能上手；同一种工作在不同人手里做法完全不同——本系统通过制度即代码、角色即视图、经验可传承三大设计理念，将党支部制度文本转化为可执行的代码工作流。

系统现有 14 个页面：首页、资料查询、意见反馈、归档库等公共页面，以及六类角色各自的工作台（党支书、党小组组长、组织委员、宣传委员、纪检委员、普通成员）。每个角色打开自己的工作台，就是该角色的全部工作视图——各项功能按 Tab 分组，无需在页面之间来回跳转；所有角色共享同一套数据，看到的是同一数据的不同视角。

三分工中的制度设计

这套系统的 8 种身份，分三层理解：上层是管全局的党支书；中间是两条管理线——支委的职能线与党小组组长的小组线；下层是普通成员与两个执行角色。

3.1 角色总览

组织者与深度参与者是扁平化执行角色，服务活动也服务专班，由党小组组长（活动）或组织委员（专班）赋权产生。

3.2 条块双线

纵线是支委的职能线：组织委员管发展党员与专班统筹、宣传委员管宣传档案、纪检委员管考勤考察——各管一类专业事务。

横线是党小组组长的小组线：按就业/学术方向划分小组，负责组织学习、开展活动。

两条线交汇于党支书——全局统筹与最终决策者。

3.3 两个执行角色：组织者与深度参与者

组织者与深度参与者是推动工作扁平化的两种角色，服务活动也服务专班，由赋权产生。

两者之间没有上下级关系，只是分工不同：组织者是项目的脑子，负责分工记录与协调；深度参与者是项目的手，负责执行具体工作、提交交付物。

3.4 活动走谁的门

党小组组长是活动的天然写入者——创建活动、向组织者赋权；组织者做好分工记录，深度参与者执行分工。

活动的考勤归纪检委员、宣传归宣传委员——一件事从创建到归档，门门有对。

3.5 专班走谁的门

发起人（书记/党小组组长/支委）提出需求，由组织委员统一招募统筹——唯一专班管理节点；招募赋权组织者与深度参与者，任务完成即解散。

活动与专班走不同的门：活动的门在党小组组长，专班的门在组织委员。

3.6 普通成员

普通成员以只读方式查看活动动态、专班进展与考勤概况——不参与管理，但有知情权与监督权。

四怎么理解具体的这个组织

4.1 这个组织靠什么运作

这个组织靠分工、协商、记录三件事运转，而不是级别：谁做什么由制度定好，组织者与深度参与者之间平等协商，做的过程有记录可查。

支委换届频繁、经验容易随人走，制度因此比个人可靠——工作不依赖某个人，才能一届一届接续下去。

你在这里的位置，由"你在做什么事"决定：承担了组织者的活就是组织者，年级与政治面貌不决定你是否胜任。

4.2 活动与专班：两种工作，两种节奏

活动是支部的常规节奏：固定时间地点、面向全体、重在参与与规范，党小组是基本单元。

专班是支部的攻坚方式：临时组建、小范围抽调、重产出，任务完成即解散；同时是考察积极分子的载体。

两种工作分开管理、走不同的赋权流程——常规的组织生活需要稳定节奏，而时效紧、跨角色、不可拆分的任务需要集中攻坚。

你在其中：活动的组织者做好分工记录；专班参与者是经组织委员统筹、从小组抽调的攻坚成员。

4.3 扁平化：不靠级别，靠协商

组织者不是"领导"——核心职能是做好分工记录，不靠命令压人；深度参与者不是"下属"——执行的是协商后的分工。

扁平化让每个人——包括积极分子——都有机会承担建设性工作；身份、年级、政治面貌都不决定是否胜任。

被赋权为组织者，你的价值在"记录好分工"；被赋权为深度参与者，你的价值在"把交付物做好"。

4.4 职能线与小组线

这套系统的中间层有两条线。一条是支委的职能线：组织委员管发展党员与专班统筹，宣传委员管宣传档案，纪检委员管考勤考察——三委员各管一摊专业事务，纵向穿透所有党小组。

另一条是党小组组长的小组线：按就业/学术方向划分小组，组织党小组活动——每个小组横向覆盖自己的成员。

两条线在书记处交汇，需要协调的事务在书记处汇总。遇到具体事务找谁，看的是该事务的职责归属：发展党员找组织委员，宣传报道找宣传委员，考勤考察找纪检委员，本组学习与活动找党小组组长。

"条"与"块"是理解这套权责关系的两把尺子——从职能视角看是"条"，从单元视角看是"块"；谁做什么，由职责定义决定。

4.5 普通成员：参与与监督

不参与管理不等于没有位置：你有知情权（活动动态/专班进展/考勤概况）与监督权。

支部工作对每个成员公开，参与感建立在了解之上。

按通知参与，用知情与监督行使你的位置。

管理事，服务人——服务人的核心，是理解真实的组织与管理：有流程的经验、有科学的协作。理解真实、善用经验、创新沉淀、框架内对话，是理解这个组织的四个入口。

五技术架构

5.1 前中后台分层

层位置职责
前台（UI）docs/*.html（8 根页面 + 6 角色工作台 = 14 页）页面骨架，零硬编码逻辑

后台（服务层）docs/src/services/（20 个 service JS）数据 CRUD、权限计算、持久化
母本层content/02_institution/sop/所有代码逻辑的制度来源

5.2 技术栈

  • 纯前端静态架构 — 无需后端部署，GitHub Pages 直接托管
  • ES Modules — 无构建工具、零打包依赖
  • Tailwind CSS CDN — 原子化样式引擎
  • sessionStorage / localStorage — 跨页面状态持久化
  • Custom Events — 组件间解耦通信
  • 多页面应用（MPA）— 14 个独立 HTML 页面
