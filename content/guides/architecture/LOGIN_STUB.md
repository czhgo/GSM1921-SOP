# 登录态打桩文档

> 本文档为角色站位系统的登录态设计预留，当前无登录系统，所有交互按"党支书站位"运行。
> 当接入登录系统后，按本文档的权限矩阵实施约束。

## 一、核心概念

| 概念 | 位置 | 含义 |
|------|------|------|
| **站位（stance）** | 右上角选择器 | "我是谁"——当前登录者的身份定位 |
| **身份视图（view）** | 侧边栏选择器 | "我看谁"——以哪个角色的视角查看工作台 |
| **模式（mode）** | 自动推导 | 站位与视图的关系决定——管理/管理者只读/成员只读 |

## 二、模式推导规则

```
stance === view           → 管理模式（manage）
stance 是 view 的赋权上游 → 管理者只读（manager-observe）
其他情况                  → 成员只读（participant-observe）
```

## 三、登录角色站位权限矩阵

### 3.1 党支书登录

| 维度 | 权限 |
|------|------|
| 可选站位 | 党支书（固定） |
| 可看视图 | 所有角色 |
| 模式 | 站位=视图→管理；站位≠视图→管理者只读 |
| 典型场景 | 以党支书站位查看组织委员视图（管理者只读），查看组长视图（管理者只读） |

### 3.2 组织委员登录

| 维度 | 权限 |
|------|------|
| 可选站位 | 组织委员（固定） |
| 可看视图 | 自身 + 宣传委员 + 纪检委员 + 组织者 + 深度参与者 |
| 模式 | 站位=视图→管理；看下游→管理者只读 |
| 典型场景 | 以组织委员站位查看组织者视图（管理者只读，专班域赋权） |

### 3.3 宣传委员登录

| 维度 | 权限 |
|------|------|
| 可选站位 | 宣传委员（固定） |
| 可看视图 | 自身 + 组织委员 + 纪检委员 |
| 模式 | 站位=视图→管理；看同级→管理者只读 |
| 典型场景 | 以宣传委员站位查看组织委员视图（管理者只读） |

### 3.4 纪检委员登录

| 维度 | 权限 |
|------|------|
| 可选站位 | 纪检委员（固定） |
| 可看视图 | 自身 + 组织委员 + 宣传委员 |
| 模式 | 站位=视图→管理；看同级→管理者只读 |
| 典型场景 | 以纪检委员站位查看宣传委员视图（管理者只读） |

### 3.5 党小组组长登录

| 维度 | 权限 |
|------|------|
| 可选站位 | 党小组组长（固定） |
| 可看视图 | 自身 + 组织者 + 深度参与者 |
| 模式 | 站位=视图→管理；看下游→管理者只读 |
| 典型场景 | 以组长站位查看组织者视图（管理者只读，活动域赋权） |

### 3.6 组织者登录

| 维度 | 权限 |
|------|------|
| 可选站位 | 组织者（固定） |
| 可看视图 | 仅自身 |
| 模式 | 管理 |
| 典型场景 | 只能看自己的工作台 |

### 3.7 深度参与者登录

| 维度 | 权限 |
|------|------|
| 可选站位 | 深度参与者（固定） |
| 可看视图 | 仅自身 |
| 模式 | 成员只读 |
| 典型场景 | 只能看自己的任务状态 |

### 3.8 普通参与者（未赋权）

| 维度 | 权限 |
|------|------|
| 可选站位 | 无（成员只读面板） |
| 可看视图 | 成员只读面板（ws-visitor.html） |
| 模式 | 成员只读 |
| 典型场景 | 查看活动动态、专班进展、个人考勤 |

## 四、当前实现状态（无登录态）

| 维度 | 当前行为 | 目标行为 |
|------|---------|---------|
| 默认站位 | 党支书（LOGIN_STANCE='secretary'） | 由登录接口返回 |
| 站位选择 | 所有角色可选（模拟党支书全权限） | 仅可选登录角色对应的站位 |
| 视图选择 | 所有角色可看 | 受站位约束 |
| 模式切换 | 自动推导（T60重构后） | 同左 |

## 五、系统检查思路

### 5.1 登录态接入检查清单

接入登录系统时，需逐一验证以下场景：

- [ ] 党支书登录 → 可选所有站位 → 可看所有视图
- [ ] 组织委员登录 → 站位固定 → 可看自身+下游
- [ ] 宣传委员登录 → 站位固定 → 可看自身+同级
- [ ] 纪检委员登录 → 站位固定 → 可看自身+同级
- [ ] 党小组组长登录 → 站位固定 → 可看自身+下游
- [ ] 组织者登录 → 站位固定 → 仅看自身
- [ ] 深度参与者登录 → 站位固定 → 仅看自身
- [ ] 未赋权参与者 → 直接进入成员只读面板

### 5.2 关键条件判定

```javascript
// auth.js 中的打桩代码
const LOGIN_STANCE = 'secretary'; // ← 接入登录后替换为动态值

function getStanceOptions() {
  if (LOGIN_STANCE === 'secretary') {
    return ALL_ROLES; // 党支书可站任何位
  }
  return [LOGIN_STANCE]; // 其他角色只能站自己的位
}
```

### 5.3 边界情况

1. **双域赋权冲突**：组织委员和党小组组长都可赋权组织者/深度参与者，但赋权域不同（专班域 vs 活动域）。当前扁平数据结构无法区分域，需在登录态接入时解决。
2. **跨模块视图**：支委在党建工作台和党务管理中的视图选项不同（MODULE_ROLES 约束）。
3. **模式回退**：切换站位后，如果当前视图不在新站位的可看范围内，需自动回退到站位本身。

## 六、与现有架构的对接

| 现有概念 | 新概念 | 映射关系 |
|---------|--------|---------|
| primaryRole | stance（站位） | 语义升级，逻辑不变 |
| activeRole | view（身份视图） | 语义升级，逻辑不变 |
| ViewModeStore.getMode() | deriveMode(stance, view) | 从手动切换改为自动推导 |
| header:role-switch | permission:stance-change | 事件重命名（经 PermissionManager 统一） |
| sidebar:role-select | permission:role-select | 事件重命名（经 PermissionManager 统一） |
