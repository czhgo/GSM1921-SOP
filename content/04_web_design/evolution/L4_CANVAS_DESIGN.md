# L4 支部工作地图设计稿 v2.0

> **定位**：支部工作的分类视图与分工载体。v1.x 曾发散编造"纪律作风/宣传教育"等大类，书记纠正：
> ① 不再细化——三会一课粒度已足够，"纪律作风/宣传教育"都是具体活动/专班的内容，不是顶层类别；
> ② **分工架构是支部自行建设**，党委不越俎代庖；分工调整最好是**支委会议题**；
> ③ **在既有工作形式、内容分类基础上推进，禁止编造**。
> v2.0 全部依据既有权威源：`content/02_institution/sop/INDEX.md` 术语段（党建/党务定义）+ 12 个既有 SOP 场景 + `ACTIVITY_CLASSIFICATION` + 工作台既有分组。**不新增任何自造类别**。

## 〇、v2.0 吸收的书记纠正

|---|---|

## 一、既有权威分类源（不编造的依据）

**1. INDEX.md 术语段（T1 官方定义，书记此前定稿）**
- **党建工作** = 党为保持先进性纯洁性开展的自我建设；组织活动（**三会一课、主题党日、专班**）归此。
- **党务工作** = 党内事务管理；**发展党员、民主评议党员、换届选举、考勤考察**归此（另含党员教育管理、党费收缴管理）。

**2. 既有 12 个 SOP 场景（sopData.js，前缀即分类）**
- `【党建工作】`：组织生活会(org-life)、党小组主题党日活动(theme-party)、支部党员大会(branch-party-meeting)、党小组会(party-group-meeting)、党课(party-lecture)、支委会(branch-committee)、团支部合办活动(joint-event)
- `【党务工作】`：制度制定与迭代(new-system)、考察积极分子(develop-activist)、信息平台支持(info-platform)、查考勤记录(attendance-check)、处理意见建议反馈(feedback-handling)

**3. 活动类型权威**：`ACTIVITY_CLASSIFICATION`（三会一课=大会/支委会/党小组会/党课，组织生活会并入；主题党日=理论/实践/座谈/其他 载体）

## 二、工作地图目录 v2（模块全部映射既有资产）

### 党建工作（组织活动——系统 `活动` 域承载，含议程/票决/考勤/考察/宣传产出）

| 工作模块 | 既有资产（不编造） | 细分粒度说明 |
|---|---|---|
| 三会一课 | ACTIVITY_CLASSIFICATION['three-meetings'].subtypes + 场景 1c/1d/1e | **已细化**（书记认可）：支部党员大会 / 支委会 / 党小组会 / 党课 |
| 主题党日 | ACTIVITY_CLASSIFICATION['theme-party'] + 场景 theme-party（党小组主题党日活动） | 载体 4 类（理论/实践/座谈/其他） |
| 组织生活会 | 场景 org-life（党建工作·组织生活会） | 含民主评议相关（与"党务-民主评议党员"衔接见缺口注） |
| 专班 | taskforce 域（短期/长期专班，SOP 场景专班工作） | 项目式小组；含组织者/深度参与者组织模式 |
| 共建活动 | 场景 joint-event（团支部合办等） | 党团协同活动 |

### 党务工作（党内事务——既有 `发展`/`考察`/`考勤`/`评议` 等域）

| 工作模块 | 既有资产 | 细分粒度说明 |
|---|---|---|
| 发展党员 | development-tab 管线（积极分子→预备→转正）+ 场景 develop-activist | 环节链：申请→确定→考察→发展对象→接收→转正（细化沿用 v1.2 已认可的环节，**培养联系人到人**为缺口） |
| 民主评议党员 | 组织生活会年度（评议明细为缺口，见 v1.2） | 每年一次 |
| 换届选举 | appointment 任命机制 + 支委会票决（部分能力） | 支委班子换届 |
| 考勤考察 | attendance/inspection 记录域 + 场景 attendance-check + OUTPUT_BLOCK_DEFS | 附着于活动/专班的纪律产出（纪检委员执行），**不是独立大类而是产出环节** |
| 党员教育管理 | 台账/档案域（薄弱） | 党员台账等 |
| 党费收缴 | 未建 | 制度列举项，支部酌情 |

> 关键认知（书记纠正后的正解）：**考勤/考察/宣传等不是"工作大类"，而是活动/专班运行中的产出环节**（系统 OUTPUT_BLOCK_DEFS 与 SOP 任务 executor 已体现：活动→考勤由纪检确认、宣传产出由宣传指导/归档）。地图上它们作为模块卡内"产出交接"标签，不升格为类。

## 三、分工：支部自行建设 + 支委会议题生效（核心修正）

**权威原则**：分工架构由支部自己定，不是党委部署产物；分工调整是支部治理决策，最好以支委会议题形式做出。

- **入口（支部侧）**：书记工作台新增「支部分工」视图（支部 config 数据），书记/支委在支部内调整；**党委台不提供分工编排**（党委只见支部实例/上报审批/监控，分工是支部内政）。
- **生效路径（支委会议题）**：分工变更在支委会"议题"里提出（复用既有 agenda：一种议题类型=班子分工/模块归属）→ 支委会表决通过 → 写入 `config.workforce`（模块→负责人 role/person）。**不经支委会的分工变更不留痕——决策即记录。**
- **数据**：`config.workforce = { moduleAssignments: { [moduleId]: { ownerType: 'role'|'person', ownerId } } }`；缺省 = 依据各 SOP 文档"责任人"列（INDEX Navigation 中已标：组织委员管发展/纪检管考勤考察/宣传管宣传/组长管党小组）。
- **落点**：指派生效后，该模块的待办/入口按负责人出现（复用既有 role 工作台 + 待办派生，不新建权限体系）。

## 四、UI 形态方向

```
书记台 → 支部分工（支部自建）
┌ 党建工作 ───────────────────────────────
│ [支部党员大会] [支委会] [党小组会] [党课]      ← 三会一课（粒度已认可）
│ [主题党日] [组织生活会] [专班] [共建活动]
│   ↳ 卡内：负责人（点改，提议变更→发起支委会议题）
┌ 党务工作 ───────────────────────────────
│ [发展党员 环节链] [民主评议党员] [换届选举] [考勤考察]
```

- 顶层两类 = **党建 / 党务**（INDEX 术语原词，工作台分组同源）。
- 模块卡 = manifest 工作包（L3 已建主题党日块/专班块；三会一课子会后续按同法补 manifest，粒度即书记认可的卡粒度）。
- 无泳道无连线；模块间协调 = 卡内"产出交接"小标签（考勤→纪检 / 宣传→宣传委）。
- 书记台可看可提议；党委台对应模块只读概览（支部运行台账已有）。
