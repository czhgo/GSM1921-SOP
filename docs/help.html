1快速上手

这一章讲登录后的通用规则：登录落在哪、工作台长什么样、哪些事你能看能改。逐台 tab 详表在第 2 章，按你的身份翻对应小节即可。

1.1登录与角色落点

登录后系统按角色直达工作台（映射见 0.2），且工作台打开即「今天」页——它是登录落点：当天到期的待办、临近的会议与分工一眼可见。 党委工作台的登录落点是「治理总览」（全院支部概览）。公共根页面未登录即可浏览，需要动手的操作一律先登录（0.3）。

1.2工作台通用骨架

七个工作台都是「一个页面、顶栏 tab 切功能」。tab 条按组分段（各组名因台而异），各台都有以下通用件：

  • 「今天」置首（登录落点）：当天到期 / 逾期与近期会议、分工的速览。行内「到期 / 逾期」点击直接去待办处理；「会议 / 分工」点击进对应活动详情；「全部」跳到本台承载活动的 tab。
  • 「待办」＝ 页顶「未读通知 N 条」轻量条 + 9 业务域折组：页顶点开逐条阅读、读后即消；下方待办按工作类型分 9 域折组——会务 / 活动与项目 / 考勤纪律 / 考察 / 成员发展 / 专班 / 决议上报 / 归档宣传 / 汇报反馈。每条待办卡片写明「做什么」并带「去处理」跳转——点按钮直达负责该事的 tab 或详情页（这就是“处理在哪做”的提示），做完自动消。书记 / 纪检等不落库的实时提醒也会并入对应域。
  • 「工作概况」三区总览：汇报 / 卡点 / 在办三区，条线数据按职责注入；书记台为「全局概况」，另含「按人视图」（各角色在办清单，谁在干什么、有无异常）与维度态势。
  • 「党建」组各域 tab：该角色的职责操作都在这组里（写活动、考勤、考察、归档……具体见第 2 章逐台表）。
  • 「我的处置」：你经手的反馈 / 上报及处理记录（书记台为「反馈管理」，成员台与党委台无此 tab）。

处理在哪做：写操作都落在对应业务的 tab 或详情页里（例如写活动在「活动管理 / 活动写入」，交思想汇报在成员台「思想汇报」）；待办只做“提醒 + 跳转”，不做操作。

1.3权限知情边界

系统权限不是“给你一个账号就什么都能做”，而是赋权关系链：谁给你赋的权，你就在谁的赋权范围里干活。能否操作由 canDo() 统一判定——常设角色（书记 / 副书记 / 组织委员 / 宣传委员 / 纪检委员 / 党小组组长）与 项目角色（组织者 / 深度参与者）的权限取并集，按“能做什么”逐项判定。党委组织员是组织级角色，走党委工作台的全院治理权限，不属于支部内部权限链。

知情边界界定“能看什么”（看 ≠ 做：看得见不等于能代劳；信息精确等于职责所需的最小充分范围）：

视角谁能看到什么
个人视角每名成员自己的考勤 / 考察 / 参与记录、在办与汇报
块块视角党小组组长本党小组组员的「组员进展」：进度 / 考勤 / 考察（点开看，不能替做）
条线视角有赋权链的角色（组织委员看专班组织者 / 深度参与者；纪检委员看全员考勤考察）被赋权者的条线在办——谁给你赋的权，你在谁的范围内被看见
全局视角书记 / 副书记全局概况“按人视图”（各角色在办、可点击直达）与维度态势；支部分工视图
组织级视角党委组织员全院支部监控台账 / 上报审批 / 支部配置——跨支部、组织级，不参与任一支部内部闭环

关键约束：

  • 创建活动仅限书记（副书记共台）与党小组组长；组长独立创建须报书记知情同意；组织委员协调的是专班（招募统筹），不是活动
  • 复盘提交入口归组织者 / 深度参与者（成员台「我的复盘」）；组长台「复盘状态」只读查看本组复盘情况
  • 宣传委员不可自行招募宣传专班，赋权操作统一归口组织委员
  • 看 ≠ 做：能看他人条线在办（按人视图 / 组员进展），不等于能代劳其操作

3.1会务（三会一课）

支部党员大会、支委会、党小组会、党课（三会一课）四类会议性活动的创建、会议议程与记录、线上异步表决、党小组会考勤上传归本域；会后的考勤确认 / 补课与材料归档分别走 ③ 考勤纪律与宣传档案线。活动日历与详情是主场地：书记台「活动管理」、组长台「活动管理」建会，成员从首页日历 / 成员台「活动动态」进入 activity.html 详情页参会与表态。

创建会议活动（支部党员大会 / 支委会 / 党课 / 党小组会）

入口：书记 / 副书记工作台 →「党建」段「活动管理」→ 活动日历卡右上「写入活动」；党小组组长工作台 →「党建」段「活动管理」（「写活动」决策树）。

谁来用：书记 / 副书记（天然写入权，建四类会议均可）；党小组组长建本组党小组会（组内场景；组长独立创建本组活动的知情约束见 1.3）。组织、宣传、纪检委员无活动写入权。

几步（书记台，两步式）：

  1. 「写入活动」→ ①选模板：点「三会一课」模板卡 → 点子类：支部党员大会 / 支委会 / 党小组会 / 党课（主题党日卡属 3.2）。
  2. ②填表单：名称、日期（T-0）、时间、地点必填；选填主持人、描述、参与人（按阶段批量选人）、预拟通知（填标题即自动发布）。三会一课另有「会议议程」行（见下条）与高级选项（发起方向：自上而下 / 自下而上；时长：短期 / 长期）。
  3. 「创建活动」→ 提示已生成 N 项后续待办，活动上日历。

自动写入即按场景实例化 SOP 任务节点（支部党员大会 / 党小组会：T-7 时间统筹·确定主题·会前谈心 → T-3 通知到人 → T0 现场发布考勤二维码 · 签到考勤 · 自评互评 · 组长总结 → T+3 后台考勤汇总与参与三层记录 → T+5 会议记录 / 档案归档 → T+7 补课安排跟进；支委会：T-3 确定议题与通知 → T0 签到考勤 · 会议记录 → T+5 档案归档 → T+7 补课跟进；党课：T-3 发布党课通知与学习材料、T+1 提醒缺席党员补课）。未选参与人时自动给组长派生「为活动赋权组织者 / 深度参与者」待办；填了预拟通知 → 自动发布通知并派生成员待办（点击直达本活动）；创建后自动广播组织者「请前往微信群建核心群」（现场协调在群、资料归档交接在系统）。

注意主题党日模板受「主题党日组织块」开关控制：支部配置停用则模板卡隐藏（党委台「支部配置 · 工作流块」可恢复）；写入失败（网络 / 权限）时表单保留、可重试；「组织生活会」属三会大类内容维度，以三会形式召开，按既有活动管理。

会议议程与记录（讨论文件 / 待讨论名单 / 决议落实）

入口：议程编排 = 创建活动表单「会议议程」区（三会一课场景）；会后记录 = 工作台内打开该活动详情页，逐条议程点「记录通过 / 记录未通过」。

谁来用：议程编排：书记 / 党小组组长；记录决议结果：书记（副书记共台）；其它委员只读知情、不代记。

几步：

  1. 创建表单「会议议程」区：填「议题 + 主持人」，可「＋ 添加议程」多条；一条议题可同时打两种类型签（不互斥）——「讨论文件」：关联会前草案（支部文件下拉；无草案时引导去资料查询页写入）；「待讨论名单」：选名单统一阶段转换（从阶段 → 到阶段 + 多选人员，如讨论 N 名发展对象转预备）。
  2. 会后在活动详情页对该条议程「记录通过 / 记录未通过」。

自动「讨论文件」记录「通过」→ 该会前草案自动转为「已归档」并记录讨论来源（资料查询页展示「经《会议》讨论通过」），宣传档案线无需二次上传；「待讨论名单」记录「通过」→ 名单内每人自动生成一条成员变更申请，走「组织委员审批 → 书记确认 → 更新发展阶段」留痕链（发展链路，见 3.5 与 4.5 发展党员链路）；支部党员大会线上表决场景下记录「通过」前先做出席 / 赞成过半数硬校验（见下条）。

注意记录「未通过」不触发上述任何派生；应到会有表决权党员出席未过半数、或赞成未过半数时系统拦截「记录通过」并给出可采取动作提示（督促未表态党员表态 / 继续沟通争取赞成票），不能强行记为通过。

线上异步表决（决策类：支委会 / 支部党员大会）

入口：书记创建活动表单「会议形式」选「线上异步表决」（仅支委会 / 支部党员大会两类决策场景出现此选项）；表态区在活动详情页「议程与表决 · 线上异步表决」区（activity.html）。

谁来用：书记创建并配置参与范围；被固化名单（应到快照）内的支委 / 有表决权党员在详情页表态；书记汇总截止后记录决议。

几步：

  1. 书记创建支委会 / 支部党员大会，会议形式选「线上异步表决」：支委会参与范围固定「支委」，表态选项为交流式（同意 / 异议 / 附言，异议须附言）；支部党员大会可切参与范围「正式党员」或「正式党员 + 预备党员」，选项为正式表决（赞成 / 反对 / 弃权 + 附言选填）。人数按现时「在校 / 滞留」口径自动剔除滞留成员，创建时固化为应到名单快照。
  2. 被圈定人员打开活动详情页 → 逐条议程表态区选一项并（按需）附言提交；同人可改票（幂等覆盖），非应到名单登录人可见「仅应到表决人可表态」提示。
  3. 书记在详情页汇总表态进度，截止后对各议程项「记录通过 / 记录未通过」（接上条议程记录）。

自动每有人表态、表态人数有新增时自动通知书记「线上表态更新（N/M）」；表决截止自动提醒书记「请记录决议」（点击直达该活动）；支部党员大会正式表决「记录通过」前自动校验——出席（含弃权）须过应到半数、赞成须过应到半数，弃权计出席不计赞成；支委会从严口径：任一「异议 / 反对」即否决。

退回 / 注意表态人数或赞成票不足时「记录通过」被拦截并提示差多少票；线下开会（默认）不写表决配置、不开放线上表态。

党小组会考勤上传（组长 → 纪检复核）

入口：党小组组长工作台 →「党建」段「考勤上传」。

谁来用：党小组组长（党小组会记录人 = 本组组长）；会议类（党课 / 支部党员大会 / 组织生活会 / 支委会）由纪检直接录入（见 3.3），不在此列；组长非组织者的其它活动为监督位（督促上传）。

几步：

  1. 「上传考勤表单」→ 选活动：仅列本组长可上传且未归档的活动（本组党小组会 / 本人为组织者的活动）。
  2. 选参会人员：党小组会候选取本组应到名单（组内党员，滞留者标灰禁选，悬浮可见滞留备注），可一次全选。
  3. 逐人出勤状态（出勤 / 缺勤 / 请假）；人多了先「批量设置：全部出勤 / 全部缺勤 / 全部请假 → 应用到全部」，再按需微调个别人 → 「提交考勤」。

自动出勤 / 已补 = 源头审校自动确认（不进纪检队列）；异常（缺勤 / 请假）自动生成补课任务（防重复：同人同活动已有任务即跳过）并进入纪检「待确认考勤」队列；本页下方同步展示本组待补课人员名单。

退回 / 注意同人同活动已有已确认记录 → 重复上传跳过（不可覆盖）；待纪检复核的异常记录改状态须走纪检确认界面，上传侧直改被拦截；纪检台对党小组会考勤只读掌握（不代传、不审改）。

3.2活动 / 项目（主题党日）

主题党日是支部实践性活动的统一承载：创建（场景维度选型）→ 报名参与 → 实施考勤（见 3.3）→ 复盘提交与复核闭环在此域。专班（跨小组集中攻坚形态：发起表决 / 招募统筹 / 定人定责定岗 / 贡献核验）属「活动与专班」的专班线，详见 3.6。

主题党日创建（场景维度选型）

入口：书记 / 副书记台「活动管理」→「写入活动」；党小组组长台「活动管理」写活动决策树（L1 组织场景选主题党日）。

谁来用：书记 / 副书记（天然）；党小组组长（本组主题党日发起，组织者默认组长本人）。

几步：

  1. Step 1 选模板：点「主题党日」模板卡（金卡；无固定子类、整卡可点，须点击进入）。
  2. Step 2 填表单：名称 / 日期 / 地点必填；「共建性质：独立开展 / 共建开展」「是否外出：校内 / 校外」「活动载体：理论学习 / 实践参访 / 交流座谈 / 其他（可多选）」三个正交维度按需选型；选填参与人（按阶段批量）、预拟通知、品牌（非品牌 / 延续已有品牌 / 创建新品牌）、高级选项（发起方向 / 时长）。
  3. 「创建活动」→ 提示已生成后续待办，活动上首页日历与成员台「活动动态」。

自动按主题党日场景实例化 SOP 节点：T-7 活动发起 · 支委扩大会讨论（通过后方可推进）· 联系条条委员 → T-2 发布活动通知 · 纪检对接考勤要求与复盘底线 → T0 活动实施（签到 / 现场拍照 / 关键发言记录 / 材料收齐）· 考勤确认 → T+1 复盘提醒 → T+3 宣传产出（摘要 + 配图）· 考察确认 → T+7 复盘提交 · 复盘监督 · 材料归档。创建即赋权组织者 / 深度参与者（未选人则自动派生组长赋权待办）。

注意支部停用「主题党日组织块」时模板卡隐藏（党委台「支部配置 · 工作流块」可恢复）；外出（校外）活动须按任务节点提前 2 天建群并确保人员到位。

报名参与

入口：活动详情页 activity.html 的「报名参与」区（从首页日历 / 活动卡、成员台「活动动态」点活动卡进入）。

谁来用：支部成员报名；「普通参与」报名即通过，「申请深度参与 / 组织者」须经活动发起人（组织者 / 创建人）审核。

几步：

  1. 登录后在详情页报名区选角色：「报名参加（普通参与）/ 申请深度参与 / 申请组织者」，可填附加说明（如可承担的角色）→「报名」。
  2. 普通参与立即「已报名 · 普通参与」并加入报名名单；申请类显示「待审核」，发起人收到审核待办。
  3. 发起人在详情页报名名单「待审核申请」区对每条点「通过 / 拒绝」；被拒者见「已拒绝」可改选「重新申请」。

自动普通参与报名即写入活动分工名单；申请通过后写入分工并自动派生参与待办（活动前提醒，含活动日期与「请按时参与并配合考勤」）；报名仅对未开始的活动开放（已发布 / 进行中且日期未过）。

退回 / 注意草稿 / 已取消 / 已结束（日期已过）活动不可报名；重复报名被拦截；「取消报名 / 撤回申请」后对应参与 / 审核待办自动销项，已通过报名取消会同步移出活动名单。

复盘提交（组织者 / 深度参与者 → 纪检复核）

入口：成员工作台 →「党建」段「我的复盘」（复盘统一提交入口 = 活动组织者 / 深度参与者）；纪检在纪检台「活动监督复盘」复核；组长台「复盘状态」只读查看本组情况。

谁来用：担任活动组织者 / 深度参与者（含组长兼组织者）的成员提交；纪检批注 / 打回 / 确认；普通成员无提交权（只读参与活动的复盘）。

几步：

  1. 成员台「我的复盘」→ 待复盘区（未提交 / 已打回）列出本人任组织者 / 深度参与者的活动 → 点开活动卡。
  2. 填「复盘总结」+ 「提出的真问题」（每行一条，书记以此计量）→ 提交。
  3. 纪检台「活动监督复盘」对「已上传」复盘行：批注（转「批注中」）/ 打回 / 确认（可开「批量确认」多选一次确认）——确认后复盘闭环、活动结束。

自动提交后状态 =「已上传」并自动进入纪检监督列表；组长台「复盘状态」同步可见；复盘确认后若未沉淀经验，纪检台出现「经验沉淀督促」清单（已确认未沉淀 → 督促深度参与者提交沉淀）。

退回 / 注意被纪检打回（附批注）→ 复盘回待提交、按批注修改后重新提交（原批注展示在表单上方）；主题党日复盘底线 T+7，超期由纪检提醒督促；批量确认只作用于「已上传」行，其余状态置灰不可勾。

3.3考勤纪律

三会一课（刚性考勤）与主题党日（弹性考勤）的纪检录入 / 确认、未到标因、滞留到场补录、补课任务与完成回写、考勤备案交接宣传全部落在纪检台「考勤管理」与「补课制度」两个 tab；组长上传位在 3.1 已讲，此处接纪检侧闭环。应到口径（书记裁定）：应到 = 在册党员（正式 + 预备）− 滞留剔除；滞留者组织关系保留、应到剔除、通知照发。

纪检会议考勤录入（会议类：党课 / 支部党员大会 / 组织生活会 / 支委会）

入口：纪检工作台 →「党建」段「考勤管理」→ 卡「会议考勤录入」→「录入会议考勤」。

谁来用：纪检委员（会议考勤记录人 = 纪检，录入即确认）；书记 / 副书记可例外承担；党小组会不在此列（组长上传见 3.1）。

几步：

  1. 选会议活动（下拉仅列纪检上传位、未归档的会议类活动）。
  2. 参会人员：候选 = 应到名单口径（在册党员 正式 + 预备 且非滞留；党课列席不计应到）；滞留者灰态可见但禁选；点「全选应到名单」一次勾选后再逐人删减。
  3. 逐人出勤状态（出勤 / 缺勤 / 请假）；缺勤、请假行须选「标因」：请假 / 无故 / 其它（纪检认定 · 固定枚举，禁造新枚举），默认按状态预填（缺勤→无故、请假→请假）可改。
  4. 滞留党员线下到场：在「滞留党员到场补录」区单独勾选（不随全选）→ 计「到席」并落「滞留 · 到场」标记。
  5. 「提交录入」→ 回执显示新增 / 更正 / 跳过计数。

自动纪检直接录入即确认（recordedBy = 纪检）；应到清点实时显示「预应到 K → 滞留到场补录 L → 实际应到 K+L」（补录者档案按在场展示）；异常（缺勤 / 请假）自动生成补课任务（7 日内）；已录条目再次提交 = 纪检更正（仅覆盖本人所录，他人权威所录跳过）。

注意无可写入（所选均为他人权威已录 / 无上传权限活动）时表单保留供改选重提；未到行标因随状态显隐联动（改回出勤即隐藏并清除旧标因）。

考勤确认（待确认队列 / 总表确认）→ 自动补课

入口：纪检台「考勤管理」顶部「待确认考勤」队列与「考勤总表」各行「确认」按钮。

谁来用：纪检委员（确认 = 复核闭环）；组长上传的党小组会异常（缺勤 / 请假）也在本队列由纪检确认。

几步：

  1. 进「考勤管理」即见待确认队列（默认展示 8 条，可「展开全部」）：仅异常（缺勤 / 请假，含超期）入队；出勤 / 已补 = 上传方源头审校自动确认，不占队列。
  2. 逐条「确认」（或到下方考勤总表搜索姓名 / 活动、按状态筛选后逐行确认）→ 该条闭环并自动聚焦下一条。

自动确认后自动生成补课任务（缺勤 / 请假且属三会一课或主题党日者；截止 = 活动日期 + 7 日；必修：自学 + 心得 / 选修：自学；防重复）；自动通知组织委员「考勤已确认并归档至考察档案」；同步销书记侧「考勤待确认」类待办。

注意活动日期已过仍未确认的异常自动标「超期」（红标）置于队列优先处理；党小组会考勤在纪检台只读掌握（下方只读块：组别 / 组长 / 上传人 / 到席 · 异常），改删走本队列 / 录入更正，不代传。

考勤矩阵与总表（查看 / 筛选 / 导出）

入口：纪检台「考勤管理」→「考勤矩阵」卡与「考勤总表」卡。

谁来用：纪检委员（管理主位）；组织侧与书记侧同源共享同一份数据（书记台「考勤概况」只读监督）。

几步：

  1. 矩阵：「按活动 / 按人」互为转置（色点 + 出 / 缺 / 假 / 补缩写），活动名搜索 + 时间区间筛选，快速看清全支部出勤。
  2. 总表：姓名 / 活动搜索 + 状态下拉（出勤 / 缺勤 / 请假 / 已补），每页 20 条；确认人列显示「自动确认 / 待确认 / 纪检姓名」。
  3. 低频操作行：「导出 CSV / 打印」（导出按当前筛选，含月份列与确认口径）。

自动已确认记录写确认人并留痕；出勤 / 已补无确认人记为「自动确认」；缺勤 / 请假未确认记为「待确认」——口径全站统一（出勤率含「已补」）。

注意活动归档后其考勤随活动退出工作区（历史数据仍在档案可查）；总表确认与队列确认同路径，操作后自动刷新。

补课任务与完成回写

入口：纪检台 →「党建」段「补课制度」；成员线下完成补课后由纪检确认；组长台「考勤上传」页下方可见本组待补课名单。

谁来用：纪检委员（确认完成、督办超期）；缺勤成员（线下自学 / 自学 + 心得后反馈）；组长督促本组。

几步：

  1. 纪检台「补课制度」查看补课任务表：姓名 / 缺席活动 / 补课方式（必修：自学 + 心得 / 选修：自学）/ 截止日期 / 状态（待补课 · 已超期 · 已完成）。
  2. 成员完成并反馈后，纪检对相应任务点「确认完成」。

自动「确认完成」→ 对应考勤自动回写「已补」（打卡化判定：完成必须对应真实产物），逾期标记清除、缺勤闭环（出勤率口径含已补）；超期任务自动汇总为「超期提醒」红块并单独列条；顶部收件箱接收组织委员发来的「补课需求回执」（组织标记材料缺失 → 纪检收到确认即闭环并自动销待办）。

退回 / 注意超期任务红色行提醒、须尽快督促；缺勤闭环前相关待办不自动消失；补课须在 7 日内（特殊情况可延至 T+14 并备注，见场景任务说明）。

考勤备案交接宣传

入口：纪检台「考勤管理」→ 总表工具条「提交考勤至宣传」；宣传委员在宣传台「待办」页顶部「数据交接 · 考勤备案」收件箱确认。

谁来用：纪检委员（发起）；宣传委员（接收备案确认）。

几步：

  1. 纪检确认考勤（仍有未确认会拦截）后点「提交考勤至宣传」。
  2. 宣传委员待办页顶部收件箱看到「考勤备案（考勤总表）」→ 确认接收。

自动提交即生成数据交接（纪检 → 宣传）并自动为宣传委员派生「数据交接：考勤备案」待办；宣传确认后自动销待办、状态落库、双向可追溯；纪检台总表显示「待宣传备案」标记。

注意已提交待备案时重复提交被拦截（提示勿重复提交）；存在未确认考勤时不允许提交。

3.4考察

考察材料是发展党员链条的素材：组长 / 组织按上传位提交 → 纪检确认（含超期提醒）→ 交接归集组织建档。活动类考察由组长（本组党小组会 / 本人组织活动）上传；专班类考察由专班负责人 / 组织委员上传；纪检不代传。

考察上传（组长 · 活动侧 / 组织 · 专班侧）

入口：组长台「党建」段「考察上传」；组织台「党建」段「考察上传」（专班侧）。

谁来用：党小组组长（活动侧上传位：本组党小组会 / 本人组织的活动）；组织委员 / 专班负责人（专班侧上传位）；纪检只确认不上传。

几步（组长 · 活动侧）：

  1. 「上传考察表单」→ 来源类型「活动」→ 选具体活动（仅列本人可上传、未归档的本组党小组会 / 本人组织活动）。
  2. 选人员 → 逐人填写考察内容描述 → 提交。

几步（组织 · 专班侧）：「上传考察表单」→ 选专班（招募中 / 运行中）→ 选人员 → 逐人考察内容 → 提交（提示「自动投递：纪检确认 → 考察总表（组织委员建档），无需选择接收方」）。

自动上传后记录状态 = 待确认（留痕上传人），自动进入纪检「考察管理」考察总表（活动视图 / 人视图均可查）；本页下方列表回显本人上传记录与确认状态（待确认 / 已确认）；专班考察行可点开查看详情（上传人 / 时间 / 参与层级 / 内容）。

注意仅限本人上传位（非本组党小组会 / 非本人组织活动提交被拦）；逐人考察内容为空不允许提交。

纪检确认与超期提醒

入口：纪检台 →「党建」段「考察管理」。

谁来用：纪检委员（考察总表确认 / 删除）；专班名单区只读同步组织委员管理的专班及考察确认进度。

几步：

  1. 考察总表（活动视图 / 人视图互切）按来源（活动 / 专班）、状态（待确认 / 已确认 / 超期）筛选或搜索姓名 / 内容。
  2. 对「待确认 / 超期」行「确认」（误传可「删除」，仅待确认可删）。

自动确认后状态 = 已确认并自动销「考察超期 / 待确认」类待办；超期判定：待确认记录超过 7 天 → 顶部「超期提醒」红块 + 表中标「超期」（默认 7 天，支部可调）；专班名单区实时显示各专班考察确认进度（确认 X / 总数）。

退回 / 注意已确认记录不可删（历史留痕，只能走档案维护）；删除仅限待确认（误传）记录。

考察交接归集组织（建档）

入口：纪检台「考察管理」→「提交考察至支委会」；组织委员在组织台「待办」页顶部收件箱接收建档。

谁来用：纪检委员（发起交接）；组织委员（接收并建档归集，人才库 / 考察档案可用）。

几步：

  1. 纪检确认（或抽查）考察后在总表工具条点「提交考察至支委会」（至少 1 条已确认才可提交）。
  2. 组织委员在待办页顶部收件箱确认接收。

自动提交即生成数据交接（纪检 → 组织）并自动为组织委员派生「数据交接：考察记录提交」待办；确认即建档归集（组织侧档案即时可用）、自动销待办、双向可追溯；纪检台按钮旁显示「待组织接收」标记；未确认条不阻塞已确认流转（可后续补提）。

注意已有待组织接收的交接时重复提交被拦截；暂无已确认考察时不可提交。

3.5成员发展

发展党员工作的三个动作面：发展管线推进（组织台「发展数据」）、思想汇报把关初阅（成员提交 ↔ 组织初阅）、成员名册与确权变更（阶段 / 在册滞留变更与移出均须书记确认）。支部党员大会「待讨论名单」记录通过后自动生成的成员变更申请链（组织审批 → 书记确认 → 阶段更新）也从这里看进度（详见 3.1 议程与记录）。

发展管线推进

入口：组织台 →「党建」段「发展数据」。

谁来用：组织委员（发展管线追踪与推进）。

几步：

  1. 看管线概览：积极分子 → 发展对象 → 预备党员 → 正式党员 四段人数与候选人卡片（每卡：姓名 / 党小组 / 进入当前阶段日期 / 考察 N 条 / 思想汇报已归档 N 篇）。
  2. 按阶段筛选；对候选人点「推进至下一阶段」→ 确认。

自动推进即更新阶段与「进入当前阶段」日期并写入发展档案，卡片与管线计数即时刷新；正式党员段显示「已转正」；考察条数、思想汇报归档数随各域写库自动归集到卡片（不再在此页展开全文，详细查看去组织台「思想汇报」/ 人才库）。大会 / 支委会「待讨论名单」记录通过自动生成的成员变更申请，在组织台「待办」页「成员变更审批」区逐条处理（通过 → 广播全体支委 → 书记确认 → 阶段更新）。

注意正式确权（阶段变更生效 + 应到口径联动）以「成员名册」行内变更经书记确认为准（见 3.5 成员名册）；本页推进面向发展管线日常追踪，两处同读一份人员档案。

思想汇报（提交 / 把关初阅 / 退回重交）

入口：成员台 →「党建」段「思想汇报」（提交 / 查看本人历史）；组织台 →「党建」段「思想汇报」（待初阅队列 + 按人浏览）。

谁来用：党员 / 发展对象提交（正文建议 1500 字以上，积极分子不作硬性要求）；组织委员把关式初阅（通过才正式归档，退回须附意见）。

几步：

  1. 成员：思想汇报 tab 文本框写正文 →「提交」（状态 = 待初阅）。
  2. 组织委员：待初阅队列（先到先阅，按提交时间升序）→「阅看」全文 →「通过 · 归档」或「退回 · 需补充」（退回必填意见）。
  3. 退回后：提交人列表该篇标「已退回 · 需补充」并展示退回意见 →「修改并重新提交」→ 回待初阅队列。

自动提交后自动通知组织委员（待初阅）；「通过」即正式归档并自动归集至个人档案（人才库 / 发展数据归档计数同步）；每次初阅留痕（谁于何时通过 / 退回 + 意见），组织侧「按人浏览」可按人查看全部汇报与留痕；重交后刷新提交时间并回待初阅队列，历史留痕保留。

退回 / 注意退回必填意见（否则拦截）；仅提交人本人可修改重交；已归档 / 非待初阅状态不可再初阅（重复处理拦截）；仅组织委员角色可初阅（其它角色打开仅提示无权限）。

成员名册（新增 / 行内调整 / 确权变更 / 移出）

入口：组织台 →「党建」段「成员名册」；确权确认 / 退回在书记台「待办」页处理。

谁来用：组织委员（名单管理主位：新增、行内调整、发起变更 / 移出）；书记 / 副书记（「成员变更待确认」组逐项确认生效或退回）；纪检 / 组长读同一名单（应到口径联动）。

几步：

  1. 新增：「＋ 新增成员」→ 姓名（必填）/ 党小组 / 发展阶段 / 在册状态（在校 · 滞留）/ 滞留备注 →「新增并加入名册」。
  2. 行内调整：改「党小组」或维护「滞留备注」→ 保存 = 即时生效；改「发展阶段」或切「在册状态（在校 ↔ 滞留）」→ 保存后行格出现「阶段变更 · 待确认 / 在册状态 · 待确认」小标（不即时落档）。
  3. 书记确权：书记台「待办」→「成员变更待确认」组逐项「确认生效 / 退回」（退回可填原因）；行内恢复可编辑并回现值。
  4. 移出：行尾「移出」→ 弹窗说明引用检查 → 确认移出（有历史则行显「移出待确认」，待书记确认）。

自动新增 / 即时字段保存 → 名册与应到口径即时生效（支部应到 = 在册党员 − 滞留剔除，页头实时显示支部与各组应到）；发展阶段、在册滞留变更经书记「确认生效」后落地并留痕（滞留含备注，纪检考勤 / 会议应到随之剔除、通知照发）；移出 = 引用清单化：无历史或仅安全引用（未开始活动分工 / 未生效报名 / 未读广播）→ 自动解除后直接移出；有历史（考勤 / 考察 / 思想汇报 / 复盘 / 表态 / 长期分工等）→ 书记确认后转「已转出」标注并移出（原记录保留、不删不匿名，专班负责人保留提示先移交）；学期末窗口（6/15–7/15、12/15–次年 1/15）书记台自动出现「学期末滞留集中复核」提醒（滞留名单一览，延续或解除由组织委员在名册发起）。

退回 / 注意书记退回的变更不生效（组织委员可重新发起）；同一人同字段已有待确认请求 → 重复发起拦截；移出待确认期间禁重复操作；现任书记（或任一支部书记）不可移出（须先完成书记交接）；移出后读链不匿名——姓名仍可解析并标「已转出」。

3.6专班（跨组攻坚 · 组织统筹）

专班是跨党小组集中推进的攻坚形态（3.2 已提示）：以组织委员为唯一统筹节点，走发起（报送支委会表决）→ 表决通过转招募中（分级报名审核）→ 启动运行中（定人定责定岗 → 成员填报产出 / 组织逐条核验 + 分阶段进度）→ 报送解散表决 → 解散 / 归档全生命周期；复盘由组织侧提交、纪检复核；书记 / 组长 / 纪检按知情权只读查看；成员在本专班内报名与填报产出。各台「待办」专班折组与通知承担提醒 + 跳转（点「去处理」直达组织台专班看板 / 专班详情页）。

发起专班（发布招募表单 → 自动报送支委会表决）

入口：组织委员工作台 tab 栏「发布招募」按钮（常驻，无需切 tab）→ 打开「发布专班招募」表单。

谁来用：组织委员（专班唯一统筹节点，见 1.3 写入范围表；书记 / 组长 / 各委员如需发起专班亦经此台代发起，统一起点便于招募统筹）。

几步：

  1. 点「发布招募」→ 填四项必填：专班名称、任务描述、所需人数（1–50）、截止日期。
  2. 选填：技能要求、周期起始 / 结束、说明；初始成员（多选——选了直接记入专班成员）；折叠区「自动发布通知」：通知标题 + 内容（填了标题才发布，只跑一次）。
  3. 「发布」→ 提示「发布成功，已报送支委会表决」，专班入组织台看板「待支委会表决」列。

自动创建即自动报送支委会表决（发起类型报送，不再派生书记单人审批待办）；预拟通知填标题 → 自动发布通知（默认正文为「已报送支委会表决，表决通过后将开放招募（截止 …），欢迎届时报名参与」）；选了初始成员 → 以「深度参与」同步授予项目角色（赋权审计快照 + 通知本人），不再派生赋权待办；未选 → 自动为组织委员派生「为专班赋权组织者 / 深度参与者」待办（后续选人即做事即销）。

退回 / 注意必填缺失 / 人数越界拦截；表决通过前专班保持「待支委会表决」只读等待（看板可撤销彻底删除，连带清理关联报名与待办）；表决未通过退回草稿后可「重新报送」或删除重建。

支委会表决专班议案（发起 / 解散；书记排入 → 生效落果）

入口：书记 / 副书记台「待办」页顶部「专班待议（支委会）」区——列出全部待表决报送（发起 / 解散，先报先议；行含类型徽标、专班名 / 任务、报送人与时间）。

谁来用：书记 / 副书记排入表决并按结果生效；应到支委（排入时固化名单）在线上支委会活动详情页表态（交流式：同意 / 异议 / 附言，异议须附言）；组织委员（报送方）只读等待结论。

几步：

  1. 书记对未排入的行点「排入支委会表决」→ 自动创建「线上支委会：审议专班『名』（发起 / 解散）」活动并通知各支委（通知直达详情页表态）。
  2. 表态完成后书记点「查看表决结果并生效」→ 弹窗汇总（出席 x / y · 同意 · 异议 / 反对 · 附言）→ 点「按表决结果生效」。

自动判据与线上支委会一致（R2-3：应到严格超过 2/3 出席且无反对，弃权允许）；发起通过 → 专班转「招募中」；发起未通过 → 退回草稿（可修改后重新报送）；解散通过 → 专班置「已解散」并落解散日期（历次表决 append-only 留痕：谁 / 何时 / 结论 / 来源活动）；解散未通过 → 专班继续运行。

退回 / 注意未达门槛（出席不足或有异议 / 反对）弹窗明示「表决未达门槛 / 尚未截止」并给判据说明，不能强行生效；已排入的行变「已排入表决」；同一报送重复排入被拦。

招募报名与分级审核（普通即通过 / 深度与组织者待审核）

入口：报名 = 专班详情页 taskforce.html「报名加入」（首页专班卡、成员台「项目分工」、待办「参与专班」均可直达）；审核 = 组织台「专班管理」→ 点「招募中」专班 → 详情「报名名单 · 待审核」区。

谁来用：支部成员报名（专班开放招募且未满员时）；审核人 = 专班发起人（组织委员）对「待审核」申请逐条处理。

几步：

  1. 详情页点「报名加入」→ 选角色：普通参与 / 申请深度参与 / 申请组织者（可填附加说明）→ 提交。
  2. 普通参与 → 立即「已通过」并进报名名单；申请类 → 「待审核」，审核人收到「审核报名」待办。
  3. 审核人在报名名单「待审核」行逐条点「通过 / 拒绝」（拒绝后报名人可见「已拒绝」）。

自动报名通过即写入专班成员（普通参与一并写入）并派生「参与专班」待办（截止 = 报名截止，直达详情页）；名额 / 截止实时展示（名额以专班成员实计 x/y）；重复报名被拦；「撤回申请 / 取消报名」同步销对应审核 / 参与待办并移出名单。

退回 / 注意非招募中 / 已过截止 / 满员的专班不可报名（给出原因提示）；招募中的专班撤销 = 彻底删除并连带清理关联报名与待办（见下）。

启动运行与成员角色（定人定责定岗）

入口：组织台「专班管理」看板（招募中列卡上「启动」）；运行中专班详情「成员角色」区（组织者 / 深度参与者两个多选 + 保存角色）。

谁来用：组织委员（启动 = recruiting → active；角色配置同步赋权链）。

几步：

  1. 招募中列点卡上「启动」→ 确认 → 专班转「运行中」。
  2. 详情「成员角色」区：分别选「组织者」「深度参与者」（预填当前成员角色）→「保存角色」。

自动保存角色同步专班成员 + 赋权审计快照 + 通知被赋权人（三合一，见 1.3 赋权链）；专班列表与工作量汇总即时刷新；发起时未选初始成员派生出的赋权待办在此环节「做事即销」。

注意仅招募中可启动（状态流转不合法被拦）；角色保存走统一赋权链，赋权即扩知情边界（组织委员可见被赋权者在办）。

运行中：中间进度填报（组织侧分阶段进展）

入口：组织台专班详情「中间进度」区（仅运行中专班显示填报表单）。

谁来用：组织委员填报（运行期分阶段进展，专班进度写口 = 组织侧）；书记 / 组长 / 纪检经「专班查看」只读同源可见。

几步：选阶段（筹备中 / 执行中 / 攻坚中 / 收尾）+ 进度说明（必填）→「添加进度」；本人填报的条目可「删除」。

自动进度入时间线（阶段标签 + 时间 + 填报人），只读专班查看（书记 / 组长 / 纪检）展示同一时间线；删除仅本人可删（旧数据无填报人由组织委员兜底）。

注意进度说明为空不落库；成员侧「进度感知」靠专班查看时间线（成员个人产出填报走下条）。

运行中：成员产出填报与组织逐条核验（同意入档 / 退回补料）

入口：填报 = 专班成员在运行中专班详情「我的产出填报」区（成员经其可打开的专班详情进入：工作概况专班行 / 待办「参与专班」/ 各台专班查看展开详情，条件 = 运行中 + 本人为专班成员）；核验 = 组织台专班详情「逐条核验 · 待核条目」区。

谁来用：专班成员本人逐条填报本人产出（by = 填报人）；组织委员逐条核验（同意入档 / 退回补料，全程留痕），另有「组织委员代录（兜底）」位（单条代录后仍须逐条核）。

几步：

  1. 成员在「我的产出填报」填本人产出说明（必填，如「完成专题稿件的采访与初稿撰写」）→「填报本条产出」。
  2. 组织委员在「待核条目」对每条点「同意入档 / 退回补料」（退回必填原因）。
  3. 被退回的成员可再次填报（原退回原因展示在条目上），重新进入核验。

自动填报条目带填报人 / 时间落「待核」；同意 →「已入档 · 核验人 XXX」；退回 →「已退回 · 原因」；已核条目幂等跳过；成员「贡献 N 项」与工作量汇总在看板详情 / 专班查看实时可见（解散前置也要读它，见下条）。

退回 / 注意填报仅限本人（所选人员非专班成员被拦）；代录所选人员亦须均为专班成员；历史字符串摘要条目只读展示、不参与核验。

专班复盘（组织侧提交 → 纪检批注闭环）

入口：组织台专班详情「专班复盘」区（运行中专班未提交时显示表单）；纪检台「党建」段「活动监督复盘」复核（活动与专班复盘同列流转）。

谁来用：组织委员提交（专班复盘提交位 = 组织侧，区别于活动复盘归组织者 / 深度参与者，见 3.2）；纪检委员批注 / 打回 / 确认（可批量确认）。

几步：

  1. 组织委员在专班详情填「专班复盘内容」（任务完成情况 / 成果 / 不足）+「待改进问题」（选填，多条用；分隔）→「提交复盘」→ 提示「待纪检委员批注」。
  2. 纪检台「活动监督复盘」对专班复盘行：批注（转批注中）/ 打回 / 确认（可开「批量确认」多选一次确认）——确认后复盘闭环。

自动提交即入纪检监督列表并同步组长台「复盘状态」；复盘已确认而未沉淀经验 → 纪检台出现「经验沉淀督促」清单（督促深度参与者提交沉淀）；复盘流转：已上传 → 批注中 → 确认 / 打回。

退回 / 注意纪检打回（附批注）后组织侧可修改重新提交；批量确认只作用于「已上传」行，其余状态置灰不可勾。

解散报送支委会表决（含关闭前置校验）

入口：组织台专班详情「解散」按钮（仅运行中专班可操作）。

谁来用：组织委员报送解散（前置 = 成员考察已确认 + 有工作量报告）；支委会表决由书记组织（见前「支委会表决专班议案」）。

几步：

  1. 点「报送解散表决」→ 系统先做关闭条件校验：成员考察未确认、或成员无产出记录（缺工作量报告）→ 弹窗列明缺失项并阻止报送（补齐后再报）。
  2. 校验通过 → 确认弹窗（明示「报送后提交支委会表决，通过后才会解散，当前仍运行中」）→ 确认 → 专班行标「待解散表决」。
  3. 书记在待办「专班待议（支委会）」排入表决：通过 → 专班置「已解散」（落解散日期）；未通过 → 专班继续运行。

自动解散结论落 dissolved + 解散日期并写历次表决留痕（append-only：谁 / 何时 / 结论 / 来源活动）；组织委员不再单人直接解散（决议走支委会表决，2026-09-06 书记裁定）。

退回 / 注意仅运行中可报送解散（其它状态被拦）；已报送待审议期间重复报送被拦（提示等待支委会审议）。

专班查看（书记 / 组长 / 纪检只读知情）与归档撤销（组织台）

入口：书记 / 组长 / 纪检台「党建」段「专班查看」；组织台「专班管理」看板卡（启动 / 归档 / 撤销按钮）。

谁来用：书记 / 副书记、党小组组长、纪检委员只读（无职责 ≠ 无知情权，见 1.3）；组织委员（管理主位）。

几步：

  1. 专班查看 = 全支部专班一览：状态分组（待支委会表决 / 招募中 / 运行中 / 已完结——含已解散），可搜索名称 / 任务；点卡展开只读详情（任务 / 人数 / 截止 / 发起人 / 成员与角色 / 贡献条目核验态 / 中间进度时间线；本人若为运行中成员另见「我的产出填报」）。
  2. 组织台看板（组织侧管理）：运行中卡「归档」（active → archived，归档不回收赋权、不生成解散留痕；解散语义走表决）；招募中 / 待表决 / 表决未通过草稿可「撤销 / 删除」（彻底删除并清理关联报名与待办）。

自动归档即销「专班归档」待办并将专班配套通知一并归档（退出工作区）；各台「待办」专班折组与通知直达本查看页并高亮定位专班卡（flash 高亮后自动褪去）。

注意纪检 / 组长台专班查看无任何流转按钮（看 ≠ 做）；专班进度 / 贡献只读知情，需要写的操作一律回组织台。

3.7决议上报

决议上报域含两个闭环：① 会议决议「待落实」跟踪——会议记录「通过」的决议可登记待落实项 → 自动生成责任人跟进待办（到期当天催办）→ 逾期自动进书记台待办督办 → 书记销项；② 支部关键事项上报党委——书记台「上报党委」发起（发展节点 / 活动报备）→ 党委台上报审批逐项批复（驳回必带意见）→ 结论回传支部侧本页。处理位提示：决议落实写在活动详情页记录决议视图（书记）；上报在书记台「对接党委」段「上报党委」，党委侧在党委工作台「上报审批」（组织级；党委台全量操作见第 5 章 5.1）。

会议决议落实（登记待落实 → 责任人跟进 → 逾期书记督办 → 销项）

入口：记录决议视图 = 书记 / 副书记打开会议活动详情页（表决汇总卡片下方——对每条已记录「通过」的议程自动出现「决议落实」卡，见 3.1 议程记录）；责任人处理 = 各责任人工作台「待办」；书记督办 = 书记台「待办」页。

谁来用：书记 / 副书记记录决议（副书记共台只读，管理位以书记为准）；责任人（支委角色或具体成员）执行；书记确认销项（误销项可恢复）。

几步：

  1. 议程「记录通过」后，决议视图出现该条决议的「决议落实」卡（可多条决议并列）。
  2. 书记逐项添加「待落实」：待落实事项（必填）+ 责任人（支委角色 或 到人）+ 落实时限（日期）→ 保存（可多次添加、增删改行后整组保存）。
  3. 责任人完成后反馈书记 → 书记在该条决议卡上点「销项」（误销可点「恢复」回待落实）→ 该条闭环。

自动保存即自动生成责任人跟进待办（责任人在本人工作台「决议上报」域折组可见；到期当天 = 催办窗口，不算逾期）；逾期未落实 → 书记台待办自动出现「决议落实逾期」提醒组（事项 / 会议 / 责任人 / 时限，直达决议视图督办销项）；销项 → 责任人跟进待办同步完成、逾期提醒消失；到期日之后待办自动转「已超期」。

退回 / 注意决议未记录「通过」不出现本卡；待落实项缺事项 / 责任人或时限不可保存；销项与恢复均留痕（谁 / 何时）。

上报党委（书记发起 · 支部侧）

入口：书记 / 副书记台「对接党委」段「上报党委」（本页顶部统计：待党委批复 / 已批准 / 已驳回）。

谁来用：书记 / 副书记（支部上报出口）；党委批复结论回传本页展示（党委侧操作见下条）。

几步：

  1. 「+ 发起上报」→ 选事项类型：发展节点（确定积极分子 / 发展对象、接收预备党员、按期转正等关键节点）或 活动报备（重要活动 / 主题党日等需党委知悉的重大事项）。
  2. 填事项标题（必填）+ 事项说明（必填：时间 / 对象 / 依据等，便于党委审批）→「提交上报」。
  3. 列表逐条看状态：待党委批复 → 已批准 / 已驳回（结论区含党委处理人 / 时间 / 意见，随结论回传本页）。

自动提交即同步党委台「上报审批」待批复区；批复后支部侧自动刷新结论；发展节点经批准后支部按 3.5 发展管线推进（获准事项在支部内继续执行）。

退回 / 注意上报后待批复期间不可撤回修改（如需更正请线下联系党委组织员）；驳回意见由党委侧必填保证，支部据此整改后可在获批范围内重报或线下沟通。

党委批复（党委台「上报审批」· 组织级）

入口：党委工作台「全院治理」段「上报审批」tab（组织级角色 party-staff；党委台全量操作见第 5 章 5.1）。

谁来用：党委组织员逐项批复（支部上报方查看结论）。

几步：

  1. 「待批复」区列出各支部上报（支部名 + 类型徽标 + 标题 / 内容 / 提交人与时间），顶部计数（待批复 / 已批准 / 已驳回）。
  2. 对每条填写「审批意见」（驳回必填；批准可填指导意见）→「批准」或「驳回」。

自动结论（批准 / 驳回 · 处理人 · 时间 · 意见）回传支部侧「上报党委」页；已处理历史在本页「已处理」区留存可查。

退回 / 注意驳回未填意见被拦（提示填写，便于支部知悉整改方向）；组织级角色不参与支部内部闭环（见 1.3）。

3.8归档与宣传

宣传线把支部工作留痕成册、对外发声：宣传任务三栏接单推进、项目看板（活动 + 专班合并卡与专班工作量）、周报报送、档案归档（待归档 → 归档中 → 已归档，材料标准清单 + 上传 / 下载）、支部文件与官方文件查询（公共页「资料查询」search.html，支部文件版本化在此页）。已覆盖相关：会议「讨论文件」记录通过自动归档走 3.1；活动复盘后的宣传产出要求见 3.2；支部公邮属纪检线（纪检台「公邮管理」，见 2.4），对外报送如需走公邮由纪检统一处理，本域不展开。宣传侧「待办」归档宣传折组负责提醒（活动归档 / 专班归档 / 材料归档均点「去处理」直达对应 tab）。

宣传任务（三栏接单 → 进行中 → 已提交）

入口：宣传委员台「党建」段「宣传任务」。

谁来用：宣传委员（本页 = 宣传任务总账；任务来源在卡片「来源」列示：支部委员会 / 副书记 / 组织委员等安排，系统内做接单推进）。

几步：

  1. 看三栏：待接收 / 进行中 / 已提交——每张卡 = 类型（素材归档 / 新闻稿 / 推送排版 / 周报报送）+ 内容摘要 + 来源与创建日期。
  2. 接单：待接收行点「接收」→ 转进行中；完成后点「提交」→ 转已提交。
  3. 低频：「导出 CSV」按当前全部任务导出（来源 / 类型 / 内容 / 状态 / 日期）。

自动状态推进即落库（刷新不丢）；与待办「归档宣传」折组联动（活动归档等提醒点「去处理」直达本页或档案归档）。

注意已提交为终态（不可回退）；宣传委员不可自行招募宣传专班——赋权统一归口组织委员（见 1.3 关键约束）。

项目看板（活动 + 专班合并卡 · 专班工作量）

入口：宣传委员台「党建」段「项目看板」（宣传活动承载位：本台活动相关都在看板卡上）。

谁来用：宣传委员（宣传活动管理位：完成 / 归档操作）；专班数据由组织侧写入、本页只读展示其宣传口径。

几步：

  1. 看板分三桶并活动 + 专班合并列卡：待启动（活动草稿 + 专班 待表决 / 招募中）/ 进行中（活动 已发布 / 进行中 + 专班 运行中）/ 已归档（活动 completed + 专班 已归档 / 已完结）——专班卡带「专班」徽章 + 人数 x/y。
  2. 进行中活动卡「确认完成」→ 归入已归档；进行中专班卡「归档专班」（仅归档不置完成，解散语义由组织委员走表决）。
  3. 看板底部「专班工作量」：各专班成员按 产出 N 项 / 专班 N 个 / 角色 汇总（宣传专班数据动态派生）。

自动看板从活动 / 专班数据动态派生；「确认完成」/「归档专班」即写库并销宣传侧「活动归档」/「专班归档」待办、配套通知随之归档退出工作区。

注意活动确认完成 / 专班归档后不再在工作区推进（历史在归档库可查）；专班关闭权归组织委员，宣传端只归档（见 3.6）。

周报报送（宣传例行周报）

入口：宣传委员台「党建」段「周报报送」。

谁来用：宣传委员（周报报送方；周报属宣传线例行汇报，汇报反馈域的其它汇报见 3.9）。

几步：

  1. 左侧「填写周报」：选周次（草稿周次自动选中）+ 填周报内容（每条一行）→「报送」。
  2. 「+ 新增周次」展开内联表单：周次标签 + 日期范围 → 保存（自动选中待填写；重名被拦）。
  3. 右侧「报送历史」按周列出历史周报（草稿 / 已报送徽章），可展开 / 收起详情。

自动报送即状态 = 已报送并落提交日期；未报送的周次保持草稿态可继续编辑。

注意报送前内容为空被拦；周报历史已报送不支持撤回（补充内容请走 3.9 汇报通道）。

档案归档（待归档 / 归档中 / 已归档 + 材料清单 + 上传与下载）

入口：宣传委员台「党建」段「档案归档」。活动 / 会议记录后的材料归档归口此处；会议「讨论文件」的自动归档线见 3.1（宣传无需二次上传）。

谁来用：宣传委员（档案归档主位：推进归档状态、上传宣传材料、管理材料文件）。

几步：

  1. 归档记录列表按归档日期倒序：每行 活动名 + 类别（新闻稿 / 照片 / 视频 / 其他）+ 状态徽章（待归档 / 归档中 / 已归档，归档中显示材料进度 x/y）；支持搜索活动名 + 类别 / 状态筛选。
  2. 待归档行「开始归档」→ 弹「材料确认清单」：按该类别的材料标准拆成勾选项（如新闻稿：含标题 / 正文 / 配图 3 张以上 / 署名 / Word + PDF 双格式）→ 勾选后推进（未全勾也可推进，但提示「请确保后续补齐」）→ 转「归档中」并记材料进度。
  3. 归档中行「确认归档」→ 弹归档总结（活动 / 类别 / 归档日期 + 材料标准）→ 确认 → 已归档（行尾 ✓）。
  4. 「上传材料」：选关联活动（必选，按日期倒序）+ 材料类别 + 多选文件（jpg / png / pdf / doc / docx / xls / xlsx / mp4 / mov）→ 上传即生成「已归档」材料行（可下载 / 删除）；本地模式单文件 ≤ 2MB、服务端模式 ≤ 10MB（页面按模式提示）。
  5. 页下两块：左侧「材料标准」对照（新闻稿 / 照片 / 视频 / 其他）；右侧「模板下载」——活动新闻稿模板（Word）、照片归档清单 / 视频元数据表模板（Excel）真实生成下载。

自动上传材料写库并同步产出物区 / 关闭校验（同源读取）；材料删除联动清理文件（服务端模式删物理文件）；上传成功自动弹「文件外发确认」（可选标记微信外发闭环，见 3.9）；已归档内容在公共「归档库」页（archive.html）与「资料查询」页可检索浏览。

退回 / 注意开始归档未全勾时状态照推（提醒后续补齐）；删除仅作用于本页材料行（有留痕口径，勿随意删）；无匹配记录时列表给空态提示。

支部文件与官方文件（公共页「资料查询」· 支部文件版本化）

入口：公共页「资料查询」search.html（侧边栏「资料查询」）→「官方文件」与「支部文件」两个板块（支部文件登录后可见，未登录给「去登录」引导）。

谁来用：全员查阅；写入管理 = 支委（宣传委员等）写普通支部文件、书记 / 副书记发布与管理「制度文本」（发布 / 上传新版 / 停用 / 重新启用——制度文本不支持删除）。

几步：

  1. 官方文件（党内法规按位阶排序：党章 → 条例 → 细则…）只读，行尾「查看官方原文」外链原文。
  2. 「写入文件」（+）→ 选用途：普通文件（附件；可先存「会前草案」仅支委可见，会议讨论通过后自动归档并标「经《XX》讨论通过」，见 3.1）/ 制度文本（正文 文本 / Markdown）→ 填标题 / 说明 / 发布说明 → 保存 =「制度 · 现行版 v1」。
  3. 全员阅读：制度文本行「阅读正文 / 收起正文」在网页内读现行版全文（正文优先，附件可选并存）；行内「历史版本」折叠可展开逐版正文（版本号 / 时间 / 发布人 / 说明）。
  4. 书记 / 副书记维护版本链：行操作「上传新版」（表单预填现行版 → 发布后旧版自动归档为历史版本、正文更新为现行版 vN+1）；「停用」结束效力（列表不再标「现行」，历史版本仍可展开查阅）；停用后可随时「重新启用」。

自动支部文件按更新时间倒序；已归档普通文件全员可读 / 下载；会议「讨论文件」通过 → 草案自动转已归档并在本页展示讨论来源（3.1 链路）；停用文本正文区自动标注「该制度当前已停用，以下为最近版本正文（仅供查阅）」。未录网页正文的制度文本给附件 / 线下文本提示。

退回 / 注意制度文本不提供删除（版本链留痕，结束效力请用「停用」）；上传新版 / 停用仅书记 / 副书记入口，其余角色不显示这些操作；匿名（未登录）不开放支部文件板块。

3.9汇报与反馈

汇报反馈域 = 支部双向互动通道：① 工作汇报闭环（成员 / 委员「一键汇报」进度 / 卡点 / 请示 → 书记「待答复收件箱」正式答复 → 汇报人确认收到闭环；书记 / 组长「了解进展」请汇报）；② 意见反馈（公共页 feedback.html 提交 → 书记台「反馈管理」批复 / 评论 / 指派 / 关闭）；③ 组长「组员进展」（本组组员汇报收件与行内答复 + 卡点知情）；④ 文件外发确认接收侧（发起侧在 3.8 档案归档）。宣传例行的「周报报送」已写在 3.8，此处不重复。待办「汇报反馈」折组 / 顶部常驻「一键汇报」与角标承担提醒（书记台另把「待答复汇报」置顶待办）。

双向工作汇报（一键汇报 → 书记答复 → 汇报人确认闭环）

入口：发起 = 各工作台顶部常驻「一键汇报」按钮（弹窗两步：选分类 + 填正文）；答复 = 书记台「待办」页顶部「待答复收件箱」（行内正式答复）；跟踪 = 各台「工作概况」汇报区 / 「我的处置」（见下）。

谁来用：全体成员 / 支委 / 组长主动发起（发往书记）；书记（副书记共台）答复；汇报人确认收到（角标提示）。

几步：

  1. 点「一键汇报」→ 选分类：进度 / 卡点 / 请示 → 填正文（必填）→「发出汇报」→ 入书记「待答复收件箱」。
  2. 书记在收件箱对每条行内「正式答复」发回（答复类置顶书记待办）。
  3. 汇报人在「我的处置 · 我发起的汇报」/「工作概况」看到答复 → 详情内点「确认已收到答复」→ 闭环关闭（留痕：发出 / 答复 / 确认，含时间线）。

自动发起即通知书记（待答复收件箱 + 高亮）；书记答复发回 → 汇报人「一键汇报」角标 +1；成员视角汇报状态徽章：待答复 / 待汇报 / 进行中 / 卡点上报中。

退回 / 注意汇报正文必填；未答复不自动关闭；卡点类（blocked）汇报在收件与组长卡点区以问题优先置顶。

「了解进展」（书记 / 组长请汇报 → 行内即发）

入口：发起 = 书记台「全局概况」卡点区行内「了解进展」（超期 / 缺口告警行）/ 组长台「组员进展」卡点区行内「了解进展」；接收 = 目标人「我的处置」① 区（或「工作概况」的「XX请汇报」条，行内填写即发）。

谁来用：书记（对任一角色超期 / 缺口）与党小组组长（对本组组员）发起温和请求；被请汇报人回应。

几步：

  1. 书记 / 组长在卡点行点「了解进展」（请求自动带上该卡点事项）→ 生成请汇报请求。
  2. 被请人在「我的处置 · XX请汇报」区看到请求（事项 + 时间）→ 行内填汇报内容 →「汇报」即发回。
  3. 书记 / 组长在收件箱正式答复 → 汇报人确认收到 → 闭环（流程同上条双向汇报）。

自动发起即给被请人「我的处置」角标 +1（未读）；请求与回应全程留痕（发起人 / 事项 / 时间 / 回应 / 答复）。

注意界面措辞为「了解进展」温和请求（不写「要求」）；组长只能请本组组员（块块边界，见 1.3）。

意见反馈（公共页提交 + 书记台反馈管理处置）

入口：公共页「意见反馈」feedback.html（列表 / 详情 / 新建；提交需登录，未登录自动跳登录页）；书记台「反馈」段「反馈管理」。

谁来用：支部成员提交（可勾匿名，书记内部仍可追溯真实提交人）；书记 / 副书记审核草稿并处置（批复 / 评论 / 指派 / 关闭 / 隐藏 / 合并）。

几步：

  1. 成员：feedback.html「新建反馈」→ 标题 * / 正文 * / 范围 *（底层架构 / 全局通用 / 权责调整 / 特定场景）/ 类型 * 多选（缺陷 / 增强 / 提案 / 疑问），可勾「匿名提交」→「提交反馈」→ 状态 = 待审核草稿（提示「待书记审核通过后公开」）。
  2. 书记「反馈管理」：顶部「待审核草稿」逐条「通过」（合并进公开列表）/ 驳回（驳回草稿不入公开列表）。
  3. 书记处置详情：批复（主操作）/ 评论（公开交流）/ 指派（选支委 / 组长 + 指派备注，生成指派时间线并通知被指派人）/ 关闭反馈（选关闭理由）/ 隐藏 / 合并到…。
  4. 列表页：状态筛选（开放中 / 已指派 / 待终审 / 已关闭）+ 指派人筛选 + 关键词搜索 + 计数摘要；工具区「导出反馈数据 / 清除缓存」。

自动草稿通过即公开（GitHub Issue 风格：编号 #N + 评论时间线 + 提交人信息卡）；指派 → 被指派人「我的处置」角标 +1；被指派人评论 / 提交处置结果 → 状态 =「待终审」提醒书记；关闭留痕（谁 / 何时 / 理由，作为批复评论写入）；隐藏评论仅书记可见。

退回 / 注意反馈提交先进草稿、书记审核后才公开（防止不实内容上墙）；驳回草稿不入公开列表；合并 = 来源隐藏并入目标（目标评论时间线记「合并自 #N」）。

我的处置（四委员台：请我汇报 / 我发起的汇报 / 指派给我的反馈）

入口：组织 / 宣传 / 纪检 / 党小组组长台「反馈」段「我的处置」。成员台无此 tab——成员的处理位在工作概况汇报区行内 + 顶部一键汇报角标（见 1.2 / 2.6）。

谁来用：组织 / 宣传 / 纪检委员、党小组组长（被请汇报人 / 汇报发起人 / 被指派人三合一）。

几步：

  1. ①「XX请汇报」块：书记 / 组长发来的「了解进展」请求，行内填汇报内容 →「汇报」即发回（对应方收到）。
  2. ②「我发起的汇报」块：我的全部汇报（状态徽章 + 分类 + 时间），点开详情看对话时间线（书记「正式答复」红色标注）→「确认已收到答复」闭环；也可评论追问。
  3. ③「指派给我的反馈」块：书记指派来处置的开放反馈（行显书记指派备注），点开 → 评论交流 / 提交处置结果（kind=result，提交后状态 =「待终审」等书记关闭）。

自动三块按提交时间倒序（最新在前）；未读角标 = 请我汇报 + 书记答复发回 + 新指派，进入本 tab 即消未读。

退回 / 注意处置结果提交后不可撤回（可继续评论补充）；反馈最终关闭权在书记（关闭后角标同步清空）。

组员进展（组长台：组员汇报收件 + 正式答复 + 卡点进度知情）

入口：党小组组长台「党建」段「组员进展」。

谁来用：党小组组长（块块视角，见 1.3：看 ≠ 做——只读知情 + 温和「了解进展」+ 答复本组组员汇报）。

几步：

  1. 顶部「组员汇报 · 本组待答复」收件箱：本组组员 open 汇报（问题优先置顶），行内正式答复——组内闭环，书记仍全局可见。
  2. 「卡点」区：本组 超期待办 / 上报卡点 / 缺勤未补 / 考察待确认 逐条列出（每条含人 + 事项 + 日期），行内「了解进展」可请该组员汇报。
  3. 「进度」区：一人一行聚合 在办 / 超期 / 缺勤 / 考察待 / 汇报状态；无卡点时显示「本组无卡点，全部正常」。

自动组员汇报 / 进展变化即时反映（数据同源聚合）；答复与请求全程留痕；答复本组组员无需转书记（块块内闭环）。

注意组长只读组员维度数据（考勤 / 考察明细的改写在纪检 / 组织台，见 3.3 / 3.5）；非本组组员不可见（块块边界）。

文件外发确认（发送方标记 → 接收方确认，两侧动作）

入口：发送侧 = 宣传委员台「档案归档」→「上传材料」成功后自动弹「文件外发确认」（3.8）；接收侧 = 接收方在各台「工作概况」卡点区（行首「文件待确认」）。

谁来用：发送方 = 宣传委员（标记「已通过微信发送」）；接收方 = 标记时选定的对象：党支部书记（审核）/ 纪检委员（留档）/ 组织委员 等（在工作概况看到并「确认收到」）。

几步（发送侧）：上传材料成功后弹「文件外发确认」→ 选接收方 + 备注（选填，如「新闻稿终稿，请审核」）→「标记已通过微信发送」（或「暂不外发」）。

几步（接收侧）：本人「工作概况」卡点区看到「文件待确认 · 发送人已微信外发（内容 + 外发人）」→ 线下在微信群收讫 → 点「确认收到」。

自动标记外发即广播接收方「材料外发待确认」通知；接收方确认后闭环——系统记录 谁 / 何时 / 发给谁 / 何时确认（可审计）；接收侧按角色过滤只显示发给自己的待确认行。

注意外发 ≠ 上传：材料本体始终在系统档案内（微信外发为线下动作，系统内只做内控闭环）；发送方未标记外发则无接收侧动作（材料仅归档）。

4业务链路

第 3 章讲「单个功能怎么用」；本章讲从起点到终点的先后顺序与交接点——每条链路按「谁 → 在哪做 → 系统自动发生什么 → 下一步去哪」写清，共 10 条（4.1—4.10）。紧下方总览图由功能目录驱动（12 条角色化链路，节点 = 执行者：任务；离线自动降级为文字说明）；同一条业务在文字里的端到端顺序与交接点，比图的节点串更细、以文字为准。

4.1三会一课链路

创建 → 议程 → 记录 → 考勤 → 归档（支部党员大会 / 支委会 / 党小组会 / 党课）

  1. 起点 · 创建：书记 / 副书记在书记台「活动管理 → 写入活动」选三会一课子类建会（党小组会由组长在组长台建）；自动按会议类型实例化 SOP 待办（T-7 筹备 → T-3 通知到人 → T0 签到考勤 → T+3 汇总 → T+5 归档 / 补课跟进），填了预拟通知即自动发布并派生成员待办。
  2. 议程编排（创建表单「会议议程」区）：一条议题可同时打「讨论文件」（关联会前草案）与「待讨论名单」（统一阶段转换）两种签；会后书记在活动详情页逐条「记录通过 / 未通过」。
  3. 记录后的自动派生：讨论文件「通过」→ 草案自动转「已归档」并标讨论来源（宣传无需二次上传）；待讨论名单「通过」→ 名单内每人自动生成成员变更申请，走「组织审批 → 书记确认 → 阶段更新」（接 4.5）；支部党员大会线上表决先做出席 / 赞成双过半硬校验。
  4. 考勤交接：党小组会考勤由组长上传（3.1），党课 / 支部党员大会 / 支委会由纪检直接录入（3.3）；出勤 / 已补源头自动确认，异常自动生成补课任务并入纪检「待确认」队列（接 4.3）。
  5. 终点 · 归档：纪检确认考勤后「提交考勤至宣传」备案（3.3）；会议材料与宣传产出由宣传台「档案归档」收口（3.8）。

4.2主题党日链路

选型创建 → 报名分工 → 实施监督 → 复盘 → 宣传归档

  1. 起点 · 选型创建：书记 / 组长在「写入活动」点主题党日模板卡（整卡可点），按共建 / 内外 / 载体三维选型填表；自动按场景排 SOP 节点（T-7 支委扩大会讨论 → T-2 通知 + 纪检对接考勤与复盘底线 → T0 实施 → T+1 复盘提醒 → T+7 材料归档）；支部停用「主题党日组织块」时模板卡隐藏（见 5.2）。
  2. 报名与分工：成员在详情页报名——普通参与即通过并写入分工名单，申请深度参与 / 组织者待发起人审核（3.2）；创建时未选参与人 → 自动派生赋权待办，组长 / 组织委员选人后即定人定责定岗。
  3. 实施与监督：现场签到 / 拍照 / 关键发言记录收齐（3.2）；纪检按弹性考勤口径核对，并监督复盘底线（超期由纪检提醒督促）。
  4. 复盘交接：组织者 / 深度参与者在成员台「我的复盘」提交 → 纪检「活动监督复盘」批注 / 打回 / 确认 → 复盘闭环；已确认未沉淀 → 纪检台自动出现「经验沉淀督促」清单。
  5. 终点 · 宣传归档：复盘闭环后宣传侧按项目看板 / 档案归档收口（摘要 + 配图等产出，见 3.8）。

4.3考勤纪律链路

组长上传 / 纪检录入 → 纪检确认 → 自动补课 → 宣传备案

  1. 起点 · 两条录入线：党小组会 = 组长台「考勤上传」（候选取本组应到名单，可批量设状态）；党课 / 支部党员大会 / 支委会 = 纪检台「考勤管理 · 会议考勤录入」（滞留党员线下到场单独补录、计到席）——纪检录入即确认。
  2. 自动分流：出勤 / 已补 = 源头审校自动确认，不进纪检队列；异常（缺勤 / 请假）自动生成补课任务（截止 = 活动日 + 7 天）并入纪检「待确认」队列，党小组会异常同样等纪检复核。
  3. 纪检确认：纪检台「考勤管理」待确认队列逐条确认（超期红标优先；也可在考勤总表按状态筛选逐行确认）→ 写确认人留痕，自动通知组织委员「考勤已确认并归档至考察档案」。
  4. 补课闭环：成员线下完成（必修 = 自学 + 心得 / 选修 = 自学）→ 纪检「补课制度」确认完成 → 对应考勤自动回写「已补」、逾期清除；超期任务自动汇总为超期提醒红块。
  5. 终点 · 备案交接：纪检「提交考勤至宣传」→ 宣传委员待办收件箱确认接收（双向可追溯）；活动归档后其考勤退出工作区、历史仍在档案可查。

4.4考察链路

考察上传 → 纪检确认 → 交接组织建档（供发展使用）

  1. 起点 · 上传位：活动侧 = 组长（本组党小组会 / 本人组织的活动）；专班侧 = 组织委员 / 专班负责人——在「考察上传」选来源对象、逐人填考察内容 → 自动入纪检台「考察管理」考察总表（状态 = 待确认，留痕上传人）。
  2. 纪检确认：纪检台「考察管理」对「待确认 / 超期」行「确认」（待确认超过 7 天自动标「超期」入顶部红块）；误传仅待确认可删。
  3. 交接建档：纪检「提交考察至支委会」→ 组织委员待办收件箱确认接收 → 自动建档归集（人才库 / 考察档案即时可用，双向可追溯）；未确认条不阻塞已确认流转。
  4. 终点 · 供发展：归集后的考察材料成为发展党员的判断素材（接 4.5）；活动类考勤确认同样自动归档至考察档案（4.3 第 3 步同口）。

4.5发展党员链路

管线推进 / 名册确权 → 书记确认（材料自动归集）

  1. 素材积累（自动）：思想汇报归档（4.6）与考察确认建档（4.4）自动归集到人，发展卡片上的考察条数 / 汇报归档数同步刷新。
  2. 管线追踪：组织台「发展数据」按积极分子 → 发展对象 → 预备党员 → 正式党员四段查看与「推进至下一阶段」（日常追踪；正式确权以名册为准）。
  3. 确权来源一 · 会议名单：大会 / 支委会「待讨论名单」记录通过 → 每人自动生成成员变更申请 → 组织台待办「成员变更审批」通过 → 广播全体支委 → 书记确认 → 阶段更新（4.1 第 3 步）。
  4. 确权来源二 · 名册行内：组织台「成员名册」改发展阶段 / 在册滞留或发起移出 → 书记台待办「成员变更待确认」确认生效或退回 → 应到口径联动（滞留剔除、通知照发）；有历史的移出经书记确认转「已转出」标注。
  5. 终点 · 节点上报：确定积极分子 / 发展对象、接收预备、转正等关键节点按 4.9 上报党委，获批后继续推进。

4.6思想汇报把关链路

成员提交 → 组织初阅 → 归档 / 退回重交

  1. 起点 · 提交：成员台「思想汇报」写正文提交（状态 = 待初阅），自动通知组织委员。
  2. 把关：组织台「思想汇报」待初阅队列先到先阅 → 「通过 · 归档」或「退回 · 需补充」（退回必填意见），每次初阅留痕（谁 / 何时 / 意见）。
  3. 退回重交：提交人见退回原因 → 修改后重新提交 → 回待初阅队列（历史留痕保留，不重复归档）。
  4. 终点：通过即正式归档并自动归集至个人档案（人才库 / 发展数据归档计数同步），供 4.4 考察与 4.5 发展调用。

4.7专班链路

发起 → 支委会表决 → 招募 → 执行核验 → 复盘 → 解散表决

  1. 起点 · 发起：组织台「发布招募」填名称 / 任务 / 人数 / 截止（可带初始成员与预拟通知）→ 创建即自动报送支委会表决（不派生单人审批待办）。
  2. 支委会表决：书记台待办「专班待议（支委会）」排入线上支委会 → 固化名单支委表态 → 书记「查看表决结果并生效」——通过转「招募中」，未通过退草稿可改后重新报送。
  3. 招募与分工：成员在专班详情页报名（普通即通过；深度参与 / 组织者待发起人审核）；组织启动专班转「运行中」→ 配置成员角色（组织者 / 深度参与者），保存即同步赋权链并通知本人。
  4. 执行与核验：成员逐条填报本人产出 → 组织「逐条核验」同意入档 / 退回补料（留痕）；中间进度由组织侧填时间线；书记 / 组长 / 纪检「专班查看」只读知情（看 ≠ 做）。
  5. 复盘：组织侧在专班详情提交复盘 → 纪检「活动监督复盘」批注 / 打回 / 确认闭环。
  6. 终点 · 解散表决：组织「报送解散表决」（前置：成员考察已确认 + 有工作量报告）→ 书记排入支委会表决 → 通过置「已解散」并落日期、未通过继续运行（历次表决 append-only 留痕）。

4.8决议落实链路

记录决议 → 责任人待办 → 逾期书记督办 → 销项

  1. 起点 · 登记：书记 / 副书记在活动详情页对已记录「通过」的议程，于「决议落实」卡添加待落实项（事项 + 责任人 + 时限）。
  2. 自动派生：保存即生成责任人跟进待办（责任人在本人工作台「决议上报」域折组可见）；到期当天 = 催办窗口，到期后待办自动转「已超期」。
  3. 逾期督办：逾期未落实 → 书记台待办自动出现「决议落实逾期」提醒组（事项 / 会议 / 责任人 / 时限），点击直达决议视图督办。
  4. 终点 · 销项：责任人完成后反馈书记 → 书记销项（误销可恢复）→ 责任人跟进待办同步完成、逾期提醒消失；销项与恢复均留痕。

4.9上报党委链路

支部上报 → 党委批复 / 驳回 → 结论回传支部

  1. 起点 · 发起：书记台「对接党委」段「上报党委」→「+ 发起上报」选事项类型（发展节点 / 活动报备）+ 标题 + 说明 → 提交，自动同步党委台「上报审批」待批复区。
  2. 党委批复：党委组织员在党委工作台「上报审批」逐项处理——「批准」（可附指导意见）或「驳回」（必填意见），操作见 5.1 表；已处理历史在党委台留存可查。
  3. 结论回传：支部侧「上报党委」列表自动刷新状态与结论（处理人 / 时间 / 意见）；获批事项按对应链路继续（如发展节点推进，接 4.5）；被驳回按意见整改后可在获批范围内重报。

4.10换届 / 换组织链路

换届任命 → 支部配置向导 5 步（数据保留语义）

  1. 换届任命：党委组织员在党委台「支部管理」对新任书记「任命书记」（选本支部成员，可写任命说明如换届选举）→ 原书记自动降回成员、任期档案记录（操作见 5.1 表）→ 新书记登录即接管本支部工作台。
  2. 换组织 / 初始化：从三入口之一进入「支部配置向导」走 5 步——① 组织信息 → ② 模块 / 块组合 → ③ 角色分工 → ④ 术语制度指引 + 换壳工作单 → ⑤ 验证与重置（入口与每步说明见 5.2）。
  3. 数据保留语义：向导改的是「壳」（名称 / 模块 / 分工 / 主题），成员档案、考勤考察、思想汇报、支部文件、档案与决议等历史数据全部保留随支部；演示形态的重置档位（回种子 / 清预览 / 初始化空支部）只作用于浏览器演示数据，正式形态数据落库持久（见 5.3）。

5.3数据保留与重置档位

重置会清什么、保留什么（面向使用者说明）

换壳不换档：向导 ①②③ 改的是支部的「壳」——名称 / 模块 / 分工 / 主题。成员档案（名册 / 发展阶段 / 在册滞留）、考勤考察、思想汇报、支部文件、档案与决议、专班历史等业务数据全部保留，随支部继续生效（历史留痕只追加、不覆盖）。

验证第⑤步的「重置」档位（本地演示形态，浏览器演示时使用）：

  • ?reset=demo（?reset=1 为其旧写法同义）：把全部演示数据复位到「种子初始态」——向导里试改的配置也会被清掉。用于演示前整体复位。
  • ?reset=preview：只清理「运行痕迹」——向导草稿与成员基础数据预览等临时状态，演示数据本身保留。用于试走向导后想从头再走、但不想丢已演示的数据。
  • ?reset=init：一键初始化为「新支部初始态」——清空试用期积累的业务过程数据（活动 / 考勤 / 考察 / 专班 / 通知 / 汇报 / 议程决议跟进 / 归档 / 交接 / 意见反馈提交等），保留组织骨架：账号与角色结构、成员档案（名册，可后续在名册再调）、支部配置 / 分工 / 术语（向导可再改）、成员在册状态（在校 / 滞留）与主题外观。用于「演示 / 试用结束、正式投入使用前」的干净起步——已配好的壳不丢、过程数据清零、空支部起步。
  • API（正式对接）形态：以上三档 URL 参数均不生效——数据经登录认证落库持久化（换届不丢档、操作有留痕）；正式数据不提供页面级清空入口（初始化 / 清档属管理员级操作：重建种子库或走管理端，见 README 快速开始 reset 说明）。

6这个系统在干什么

这个系统是北京大学光华管理学院本科生党支部的数字化管理工具——把党支部制度文本转化为可执行的代码工作流，让工作不随人走。

它要解决的核心问题是：党支部工作如何从"人治"走向"制度治理"？支委换届频繁，经验随人走、制度随人变；新支委上任后需要数月摸索才能上手；同一种工作在不同人手里做法完全不同。围绕这个问题，系统展开三个理念：

制度即代码

把制度文本转化为可执行的代码工作流，让工作不依赖某个人。

角色即视图

每个角色打开工作台就是该角色的全部工作视图，无需来回跳转。

经验可传承

复盘与归档沉淀经验，让新支委快速上手、制度随届接续。

系统现有 18 个页面：11 个根页面（首页、登录、资料查询、归档库、活动 / 通知 / 专班详情、意见反馈、帮助、关于、换组织向导）+ 7 个角色工作台（书记、组织委员、宣传委员、纪检委员、党小组组长、成员、党委工作台；副书记与书记共台，组织者 / 深度参与者归入成员工作台）。每个角色登录后直达自己的工作台，该工作台就是该角色的全部工作视图——各项功能按 tab 分组，无需在页面之间来回跳转；所有角色共享同一套数据，看到的是同一数据的不同视角。

系统采用「静态前端 + 一体化后端」：界面在浏览器渲染，数据经登录认证后落库持久化——换届不丢档、操作有留痕。谁负责哪块、谁能看到哪层，由赋权链计算：书记向下委托执行边界，其余角色的操作权限与知情范围随之派生（详见第 1 章 1.3「权限知情边界」）。

  • Tailwind CSS CDN — 原子化样式引擎
  • REST API（/api/v1）— 登录认证、资源表读写、附件上传、快照持久化
  • Custom Events — 组件间解耦通信
