# 条条支委与党小组交互机制

> **2026-05-03 重要更新**：补充了短期/长期活动的具体组织协同模式（§B.4），明确了纪检+宣传委员在双轨工作流中的操作节点。品牌活动维度本轮搁置。
>
> 本文档定义条条（纵向职能线）与块块（横向党小组）双线管理体系下的交互机制，涵盖职责边界、短期交互模式、长期系统化路径及冲突解决规则。
> 定位：[人机] — 人类决策参考 + AI 自主读取作为实施上下文。

---

## A. 职责定位与工作边界

### A.1 条条支委职责域

条条支委以职能线身份横跨三个党小组，侧重制度建设与职能保障。

| 条条支委 | 职能域 | 核心职责 |
|----------|--------|---------|
| 组织委员 | 组织域 | 发展党员全流程管理 / 材料催缴 / 思想汇报统计归档 / 合规文件引用管理 / 考察档案管理 |
| 宣传委员 | 宣传域 | 档案归档 / 材料标准制定 / 模板管理 / 周报报送 / 考勤备案 |
| 纪检委员 | 纪检域 | 补课跟踪 / 公邮提醒 / 参与汇总（提交组织委员）/ 考勤汇总（提交宣传委员）/ 复盘督办 |

> 权限细节参见 [COMMISSIONER_ORGANIZATION_ROLE.md §二](file:///d:/GitHub/GSM1921-SOP/content/guides/COMMISSIONER_ORGANIZATION_ROLE.md) 支委权限矩阵。

### A.2 块块党小组长职责域

块块组长以党小组为单位，侧重活动组织与成员管理。

| 职责项 | 说明 |
|--------|------|
| 活动组织与执行 | 策划并实施本党小组日常活动（每月至少1次）及品牌活动 |
| 小组成员考勤管理 | 配合纪检委员完成本组出勤确认 |
| 活动复盘与反馈 | 活动结束后T+7天内完成复盘，接受纪检委员督办 |

### A.3 交叉区域（条条+块块共同负责）

条条与块块在活动全生命周期中形成三阶段交叉协作：

| 阶段 | 条条支委 | 块块组长 |
|------|---------|---------|
| 活动策划 | 定规范（合规审查 / 宣传标准 / 考勤要求） | 定方案（活动内容 / 形式 / 分工） |
| 活动执行 | 监督（纪检记录参与 / 宣传指导产出 / 组织协调信息） | 主导（现场组织 / 任务分配 / 进度把控） |
| 活动复盘 | 归档（组织委员建档 / 宣传委员备案 / 纪检委员汇总提交） | 总结（复盘报告 / 经验提炼 / 改进建议） |

## B. 短期交互模式（当前学期）

### B.1 任务对接机制

#### B.1.1 条条→块块：支委下发职能任务

条条支委以职能身份向块块组长下达职能性任务：

| 条条支委 | 典型下发任务 | 触发条件 |
|----------|------------|---------|
| 组织委员 | 发展党员材料催缴 / 思想汇报催缴 / 考察材料补充 | 材料缺失或到期 |
| 宣传委员 | 宣传材料提交 / 档案补充 / 周报截图 | 活动结束后或周期性节点 |
| 纪检委员 | 补课安排确认 / 参与记录确认 / 复盘提交提醒 | 考勤异常或复盘逾期 |

#### B.1.2 块块→条条：组长上报执行结果

块块组长以执行身份向条条支委反馈执行结果：

| 上报内容 | 接收条条 | 时限 |
|----------|---------|------|
| 活动参与记录（组织/深度参与/出勤） | 纪检委员（汇总）→ 组织委员（建档） | 活动结束后T+3天 |
| 宣传材料（摘要+配图） | 宣传委员（审核+归档） | 活动结束后T+3天 |
| 复盘报告 | 纪检委员（督办确认） | 活动结束后T+7天 |

#### B.1.3 双向确认：任务闭环

```
条条支委                              块块组长
   |                                     |
   |──── ① 下发职能任务 ────────────────>|
   |                                     |
   |                                     |──── ② 执行任务 ────>|
   |                                     |
   |<──── ③ 上报执行结果 ────────────────|
   |                                     |
   |──── ④ 确认/驳回 ──────────────────>|
   |                                     |
   |     （驳回则回到②重新执行）           |
   |                                     |
   |──── ⑤ 归档完成 ──────────────────>|
```

### B.2 信息共享渠道

#### B.2.1 支委会例会（每周/双周）

| 议程项 | 汇报方 | 内容 |
|--------|--------|------|
| 条条汇报 | 三位支委 | 各职能域工作进展 + 待协调事项 |
| 块块汇报 | 党小组组长 | 各组活动执行情况 + 成员动态 |
| 交叉议题 | 共同讨论 | 条块协作中的问题 + 下阶段工作部署 |

#### B.2.2 公邮通知

条条支委统一发布制度性通知，块块组长负责传达至本组成员并确认知悉。

#### B.2.3 网页系统

- 条条入口：党务管理模块中的三委面板（[COMMISSIONER_ORGANIZATION_ROLE.md §三](file:///d:/GitHub/GSM1921-SOP/content/guides/COMMISSIONER_ORGANIZATION_ROLE.md) 操作入口设计）
- 块块入口：活动推演工作台中的党小组管理视图

### B.3 协同决策流程

#### B.3.1 活动策划

```
块块组长提出方案 → 条条审核合规性 → 书记审批 → 立项执行
```

- 组织委员审核：信息平台支持 / 材料归档要求
- 宣传委员审核：宣传标准 / 档案规范
- 纪检委员审核：考勤要求 / 参与记录标准

#### B.3.2 制度制定

```
条条起草 → 块块反馈可行性 → 支委会通过 → 全支部实施
```

- 条条支委牵头起草本职能领域制度初稿
- 块块组长在本党小组内试点征求意见
- 支委会集中讨论形成全支部制度

#### B.3.3 紧急事项

```
条条/块块任一方发起 → 书记直接决策 → 事后补流程
```

- 紧急事项不跳过决策，但允许先执行后补办审批手续
- 事后须在下次支委会例会上补充说明

#### B.4 活动组织中的条块协同模式（核心）

#### B.4.1 短期活动协同（一次性完成：参访、线下学习等）

```
组织者（可由党小组组长担任，或在群内/支部群招募）
    │
    ├──→ 建活动群 + 核心群（一套核心班子）
    │
    ├──→ 对接【纪检委员】：审核考勤要求 → 活动当天签到执行
    │        纪检委员事后汇总：参与记录（→组织委员）+ 考勤记录（→宣传委员）
    │
    └──→ 对接【宣传委员】：审核宣传标准
             宣传委员对接具体负责宣传工作的深度参与者 → 统筹宣传产出
             招人目的：前期学习材料筹备 + 宣传素材准备
```

| 节点 | 条条操作为主 | 块块操作为主 | 时限 |
|------|------------|------------|------|
| 活动策划 | 支委审核合规（纪检考勤/宣传标准） | 组织者提出方案 | T-7天 |
| 建群招人 | 条条指导要求 | 组织者执行建群+招募深度参与者 | T-5天 |
| 活动执行 | 纪检现场监督签到 | 组织者主导现场 | T-0天 |
| 活动收尾 | 宣传对接统筹产出 / 纪检汇总提交 | 组织者提交基础材料 | T+3天 |

#### B.4.2 长期活动协同（持续打磨/多活动小组同步推进）

```
大活动群（全体参与者的信息汇总群）
    │
    ├── 活动小组A 小群（组织者A + 深度参与者A组）
    ├── 活动小组B 小群（组织者B + 深度参与者B组）
    └── ...
    
核心群 = 各活动小组组织者 + 承办党小组组长 + 纪检委员 + 宣传委员

（注意区分：活动小组 ≠ 党小组）
```

**角色定义**：
| 角色 | 职责 | 流动性 |
|------|------|--------|
| 组织者（每个活动小组一个） | 协调本组深度参与者工作 + 把握活动方向 + 对接核心群 | 长期深耕，不轻易流动 |
| 深度参与者 | 承担具体工作 | 可离开，可轮换 |
| 组织层 | 所有组织者的协调网络 | 长期稳定 |

**组织者协调清单**：
- 协调承办党小组组长 → 方向对齐 + 资源协调
- 协调纪检委员 → 考勤要求 + 参与记录汇总
- 协调宣传委员 → 内容同步 + 宣传产出统筹
- 协调组内深度参与者 → 任务分配 + 进度把控
- 协调活动小组间关系 → 避免冲突 + 经验共享

## C. 长期交互模式（系统化）

### C.1 数字化工作流

#### C.1.1 任务看板

```
条条下发任务 → 块块认领 → 进度追踪 → 完成确认
```

| 阶段 | 操作方 | 系统行为 |
|------|--------|---------|
| 下发 | 条条支委 | 创建任务卡片，指定接收党小组 + 截止日期 |
| 认领 | 块块组长 | 任务状态变为"进行中"，系统记录认领时间 |
| 追踪 | 双方可见 | 进度条实时更新，超期自动标红 |
| 确认 | 条条支委 | 审核执行结果，确认后任务归档 |

#### C.1.2 自动提醒

| 触发条件 | 提醒对象 | 提醒方式 |
|----------|---------|---------|
| 任务到期前3天未完成 | 条条+块块 | 系统内通知 + badge |
| 任务逾期未完成 | 条条+块块+书记 | 系统内通知标红 |
| 复盘T+5天未提交 | 块块组长 | 纪检督办提醒 |
| 月底参与记录未汇总 | 纪检委员 | 系统提醒提交 |

#### C.1.3 数据回流

```
块块执行数据 → 条条审核 → 系统归档
```

- 活动参与记录：块块确认 → 纪检汇总 → 组织建档
- 考勤记录：块块确认 → 纪检汇总 → 宣传统备
- 宣传材料：块块提交 → 宣传审核 → 系统归档

### C.2 角色权限矩阵（网页系统实现）

| 操作 | 组织委员 | 宣传委员 | 纪检委员 | 党小组长 |
|------|---------|---------|---------|---------|
| 下发职能任务 | Y(组织域) | Y(宣传域) | Y(纪检域) | -- |
| 上报执行结果 | -- | -- | -- | Y |
| 审核执行结果 | Y(组织域) | Y(宣传域) | Y(纪检域) | -- |
| 发起活动 | -- | -- | -- | Y |
| 审核活动方案 | Y(合规) | Y(宣传) | Y(纪检) | -- |
| 归档活动记录 | -- | Y | -- | Y(配合) |

### C.3 季度评审机制

#### C.3.1 条条工作评审

| 指标 | 数据来源 | 达标标准 |
|------|---------|---------|
| 职能任务完成率 | 任务看板统计 | >= 90% |
| 合规率 | 审核驳回率 | <= 10% |

#### C.3.2 块块工作评审

| 指标 | 数据来源 | 达标标准 |
|------|---------|---------|
| 活动执行率 | 活动推演工作台 | >= 95% |
| 参与率 | 参与记录汇总 | >= 85% |
| 满意度 | 成员反馈 | >= 4.0/5.0 |

#### C.3.3 交叉评审

| 指标 | 数据来源 | 达标标准 |
|------|---------|---------|
| 条块协作效率 | 任务平均完成周期 | <= 7天 |
| 信息传递时效 | 任务响应时间 | <= 24小时 |
| 冲突解决率 | 冲突记录统计 | 100%解决 |

## E. 冲突解决机制

### E.1 条条与块块职责冲突

| 冲突场景 | 解决方式 | 决策者 |
|----------|---------|--------|
| 条条要求与块块执行能力不匹配 | 支委会协商调整要求或增配资源 | 书记仲裁 |
| 条条间对同一块块下达矛盾任务 | 按职能优先级排序：组织>纪检>宣传 | 书记仲裁 |
| 块块对条条规范有异议 | 块块书面反馈，条条7日内回应 | 支委会裁决 |

### E.2 双重身份角色冲突

当条条支委兼任块块组长时，按**主身份优先原则**处理：

| 场景 | 主身份 | 行为规则 |
|------|--------|---------|
| 支委会上讨论本组活动 | 条条支委 | 以职能视角发言，不为本组争利 |
| 本党小组内部执行职能要求 | 块块组长 | 以执行者身份落实，不因支委身份降低标准 |
| 本组活动涉及本人职能审核 | 条条支委 | 主动回避，由其他支委代为审核 |

### E.3 资源竞争

| 竞争类型 | 解决方式 |
|----------|---------|
| 多个党小组竞争同一时段活动 | 支委会协商排期，优先保障品牌活动 |
| 深度参与者跨组分配冲突 | 组织委员统筹协调，按任务紧急度分配 |
| 宣传资源（推文排期）竞争 | 宣传委员按活动重要性排期，块块组长提前预约 |
