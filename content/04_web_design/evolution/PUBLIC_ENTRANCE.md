# 学院党委公共门厅——未登录入口与公开内容（已裁定）

> **本文负责**：记录 V-11 的裁定结论（D-858）、门厅的显示与不显示范围、登录后的读面、公开权限与审计边界、验收判据，以及三种候选方向中未选两个的理由。
> **本文不负责**：① 角色与权限的规范条文 → [SYSTEM_ROLE_PERMISSION.md](../../02_institution/SYSTEM_ROLE_PERMISSION.md) §9a.1；② 公开门厅的版式与组件规范 → 设计系统（编号待登记，见 `design-system/CASES.md` CASE-DESIGN-035 与 `.ctx/REVIEW_QUEUE.md`）；③ 多支部同实例的技术路线与开关 → [ARCHITECTURE_EVOLUTION.md](./ARCHITECTURE_EVOLUTION.md) §十；④ 登录实现细节 → `docs/src/entries/pages/login-entry.js`。
> **性质**：演进档案，只写「为什么这样定、边界在哪、什么没选」。规范效力以 `SYSTEM_ROLE_PERMISSION.md` 与设计系统条文为准；字段与接口口径见 `DATA_MODEL.md` / `DATA_CONTRACT.md`。

## 一、裁定结论

1. **入口形态**：未登录首页为「学院党委公共门厅」，不显示任何具体支部的视野。
2. **品牌**：党徽 ＋「光华管理学院党建平台」。未登录面不得出现具体支部名。
3. **读面**：未登录只看党委公开内容；登录回到工作台，活动 / 通知 / 资料按党委与支部并集展示。
4. **公开权限**：`publishScope='public'` 只归党委，必须有未来有效期，全部动作写审计。
5. **上线形态**：仍为一实例一支部；多支部开关保持关闭，门厅不依赖多支部能力。

## 二、未登录门厅看到什么

| 区块 | 内容 | 来源 |
|---|---|---|
| 公开通知 | 全文（标题、正文、发布时间） | `notices` 中 `publishScope='public'` 且未过期的党委通知 |
| 公开活动 | 摘要（标题、类型、时间、地点、摘要） | `activities` 中 `ownerScope='committee'`、`publishScope='public'` 且未过期的行 |
| 公开资料 | 列表 ＋ 详情 ＋ 附件下载 | `branch_docs` 中 `publishScope='public'` 且未过期的院级资料 |
| 登录入口 | 通向学号登录 | 既有登录页 |

## 三、未登录门厅不显示什么

- **具体支部名**：未登录面按学院品牌呈现；支部名只出现在登录后的工作台与登录后的支部档案。
- **成员姓名与 `personId`**：匿名接口的字段白名单不含成员明细。
- **统计卡、工作组、活动风采、通知角标**：未登录不发起这些数据域请求，也不渲染对应容器。
- **个人数据**：成员档案、党费、思想汇报、考勤明细、参与名单一律不进入公开面。

说明：门厅承载的是党委对外公开的内容，支部内部运行数据（成员、统计、工作组、活动风采）不属于公开范围。匿名可读的范围由 `publishScope='public'` 与有效期共同限定，公开权限只归党委。

## 四、登录后的读面

1. 登录后访问首页仍是既有工作台；门厅只在无会话时渲染。
2. **活动**：列表为本支部活动 ＋ 面向本支部或全部的党委活动；本支部已有副本时，列表隐藏对应党委原件。直达已隐藏原件时只读展示并提示「本支部已采用」。
3. **通知**：本支部通知 ＋ 面向本支部或全部的党委通知 ＋ 未过期的公开通知；空受众的系统通知仍按 fail-closed 处理。
4. **资料**：本支部资料 ＋ 院级党委资料中 `login` 或 `public` 且未过期的行；党委资料标注「院级」。
5. 党委工作台选中某一支部时，同时看到该支部活动与面向该支部的党委活动，并标注「已采用 / 未采用」。

## 五、公开权限与审计

- 只有党委能设置或撤销 `publishScope='public'`；支部账号设置返回 403。
- 设为 `public` 必须同时提供未来的 `publishExpiresAt`；缺失或已过期返回 422。
- 过期后匿名接口一律不返回该条内容（fail-closed）；登录用户的可见性仍按受众与目标支部判定。
- 公开、撤下、有效期变更与匿名下载写 `publication_audits`；匿名下载的 `actorId` 为空。
- 匿名接口一律返回字段白名单内的键；不存在与无权访问统一返回 404，不区分两者。

## 六、验收判据

1. **未登录无支部名**：未登录首页 DOM 与页面标题都不出现任何具体支部名。
2. **公开内容可见**：公开通知全文、公开活动摘要、公开资料列表与下载在未登录态可用；下载后 `publication_audits` 有 `action='download'` 的行。
3. **登录并集**：支部账号登录后活动、通知、资料列表含党委行；已采用副本的党委原件从列表隐藏。
4. **过期 fail-closed**：把 `publishExpiresAt` 调到过去后，匿名接口对该条返回 404；登录用户按受众与目标支部仍可见。
5. **宽度可用**：390px 单列、无横向滚动，下载与登录入口可点；1440px 区块层级清晰，空态、加载态与失败重试齐全。
6. **字段白名单**：匿名响应不出现 `organizer`、`assignments`、`voteConfig`、`createdBy`、任何 `personId` 与内部审批字段。

## 七、未选方案与不选理由

| 方向 | 做法 | 不选理由 |
|---|---|---|
| A 最小收紧 | 保持一实例一支部；未登录只显示中性「党支部管理系统」，登录后按支部档案显示支部名 | 只改标题来源与一条守卫，未登录面拿不到任何党委公开内容；支书要求的「未登录可看党委公开通知、活动摘要与资料」无法满足 |
| B 学院级统一入口 | 中性品牌 ＋ 学号登录 ＋ 服务端按人解析支部并路由；登录前不显示支部名 | 需要「人 → 支部」解析、待归属状态、跨支部路由与错误态，与多支部 Phase 1 强耦合；当前生产一实例一支部，按人解析支部暂无必要 |
| C 公共门户 | 学院与支部公开信息聚合 ＋ 登录入口，另设公开数据域与审核流程 | 超出当前需求：需要独立的公开数据域、审核责任人与对外展示责任；本轮只需党委公开内容可读，不扩到对外门户 |

选中的方向在本文 §一 至 §五；A、B、C 保留在此只作历史记录，不再是待裁项。

## 八、边界与未决

- **与多支部开关的关系**：门厅只用党委伪支部 `pc-gsm` 的公开行，不依赖 `ALLOW_MULTI_BRANCH`；开关保持关闭时门厅照常工作。
- **显式广播是否匿名可读**：本裁定只开「`publishScope='public'` 且未过期」这一条窄口；`audience:['all']` 的系统广播仍不对匿名开放。
- **跨支部公开**：一条党委活动可面向 `['all']` 或指定支部；公开可见性与目标支部是两个维度，目标支部决定登录后谁能看到，公开范围决定未登录能否看到。
- **未登记项**：门厅的版式与组件编号待设计系统登记；登记前实现侧按本文件验收判据执行。
