> 本文档合并原 `COMMISSIONER_ORGANIZATION_ROLE.md`（支委党务管理职能）与 `COMMISSIONER_GROUP_INTERACTION.md`（支委×党小组交互机制），消除两文件间的角色定义和权限矩阵重复。

## A. 设计背景与核心定义

### A.1 问题缘起

E1（ORGANIZATION_BUILDING_MODULE）定义了党务管理模块功能；E2（MANAGEMENT_MODE_ARCHITECTURE）定义了三级管理权限。**缺口**：三位条条支委在党务管理模块中的权限、入口、协作模式以及与党小组的交互关系尚未系统化。

### A.2 设计目标

| 目标 | 说明 |
|------|------|
| 权限明确 | 每位支委在党务工作域 + 条块交互域中各能做什么 |
| 入口自然 | 侧边栏进入"党务管理"后，系统自动识别角色展示对应面板 |
| 协作闭环 | 三委数据交接 + 条块任务对接均在系统内自动流转 |
| 最小侵入 | 不修改现有 SPA 路由和角色卡片体系 |

## B. 条块双线职责体系

### B.1 条条支委职责域

条条支委以职能线身份横跨三个党小组，侧重制度建设与职能保障。

| 条条支委 | 职能域 | 核心职责 | 人名 |
|----------|--------|---------|------|
| 组织委员 | 组织域 | 发展党员全流程 / 材料催缴 / 思想汇报归档 / 合规文件管理 | 侯嘉嵘 |
| 宣传委员 | 宣传域 | 档案归档 / 材料标准 / 模板管理 / 周报报送 / 考勤备案 | 闫鑫岳 |
| 纪检委员 | 纪检域 | 补课跟踪 / 公邮提醒 / 参与汇总→组织委员 / 考勤汇总→宣传委员 / 复盘督办 | 韩思宁 |

### B.2 块块党小组长职责域

| 职责项 | 说明 |
|--------|------|
| 活动组织与执行 | 每月至少1次本组活动 |
| 考勤管理 | 配合纪检委员完成出勤确认 |
| 复盘反馈 | T+7天内完成复盘，接受纪检督办 |

### B.3 交叉区域（条块三阶段协作）

| 阶段 | 条条支委 | 块块组长 |
|------|---------|---------|
| 策划 | 定规范（合规/宣传标准/考勤要求） | 定方案（内容/形式/分工） |
| 执行 | 监督（纪检记录/宣传指导/组织协调） | 主导（现场/任务/进度） |
| 复盘 | 归档（组织建档/宣传备案/纪检汇总） | 总结（复盘报告/经验提炼） |

## D. 操作入口与 UI 体系

### D.1 入口架构

```
侧边栏
  └── [党务管理] module-tab
         |
    +----+----+----+
    |    |    |    |
  纪检  组织  宣传  默认概览
 (琥珀) (蓝) (翠绿) (只读四宫格)
```

### D.2 入口触发逻辑

用户点击 [党务管理] → 系统检查 activeRole → 展示对应支委面板。非支委用户（党小组长/深度/普通参与者）展示只读概览。

### D.3 支委面板子 Tab

| 纪检委员面板 | 组织委员面板 | 宣传委员面板 |
|------------|------------|------------|
| 补课跟踪 | 发展党员（五阶段看板） | 档案归档 |
| 公邮提醒 | 材料催缴 | 材料标准 |
| 参与汇总 | 思想汇报 | 模板管理 |
| 复盘督办 | 合规文件 | 周报报送 |

### D.4 HTML/JJS/CSS 集成

HTML 结构：`view-party` 内嵌四个 `commissioner-panel` div（data-commissioner="inspector/organizer/publicity/default"），各含 `commissioner-tab-bar` 子导航。

JS 判定逻辑：`getActiveCommissioner()` 从 State.activeRole 提取 → `renderCommissionerPanel()` 显隐对应 panel。

CSS：commissioner-tab-bar 复用现有 module-tab 样式，active tab 按角色色系着色。

## E. 三委数据协作流

### E.1 月度闭环流程

```
活动结束
  → 纪检 [参与汇总] 确认三层参与 + 考勤记录
  → 纪检点击「提交至组织委员」（参与记录）
  → 纪检点击「提交至宣传委员」（考勤记录）
  → 组织 [思想汇报] 接收参与记录→建档→更新发展党员统计
  → 宣传 [档案归档] 接收考勤记录→备案
```

### E.2 数据交接协议

| 方向 | 数据内容 | 触发方式 | 通知机制 |
|------|---------|---------|---------|
| 纪检→组织 | 三层参与记录 (JSON) | 纪检点击「提交至组织委员」 | 组织面板 badge +1 |
| 纪检→宣传 | 考勤记录 (JSON) | 纪检点击「提交至宣传委员」 | 宣传面板 badge +1 |
| 组织→纪检 | 补课需求回执 | 组织标记材料缺失 | 纪检补课跟踪高亮 |
| 宣传→纪检 | 考勤备案确认 | 宣传确认备案 | 纪检状态→"已备案" |

## F. 条块交互机制

### F.1 任务对接闭环

```
条条支委 → ①下发职能任务 → 块块组长
                                    → ②执行任务
条条支委 ← ③上报执行结果 ← 块块组长
条条支委 → ④确认/驳回 → 块块组长（驳回则回②）
条条支委 → ⑤归档完成 → 块块组长
```

### F.2 活动组织协同模式（核心）

#### 短期活动（一次性：参访、线下学习等）

```
组织者（党小组长或群内招募）
  ├→ 建活动群 + 核心群
  ├→ 对接纪检：审核考勤要求 → 活动当天签到
  │     纪检事后汇总：参与→组织委员、考勤→宣传委员
  └→ 对接宣传：审核宣传标准 → 统筹宣传产出
```

| 节点 | 时限 | 条条 | 块块 |
|------|------|------|------|
| 策划 | T-7 | 支委审核合规 | 组织者提出方案 |
| 建群招人 | T-5 | 条条指导要求 | 组织者执行 |
| 执行 | T-0 | 纪检监督签到 | 组织者主导 |
| 收尾 | T+3 | 宣传统筹/纪检汇总 | 组织者提交材料 |

#### 长期活动（持续打磨/多小组并行）

```
大活动群（全员信息汇总）
  ├─ 活动小组A 小群（组织者A + 深度参与者A组）
  └─ 活动小组B 小群（组织者B + 深度参与者B组）

核心群 = 各组织者 + 承办党小组长 + 纪检 + 宣传
（注意：活动小组 ≠ 党小组）
```

| 角色 | 职责 | 流动性 |
|------|------|--------|
| 组织者（每组一个） | 协调本组深度参与者 + 对接核心群 | 长期深耕 |
| 深度参与者 | 承担具体工作 | 可轮换 |
| 组织层 | 所有组织者协调网络 | 长期稳定 |

组织者协调清单：承办党小组长（方向对齐）、纪检（考勤+记录）、宣传（内容同步+产出）、组内深度参与者（任务分配）

### F.3 信息共享渠道

| 渠道 | 用途 |
|------|------|
| 支委会例会（每周/双周） | 条条+块块汇报进展、交叉议题讨论 |
| 公邮通知 | 制度性发布、块块组长传达 |
| 网页系统 | 党务管理三委面板 + 活动党建工作台 |

### F.4 协同决策

- 活动策划：块块提案 → 条条审核合规 → 书记审批
- 制度制定：条条起草 → 块块反馈 → 支委会通过
- 紧急事项：条条/块块发起 → 书记直接决策 → 事后补流程

### F.5 冲突解决

| 场景 | 解决方式 | 决策者 |
|------|---------|--------|
| 条条要求与块块能力不匹配 | 协商调整或增配资源 | 书记仲裁 |
| 多条条对同一块块下达矛盾任务 | 优先级：组织>纪检>宣传 | 书记仲裁 |
| 块块对条条规范有异议 | 块块书面反馈，条条7日回应 | 支委会裁决 |
| 支委兼任组长时冲突 | 主身份优先，涉及本人审核主动回避 | — |

## G. 季度评审机制

| 评审对象 | 指标 | 达标标准 |
|---------|------|---------|
| 条条 | 职能任务完成率 / 合规率 | ≥90% / ≤10% |
| 块块 | 活动执行率 / 参与率 / 满意度 | ≥95% / ≥85% / ≥4.0/5.0 |
| 交叉 | 协作效率（平均完成周期） / 响应时间 / 冲突解决率 | ≤7天 / ≤24h / 100% |
