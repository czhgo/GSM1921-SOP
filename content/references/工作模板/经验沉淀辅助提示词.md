# 经验沉淀辅助提示词

> **定位**：通用提示词模板，用于辅助深度参与者（归档沉淀维护角色）从日常工作沟通、决策原始材料中提炼可复用的经验知识。
> **原则**：复盘是过程中的工作，边做边学边沉淀。不是事后补写，而是持续积累。

---

# 第一部分：使用说明

## 谁用

深度参与者中承担"归档沉淀维护"角色的人员。

## 何时用

- **活动场景**：活动结束后1周内，在关键节点（里程碑完成、重要决策后、阶段性复盘时）
- **专班场景**：专班运作过程中，每完成一个阶段目标后

## 输入什么

工作群聊记录、决策讨论截图、会议纪要、工作文档草稿等原始材料。

## 输出到哪里

提炼结果经人工审核后，写入 `content/insights/` 对应文件。

## 按场景选择提示词

本模板提供两类差异化提示词，按工作性质选择：

| 工作性质 | 适用场景 | 提示词侧重 |
|---------|---------|-----------|
| **合规性** | 三会一课、发展党员、考勤监督、档案审查等党务工作 | 制度合规、流程规范、风险防范 |
| **探索性** | 主题党日、品牌活动、学术共建、宣传策划等党建工作 | 创新方法、协作效率、可复用模式 |

> **判断标准**：合规性工作有明确的制度条文作为准绳，探索性工作没有标准答案需要创新尝试。

## 与仓库沉淀体系的关系

- **Guides**（`content/guides/`）：设计理念——不管功能是否完成，设计理念始终存在
- **Insights**（`content/insights/`）：经验沉淀——从实践中提炼的可复用模式
- **Decision Log**（`.ctx/logs/DECISION_LOG.md`）：决策记录——为什么这样做
- **Execution Log**（`.ctx/logs/YYYY-MM-EXECUTION_LOG.md`）：执行记录——做了什么

本提示词产出的经验，经人工审核后归入 Insights 体系，与决策日志蒸馏形成互补。

# 第二部分：提示词正文

## 通用提示词（所有场景共用）

```
你是一位经验沉淀助手。你的任务是从以下工作沟通/决策原始材料中，提炼出可复用的经验知识。

## 输入材料

{在此粘贴工作沟通记录、决策讨论、会议纪要等原始材料}

## 基本信息（从材料中提取）

| 项目 | 内容 |
|------|------|
| 活动或专班名称 | |
| 时间 | |
| 类型 | 合规性 / 探索性 |
| 负责人 | |
| 参与人数 | |

## 目标达成情况

| 原定目标 | 达成？ | 一句话说明 |
|---------|--------|-----------|
|  | ✅ / ⚠️ / ❌ | |

## 提炼要求

1. **识别模式**：从材料中识别出反复出现的工作模式、决策逻辑、协作方式
2. **正反两面**：对每个经验点，同时回答"为什么是这样"和"为什么不是那样"
3. **场景还原**：保留足够的上下文，让未参与的人也能理解经验适用的场景
4. **边界标注**：标明经验的适用范围和不适用的场景

## 输出格式

对每个提炼出的经验点，按以下格式输出：

### 经验：<一句话概括>

- **适用场景**：<什么情况下用>
- **具体做法**：<怎么做>
- **为什么这样做**：<背后的逻辑>
- **为什么不那样做**：<常见误区的反面论证>
- **边界条件**：<什么时候不适用>

## 执行摘要

- **做得好的（可复用的）**：
  -
- **卡壳/出问题的（如实写）**：
  -
- **下次怎么改（具体，不要写"下次做好"）**：
  -

## 后续行动

| 行动 | 责任人 | 截止 |
|------|--------|------|
|  |  |  |

## 注意事项

- 不要编造材料中不存在的经验
- 经验应当是可操作的，不是空泛的原则
- 如果材料不足以提炼经验，直接说明"材料不足，无法提炼"
- 留出开放空间：如果材料暗示了某种模式但证据不足，标注为"待验证假设"而非确定结论
```

## 合规性工作补充提示词

> 在通用提示词基础上，追加以下提炼维度。适用于：三会一课、发展党员、考勤监督、档案审查等。

```
## 合规性工作额外提炼维度

1. **制度对照**：本次工作涉及哪些制度条文？实际执行与制度要求是否有偏差？
2. **风险点**：过程中是否出现合规风险？如何规避？
3. **流程优化**：现有流程是否有冗余步骤？哪些步骤可以简化但不影响合规？
4. **补课机制**：如有缺勤或遗漏，补课流程是否顺畅？有何改进？

## 合规性经验输出格式

### 合规经验：<一句话概括>

- **涉及制度**：<哪条制度/规范>
- **实际偏差**：<执行与制度的差距>
- **修正方案**：<如何消除偏差>
- **预防措施**：<下次如何避免>
```

## 探索性工作补充提示词

> 在通用提示词基础上，追加以下提炼维度。适用于：主题党日、品牌活动、学术共建、宣传策划等。

```
## 探索性工作额外提炼维度

1. **创新点**：本次工作有哪些创新做法？效果如何？
2. **协作效率**：团队协作是否顺畅？沟通成本如何？有无更好的分工方式？
3. **可复用模式**：本次做法能否标准化为可复用模式？适用范围多大？
4. **参与反馈**：参与者反馈如何？哪些环节参与度最高/最低？

## 探索性经验输出格式

### 创新经验：<一句话概括>

- **创新做法**：<具体做了什么不同的事>
- **效果验证**：<怎么证明有效>
- **推广条件**：<其他团队/场景要复用需要什么条件>
- **失败风险**：<什么情况下这个创新会失效>
```

## 迭代版提示词

> **适用场景**：已有经验沉淀文本，新一轮实践完成后，需要将新实践与已有经验对比，更新沉淀内容。
> **与初版的区别**：初版从零提炼，迭代版需要带着已有经验去审视新实践——验证、修正、补充。

### 迭代版通用提示词

```
你是一位经验沉淀助手。你的任务是将新一轮工作实践与已有经验沉淀进行对比，识别验证、修正和新增，输出更新后的经验沉淀。

## 输入材料

### 已有经验沉淀

{在此粘贴 content/insights/ 中已有的经验沉淀文本}

### 新一轮实践材料

{在此粘贴本次工作沟通记录、决策讨论、会议纪要等原始材料}

## 基本信息（从新材料中提取）

| 项目 | 内容 |
|------|------|
| 活动或专班名称 | |
| 时间 | |
| 类型 | 合规性 / 探索性 |
| 负责人 | |
| 参与人数 | |

## 对比分析要求

1. **逐条对照**：将新材料中的实践与已有经验逐条对比，不遗漏
2. **验证强化**：已有经验在新实践中再次得到印证的，标注新证据
3. **条件修正**：已有经验的适用条件被新实践缩小/扩大/改变的，标注修正
4. **新增发现**：新实践中出现的、已有经验未覆盖的模式，标注为新增
5. **推翻标记**：已有经验被新实践明确否定的，标注推翻及理由（后推翻前原则）
6. **正反两面**：对每个修正和新增点，仍需回答"为什么是这样"和"为什么不是那样"

## 输出格式

### 一、验证强化

> 已有经验在新实践中再次得到印证。

#### 经验：<已有经验的一句话概括>

- **已有表述**：<原文摘录或概括>
- **新证据**：<新实践中什么情况再次印证了这条经验>
- **强化结论**：<是否需要收紧/放宽适用条件，还是维持不变>

### 二、条件修正

> 已有经验的适用条件被新实践修正。

#### 经验：<已有经验的一句话概括>

- **原表述**：<原文摘录或概括>
- **原适用条件**：<之前认为的适用范围>
- **新实践情况**：<新实践中发生了什么不同的情况>
- **修正后适用条件**：<调整后的适用范围>
- **修正理由**：<为什么需要修正，新实践揭示了什么之前未考虑的因素>

### 三、新增经验

> 新实践中出现的、已有经验未覆盖的模式。

#### 经验：<一句话概括>

- **适用场景**：<什么情况下用>
- **具体做法**：<怎么做>
- **为什么这样做**：<背后的逻辑>
- **为什么不那样做**：<常见误区的反面论证>
- **边界条件**：<什么时候不适用>

### 四、推翻

> 已有经验被新实践明确否定。

#### 经验：<已有经验的一句话概括>

- **原表述**：<原文摘录或概括>
- **推翻证据**：<新实践中什么情况明确否定了这条经验>
- **推翻理由**：<为什么原经验不再成立>
- **替代表述**：<如果有的话，用什么新经验替代>

## 迭代摘要

| 类别 | 数量 | 关键条目（一句话） |
|------|------|-------------------|
| 验证强化 | | |
| 条件修正 | | |
| 新增经验 | | |
| 推翻 | | |

## 执行摘要

- **本次迭代最大的认知变化**：<一句话>
- **最需要关注的风险**：<条件修正或推翻中隐含的风险>
- **下次迭代应重点关注**：<哪些经验仍待验证>

## 注意事项

- 不要为了"有变化"而强行修正——验证强化同样是有效的迭代结果
- 推翻必须基于明确证据，不能仅凭一次异常就推翻（除非异常本身揭示了结构性问题）
- 条件修正要写清楚"从什么变成什么"，不能只写"条件变了"
- 新增经验的标准与初版一致：可操作、有正反两面、有边界
- 如果新材料不足以与已有经验进行对比，直接说明"材料不足，无法迭代"
```

### 迭代版合规性补充提示词

```
## 合规性工作额外对比维度
```

### 迭代版探索性补充提示词

> 在迭代版通用提示词基础上，追加以下对比维度。适用于探索性工作的经验迭代。

```
## 探索性工作额外对比维度

1. **创新点验证**：之前的创新做法在新实践中是否仍然有效？效果是否如预期？

- **结论**：<可稳定复用 / 需附加条件 / 不建议复用>

### 创新经验条件修正

#### 经验：<已有创新经验概括>
```
